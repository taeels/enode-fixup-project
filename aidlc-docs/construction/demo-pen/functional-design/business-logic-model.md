# 흐름 — demo-pen

화면이 보여야 하는 흐름 다섯. 시안은 각 흐름의 정지 화면을 한 장씩 갖는다.

## F1. 들어오기

```text
   브라우저 열림
     |
     v
   캐시에 user_<번호> 있나?
     | 없다                          | 있다
     v                               v
   first_visit = true              D1 (번호를 보이고 같은 버튼)
   D0 온보딩 카드 (타 팀원)            |
     |                               |
     v                               v
   D1 [Guest 로그인] --> 번호 배정 --> D2
     |
     v
   tour_done 이 false 면 D3 를 얹는다
```

## F2. 투어

```text
   D3 1/4 웹캠 --다음--> 2/4 노드 현황판 --다음--> 3/4 현재 작업 목록
      --다음--> 4/4 새 작업 --시작하기--> D2   (tour_done = true)
   어느 스텝에서든 [건너뛰기] --> D2   (tour_done = true)
```

## F3. 새 작업 보내기

```text
   D2 [새 작업] --> D4
   D4 [LED Toggle 작업 요청] 또는 [사운드 재생 작업 요청]
     --> 프리셋 계약을 POST /v1/runs 로 보낸다 (코드 회차)
     --> 201: 새 run 이 목록 맨 위 · 선택됨 · 좌 상단이 run 뷰 (D5)
     --> 409 CodeAllBusy 또는 QUEUED: 목록에 QUEUED 로 오르고 D5 는 미배정
         슬롯만 보인다.  「노드가 다 차 있으면 기다린다」가 여기서 보인다
     --> 422 CodeNoCandidate: 목록에 FAILED 로 오른다.  시안은 그리지 않는다
   D4 [닫기] --> D2
```

## F4. run 보기

```text
   D2 우 열 Run 행 클릭 --> 좌 상단 패널이 그 run 의 3D run 뷰 (D5)
   D5 단계 클릭 --> 상세 카드 갱신
   D5 모형 클릭 --> 노드 상세 패널
   D5 [함대로] --> D2
   D5 다른 Run 행 클릭 --> 그 run 의 D5
```

## F5. 갱신

```text
   폴링 (간격은 decisions.md 2절).  화면은 「마지막 갱신 n초 전」 자리만 둔다
   실패가 쌓이면 카운트다운을 멈추고 상단바에 표시 (S1b 와 같다).  시안은 그리지 않는다
   웹캠은 폴링과 무관하다.  브라우저가 직접 받는다
```

## 시안이 그리는 정지 화면

```text
   D1   F1 의 첫 방문 · 버튼 누르기 전
   D2   F1 이 끝난 직후 · 함대 뷰 · 투어 없음
   D3   F2 의 1/4
   D4   F3 의 버튼 고르기 전
   D5   F3 이 201 로 끝난 직후 · led-toggle-0417 선택 · flash.led 가 RUNNING
```
