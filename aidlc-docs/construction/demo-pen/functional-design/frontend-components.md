# 화면 사양 — demo-pen (아트보드 D1~D5)

이 문서가 `design/enode-demo.pen` 을 그리는 사양이다. 값은 지어내지 않는다 —
enum 은 `design/README.md` 6절의 원문, 필드는 `GET /v1/nodes` · `GET /v1/runs`
· `GET /v1/runs/{id}` 가 주는 것만. 샘플 값(run_id · 노드 label · 시각)은
그림을 채우는 것이지 계약이 아니다.

## 0. 공통

```text
   아트보드 크기      1920 x 1080 (Q6: B).  데모 전시용 큰 화면
   테마              기존 S0~S7 과 같은 다크.  색 · 글꼴 · 카드 결을 그대로 쓴다
   상단바            좌: 「enode 데모 현황판」 · 우: observed_at · 마지막 갱신 ·
                     뷰 전환 칩 [격자 | 그래프 | 3D] · 게스트 배지 「user_4821」
   게스트 배지        Q2: 이름을 뽑지 않는다.  user_<번호> 하나.  브라우저 캐시가 구분
   틀                D2 · D3 · D4 · D5 는 한 틀이다 — 좌 열(3D 패널 + 웹캠) ·
                     우 열(현재 작업 목록).  D3 · D4 는 D2 위에 얹는 층이고
                     D5 는 좌 상단 패널만 바뀐다.  우 열은 어느 장에서도 안 가려진다
```

## 1. D1 — 데모 진입 (Guest 로그인)

S0 의 틀(가운데 카드 · 폭 610)을 유지하고 토큰 입력을 뺀다.

```text
   제목        enode 데모 현황판
   설명        토큰 없이 들어간다.  이 브라우저에 user_<번호> 를 배정하고
               그 번호로 사람을 가른다.  실물 보드 함대에 작업을 보낼 수 있다
   버튼        [Guest 로그인]  primary · 폭 전체
   각주        번호는 이 브라우저에만 남는다.  지우면 새 번호를 받는다
```

버튼 전수: **Guest 로그인** (-> D2. 첫 방문이면 D3 가 위에 얹힌다).

## 2. D2 — 데모 현황판 본판

### 2.1 좌 상단 — 3D 함대 탑뷰 (S6 이식)

```text
   헤더        함대  ·  GET /v1/nodes  ·  N 노드      우측: 범례 (S1 과 같은 다섯)
   평면        아이소메트릭 격자.  노드마다 로우폴리 모형 하나
               워크스테이션 = 모니터 + 타워    보드 = 칩
   상태색      작업 중인 노드만 화면(모니터/칩 윗면)이 켜진다.  색은 S1 배지와 같다
               임대 없음 초록 · 임대 중 파랑 · draining 보라 · 만료 임박 회색 흐림 ·
               사람 대기 주황
   이름표      모형 아래 label 만 (ADR-065 — principal 을 내지 않는다)
   상호작용    모형 클릭 -> 노드 상세 패널 (패널 우상단에 작은 카드로.  S6 과 같다)
```

노드 여섯을 샘플로 둔다 — S1 과 같은 여섯 상태가 한 번씩 보이게.

### 2.2 좌 하단 — 웹캠

```text
   헤더        웹캠  ·  실물 보드 함대  ·  LIVE 점
   본문        16:9 영상 자리.  회색 플레이스홀더 + 「카메라 1 · 보드 선반」
   각주        영상은 브라우저가 직접 받는다.  Mediator 를 거치지 않는다
```

버튼 없음.

### 2.3 우 열 — 현재 작업 목록

```text
   헤더        현재 작업 목록  ·  GET /v1/runs  ·  시간 역순
   버튼        [새 작업]  primary · 폭 전체  (-> D4)
   필터 칩     [전체] [RUNNING] [QUEUED] [SUCCEEDED] [FAILED]   기본 선택: 전체
   행 (C2)     run_id · 상태 배지(enum 원문) · 한 줄 요약 (노드 · 단계 · 시각)
               클릭 -> 좌 상단 패널이 그 run 의 3D run 뷰로 바뀐다 (D5)
   안내 상자   QUEUED 인 Run 은 어느 모형에도 안 얹힌다.  대기가 보이는 자리는 이 목록뿐이다
   하단        페이지네이션 자리만 (S1 과 같다)
```

샘플 행 여섯: RUNNING 둘 · QUEUED 둘 · SUCCEEDED 하나 · FAILED 하나.
run_id 는 데모 작업 이름을 딴다 — `led-toggle-0417` · `sound-play-0416` 꼴.

### 2.4 버튼 전수 (D2)

```text
   상단바      뷰 전환 칩 격자 · 그래프 · 3D      (3D 가 선택된 상태)
   좌 상단     노드 모형 클릭 -> 노드 상세 패널
   우 열       새 작업 -> D4
               필터 칩 다섯
               Run 행 클릭 -> D5
```

## 3. D3 — 가이드투어 (D2 위의 층, 첫 방문)

Q5: A 스포트라이트. D2 를 검게 덮고(불투명 72%) 대상 영역만 뚫어 밝힌다.
말풍선은 대상 옆에 붙고 꼬리가 대상을 가리킨다.

```text
   스텝  대상            제목                 본문 (한 줄)
   1/4   웹캠            실물이 여기 있다      화면의 노드는 저 선반의 보드다.  작업이 가면 LED 가 켜진다
   2/4   노드 현황판      누가 놀고 있나        모형의 화면이 켜진 것이 일하는 노드다.  꺼진 것은 놀고 있다
   3/4   현재 작업 목록   기다리는 작업         노드가 다 차면 여기서 QUEUED 로 기다린다
   4/4   새 작업         직접 보내 보자        버튼 하나로 보드에 작업을 보낸다.  결과는 웹캠으로 본다
```

말풍선 구성: 진행 「1 / 4」 · 제목 · 본문 · [건너뛰기] (ghost) · [다음] (primary,
4/4 에서는 [시작하기]).

아트보드에는 **1/4 (웹캠) 상태**를 그린다. 나머지 셋의 글은 아트보드 밖 주석
카드에 표로 적는다 — 구현이 그 표를 그대로 옮긴다.

버튼 전수: **다음** · **건너뛰기** · (4/4) **시작하기**. 셋 다 -> D2.

## 4. D4 — 새 작업 모달 (D2 위의 층)

Q1: 계약을 적지 않는다. 버튼 둘.

```text
   덮개        D2 를 검게 덮는다 (불투명 60%).  우 열도 덮이지만 목록 윤곽은 비친다
   카드        가운데 · 폭 720
   제목        새 작업                                          우상단 [x 닫기]
   설명        보드 함대에 보낼 작업을 고른다.  계약은 데모가 미리 적어 두었다
   버튼 1      [LED Toggle 작업 요청]    부제: 보드의 LED 를 켜고 끈다.  웹캠으로 확인
   버튼 2      [사운드 재생 작업 요청]    부제: 보드의 스피커로 소리를 낸다
   각주        제출하면 이 run 의 3D 뷰로 넘어간다.  노드가 다 차 있으면 QUEUED 로 기다린다
```

버튼 전수: **LED Toggle 작업 요청** · **사운드 재생 작업 요청** (둘 다 제출 ->
D5, 새 run 이 목록 맨 위에 오르고 선택된다) · **닫기** (-> D2).

## 5. D5 — 작업 그래프 (좌 상단 패널이 run 뷰)

Q3 · Q4: D2 의 틀 그대로. 좌 상단 패널만 S7 run 뷰로 바뀐다. 우 열은 그대로
살아 있고 선택된 run 행이 밝다. 웹캠도 그대로다.

```text
   패널 헤더   [<- 함대로]  함대 / led-toggle-0417  [RUNNING]     우측: 범례
               (DONE 초록 · RUNNING 파랑 · PENDING 주황 · SKIPPED 회색 · ASKED 노랑)
   평면        아이소메트릭.  단계(step)가 노드다.  needs[] 가 간선이다
               배정된 단계   그 기계의 로우폴리 모형 + 단계 이름 + state 배지
               미배정 단계   슬롯 마커 (점선 바닥판) + 「노드 미배정」
               chosen=false  흐리게 (S2 의 SKIPPED 와 같다)
   상세 카드    패널 우상단 작은 카드 「선택한 단계」 — state · node · attempt ·
               started_at · needs[] · chosen.  S2 우측 패널의 축소판
   상호작용    단계 클릭 -> 상세 카드 갱신
               모형 클릭 -> 노드 상세 패널 (D2 와 같다)
               [<- 함대로] -> D2
```

샘플 run: `led-toggle-0417` · 단계 셋 `plan -> flash.led -> verify` ·
`flash.led` 가 RUNNING 이고 board-01 에 배정.

버튼 전수 (D5): **함대로** (-> D2) · 단계 클릭 · 노드 모형 클릭 · 우 열의
**새 작업** · 필터 칩 · Run 행 클릭(다른 run 으로 전환) · 상단바 뷰 전환 칩.

## 7. 아트보드 밖 주석 (pen 에 노트로 둔다)

- D0 온보딩 카드는 다른 팀원의 시안이다. 첫 방문의 순서: D0 -> D1 -> D2 + D3
- 첫 방문 판정과 user_<번호> 는 브라우저 캐시에 산다 (business-rules.md R1 · R2)
- 3D 모형은 `enode-ux.pen` S6 · S7 의 것을 복사한다. 새로 만들지 않는다
- 폴링 간격 · 임계값은 그리지 않는다 (design/README.md 5절)
