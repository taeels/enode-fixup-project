# Business Rules — cardnews-guest-login

## BR-1 Guest Login 의 분기

`enterGuest()` 는 `guest.hasOnboarded()` 를 딱 한 번 읽는다.

- `false`(첫 방문) -> `/ui/cardnews/` 로 이동
- `true`(재방문) -> `/ui/demo/` 로 곧장 이동. 카드뉴스 페이지를 절대
  거치지 않는다(요청 서버 로그도 없다 — 정적 파일이라도 요청 자체가 안 남)

## BR-2 카드 인덱스는 0 ~ 3 을 벗어나지 않는다

- 초기값 0
- `prev()` 를 인덱스 0 에서 부르면 아무 일도 없다(감소하지 않는다).
  이전 버튼은 인덱스 0 에서 `disabled` 속성을 받는다
- `next()` 를 인덱스 3(마지막 카드)에서 부르면 인덱스를 증가시키지
  않고 `finish()` 를 부른다. 마지막 카드의 다음 버튼 라벨은 "다음" 이
  아니라 "현황판 보기" 로 바뀐다(BR-4)

## BR-3 종료는 한 곳으로 모인다

닫기 버튼 · 마지막 카드의 "현황판 보기" 버튼 · (있다면) `Escape` 키
전부 `finish()` 하나를 부른다. `finish()` 의 몸통은 정확히 둘 —
`guest.markOnboarded()` 그리고 `window.location.href =
"/ui/demo/"`. 순서가 중요하다 — 저장이 이동보다 먼저다(이동 뒤에는
그 페이지의 JS 컨텍스트가 사라진다).

## BR-4 카드 콘텐츠는 정적 배열이다

```js
const CARDS = [
  { title: "...", body: "..." },  // index 0: 소개
  { title: "...", body: "..." },  // index 1: 시나리오 1 (구형 보드)
  { title: "...", body: "..." },  // index 2: 시나리오 2 (동료 보드 공유)
  { title: "...", body: "..." },  // index 3: 마무리 (CTA)
]
```

문안은 `frontend-components.md` §2 가 확정한다. 서버가 이 배열을
내려주지 않는다 — `cardnews.js` 안의 상수다(`services.md` 의
"CardContentService 를 안 둔다" 결정 그대로).

## BR-5 로컬 저장소 실패는 조용히 흡수한다

`localStorage` 접근(사생활 모드 · 저장소 차단 브라우저에서 던질 수
있다)은 항상 `try/catch` 로 감싼다. 실패하면:

- `hasOnboarded()` 는 `false` 를 돌려준다(매번 카드를 보여주는 쪽이
  안전 — "관리자 인증을 건너뛴다" 류의 실패가 아니라 "카드를 한 번 더
  본다" 류의 실패이므로 열린 쪽 실패가 사용자에게 해롭지 않다)
- `markOnboarded()` 는 예외를 삼키고 아무 일도 안 한다(다음에도 카드가
  다시 뜬다 — 데이터 손실이 아니라 반복일 뿐이다)
- `guestName()` 은 저장에 실패해도 그 세션(같은 페이지 로드) 동안
  메모리에 쥔 이름을 돌려준다. 새로고침하면 새 이름이 생성된다

## BR-6 Guest 식별은 서버로 안 나간다

`guest.js` 어디에도 `fetch` · `XMLHttpRequest` · `<form>` 제출이
없다. 이름은 화면 표시(데모 placeholder 의 "Guest — <이름>" 문구)
용도로만 쓰인다. 이 규칙은 코드 리뷰로 검증한다(네트워크 호출 자체가
없으므로 자동화된 정적 검사가 필요 없다 — 만들지 않은 것을 테스트할
수는 없다).

## 관리자 흐름 회귀 방지 (US-5)

이 유닛은 `internal/api/api.go` 의 기존 15개 라우트 등록 줄을 **하나도
고치지 않는다.** 더하는 것은 새 줄 하나(`GET /ui/`)뿐이다. 랜딩 화면의
관리자 로그인 영역은 `<form>` 이 없는 정적 자리표시다 — 제출할 동작이
없으므로 회귀시킬 동작 자체가 없다.
