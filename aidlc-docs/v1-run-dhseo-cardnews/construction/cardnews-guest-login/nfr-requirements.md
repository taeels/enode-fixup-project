# NFR Requirements — cardnews-guest-login

## 확장 적용 범위

`security-baseline` 이 켜져 있다(`decisions.md` §1 · §8.3). 이 유닛이
만드는 표면은 정적 HTML 서빙 하나뿐이라 열다섯 규칙 대부분이 **해당
없음**이다 — 데이터 저장소 · 네트워크 구성 · 로그인 흐름 · 서버 쪽
사용자 입력이 이 표면에 없기 때문이다. 아래는 규칙별 적용 여부와,
적용되는 것에 대한 요구 수준이다. 구체 구현은 `nfr-design.md`.

| 규칙 | 적용 | 요구 |
|---|---|---|
| SECURITY-01 암호화 | 해당 없음 | 데이터 저장소가 없다 |
| SECURITY-02 접근 로깅 | 해당 없음 | 이 유닛이 새 로드밸런서/게이트웨이를 안 둔다 |
| SECURITY-03 애플리케이션 로깅 | 해당 없음 | 서버 쪽 로직이 없다(정적 파일 서빙에 비즈니스 로그가 없다) |
| SECURITY-04 HTTP 보안 헤더 | **적용** | `GET /ui/*` 가 HTML 을 낸다 — CSP · HSTS · X-Content-Type-Options · X-Frame-Options · Referrer-Policy 다섯을 전부 응답에 실어야 한다 |
| SECURITY-05 입력 검증 | 해당 없음 | 서버가 받는 사용자 입력이 없다(전부 `GET`, 바디 없음) |
| SECURITY-06 최소 권한 | 해당 없음 | IAM/클라우드 정책 대상이 아니다 |
| SECURITY-07 네트워크 구성 | 해당 없음(기존 코드 사실) | Mediator 의 바인딩은 기존 사실 — 이 유닛이 안 바꾼다 |
| SECURITY-08 접근 제어 | **적용 — 문서화된 예외** | `GET /ui/*` 는 명시적 public 표면이다. 인증을 안 거는 것이 요구사항(`enode-features.md` §3.4.1)이지 누락이 아니라는 것을 여기 문서로 남긴다 |
| SECURITY-09 하드닝 | **적용** | 디렉터리 목록이 꺼져 있어야 한다. 에러 응답(404)이 스택 트레이스를 안 보여야 한다 |
| SECURITY-10 공급망 | **적용 — 이미 만족** | 새 의존을 안 받는다(`go.mod` 불변, JS 라이브러리 0). 지킬 것이 늘지 않는다 |
| SECURITY-11 보안 설계 | **부분 적용** | 인증/결제 같은 민감 로직이 없어 "격리" 항목은 해당 없음. 다만 "오용 사례 고려"는 적용 — Guest 식별이 인증으로 오인되지 않게 설계 문서화가 요구된다(BR-6) |
| SECURITY-12 인증 · 자격증명 | 해당 없음 | 이 표면에 인증이 없다. Guest 식별은 인증이 아니다(설계로 확정, `domain-entities.md`) |
| SECURITY-13 무결성 검증 | 해당 없음 | 역직렬화 대상 · CDN 스크립트가 없다(새 의존 0) |
| SECURITY-14 경보 · 모니터링 | 해당 없음 | 보안 이벤트(로그인 실패 등)가 발생할 표면이 없다 |
| SECURITY-15 예외 처리 | **적용 — 좁은 범위** | `localStorage` 접근 실패를 안전하게 흡수해야 한다(BR-5). 서버 쪽은 표준 `http.FileServerFS` 의 404 가 이미 안전한 기본값이다 |

## 비-보안 NFR

- **성능**: 정적 파일 하나당 요청 하나. 별도 성능 목표를 안 세운다 —
  파일 크기가 수 KB 대라 임계값을 잴 이유가 없다
- **신뢰성**: 실패 모드가 404 뿐이다(파일이 embed 에 없으면). 빌드
  타임에 전부 포함되므로 런타임에 파일이 사라질 수 없다
- **유지보수성**: `constraints.md` 의 패키지별 커버리지 하한 80% 를
  `internal/api/ui` 에 적용한다(`decisions.md` 8.2)
- **접근성**: `frontend-components.md` §2.5 — 키보드 내비게이션 ·
  `aria-live` 진행 표시
