# U5 `panel-live` — Functional Design 계획 (Part 1)

```text
   유닛     panel-live (U5) · 웨이브 W-c · 브랜치 unit/panel-live
   맡는 것   FR-4 의 절반 (도는 것).  지난 것은 U6 이다
            NC-1 경과 · NC-2 링 잘림 · NC-3 링 잔여 · requirements 5.5 보안 헤더
   지는 게이트  **CB1**.  뒤의 셋(U6 · U7 · U8)이 전부 딛는다
   기준선    05ee710.  W-b 가 병합된 main.  라우트 18
```

이 문서는 **묻는 것**이다. 답이 오면 5절의 순서로 산출물 셋을 낸다.

## 0. 이 단계가 닫는 것과 안 닫는 것

```text
   닫는다     사건이 어디서 나는가 (제어판이냐 브라우저냐) · 폴링 응답의 모양 ·
             경과와 잘림과 잔여를 무엇으로 재는가 · 원문 토글의 출처 ·
             보안 헤더 다섯을 이 페이지에 어떻게 거는가

   안 닫는다   코드.  Code Generation 이 낸다
             지난 것 (U6) · 노드 업로더 (U7) · 현황판 카드 (U8)
             파서 자체 (U1 이 닫았다).  링의 쓰는 쪽 (U2 가 닫았다)
             GET log 라우트 (U4 가 닫았다) — 이 유닛은 Mediator 를 안 탄다
```

**이 유닛이 Mediator 를 안 타는 것이 배치의 값이다.** 링을 직접 읽으므로 U4 의
라우트가 빨개도 CB1 을 잴 수 있다. 딛는 것은 U1 의 파서와 U2 의 tee 다.

## 1. 실측 — 코드가 지금 어떻게 생겼나 (2026-09-16 · 05ee710)

**계획을 짓기 전에 읽었다.** W-a 가 배우고 W-b 가 다시 확인한 것이다 — 문서가
코드와 갈린 자리는 계획을 짓는 동안에만 싸게 찾힌다. **W-b 는 그렇게 다섯을
찾았다.** 이번에는 여섯이고, 그중 하나가 이 유닛의 범위를 정면으로 바꾼다.

### 1.1 `handleTranscript` 는 파싱을 0 한다 — 링 바이트를 그대로 넘긴다

```go
   transcript.go:20   snap, err := enode.ReadRing(enode.TranscriptPath(s.cfg.ConfigPath))
   transcript.go:26   writeJSON(w, map[string]any{
                        "available": true, "generation": snap.Generation,
                        "total": snap.Total, "data": string(snap.Data)})
```

화면도 파싱을 안 한다 — `page.go:266` 이 `pre.textContent = t.data` 한 줄이다.
**오늘 제어판에 보이는 것은 하네스의 JSON 원문 그대로다.** 문장도 도구 이름도
없다. `total` 은 이미 응답에 실려 있는데 화면이 안 그린다 (`user-stories.md`
NC-2 가 적은 그대로다).

### 1.2 `page.go` 는 통짜 인라인이라 `default-src 'self'` 가 이 페이지를 죽인다

**이것이 이 실측의 가장 무거운 것이다.**

```text
   page.go 안에 있는 것   <style> 한 벌 · <script> 한 벌 ·
                        onclick= 아홉 · style= 속성 다수
                        전부 indexHTML 문자열 상수 하나에 산다
```

`requirements.md` 5.5 는 **「`ui.go:64-71` 과 같은 다섯 줄이다」** 로 적었다. 그
다섯 중 하나가 `Content-Security-Policy: default-src 'self'` 다. **그 한 줄을
글자 그대로 걸면 인라인 스타일과 인라인 스크립트가 전부 막힌다** — 제어판이
스타일 없는 맨 HTML 로 뜨고 버튼 아홉이 전부 죽는다.

**`/ui/` 가 그 헤더로 사는 이유는 구조가 달라서다** — 거기는 `static/` 아래 파일을
따로 낸다 (`.mjs` · `.css`). 제어판은 그런 자리가 0 이다.

```text
   즉  「같은 다섯 줄」이 이 페이지에는 같은 다섯 줄이 아니다.
      5.5 를 쓴 자리가 page.go 의 모양을 안 보고 썼다
```

물음 1 이 이 자리다. **범위가 는다고 요구가 적은 자리이므로 임의로 못 줄인다.**

### 1.3 `Snapshot` 에 용량이 없다 — `truncated` 를 못 채운다

```go
   transcript.go:48   type Snapshot struct { Data []byte; Generation, Total uint64 }
   parse.go:32        func Parse(b []byte, truncated bool) Result
```

`Parse` 는 **앞이 잘렸는지를 부르는 쪽이 말해 달라**고 한다. 잘렸다는 것은
`Total > capacity` 인데 **`Snapshot` 이 capacity 를 안 낸다.** 파일 머리에는
있다 (`hdr[8:16]`) — `ReadRing` 이 읽고 버린다.

NC-2 가 재는 것이 정확히 그 값이고, `requirements.md` 6절의 CB1 줄도
**「첫 줄이 잘린 채로도 파싱된다」**를 잰다. 물음 4 가 그 출처를 정한다.

### 1.4 파서는 시계를 안 받는다 — 경과는 화면이 뺀다고 파서가 적었다

```text
   parse.go:25   시계를 안 받는다.  같은 입력에 언제나 같은 Result 를 낸다 —
                 경과와 갱신 시각은 화면이 뺀다
```

**NC-1 의 출처가 파서 밖이라는 것을 파서가 이미 못 박았다.** 링에도 시각이
없다 — `Snapshot` 은 `Data` · `Generation` · `Total` 셋뿐이다. 물음 3 이 그
시계를 어디에 둘지 정한다.

### 1.5 「밀렸다는 표시는 앞 팩 그대로」가 거짓이다 — 앞 팩에 0 이다

`features.md` 3.3 과 `requirements.md` FR-4 가 둘 다 **「밀렸다는 표시는 앞 팩
그대로」**로 적었고, `scene-gates.md` 2.1 의 CB1 화면 검증도 **「밀렸다는 표시」**를
본다. `page.go` 를 다 읽었다 — **그런 표시가 없다.** 폴링이 실패하면
`.catch(function(){})` 가 조용히 삼키고 화면은 마지막 값을 그대로 들고 있다.

```text
   즉  CB1 이 「그대로 있는지」 볼 것이 아니라 이 유닛이 새로 짓는 것이다.
      NC-1 과 같은 것인지 다른 것인지가 물음 5 다
```

### 1.6 세대가 바뀔 때 비우는 코드가 사실상 없다

```js
   page.go:265   if(t.generation !== lastTxGen){ lastTxGen = t.generation; }
```

**비교하고 대입만 한다.** 오늘 이것이 안 틀리는 이유는 다음 줄이 `pre.textContent`
를 통째로 갈아치우기 때문이다 — 비울 것이 없다. **사건 열로 바뀌면 그 공짜가
없어진다.** 쌓아 그리는 모양이면 비우는 자리가 실제로 필요해진다.

### 1.7 링 전체가 매초 나간다 — 파싱을 더하면 그 비용이 는다

몸통이 512 KiB 다 (`DefaultTranscriptCapacity`). 폴링이 1초이므로 오늘도 최대
512 KiB/s 가 루프백으로 나간다. **파싱을 제어판이 지면 매초 512 KiB 를 다시
읽는다.** `requirements.md` 5.7 이 「파서 — 줄 단위. 전체를 메모리에 다시 담지
않는다」로 적었는데, 그것은 한 번 읽는 비용이지 **매초 반복하는 것**을 안 적었다.

`GET log` 는 `from=` 으로 이 자리를 닫았다 (FR-6). 제어판 API 에는 그런 것이
없다. 물음 2 가 그 자리다.

### 1.8 안 만져도 되는 것을 확인했다

```text
   경계 검사       internal/panel -> internal/transcript 는 금지 표에 없다.
                 panel 은 이미 internal/enode 를 임포트한다 (ReadRing).  새 금지 0
   handleRecord   U6 의 것이다.  이 유닛은 같은 파일의 다른 함수만 만진다
                 (파일 행렬 2절이 U5 -> U6 으로 순서를 박았다)
   데몬 로그 카드   그대로 옆에 있다.  이 유닛이 안 만진다 (FR-4)
   requireToken   그대로다.  LAN 노출의 토큰 규칙을 이 유닛이 안 바꾼다
```

## 3. 물음 여덟

형식은 `common/question-format-guide.md` 다.

**물음이 권장대로 닫혔다 (2026-09-16 · 사용자 「권장대로. 여기서도 nfr skip」).**
권장과 갈린 답이 0 이다 — 일곱이 A 이고 다섯째만 C 다 (거기 권장이 C 였다).

### Question 1 — 보안 헤더 다섯을 이 페이지에 어떻게 거나

1.2 가 낸 물음이다. `default-src 'self'` 를 글자 그대로 걸면 제어판이 죽는다.

```text
   A   넷을 그대로 걸고 CSP 만 이 페이지의 모양에 맞춘다 —
       default-src 'self'; style-src 'self' 'unsafe-inline';
       script-src 'self' 'unsafe-inline'
       인라인은 살고 **밖으로 나가는 길은 막힌다** (connect-src · img-src 가
       default-src 를 물려받는다).  어긋남을 decisions 에 적는다
   B   page.go 의 CSS 와 JS 를 static 파일로 갈라 내고 다섯을 글자 그대로 건다.
       /ui/ 와 같은 구조가 된다 — 진짜 CSP 다
   C   넷만 걸고 CSP 는 뒤 유닛으로 미룬다
```

**권장은 A 다.** 5.5 가 이 헤더를 요구한 이유는 **「이 회차가 신뢰할 수 없는
하네스 출력을 그린다」**이고, 5.6 ④ 가 그 위험의 일차 방어를 **「화면이
텍스트로만 그린다」**로, CSP 를 **「한 겹 더」**로 적었다. A 는 그 한 겹 중
실제로 값이 있는 부분을 지킨다 — **주입이 일어나도 밖으로 못 보낸다.**

**A 의 대가** — `'unsafe-inline'` 이 script 에 붙으므로 주입된 스크립트 자체는
CSP 가 못 막는다. 막는 것은 `esc()` 와 `textContent` 다. **그 둘이 유일한
방어가 되는 것을 이름으로 적는다.**

**B 가 정직한 답이다.** 대가는 이 유닛의 범위다 — `page.go` 312줄을 세 파일로
가르고 라우트를 더하고 시험을 다시 쓴다. **CB1 을 먼저 보는 것이 이 웨이브를
단독으로 둔 이유인데, B 는 그 눈을 뒤로 민다.**

**C 를 고르면** 5.5 가 안 닫히고 SECURITY-04 판정이 다시 조건부가 된다.

[Answer]: A

### Question 2 — 사건을 어디서 만드나 · 매초 무엇을 보내나

1.1 과 1.7 이 함께 내는 물음이다.

```text
   A   제어판이 internal/transcript 로 파싱해 사건 배열을 낸다.  매번 전체를
       파싱한다.  total 이 안 바뀌었으면 파싱을 건너뛰고 앞 답을 다시 낸다
   B   A 와 같되 from= 을 더해 새 바이트만 보낸다 (GET log 와 같은 모양)
   C   제어판은 지금처럼 원문을 보내고 브라우저가 JS 로 파싱한다
```

**권장은 A 다.** 파서가 한 벌인 것이 이 팩의 논지다 — C 는 **파서를 두 벌로
만든다** (`CONVENTIONS.md` 1.4 의 「도구는 두 벌로 두지 않는다」). 그리고 U6 ·
U8 이 Go 쪽 파서의 사건 배열을 그대로 받으므로, C 를 고르면 제어판만 다른 길로
간다.

**B 를 지금 안 하는 이유** — `from=` 은 **경계 상태를 브라우저에 둔다.** 링은
감기므로 브라우저가 든 오프셋이 이미 지나간 자리를 가리킬 수 있고, 그 복구
규칙이 U4 가 `GET log` 에서 판 것과 같은 크기의 일이다. **루프백에서 512 KiB 를
아끼려고 그 상태를 들이지 않는다.** 필요해지면 CB1 이 그 값을 낸다.

**A 의 짧은 길이 실제로 듣는 자리** — 침묵이다. 하네스가 수십 초 말이 없으면
`total` 이 안 변하고 파싱이 0 이 된다. **NC-1 이 필요한 바로 그 구간이 가장 싸다.**

[Answer]: A

### Question 3 — NC-1 의 경과를 무엇으로 재나

1.4 가 낸 물음이다. 파서에도 링에도 시각이 없다.

```text
   A   링 파일의 mtime.  제어판이 os.Stat 으로 읽어 「마지막 쓰기 이후 경과」를
       낸다.  Ring.Write 가 쓸 때마다 flushHeader 하므로 mtime 이 정확하다
   B   제어판이 기억한다 — total 이 바뀐 시각을 메모리에 들고 그 차를 낸다
   C   브라우저가 잰다 — total 이 바뀌면 타임스탬프를 리셋한다
```

**권장은 A 다.** 셋 중 **탭을 새로 열어도, 제어판을 다시 띄워도 같은 값**을
내는 것이 A 하나다. B 는 제어판 프로세스가 단계 도중에 뜨면 0 부터 세고, C 는
탭을 침묵 한가운데서 열면 **「방금 왔다」로 거짓말한다** — 그것이 정확히 NC-1 이
없애려는 오독이다 (US-1 「생각 중인지 멈춘 것인지」).

**A 의 대가** — 파일시스템의 mtime 해상도에 매인다. 1초 폴링에 초 단위면 족하다.
`Ring.Reset()` 도 머리를 써서 mtime 을 올리므로 **단계 시작이 경과 0 으로 잡힌다** —
맞는 값이다.

[Answer]: A

### Question 4 — NC-2 의 「앞이 잘렸다」를 무엇으로 아나

1.3 이 낸 물음이다. `Parse` 의 `truncated` 를 채워야 한다.

```text
   A   enode.Snapshot 에 Capacity 를 더한다.  ReadRing 이 이미 읽어 놓고
       버리는 값이다.  internal/enode/transcript.go 가 **파일 행렬 밖**이다
   B   panel 이 enode.DefaultTranscriptCapacity 상수를 쓴다.  행렬은 안 깨지나
       같은 사실이 두 자리에 산다
   C   Total 만 쓰고 잘림을 화면이 안 그린다 — NC-2 를 안 닫는다
```

**권장은 A 다.** `ReadRing` 이 `capacity` 를 지역 변수로 읽어 쓰고 버린다 —
**더하는 것이 필드 하나와 대입 한 줄이다.** B 는 링이 다른 용량으로 열리는 날
조용히 틀린다 (`OpenRing` 은 용량을 인자로 받는다 — 오늘 부르는 자리가 하나라
같을 뿐이다).

**행렬 밖인 것을 미리 적는다.** W-b 가 같은 모양을 둘 겪었고 (`record.go` ·
`transcript.go`) **병합 충돌이 0 이었다** — 이미 병합된 유닛의 파일이라 그렇다.
`internal/enode/transcript.go` 도 U2 가 이미 병합된 파일이다. **동작 diff 는
0 이다** — 읽는 값이 하나 더 나갈 뿐이다.

[Answer]: A

### Question 5 — 「밀렸다는 표시」가 NC-1 과 같은 것인가

1.5 가 낸 물음이다. 앞 팩에 그 표시가 0 이라 「그대로」가 가리킬 것이 없다.

```text
   A   같은 것이다.  마지막 사건 이후 경과 하나가 침묵도 정지도 밀림도 말한다
   B   다른 것이다.  경과(NC-1)와 별개로 「폴링이 실패하고 있다」를 따로 그린다
   C   같은 것으로 두되 폴링 실패는 카드를 회색으로 죽이는 것으로 가른다
```

**권장은 C 다.** A 와 B 가 각각 한쪽을 못 본다 — **경과만 그리면 폴링이 죽어도
경과가 멈춘 채 그럴듯하게 보이고** (마지막 성공 값이 화면에 남는다), 둘을 따로
그리면 읽는 사람이 두 수를 맞춰 봐야 한다.

C 는 하나를 그리고 **그 값을 믿을 수 있는지를 카드의 상태로 가른다.** 오늘
`.catch(function(){})` 가 조용히 삼키는 자리가 그 자리다 (1.5).

[Answer]: C

### Question 6 — 원문 토글의 바이트를 어디서 가져오나

CB1 이 **「원문 토글이 JSON 줄을 보인다」**를 잰다.

```text
   A   같은 응답이 사건 배열과 원문을 둘 다 싣는다.  토글은 그리기만 바꾼다
   B   토글을 켤 때 따로 요청한다 (?as=raw)
```

**권장은 A 다.** B 는 **두 번째 읽기가 다른 스냅샷을 본다** — 링은 계속 감기므로
토글을 켠 순간 사건 열과 원문이 다른 창을 보이고, 읽는 사람은 그것을 파서의
버그로 읽는다. A 는 **한 번 읽은 같은 바이트**를 두 모양으로 그린다.

**A 의 대가** — 응답이 두 배다 (최악 512 KiB + 사건 JSON). 루프백이고 상한이
링 용량에 묶여 있어 수락한다. 2 = A 의 짧은 길(`total` 불변이면 재사용)이 이
비용에도 그대로 듣는다.

[Answer]: A

### 5.2.1 모순 검사 결과 (2026-09-16) — 막은 것 둘 · 교차가 하나 더

**W-a 가 셋, W-b 가 유닛마다 하나씩 막았다. 이번에는 둘이다.**

#### 막은 것 ① — 2 = A 의 짧은 길이 3 = A 의 경과를 얼린다

2 = A 는 **「`total` 이 안 바뀌었으면 앞 답을 다시 낸다」**이고, 3 = A 는 mtime 으로
**경과**를 낸다. 둘을 글자 그대로 합치면 **제어판이 경과를 초 단위 수로 계산해
응답에 싣고, 그 응답이 캐시된다.**

```text
   침묵이 길어진다 -> total 이 안 바뀐다 -> 캐시가 나간다 ->
   경과가 「3초 전」에서 안 움직인다
```

**침묵이 바로 NC-1 이 있는 이유인데, 그 구간에서만 값이 언다.** 멈춘 것을
못 가리는 정도가 아니라 **시계가 멈춘 거짓말**이라 아무 표시도 없는 것보다 나쁘다.

**막는 것은 「응답에 기간을 안 싣는다」다** — 제어판은 **시각**(mtime)만 싣고
브라우저가 뺀다. 그러면 응답이 **바이트의 순수 함수**가 되어 캐시가 성립하고,
덤으로 표시가 폴링 사이에도 흐른다 (1초마다 계단이 아니다).

**캐시 열쇠에 mtime 을 넣는다.** `(generation, total)` 만으로는 링이 통째로 다시
만들어져 `(0, 0)` 으로 돌아온 자리가 옛 항목에 맞는다 (`OpenRing` 의 재초기화).

#### 막은 것 ② — 8 = A 의 통째 갈아 그리기가 CB1 의 「접힌 결과」를 못 펴게 한다

CB1 이 재는 것에 **「도구 호출이 이름으로 보이고 결과가 접혀 있다」**가 있다.
접혀 있다는 것은 **사람이 눌러 편다**는 뜻이다. 8 = A 는 매 폴링마다 사건 열을
통째로 다시 그린다.

```text
   결과를 편다 -> 1초 뒤 폴링이 DOM 을 갈아치운다 -> 접힌다 -> 못 읽는다
```

**오늘 이 자리가 안 아픈 이유는 접을 것이 없어서다** — `<pre>` 한 장이라 펼 것이
0 이다. **이 유닛이 접기를 들여오면서 같이 들어오는 모순이다.**

**막는 것은 열쇠다** — `Event.ID` 가 `tool_use_id` 이고 `tool_use` 와
`tool_result` 가 둘 다 든다. **하네스가 준 신원이라 링이 감겨도 안 바뀐다.**
펼침 상태를 그 열쇠로 들면 통째로 다시 그려도 살아남는다. `Line` 은 못 쓴다 —
`Parse` 가 창 안에서 1 부터 세므로 링이 감기면 전부 밀린다.

**스크롤도 같은 자리다.** 오늘 `page.go:267` 이 매 폴링마다 무조건
`pre.scrollTop = pre.scrollHeight` 한다 — **도는 동안에는 위로 올려 읽는 것이
불가능하다.** 접기가 생기면 더 아프다. **바닥에 있을 때만 바닥을 따라간다.**

#### 교차 검사가 하나 더 잡았다 — U4 는 머리에, U5 는 몸통에 싣는다

U4 가 이미 병합됐으므로 선 위 모양을 실측했다 (`log.go`).

```text
   U4 as=events   몸통 = transcript.Result 그대로.  메타는 헤더 넷 —
                  X-Enode-Log-Bytes · Source · Attempt · Capped
   U5 /api/transcript   몸통이 객체다 (available · generation 이 이미 거기 있다).
                  메타를 헤더에 못 옮긴다 — 앞 팩이 세운 모양이다
```

**U6 이 그 둘을 잇는다** — `handleRecord` 의 출처를 U4 의 라우트로 바꾸면서 같은
화면 함수에 넘겨야 한다. **U5 가 지금 봉투 이름을 안 정하면 U6 이 둘째 봉투를
짓고, 그때 화면 함수가 두 벌이 된다** — 이 팩이 파서를 하나로 만든 값을 그리는
쪽에서 도로 잃는다.

**U5 가 정한다** — `transcript.Result` 를 `transcript` 키 하나에 통째로 담고,
메타는 그 옆에 형제 키로 둔다. **U6 은 U4 의 헤더 넷을 같은 형제 키로 옮겨
담기만 한다.** 화면 함수는 `payload.transcript` 하나만 본다.
