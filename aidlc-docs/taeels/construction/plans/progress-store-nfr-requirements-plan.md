## 0. 회차 계획이 이 단계를 「유닛마다 · 최소」로 걸었다

`execution-plan.md` 3절이다. **최소는 얕게 쓰라는 뜻이 아니라 옮겨 적기를 하지
말라는 뜻이다.**

```text
   안 한다   requirements.md 5.1 의 차단 게이트 다섯을 다시 자르는 것
            5.3 의 규칙별 처리 표를 유닛마다 복사하는 것
            FD 가 닫은 형식과 규칙을 다시 적는 것

   한다     이 유닛에서 **처음 정해지는 값**만.  그것이 N2 다
```

## 0.1 이 단계가 지는 것 — N2 하나이고 값이 여럿이다

FD 가 규칙의 모양까지 짓고 숫자를 여기로 넘겼다 (`business-rules.md` R24 · 5.4).
**회차가 이 값을 미결로 들고 온 역사가 있다.**

```text
   회차 상태 파일   「① 에 상한이 없다.  「봉인 때 지워진다」는 맞다 — 종료 상태에
                   이르면 sealExpired 가 잡는다.  그러나 **종료 안 된 채 오래 도는
                   Run** 의 노출 기간에는 값이 한 줄도 없다.  N2 가 그 자리다」

   FD 가 조인 것    그 문장이 **반만 참이다.**  오늘 값은 「상한이 없다」가 아니라
                   **「지우는 코드가 0」**이고 구멍이 둘이다 —
                   reap.go:126 의 한 시간 창 · reap.go:104 의 n > 0
```

**그래서 N2 는 「몇 시간」 하나가 아니다.** 값 여섯이 서야 한다.

| | 값 | 어디서 정하나 |
|---|---|---|
| V1 | 쓸기의 **주기** | **2.2 가 실측으로 채운다.** 안 묻는다 |
| V2 | 쓸기가 **도는 자리** | **2.2 가 실측으로 채운다.** 안 묻는다 |
| V3 | 고아로 판정하는 **조건** | **물음 1** |
| V4 | 종료 상태 Run 의 **유예** | **물음 2** |
| V5 | 살아 있는 Run 의 **노출 기간 상한** | **물음 3.** 잔여 ① 이 이 값이다 |
| V6 | 디스크가 찰 때의 **거동** | **물음 4** |

**디스크 값도 여기 선다** — `execution-plan.md` 가 Infrastructure Design 을 SKIP
하면서 「디스크가 더 쓰인다는 사실은 남는다. 그 값은 **N2 로 옮겼다**」고 적었다.

## 1. 착수 전에 실측한 것 (2026-09-15)

### 1.1 쓸기가 얹힐 자리가 이미 있다 — 새 타이머가 0 이다

```go
// cmd/mediator/main.go:89
st.RunReaper(ctx, time.Duration(cfg.Lease.RenewSeconds)*time.Second, log)

// internal/store/reap.go:157
func (s *Store) RunReaper(ctx context.Context, every time.Duration, log *slog.Logger) {
	t := time.NewTimer(0)     // **기동에 한 번 먼저 돈다**
```

```text
   주기       cfg.Lease.RenewSeconds.  기본 **60초** (config.go:100)
   기동 스캔   time.NewTimer(0) 이라 **뜨자마자 한 번 돈다**.  공짜다
```

**R24 가 요구한 「기동과 주기마다」가 이미 거기 있다.** 새 고루틴도 새 설정 키도
안 만든다.

### 1.2 구멍 둘 중 하나는 **자리만 바꾸면** 닫힌다

```text
   Reap()          주기마다 **무조건** 돈다
   └ sealExpired   if n > 0 일 때만 불린다 (reap.go:104).  **구멍 ②**
     └ 쿼리         ended_at > now() - interval '1 hour'.  **구멍 ①**
```

**쓸기를 `sealExpired` 안이 아니라 `Reap` 안에 두면 구멍 ② 가 그 자리에서
닫힌다.** 구멍 ① 은 쿼리의 창이라 쓸기가 자기 조건을 따로 들면 안 걸린다.

### 1.3 N2 는 **Run 을 못 묶는다** — 무한 대기가 설계다

```go
// internal/contract/contract.go:130
// Timeout 은 선택이다. 없으면 무한 대기 — 사람의 시간을 시스템이
```

`ADR-032` 가 그것을 못 박았고 `reap.go` 의 주석이 실측 사고까지 적어 두었다 —
「실측 승인을 기다리던 Run 이 정확히 180초 만에 FAILED 가 됐다. 사람은 아직 보는
중」. **그래서 ASKED 는 임대 만료에서 아예 빠진다.**

**결론** — N2 는 「오래 도는 Run 을 죽인다」가 될 수 없다. **진행 파일의 수명을
Run 의 수명과 따로 재야 한다.**

### 1.4 오늘 시간이 묶는 것과 안 묶는 것

| | 값 | 어디 | 묶나 |
|---|---|---|---|
| 임대 `not_after` | `60 × 3 = 180초` | `config.go:100` 의 `RenewSeconds` · `NotAfterFactor` | **묶는다** |
| 회수 주기 | 60초 | `main.go:89` | 묶는다 |
| **노드가 죽은 Run** | **≤ 240초** | 180 + 60 | **묶인다.** 그 뒤 `sealRecord` 가 돈다 |
| 되묻기 대기 | 무한 | `contract.go:130` | **안 묶인다** |
| 단계 수 | 상한 0 | `grep MaxSteps` 가 0 을 낸다 | **안 묶인다** |
| Run 당 노드 수 | `MaxPerRun = 0` (무제한) | `config.go` 의 `Lease` | **안 묶인다** |

**노드가 죽는 경로는 이미 4분 안에 닫힌다.** 안 닫히는 것은 **사람을 기다리거나
정말로 오래 도는 Run** 하나다.

### 1.5 디스크를 미는 것은 **단계 수**다

```text
   한 단계의 진행 파일   <= MaxBlobBytes + 표시 줄.  기본 10 MiB + 약 40 바이트
   한 (run, seq, name)  **파일 하나.**  R9 가 앞 시도를 걷는다
   한 Run 의 트리        **지금까지 실행한 단계 수** x 위 값.
                        **끝난 단계의 파일도 봉인까지 남는다** — 이것이 미는 힘이다
   동시에 도는 Run       <= 노드 수 (I1 — 한 노드에 한 Run)
```

**최악의 봉투** (R = 동시 Run · S = Run 당 단계).

| R | S | 피크 |
|---|---|---|
| 1 | 5 | 50 MiB |
| 10 | 20 | **2 GiB** |
| 50 | 20 | **10 GiB** |

**10 MiB 는 상한이지 보통값이 아니다.** 보통값은 1.7 이 「못 잰다」로 적는다.

### 1.6 Mediator 에 디스크 여유 검사가 **0 이다**

```text
   노드 쪽    있다.  detect.go:68 이 여유가 모자라면 build 능력을 광고에서 뺀다
              헬퍼는 freeBytes — disk_unix.go · disk_windows.go 의 빌드 태그 쌍
   Mediator   **0 이다.**  record 도 store 도 api 도 자기 디스크를 안 본다
```

**이 유닛이 새 디스크 소비자를 하나 더한다.** 그리고 디스크가 차면 **봉인 쓰기도
같이 실패한다** — 진행 파일 쓰기는 보조지만 (R25) 봉인은 아니다. 물음 4 가 이
자리다.

**대가 하나를 미리 잰다** — `freeBytes` 는 `internal/enode` 의 **비공개** 함수다.
`record` 가 쓰려면 **같은 함수가 두 벌이 된다** (`CONVENTIONS.md` 1.4 가 막는
자리). `golang.org/x/sys` 는 이미 직접 의존이라 **새 의존은 0 이다.**

### 1.7 못 잰 것 하나 — 단계 하나가 **실제로** 내는 바이트

```text
   왜 못 재나    저장소에 stream-json testdata 가 없다.
                internal/enode/testdata 디렉터리가 존재하지 않는다 (실측)
                하네스를 여기서 돌릴 수 없다

   무엇이 있어야 재나   U1 이 자기 계획에 「실측한 stream-json 줄을 testdata 에
                     둔다」를 적었다 (execution-plan.md 의 Code Generation 절).
                     그것이 서면 줄 길이와 단계당 줄 수로 봉투가 좁혀진다.
                     그 전에는 CB3 의 실측이 첫 숫자다

   옆 값 하나     노드의 링이 512 KiB 이고 그 주석이 「80자 줄로 대략 6,400줄」
                로 잡았다 (transcript.go:28).  **판단이지 측정이 아니다** —
                그대로 N2 의 근거로 쓰지 않는다
```

**짐작한 보통값을 적지 않는다.** 1.5 의 봉투는 **상한**이고 그것은 실측값이다.

### Question 4

**디스크가 찰 때 무엇을 하나.** 1.6 이 Mediator 에 여유 검사가 0 인 것을 쟀고
