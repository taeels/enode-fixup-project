# U6 `panel-past` — Functional Design 계획 (Part 1)

```text
   유닛     panel-past (U6) · 브랜치 unit/panel-past · 담당 taeels
   회차     v3-run-transcript · W-d (U7 과 병렬이었다.  순서가 바뀌어 마지막에 돈다)
   맡는 것   FR-4 의 나머지 — 제어판의 「지난 작업」을 같은 파서로 읽게 한다
   지는 게이트  **CB2** (읽힌다).  그리고 **CB6 의 ⑥ 을 닫는다**
   딛는 게이트  CB1 (U5).  **초록이고 병합됐다** (PR #46)
   기준선    b3c7a24 — `unit/fleet-card` 위에서 땄다.  물음 1 이 그 자리다
```

**이 유닛이 이 회차의 마지막 구멍이다.** 게이트 일곱 중 CB2 하나가 유닛이 없어
안 섰고, CB6 이 그것 때문에 보류다 (U8 의 측정 기록).

이 문서는 **묻는 것**이다. 답이 오면 5절의 순서로 산출물 셋을 낸다.

## 0. 이 단계가 닫는 것과 안 닫는 것

```text
   닫는다     지난 트랜스크립트의 출처와 봉투 모양 · 단계 목록을 어디서 얻나 ·
             걷힌 양을 어떻게 보이나 · 봉인 전 Run 을 누르면 무엇을 보이나 ·
             요청 수의 규율

   안 닫는다   코드.  Code Generation 이 낸다
             파서 · 라우트 (U1 · U4 가 닫았다) · 카드 렌더러 (U8 이 닫았다)
             verdict.  지금처럼 Run 목록에서 온다 (유닛 정본이 그렇게 적었다)
             도는 것 (U5 의 handleTranscript).  이 유닛이 안 만진다
```

## 1. 실측 — 코드가 지금 어떻게 생겼나 (2026-09-17 · `b3c7a24`)

### 1.1 `loadRecord` 가 원문을 `<pre>` 로 그린다 — 정본의 경로 줄에 `page.go` 가 없다

```js
   page.go:443   fetch("/api/record?run=" + ...).then(...)
                 logs.map(l => "<div>" + esc(l.name) + "</div><pre>" + esc(l.content) + "</pre>")
```

**바이트를 그대로 `<pre>` 에 붓는다.** 그래서 출처만 바꾸면 화면이 안 바뀐다 —
tar 에서 꺼낸 바이트 대신 `GET` 이 준 같은 바이트를 같은 `<pre>` 에 붓는 것이라
**CB2 의 「같은 파서의 같은 모양이다」가 서지 않는다.**

```text
   유닛 정본의 경로   internal/panel/transcript.go · internal/runctl/client.go
   실제로 필요한 것    거기에 **internal/panel/page.go** 가 하나 더 든다
   파일 행렬          page.go 는 U5 · U8 의 것이다.  U6 이 만지면 행렬 밖이다
```

**정본이 틀린 것이 아니라 덜 적은 것이다** — 그 줄은 「출처를 바꾼다」만 보고
쓰였고, 그리는 쪽이 원문을 붓고 있다는 것을 안 봤다.

### 1.2 그리는 것이 이미 한 벌이다 — U8 이 그 자리를 옮겨 놨다

```text
   앞 판이었으면   지난 것을 그리는 코드를 page.go 안에 또 지어야 했다.
                 도는 것(U5)과 같은 모양을 두 번째로 짓는 자리다
   지금은         window.enodeCard.renderEvents(container, events, opts) 가 있다.
                 제어판이 /static/card.mjs 로 이미 로드한다
```

**U6 의 의존이 설계 변경으로 바뀌었다.** 의존 행렬은 U6 의 코드 의존을
`U1 · U4` 로, U5 를 게이트로만 적는다. **U8 은 아예 칸이 없다** — 2026-09-17 의
「그리는 것이 한 벌」 변경이 그 행렬보다 뒤다. 물음 1 이 그 자리다.

### 1.3 `?name=` 의 함정이 그대로 있다 — U8 이 밟은 자리다

```go
   runctl.Step   Seq int · ID string · State · Uses · Node · Needs · Attempt · Chosen
```

`Client.Status` 가 주는 단계에 **`name` 이 없고 `ID` 가 곧 로그의 이름이다.**
U8 이 현황판에서 정확히 이 자리를 밟았고 (빈 카드가 200 에 0 바이트로 왔다),
`GET log` 의 `name` 기본값은 아직 `step` 이다.

**이 유닛이 같은 함정을 두 번째로 밟는다.** 답은 이미 나와 있다 — `Step.ID` 를
`?name=` 으로 넘긴다. 물음이 아니라 4절에 적는다.

### 1.4 봉인된 로그는 진행 파일의 9% 다 — 걷힌 양이 줄 하나로 있다

`cb4-card-4` 의 `survey` 단계를 실측했다.

```text
   진행 파일 (도는 동안)   127,117 바이트
   봉인된 로그            11,553 바이트        **9%**
   걷힌 양               enode.elided 한 줄 — {"events":98,"bytes":408989}
```

**「본문 N 개가 걷혔다」가 그릴 값이 실제로 거기 있다.** 파서가 그 줄을
`Result.Elided` 로 이미 낸다 (`{Events, Bytes}`). 물음 4 가 그 자리다.

**그리고 이것이 이 유닛의 값이 왜 큰지를 말한다** — 봉인된 것은 도는 동안 본
것과 **다른 물건**이다. 9% 만 남고 나머지는 수 둘로 접혀 있다.

### 1.5 `GET` 과 tar 가 같은 바이트인 것을 이미 쟀다

U8 의 CB4 측정에서 세 단계 전부 `cmp` 로 확인했다.

```text
   seq 1 survey    11,553 바이트   tar == GET
   seq 2 count        102 바이트   tar == GET
   seq 3 verdict    4,790 바이트   tar == GET
```

**출처를 바꿔도 내용이 안 바뀐다는 것이 측정으로 서 있다.** CB2 가 그것을
다시 재지만, 이 유닛은 이미 그 사실 위에서 지어진다.

### 1.6 `Client.Record` 는 안 없어진다 — `runctl` 이 쓴다

```text
   cmd/runctl/main.go:365   report(c.Record(ctx, arg, w))   — runctl record <id> -o r.tar
   internal/panel/transcript.go:215   이 유닛이 이 호출 하나를 걷는다
```

**`archive/tar` 가 `internal/panel` 에서 사라지는 것**이 CB2 가 재는 줄이고,
`internal/runctl` 에서는 안 사라진다. 둘을 안 헷갈리게 적어 둔다.

### 1.7 요청이 하나에서 N+1 이 된다

```text
   지금    GET /v1/runs/{id}/record          한 번.  tar 하나에 전부 들어 있다
   뒤     GET /v1/runs/{id}                 단계 목록
          GET /v1/runs/{id}/steps/{seq}/log  단계마다 하나
```

3단계 Run 이면 1 -> 4 다. **한 번 누를 때만 나가고 폴링이 아니므로** U4 의
전역 한도(N1)에 붙는 양은 작지만, 단계가 스물인 Run 이면 21 이다. 물음 5 가
그 규율을 정한다.

### 1.8 안 만져도 되는 것을 확인했다

```text
   verdict              handleRuns 의 pastRun 이 Run 목록에서 싣는다.  그대로다
   handleTranscript     U5 의 것.  도는 것이라 이 유닛이 diff 0
   라우트 수             GET /api/record 가 이미 있다.  panel.go 의 11 이 그대로다
   card.mjs             U8 이 닫았다.  이 유닛이 렌더러를 안 고친다
   봉인 뒤 진행 파일      U3 이 지운다.  GET log 가 봉인된 것으로 넘어간다 (source=sealed)
```

## 3. 물음 여섯

형식은 `common/question-format-guide.md` 다.

**물음이 권장대로 닫혔다 (2026-09-17 · 사용자 「권장대로」). 여섯이 전부 A 이고
갈린 답이 0 이다.**

### Question 1 — 어디서 따고 무엇으로 그리나

1.2 가 낸 물음이다. **이 유닛의 크기를 정하는 자리다.**

```text
   A   unit/fleet-card 에서 딴다.  window.enodeCard.renderEvents 를 부른다.
       U8 이 PR 로 먼저 가고 U6 이 뒤따른다.  그리는 코드가 0 줄이다
   B   main 에서 딴다.  page.go 에 있는 U5 의 인라인 drawEvent 를 부른다.
       U8 과 독립이나 **U8 이 병합되면 그 함수가 없어진다** — 충돌이 확정이다
   C   main 에서 따고 지난 것 전용 그리기를 새로 짓는다.  두 벌이 된다 —
       U8 이 방금 없앤 바로 그 모양이다
   X   Other (아래 [Answer]: 뒤에 적는다)
```

**권장은 A 다.** B 는 없어질 함수를 부르는 것이라 병합 순서와 무관하게 한 번은
깨지고, C 는 이 회차가 값을 치르고 없앤 두 벌을 되살린다.

**A 의 대가** — U6 이 U8 에 묶인다. 둘이 따로 병합될 수 없고 U8 -> U6 순서가
못 박힌다. **그 대가가 이미 치러져 있다** — CB6 은 어차피 마지막 유닛이 지는
장면 전체 게이트라 U6 없이 못 닫고, U8 없이도 못 닫는다.

[Answer]: A

### Question 2 — 봉투를 어떤 모양으로 내나

1.1 이 낸 물음이다. 지금은 `{logs: [{name, content}]}` 다.

```text
   A   단계마다 U5 의 봉투와 **같은 키**로 낸다 —
       {steps: [{seq, id, state, transcript: <Result>, data: "<원문>"}]}
       화면 함수가 도는 것과 지난 것에 하나로 선다
   B   {logs: [{name, content}]} 를 그대로 두고 브라우저가 파싱한다.
       파서가 Go 에만 있으므로 **브라우저에 파서를 하나 더 지어야 한다**
   C   단계마다 사건 배열만 낸다.  원문 토글이 지난 것에서 못 선다
   X   Other
```

**권장은 A 다.** U5 의 `liveTranscript` 가 `transcript` 키에 `Result` 를 통째로
담은 이유가 **정확히 이 유닛을 위해서였다** — 그 유닛의 도메인 문서가
「U6 이 U4 의 라우트로 출처를 바꿀 때 그쪽 몸통이 이미 `transcript.Result` 다.
같은 키에 그대로 담으면 화면 함수가 하나로 선다」고 적었다.

**B 는 이 팩의 기둥을 어긴다** — 「공용 파서 하나를 셋이 쓴다」(FR-3)이고
파서가 둘이면 화면이 갈린다.

[Answer]: A

### Question 3 — 봉인 전 Run 을 누르면

`scene-gates.md` 의 CB2 화면 검증이 **「아직 안 끝난 Run 은 「봉인 전」이 적혀
있다」**로 적는다. 무엇을 보이는지는 안 적었다.

```text
   A   「봉인 전」을 적고 **그 시점의 진행 파일을 그대로 보인다.**
       GET log 가 봉인 전에도 답하므로 (FR-6) 새로 할 일이 0 이다
   B   「봉인 전」만 적고 내용을 안 보인다.  지난 작업은 끝난 것만 읽는다는 뜻이다
   C   누르지 못하게 막는다.  오늘 되던 것이 안 되게 된다
   X   Other
```

**권장은 A 다.** 같은 기계의 제어판에 **도는 것 카드가 이미 있으므로** B 를
고르면 한 화면에서 같은 Run 을 위에서는 보고 아래서는 못 보는 모양이 된다.

**A 가 공짜인 이유** — `GET log` 는 봉인 전이면 진행 파일을, 뒤면 봉인된 로그를
같은 라우트로 낸다. **응답의 `X-Enode-Log-Source` 가 어느 쪽인지 말한다** (NC-5).
화면은 그 값을 그리기만 한다.

[Answer]: A

### Question 4 — 걷힌 양을 어디에 그리나

1.4 가 낸 물음이다. `Result.Elided` 가 `{events: 98, bytes: 408989}` 를 든다.

```text
   A   단계마다 한 줄.  사건 열 위에 「본문 98 개가 걷혔다 (408,989 바이트)」
       걷힌 것과 남은 것이 같은 카드 안에서 붙어 있다
   B   Run 하나에 한 줄로 합친다.  단계마다의 값이 사라진다
   C   안 그린다.  봉인된 것이 원래 선별본이라는 것을 화면이 말 안 한다
   X   Other
```

**권장은 A 다.** 실측이 9% 를 냈다 (1.4) — **화면이 그 말을 안 하면 읽는 사람이
지난 것을 도는 동안 본 것과 같은 물건으로 읽는다.** 그리고 U5 가 도는 쪽에서
「감겨 나갔다」를 같은 자리에 그리므로 (R11) 모양이 맞는다.

**「없는 줄보다 틀린 줄이 나쁘다」의 반대 자리다** — 여기서는 **없는 줄이
틀린 인상을 만든다.**

[Answer]: A

### Question 5 — 요청 N+1 을 언제 내나

1.7 이 낸 물음이다. 단계가 스물이면 21 이다.

```text
   A   누를 때 전부 한 번에.  제어판이 서버 쪽에서 모아 한 응답으로 낸다.
       브라우저는 요청 하나.  Mediator 로는 N+1 이 나가나 **한 번뿐이다**
   B   단계마다 브라우저가 따로 부른다.  제어판이 얇아지나 브라우저에
       N+1 의 실패 갈래가 생긴다
   C   첫 단계만 받고 나머지는 펼칠 때.  요청이 준다.  누를 때마다 기다린다
   X   Other
```

**권장은 A 다.** 제어판이 이미 그 모양이다 — `handleRecord` 가 tar 하나를 받아
`logs` 배열로 내고 브라우저는 요청 하나였다. **A 는 그 계약을 안 바꾼다.**

**폴링이 아닌 것이 이 답을 싸게 만든다** — 봉인된 것은 안 자라므로 한 번 읽으면
끝이다. 물음 3 = A 의 봉인 전 Run 만 예외이고, 그것은 **다시 누르면 다시 읽는다**
(자동 갱신을 안 넣는다 — 도는 것 카드가 그 일을 이미 한다).

[Answer]: A

### Question 6 — 로그가 없는 단계를 어떻게 다루나

갈림길에서 안 간 단계(`SKIPPED`)와 아직 안 온 단계는 총 길이 0 이다.

```text
   A   단계를 **그대로 보이고** 「이 단계는 남긴 것이 없다」를 적는다.
       단계 목록이 계약 그대로라 그래프와 수가 맞는다
   B   그런 단계를 목록에서 뺀다.  화면이 짧아지나 **왜 없는지**를 못 말한다
   X   Other
```

**권장은 A 다.** `Step.Chosen` 이 「갈림길에서 골라진 적이 있는가」를 이미
나르고, 그 열이 있는 이유가 **「경로가 갈려 안 갔다」와 「골랐는데 못 닿았다」를
가르려고**다. B 는 그 구별을 화면에서 지운다.

[Answer]: A

## 5. 실행 단계 — 답을 받은 뒤

### 5.1 순서

```text
   ①  답 여섯을 계획에 박는다
   ②  모순 검사 — 5.2
   ③  domain-entities — 봉투 · 단계 · 걷힌 양 · 출처 표시
   ④  business-logic-model — 한 번 누르면 무엇이 도나.  봉인 전과 뒤의 갈림
   ⑤  business-rules — R 번호를 U8 의 R61 에 **이어서** 매긴다 (R62 부터)
```

### 5.2 모순 검사에서 볼 자리 — 미리 이름으로 든다

```text
   1 x 2    한 벌의 렌더러가 받는 것은 사건 배열 하나다 (R36).  봉투가 단계마다
            Result 를 담으면 화면이 그 안에서 events 를 꺼내 넘겨야 한다 —
            꺼내는 자리가 도는 것과 지난 것에서 같은 모양인지

   3 x 5    봉인 전 Run 을 보인다면 그 응답은 안 굳는다.  「한 번 읽고 끝」이라는
            5 = A 의 전제가 그 갈래에서만 거짓이다

   4 x 2    걷힌 양은 Result.Elided 에 있다.  봉투가 Result 통째를 담으면
            화면이 그리기만 하면 되고, 안 담으면 서버가 따로 꺼내 실어야 한다

   6 x 5    로그가 없는 단계도 요청을 하나 쓴다.  안 쓰고도 「남긴 것이 없다」를
            말할 수 있는지 — Step.State 로 미리 아는 자리가 있는지
```

### 5.2.1 모순 검사 결과 (2026-09-17) — 막은 것 0 · 값을 정한 것 셋 · 넓힌 것 하나

5.2 가 이름으로 든 넷을 전부 돌렸다. **이번에는 막은 것이 없다** — 답 여섯이
서로를 안 무른다. 대신 값을 셋 정하고 답 하나를 넓혔다.

#### 값을 정한 것 ① — 봉투의 키 이름이 도는 것과 같다 (1 x 2)

렌더러가 받는 것은 사건 배열 하나다 (R36). 그러면 화면이 봉투에서 그것을 꺼내야
하고, **꺼내는 식이 도는 것과 지난 것에서 같은 모양이어야** 화면 함수가 하나로 선다.

```text
   도는 것 (U5)   t.transcript.events        page.go 의 drawTranscript 가 이미 쓴다
   지난 것 (U6)   s.transcript.events        단계 하나가 t 자리에 온다
```

**키 이름을 `transcript` 로 맞추는 것이 이 답의 전부다.** U5 의 도메인 문서가
이미 그 이유를 적어 뒀다 — 「같은 키에 그대로 담으면 화면 함수가 하나로 선다.
펼치면 U6 이 다시 조립해야 하고, 그 조립이 둘째 봉투다」.

#### 값을 정한 것 ② — 「한 번 읽고 끝」은 「누를 때마다 한 번」이다 (3 x 5)

3 = A 가 봉인 전 Run 도 보이게 했고, 그 응답은 안 굳는다. 5 = A 의 「한 번 읽고
끝」이 그 갈래에서만 거짓으로 보인다.

**거짓이 아니라 말이 짧았던 것이다.**

```text
   뜻하는 것    누르면 한 번 읽는다.  **자동 갱신이 0 이다**
   안 뜻하는 것  영원히 한 번.  다시 누르면 다시 읽는다
   왜 자동 갱신이 0 인가   도는 것 카드가 그 일을 이미 한다 (U5 · 1초 폴링).
                       지난 작업이 또 폴링하면 같은 기계에서 같은 것을 두 번 민다
```

**같은 Run 을 봉인 전과 뒤에 누르면 다른 것이 온다** — 진행 파일과 봉인된 로그는
다른 파일이고 크기가 9% 로 준다 (1.4). **그것을 설명하는 줄이 출처다** (NC-5) —
화면이 `X-Enode-Log-Source` 를 그대로 그린다.

#### 값을 정한 것 ③ — 걷힌 줄은 봉인된 것에만 있다. 그래서 그것이 신호다 (4 x 2)

2 = A 가 `Result` 를 통째로 담으므로 `Elided` 가 따라온다 — 서버가 따로 꺼낼
것이 0 이다. **그리고 실측이 하나 더 준다.**

```text
   진행 파일    enode.elided 가 **없다.**  걷는 일이 봉인 때 일어난다
   봉인된 로그   enode.elided 한 줄.  cb4-card-4 의 survey 는 98 사건 · 408,989 바이트
```

**걷힌 줄의 유무가 봉인 전과 뒤를 가르는 둘째 신호다.** 출처 헤더가 첫째이고
이것이 둘째이며, **둘이 같은 답을 내야 한다.** 안 내면 둘 중 하나가 틀린 것이고,
그 자리를 `business-rules` 가 불변식으로 적는다.

#### 넓힌 것 — 답 6 의 한 문장이 셋이 된다 (6 x 5)

6 = A 가 「남긴 것이 없다」 한 줄로 적었다. 5.2 가 「상태로 미리 아는 자리가
있는지」를 보라고 했고, 보러 갔더니 **상태가 이유를 셋으로 가른다.**

```text
   State 가 SKIPPED · Chosen 이 거짓    경로가 갈려 안 갔다
   State 가 SKIPPED · Chosen 이 참      골랐는데 못 닿았다
   그 밖에 총 길이가 0                  돌았고 아무 말도 안 했다
```

**`Step.Chosen` 이 있는 이유가 정확히 이 구별이다** — 그 열의 주석이
「false 를 생략하면 SKIPPED 하나가 두 가지를 다시 뜻하게 된다」고 적는다.
한 문장으로 접으면 그 열이 나른 값을 화면에서 버리는 것이다.

**요청은 그래도 단계마다 낸다** — 상태로 미리 거르면 「돌았는데 아무 말도 안
했다」를 못 가른다. 그 셋째는 총 길이를 실제로 봐야 안다.

#### 교차 검사 — U8 에서 받는 것과 U8 에 넘기는 것

```text
   받는 것    window.enodeCard 의 renderEvents · statusLine · parseEvents.
             제어판이 /static/card.mjs 로 이미 로드한다 (U8 의 답 2 = A)
   넘기는 것   0.  U8 은 병합만 먼저 가면 된다
   묶이는 것   병합 순서 U8 -> U6.  답 1 = A 의 대가이고 이미 치러져 있다 —
             CB6 은 마지막 유닛이 지는 장면 전체 게이트라 둘 다 있어야 닫힌다
   안 부르는 것 statusLine.  지난 것에 「쓰는 중」이 없다 — 끝난 단계다 (R56 과 같은 값)
```
