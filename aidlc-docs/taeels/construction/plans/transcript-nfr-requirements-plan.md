## 0. 이 단계가 「최소」인 뜻

`aidlc-docs/v3-run-transcript/inception/plans/execution-plan.md` 3절이 이 단계를
**유닛마다 · 최소**로 걸었다. **최소는 얕게 쓰라는 뜻이 아니라 옮겨 적기를 하지
말라는 뜻이다** — 이미 값이 정해진 것은 어디서 정해졌는지를 가리키고, **이
유닛에서 처음 정해지는 것만 여기서 짓는다.**

### 0.1 U1 이 이 단계를 도는 이유

`unit-of-work.md` U1 절이 한 줄로 적었다 — **「파서가 새 표면이고 신뢰할 수 없는
입력을 받는다 (SECURITY-13)」.** 그것이 이 단계의 중심이다.

```text
   U1 이 지는 N 값    없다.  N1 은 U4 (함대 규모의 폴링 부하) · N2 는 U3 (진행 파일 수명)
   U1 의 새 표면      internal/transcript 의 공개 면 여덟 (domain-entities 7절)
   U1 의 신뢰 경계    Parse 의 입력 바이트.  하네스가 낸 것이고 우리가 안 만들었다
```

### 0.2 옮겨 적기가 아닌 자리 셋

FD 가 끝난 지금 **팩도 FD 도 값을 안 닫은 자리**가 셋 남아 있다. 이 단계가 내는
값은 그 셋이고, 4절의 물음 셋이 그대로 그것이다.

```text
   ①  표시 상한의 단위    팩은 「200자 · 500자」이고 FD 의 R8.1 은 「200 바이트 ·
                        500 바이트」다.  한글은 UTF-8 에서 글자당 3바이트라
                        **같은 숫자가 3배 다른 값**이고, 바이트로 자르면 룬이
                        쪼개져 잘못된 UTF-8 이 나간다 (1.4)

   ②  사건 증폭의 주인    입력 10 MiB 가 Event 배열 약 112 MB 가 된다 (1.3).
                        입력 상한은 있고 **출력 상한은 아무 데도 없다.**
                        U4 의 as=events 가 그 값을 그대로 받는다

   ③  패닉 0 의 증명 수단  FD 의 R10.2 가 「어떤 입력에도 패닉하지 않는다」를
                        규칙으로 적었는데 그것을 재는 수단을 안 정했다.
                        저장소에 퍼즈 시험이 0 이다 (1.2)
```

**셋 다 나중에 되돌리는 값이 크다.** ①은 이미 두 문서가 갈린 자리라 비워 둘 수
없고, ②는 U4 가 착수하면 그 유닛의 N1 안으로 굳으며, ③은 Code Generation 이
시험 목록을 짜기 전에 정해져야 한다.

## 1. 착수 전에 실측한 것

물음의 선택지가 짐작이 아니라 사실 위에 서게 하려고 먼저 쟀다.
**툴체인은 `go1.26.6 linux/amd64`** 이고 아래 인용은 전부 그 판의 소스다.

### 1.1 파서가 한 줄에 쓰는 메모리 — 입력의 약 두 배

`Q7 = A`(맵을 `map[string]json.RawMessage` 로 유지)가 이 값에 어떻게 걸리는지를
표준 라이브러리 소스로 쟀다.

```text
   ①  json.Unmarshal 은 무엇을 담든 먼저 전체를 스캔한다
       decode.go:102-114 — checkValid(data, &d.scan) 가 먼저 돈다.
       줄 하나가 10 MiB 면 그 10 MiB 를 한 번 훑는다.  담는 타입과 무관하다

   ②  RawMessage 는 별칭이 아니라 복사다
       stream.go:272-278 — *m = append((*m)[0:0], data...)
       최상위 값마다 한 번 복사한다.  합이 줄 길이에 가깝다

   ③  그래서 한 줄의 최대 비용이 스캔 1x + 복사 1x = 약 2x 다.
       **중첩 깊이에 안 비례한다** — 안쪽 값은 안 푼다
```

**`map[string]any` 였다면 이 값이 안 선다.** `any` 는 안쪽까지 전부 풀어
문자열 · 맵 · 슬라이스를 노드마다 따로 할당하고 인터페이스로 감싼다. 배수를
실측하지는 않았으므로 **몇 배인지는 적지 않는다** — 적는 것은 **상한이 입력
길이에 선형으로 안 묶인다**는 것이다. `Fields` 는 묶인다.

### 1.2 오늘 코드에 막는 것이 있나 — 있는 것 셋과 없는 것 둘

```text
   막는다   중첩 깊이        scanner.go:148 const maxNestingDepth = 10000
                            넘으면 Unmarshal 이 오류다 -> ParseLine 이 ok=false
                            -> R3.1 로 text/plain.  **표준 라이브러리가 막는다**

   막는다   링 경로의 입력    DefaultTranscriptCapacity = 512 * 1024
                            (transcript.go:28).  제어판이 읽는 최대다

   막는다   파일 경로의 입력   MaxBlobBytes 기본 10 MiB (config.go:51 · :100).
                            AppendLog 이 io.LimitReader 로 건다 (record.go:64)

   안 막는다  한 줄의 길이     저장소 어디에도 줄 길이 상한이 0 이다.
                            splitLines 는 bytes.Split 이라 상한이 없고,
                            **bufio.Scanner 를 쓰는 자리가 파서 경로에 0 이다**
                            (grep — mcp.go:645 · setup.go 둘뿐이고 전부 다른 일)

   안 막는다  노드의 stdout    runner.go:185 var stdout, stderr bytes.Buffer 이고
                            cmd.Stdout = &stdout 이다 (:195).  하네스가 뱉는 만큼
                            노드 프로세스가 자란다.  **기존 코드 사실이다** —
                            이 유닛이 만든 것도 넓힌 것도 아니다
```

**퍼즈 시험이 저장소에 0 이다** — `grep -rn "func Fuzz" --include=*_test.go` 가
0 을 낸다. R10.2 를 재는 수단이 오늘 표 시험뿐이다.

### 1.3 사건 증폭 — 입력 10 MiB 가 Event 배열 약 112 MB

**입력 상한은 있는데 출력 상한이 없다.** 계산이다 (실측이 아니다 — 벤치마크를
안 돌렸다. Code Generation 이 잰다).

```text
   Event 한 칸의 크기 (amd64 · FD domain-entities 4절의 필드 그대로)
     Kind 16 · Sub 16 · Line 8 · Text 16 · Name 16 · ID 16 · OK 8 · Cut 8 ·
     Shell 1(+7 채움) · Tokens 8 · Info 104            합계 224 바이트

   최악의 입력 — 껍데기 줄만 이어진 파일
     {"type":"assistant"} + 개행 = 21 바이트.  R5 가 사건 하나를 보증한다
     10 MiB / 21 = 사건 약 499,000 개
     499,000 x 224 B = 약 112 MB.  슬라이스가 자라는 동안 잠깐 그 두 배다

   제어판 경로는 안 문제다
     512 KiB / 21 = 사건 약 25,000 개 x 224 B = 약 5.6 MB
```

**증폭이 문제가 되는 자리는 하나다** — Mediator 의 `as=events` 가 진행 파일
전체를 한 번에 파싱할 때다. **그것이 U4 의 N1 이다.** U1 은 그 값을 만들고 U4 가
진다. 물음 2 가 그 경계를 정한다.

### 1.4 표시 상한의 단위가 팩과 FD 에서 갈렸다

```text
   팩       requirements/transcript/decisions.md:50
            「tool_use 는 이름과 입력 요약 200자.  tool_result 는 앞 500자」

   FD       business-rules.md R8.1
            「tool_use 의 입력 요약 200 바이트, tool_result 의 본문 500 바이트」
```

**같은 숫자가 3배 다른 값이다** — 한국어는 UTF-8 에서 글자당 3바이트다.
500바이트는 한글 약 166자이고, 500자는 1,500바이트다.

**그리고 바이트로 자르면 조용히 손상된다.** 룬 가운데서 끊긴 문자열을
`encoding/json` 이 인코딩할 때 잘못된 바이트를 `�` 로 바꾼다
(`encode.go:1040-1042`). `as=events` 응답과 제어판 카드가 그 자리에서
**오류 없이 틀린 글자**를 받는다.

**FD 의 잘못이다** — 팩의 「자」를 「바이트」로 옮겨 적으면서 단위가 바뀌었고 그
차이를 안 적었다. 물음 1 이 그것을 닫고, 6절이 어느 문서를 고칠지 적는다.

### 1.5 커버리지와 게이트 — 새 패키지가 자동으로 걸린다

**FD 14절이 이미 쟀다. 다시 재지 않는다** — 옮긴 뒤 `internal/enode` 84.8% ·
새 패키지가 63/65 = 96.9% 에서 시작한다.

여기서 새로 확인한 것은 **게이트가 그 값을 어떻게 집행하는가**다.

```text
   ci.yml:265-...   awk 가 /tmp/cover.out 의 프로파일에서 패키지를 뽑는다.
                    하한은 그 스텝 안의 -v floor=80 이다.
                    **새 패키지는 파일을 한 줄도 안 고쳐도 자동으로 걸린다**

   .coverage-        floor 절에 default_pct: 80 과 exclude 뿐이다.
   contract.yml      **패키지별 하한을 따로 거는 장치가 없다.**  그래서
                    「파서만 90% 로 올린다」는 이 유닛이 고를 수 있는 값이 아니다

   packages: 절      그 회차의 기준선 기록이다.  집행 입력이 아니다 —
                    집행은 프로파일에서 뽑는다.  파일 머리가 「U7 이 단독으로
                    소유하고 단독으로 쓴다」로 주인을 따로 적었다
```

**그래서 이 유닛은 `.coverage-contract.yml` 을 안 만진다.** 기준선 표에
`internal/transcript` 행을 더할지는 그 파일의 주인과 진행자의 것이다 (6절 ③).

### 1.6 공급망과 기술 스택 — 고를 것이 없다

```text
   go.mod 직접 의존 셋      pgx/v5 · golang.org/x/sys · yaml.v3.
                           **셋 다 internal/transcript 가 안 쓴다**
   go.sum                  커밋되어 있다.  잠금 파일이 있다
   취약점 스캐너            ci.yml:137-138 이 govulncheck v1.7.0 을 **판으로 박아**
                           설치하고 :188 이 ./... 에 돌린다.  latest 가 아니다
   툴체인                   go.mod 이 go 1.26 · toolchain go1.26.6 으로 묶었다
   go list -deps           표준 라이브러리만 쓰면 내부 의존이 자기 하나다
                           (FD 9.2 의 실측 — 그런 패키지가 이미 일곱이다)
```

**이 유닛이 새로 고를 기술이 0 이다.** `tech-stack-decisions.md` 는 그 0 을
근거와 함께 적는 문서가 된다 — 빈 문서가 아니라 **왜 0 인지를 재는 문서**다.

### 2.1 센 것 — 차단 findings **0**

```text
   준수     일곱    03 · 05 · 09 · 10 · 11 · 13 · 15
   N/A      여덟    01 · 02 · 04 · 06 · 07 · 08 · 12 · 14
   미준수    0
                   일곱 + 여덟 = 열다섯.  빈 칸이 0 이다
```

**미준수가 0 이므로 이 단계는 차단 findings 없이 닫힌다.**
