```text

   회차     v3-run-transcript · W-e (마지막 유닛)

   딛는 것    코드로 U4 · **U5 (page.go 를 가른다)** · 게이트로 CB3
   설계 변경   2026-09-17 에 사용자가 둘을 들였다 — 「그리는 것이 한 벌」 ·
```

## 1. 실측 — 코드가 지금 어떻게 생겼나 (2026-09-17 · `unit/panel-live` 위)

### 1.1 `steps[]` 에 `name` 이 없다 — `id` 가 로그의 이름이다

**실측으로 밟았다** (`cb3-live-1` · 2026-09-16). `GET .../steps/{seq}/log` 는
`?name=` 을 받고 없으면 `"step"` 을 기본값으로 쓴다.

```text
   name 없이        200 · X-Enode-Log-Bytes: 0      **빈 카드**
   name=summarize   200 · X-Enode-Log-Bytes: 6785   내용이 온다
```

**404 가 아니라 200 에 0 바이트라 더 아프다** — 화면이 「에이전트가 아무 말도 안
했다」로 그리고, 보는 사람도 짓는 사람도 어디가 틀렸는지 못 짚는다.

`model.mjs` 의 계약 검사가 `steps[].id` 를 필수 문자열로 이미 검증하고
(`string(s.id, 'step.id')`), `observe.go:54` 의 `SELECT seq, name, ...` 이 그
칸에 `steps.name` 을 그대로 싣는다. **물음 5 가 그 출처를 못 박는다.**

### 1.2 `ObservationClient` 는 타이머 하나다 — 「별개 타이머」가 구조로 안 선다

```text
   client.mjs:66   start() { this.interval = setInterval(() => this.refresh(), 5000) }
   refresh()       자원 전부를 한 번에 돈다 (nodes · runs · asks · detail:<id>)
```

**자원마다 간격이라는 개념이 없다.** CB4 가 재는 것은 「목록 폴링을 멈춰도 카드는
자란다」이고, 그 문장이 재는 것은 **타이머가 둘이라는 구조**다. 카드를 이
클라이언트의 자원 종류로 더하면 간격 분기를 클라이언트 안에 만들게 되고 **CB4 가
구현 세부를 재게 된다.** 물음 3 이 그 자리를 정한다.

### 1.3 `GET log` 는 데모에서 무인증이고 한도가 걸린다 — 폴러가 그 규율을 진다

```text
   api.go:107     mux.HandleFunc("GET /v1/runs/{run}/steps/{seq}/log", read(s.getLog))
   api.go:82      read = 데모면 s.limit(무인증 + 한도) · 실 함대면 s.auth
```

`ObservationClient` 는 그 규율을 이미 진다 — `429` 에서 `Retry-After` 를 읽어
`retryAt` 을 밀고(`retryDelay`), 4초 제한시간과 `AbortController` 를 걸고, 실패
셋이면 `frozenAt` 으로 얼린다. **카드 폴러를 따로 두면 그 규율이 두 벌이 된다.**

**`requirements.md` SECURITY-08 은 「`GET log` 는 `s.auth` 뒤다」로 적는다.**
데모 모드에서는 아니다 — 갈림이 `read` 안에 있다. 문서가 틀린 것이 아니라
**한쪽 모드만 적은 것**이고, 카드가 데모에서도 도므로 이 유닛이 그 반쪽을 진다.

### 1.4 현황판은 통째로 갈아 그린다 — 그러나 펼침 보존 장치가 이미 있다

```text
   view.mjs:33-35   details[data-testid][open] 를 기억했다가 갈아 그린 뒤 되돌린다
   replaceContents(el, items, signature)   signature 가 같으면 DOM 을 안 건드린다
```

**U5 가 R19 · R20 에서 밟은 자리와 같은 모양인데 해법이 이미 하나 있다.** U5 는
펼침 열쇠를 `tool_use_id` 로 들었고 (링이 감겨도 안 밀린다), 현황판은
`data-testid` 로 든다. **한 벌로 만들면 둘 중 하나를 골라야 한다** — 물음 1 의
대가에 들어간다.

### 1.5 그리는 코드가 두 언어에 산다 — 한 벌로 만들려면 두 서버가 같은 바이트를 내야 한다

```text
   제어판    page.go 의 indexHTML 문자열 상수 안 (drawEvent · evLabel · evSummary)
   현황판    internal/api/ui/static/shared/fleet/*.mjs — //go:embed static 으로 나간다
   경계      boundary_test.go:34  internal/panel -> internal/api 금지
```

**제어판이 현황판의 static 트리를 임포트할 수 없다.** 그래서 한 벌의 자리는
**둘 다 임포트할 수 있는 새 잎 패키지**뿐이다. 물음 1 이 그것을 정하고,
물음 2 가 제어판 페이지가 그 모듈을 어떻게 싣는지를 정한다.

### 1.6 사건 배열에는 계약 검사가 0 이다

`model.mjs` 의 `parseObservation` 이 `nodes` · `runs` · `detail` · `asks` 넷을
필드마다 검증하고 **모르는 모양이면 `ContractError` 로 던진다.** `as=events` 의
응답은 그 표에 없다 — 이 유닛이 처음 그린다.

```text
   지금     사건 배열을 검증하는 자리가 화면 어디에도 없다
   위험     하네스 바이트가 계약 검사 없이 카드까지 온다.  본문을 텍스트로만
           그리는 것(SECURITY-05)은 XSS 를 막지만 **모양이 틀린 응답**은 못 막는다
   값      제어판도 같은 검사를 쓰게 된다 — 한 벌의 덤이다
```

### 1.7 매 폴링마다 전체를 다시 받으면 N1 이 는다

```text
   진행 파일   총 길이 상한이 있다 (U3 · R45).  상한에 닿으면 capped 줄로 닫힌다
   헤더       X-Enode-Log-Bytes 가 총 길이를 낸다.  ?from= 이 오프셋을 받는다
   곱하기     단계 N 개 x 2초 x 보는 사람 수.  U4 가 N1 을 그 자리에서 졌다
```

**`from=` 으로 이어 받는 데 함정이 하나 있다.** 창 [0, N) 과 [N, M) 을 따로
받으면 **N 을 가로지르는 줄이 양쪽에서 다 빠진다** — 앞 창에서는 끝이 안 닫힌
조각(`partial`)이고 뒤 창에서는 머리가 잘린 조각(`head`)이라 파서가 둘 다
버린다. 물음 8 이 그 대가를 놓고 고른다.

### 1.8 안 만져도 되는 것을 확인했다

```text
   identity.mjs   함대 격자의 카드 면은 고정 키 목록이다.  이 유닛은 Run 상세만
                  만지므로 그 목록을 안 건드린다 (앞 회차 CA2 가 같은 자리를 적었다)
   scene.mjs      그래프 배치.  카드가 그래프를 안 가린다(FR-7)는 것은 배치가 아니라
                  자리의 문제다 — .pen 이 정한다
   ui.go 의 헤더   보안 헤더 다섯이 이미 걸려 있다 (ui.go:64-71).  그대로 탄다
```

## 3. 물음 여덟

형식은 `common/question-format-guide.md` 다.

**물음이 권장대로 닫혔다 (2026-09-17 · 사용자 「모두 권장안으로」). 여덟이 전부
A 이고 갈린 답이 0 이다.**

### Question 1 — 한 벌의 자리를 어디로 하나

1.5 가 낸 물음이다. 두 서버가 같은 바이트를 내야 한다.

```text
   A   internal/transcriptui (신규 · 잎 패키지).  card.mjs 한 장을 //go:embed 로 들고
       panel 과 api/ui 가 각자 라우트로 낸다.  경계에 금지 넷을 더한다 (파일 행렬 6.5)
   B   현황판의 static 트리에 두고 제어판은 빌드 때 복사한다.  경계를 안 건드리나
       같은 바이트가 두 자리에 생겨 **두 벌이 이름만 바뀐다**
   C   제어판 페이지를 통째로 static 으로 가른다 (U5 의 답 1 = B 를 뒤늦게 고르는 것).
       CSP 도 함께 닫히나 onclick 아홉과 페이지 구조가 전부 바뀐다 — U8 밖으로 넘친다
```

**권장은 A 다.** 잎 패키지라 새 결합이 0 이고, `.mjs` 한 장이 `node --test` 의
하네스에 그대로 들어간다 — **DOM 규칙 다섯(R14 · R19 · R20 · R21 · R30)이 사람
눈에서 내려온다.** C 가 더 깨끗하지만 이 유닛의 범위가 아니고, U5 에서 이미
사용자가 A(인라인 유지)를 골랐다.

**대가를 미리 적는다** — 1.4 의 펼침 열쇠가 두 벌(`tool_use_id` 대 `data-testid`)
이라 한 벌로 만들면서 하나를 골라야 한다. 렌더러가 `tool_use_id` 를 쓰고
현황판의 `details` 보존 장치는 카드 밖(단계 목록)에만 남기는 쪽이 작다.

[Answer]: A

### Question 2 — 제어판 페이지가 그 모듈을 어떻게 싣나

```text
   A   <script type="module" src="/static/card.mjs"> 하나를 더하고, 기존 인라인
       스크립트는 그대로 둔다.  모듈이 export 한 함수를 window 에 걸어 인라인이 부른다
   B   페이지 전체를 모듈로 바꾸고 onclick 아홉을 addEventListener 로 걷는다.
       CSP 의 'unsafe-inline' 을 script-src 에서 뺄 수 있게 되나 페이지가 다 바뀐다
   C   인라인이 fetch 로 받아 실행한다.  CSP 와 싸우고 얻는 것이 0 이다
```

**권장은 A 다.** 제어판의 CSP 는 `script-src 'self' 'unsafe-inline'` 이라
같은 출처의 모듈이 그대로 선다 (U5 의 R25). B 는 CSP 를 한 칸 조이지만 이
유닛이 카드 밖의 페이지를 다시 짓게 되고, **CB1 을 다시 빨갛게 만들 표면이
넓어진다** — 이 유닛은 이미 CB1 카드 줄 재확인을 지고 있다.

[Answer]: A

### Question 3 — 카드의 폴링을 어디에 두나

1.2 · 1.3 이 낸 물음이다. CB4 가 「별개 타이머」를 잰다.

```text
   A   ObservationClient 밖에 작은 폴러 하나를 새로 둔다 (2초).  429 · 제한시간 ·
       중단의 규율은 client.mjs 에서 **함수로 빼 쓴다** (두 벌로 안 만든다)
   B   ObservationClient 에 자원 종류 log:<run>/<seq> 를 더하고 간격을 자원마다 둔다.
       규율은 한 벌이나 CB4 가 「간격 분기」라는 구현 세부를 재게 된다
   C   5초 한 타이머에 합친다.  CB4 의 그 줄을 못 닫는다
```

**권장은 A 다.** CB4 의 문장이 재는 것은 **타이머가 둘**이라는 구조이고,
A 는 그것을 코드의 모양으로 만든다. B 는 같은 동작을 내지만 「목록 폴링을 멈춘다」를
시험으로 옮길 때 클라이언트 내부를 흔들어야 한다.

**규율을 함수로 빼는 것이 A 의 조건이다** — 안 빼면 1.3 의 두 벌이 생긴다.

[Answer]: A

### Question 4 — 동시에 몇 개의 카드를 폴링하나

`FR-7` 은 「Run 상세에 **단계마다** 트랜스크립트 카드. **도는 단계는 폴링으로
자라고 끝난 단계는 한 번 읽는다**」로 적는다. 1.7 의 곱하기가 여기 걸린다.

```text
   A   FR-7 그대로 — 단계마다 카드를 두되 **도는 단계만 2초로 돈다.**
       끝난 단계는 한 번 읽고 멈춘다 (state 가 DONE 이면 재요청 0)
   B   고른 단계 하나만 카드를 띄운다.  요청이 언제나 1 이나 FR-7 의 「단계마다」를 줄인다
   C   단계마다 전부 2초로 돈다.  팩의 문장에 가장 가까우나 끝난 단계까지 매 2초 다시 받는다
```

**권장은 A 다.** FR-7 이 이미 그 가름을 문장에 넣어 놨다 — 「도는 단계는 폴링으로
자라고 끝난 단계는 한 번 읽는다」. 한 Run 에서 동시에 도는 단계는 보통 하나이므로
**2초 요청의 수가 단계 수가 아니라 1 근처**가 된다.

[Answer]: A

### Question 5 — `?name=` 을 무엇으로 넘기나

1.1 이 낸 물음이다. 실측이 이미 답을 가리킨다.

```text
   A   steps[].id 를 그대로 넘긴다.  U8 안에서 닫히고 「ui.go 의 Go diff」를 안 늘린다
   B   서버의 기본값을 그 단계의 실제 이름으로 바꾼다.  Go 를 고치고 U4 의 라우트를 다시 연다
   C   안 넘긴다.  오늘의 빈 카드 그대로 — 안 고른다
```

**권장은 A 다.** `StepView.ID` 가 `steps.name` 을 그대로 싣는 것을 DB 로 확인했고
(여러 단계짜리 Run 에서도 같다), 화면 쪽에서 닫으면 이 유닛의 경계를 안 넘는다.
**B 가 틀린 것은 아니다** — 다만 기본값이 맞는 Run 이 몇인지 아무도 안 셌으므로
(2절 ③) 그 셈을 하기 전에 서버를 고치면 근거 없이 고치는 것이 된다.

[Answer]: A

### Question 6 — 「지금 쓰는 중」을 무엇으로 판정하나

사용자가 It's a Plan 의 `activeTool` 을 보고 들인 것이다. 그쪽은 `tool-start` 를
받고 `tool-end` 가 아직이면 그 이름을 상태 줄에 세운다.

```text
   A   사건 열에서 마지막 tool_use 의 id 에 짝이 되는 tool_result 가 없으면 그 이름.
       짝이 다 있으면 「생각 중」.  단계가 도는 동안만 낸다 (step.state 로 가른다)
   B   서버가 판정해 헤더로 낸다.  U4 의 라우트를 다시 열어야 한다
   C   마지막 사건의 종류만 본다 (tool_use 면 쓰는 중).  짝을 안 보므로 결과가 먼저
       온 뒤에도 「쓰는 중」이 남는다
```

**권장은 A 다.** 짝짓기는 파서가 이미 해 놨다 — `Event.ID` 가 `tool_use_id` 이고
U5 의 접기가 그 열쇠를 쓴다. **화면이 가진 것으로 닫히므로 서버를 안 건드린다.**

**이 판정이 한 벌에 들어간다** — 제어판도 같은 줄을 얻는다. 제어판에는 오늘
경과(NC-1)만 있어서 조용한 구간에 멈춘 건지 생각 중인지 화면이 말을 안 한다.

[Answer]: A

### Question 7 — 원문 토글의 바이트를 어디서 받나

U5 는 같은 응답의 `data` 를 함께 받았다 (R23 — 링이 감기므로 두 번째 읽기는 다른
창이다). 중앙은 같은 자리가 아니다 — 두 표현이 **다른 쿼리**다.

```text
   A   토글을 켤 때 as=raw 로 한 번 더 부른다.  평소 바이트가 안 늘고, 켠 동안만
       두 배가 된다.  켠 채로 두면 2초마다 둘 다 받는다
   B   언제나 둘 다 받아 둔다.  토글이 즉시 뜨나 바이트가 늘 두 배다
   C   as=events 의 사건에서 원문을 재구성한다.  raw 만 줄 전체를 들고 있으므로
```

**권장은 A 다.** C 는 실측으로 불가능하고(`Event.Text` 가 종류마다 다른 것을

같은 렌더러가 **두 출처를 받게** 되므로 렌더러의 입력은 「사건 배열」과
「원문 문자열」 둘 다 선택 가능해야 한다.

### Question 8 — 사건 창을 매번 다 받나, 이어 받나

```text
   A   매 폴링마다 처음부터 다 받는다.  줄이 안 빠지고 화면이 언제나 전체를 든다.
       대가는 바이트다 — 진행 파일이 상한까지 자라면 2초마다 그만큼 나른다
   B   X-Enode-Log-Bytes 를 오프셋으로 ?from= 에 넣어 새 바이트만 받는다.

   C   B 를 하되 서버가 「마지막 완전한 줄의 끝」을 헤더로 하나 더 내게 한다.
```

**회차 밖으로 낸다** — 그 전에 A 로 서고, N1 이 아프면 그때 C 를 연다.

### 5.2 모순 검사에서 볼 자리 — 미리 이름으로 든다

```text
   ①  Q1 = A 의 한 벌과 Q7 의 두 출처.  렌더러가 두 입력을 받으면 「한 벌」이

   ④  Q6 의 「도는 동안만」과 봉인 뒤 카드.  끝난 단계에는 상태 줄이 없어야 한다
```

### 5.2.1 모순 검사 결과 (2026-09-17) — 막은 것 하나 · 값을 정한 것 셋

#### 막은 것 — 물음 7 의 마지막 줄이 한 벌을 쪼갠다

물음 7 의 답을 적으면서 **「렌더러의 입력은 사건 배열과 원문 문자열 둘 다 선택
가능해야 한다」**고 적었다. 5.2 ① 이 그것을 보라고 적었고, 보러 갔더니 그 문장이
물음 1 = A 를 무른다.

```text
   두 입력을 받으면    렌더러 안에 「어느 쪽인가」 갈림이 선다.
                     한 벌이 함수 안에서 두 벌이 된 것이고, 두 화면이 그 갈림의
                     다른 가지만 쓰므로 한쪽 가지는 영영 안 밟힌다
```

**그래서 렌더러의 입력은 사건 배열 하나다.** 원문 토글은 렌더러 밖에 둔다 —
그리는 일이 `pre.textContent = 바이트` 한 줄이라 두 화면에 한 줄씩 있는 것이
「두 벌」이 아니다. 갈리는 것은 **바이트를 어디서 얻나**이고 그것이 이미 갈려
있다 (제어판은 같은 응답의 `data` · 현황판은 `as=raw` 두 번째 쿼리).

```text
   한 벌이 지는 것   사건 -> DOM · 「지금 쓰는 중」 판정 · 계약 검사 (1.6)
   한 벌이 안 지는 것 원문 토글의 출처와 그 한 줄 · 폴링 · 스크롤 컨테이너의 자리
```

**물음 7 의 답은 그대로 A 다** — 바뀐 것은 그 답이 렌더러에 거는 조건이다.

#### 값을 정한 것 ① — 「끝났다」를 폴러가 스스로 정하지 않는다

5.2 ② 다. 물음 3 = A 가 타이머를 가르고 물음 4 = A 가 「끝난 단계는 한 번」을
정했는데, **끝나는 순간을 아는 것은 5초 타이머 쪽**이다.

**방향을 한쪽으로 못 박는다 — 화면이 폴러에게 말한다.** 폴러가 상세 자원을
구독하지 않는다. 그릴 때마다 화면이 폴러에게 `{seq, name, state}` 목록을 넘기고,
폴러는 **시각만** 진다.

```text
   멈추는 신호 둘    상세가 DONE · FAILED 를 말한다        -> 마지막으로 한 번 읽고 멈춘다
                   응답이 X-Enode-Log-Source: sealed    -> 파일이 안 자란다.  멈춘다
   못 들으면        계속 돈다
```

**「못 들으면 계속 돈다」가 CB4 가 재는 바로 그 동작이다.** 목록 폴링을 막으면
상세가 안 오므로 상태가 `CLAIMED` 에 멈춰 있고, 카드는 그대로 자란다. 폴러가
스스로 끝을 판정하면 **그 조각이 초록인 이유가 우연**이 된다.

#### 값을 정한 것 ② — 카드의 사건 열은 `replaceContents` 를 안 탄다

5.2 ③ 이다. 물음 8 = A 가 매번 전체를 받으므로 그릴 것도 매번 전체다.

```text
   replaceContents   갈아 그린 뒤 scrollTop 을 **되돌린다** (view.mjs:36)
   R21              바닥에 있었으면 **바닥을 따라간다.**  그리기 전에 잰다
```

**둘이 반대다.** 같은 함수를 태우면 U5 가 CB1 에서 고친 동작이 현황판에서 도로
빨개진다. 그래서 사건 열의 스크롤은 **렌더러가 진다** — R21 이 한 벌에 실려 그대로
따라온다. 카드의 나머지(제목 · NC 줄 · 토글 버튼)는 현황판의 함수를 그대로 탄다.

**바이트와 DOM 을 가른다** — 물음 8 = A 는 **받는 것**이 매번 전체라는 뜻이고,
`X-Enode-Log-Bytes` 가 안 움직였으면 **DOM 은 안 갈아 그린다.** 조용한 구간의
비용이 0 이 되고, 1.7 의 곱하기에서 DOM 쪽 항이 빠진다.

#### 값을 정한 것 ③ — 상태 줄은 `step.state` 가 연다. 사건이 열지 않는다

5.2 ④ 다. 물음 6 = A 가 「단계가 도는 동안만」이라 적었고, 그 「도는」의 출처를
못 박는다.

```text
   연다      step.state == CLAIMED 일 때만 상태 줄이 있다
   안 연다    DONE · FAILED · 그 밖.  줄이 0 이다
```

**끝난 단계에 짝 없는 `tool_use` 가 남아 있을 수 있다** — 도구가 도는 중에 단계가
죽으면 그렇다. 그때 「쓰는 중」을 세우면 **화면이 끝난 것을 도는 것으로 그린다.**
상태가 그 줄을 닫는다.

**CB4 에서 이 줄은 `CLAIMED` 에 멈춰 있는다** — 목록 폴링을 막았으니 상태가 안
바뀐다. 그 자리에서 화면이 참말을 하는 법은 NC-6 이다 — 「마지막 갱신 N초 전」이
자라는 것이 **상태 줄이 낡았다는 신호**다.

#### 교차 검사 — 제어판이 이 유닛에서 받는 것

물음 1 = A 가 렌더러를 옮기므로 **이 유닛이 U5 의 화면을 만진다.** 무엇이 가고
무엇이 남는지를 먼저 적는다.

```text
   간다      evLabel · evSummary · drawEvent · 펼침 열쇠 · R21 의 스크롤 판정
             -> internal/transcriptui 의 .mjs 한 장
   남는다     폴링(1초) · 세대 리셋(R20) · 경과(R14) · 잘림 줄(R11) · 링 경로(NC-3)
             -> page.go.  링은 제어판에만 있는 것이라 한 벌에 안 들어간다
   는다      제어판이 상태 줄을 얻는다 (물음 6).  오늘 없는 줄이다
```

**이 유닛이 U5 에서 받는 규칙이 하나다** — **R30(raw 한 줄)을 그대로 옮긴다.**
CB1 이 실 하네스로 재서 낸 값이고 (사건 29 중 16 이 raw), 옮기면서 고치면 그
측정이 무효가 된다. `business-rules` 의 첫 줄이 R14 ~ R30 을 이 유닛의 규칙으로
잇는 이유가 그것이다.
