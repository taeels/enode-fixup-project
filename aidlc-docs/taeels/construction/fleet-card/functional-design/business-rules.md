# U8 `fleet-card` — 불변식

```text
   유닛    fleet-card (U8) · 웨이브 W-e (마지막) · 브랜치 unit/fleet-card
   답      1=A · 2=A · 3=A · 4=A · 5=A · 6=A · 7=A · 8=A
   기준선   10224f8
```

**U5 의 `R14` ~ `R30` 이 이 유닛의 규칙이기도 하다.** 답 1 = A 가 그리는 코드를
한 벌로 만들었으므로 제어판의 카드 규칙이 그대로 현황판의 규칙이 된다. 여기서는
`R31` 부터 이어 매기고, 옮기면서 바뀌는 줄만 다시 적는다.

**세는 것으로 지킨다.** 각 줄에 무엇이 재는지를 적는다.

---

## 1. 경계와 라우트

```text
   R31   internal/transcriptui 는 잎이다.  금지 넷을 boundary_test.go 의 표에 더한다 —
         transcriptui -> panel · api · store · enode.
         재는 법 — go list -test -deps 에 그 넷이 0 줄이다
   R32   라우트가 둘 는다.  ui.go 와 panel.go 가 각자 낸다.
         **U5 의 R1 이 이 유닛에서 바뀐다** — panel.go 의 HandleFunc 가 10 에서 11 이다
   R33   CB0 이 세는 수는 안 는다.  internal/api/api.go 의 HandleFunc diff 가 0 이다 —
         현황판 쪽은 ui.Handler() 안이다
   R34   두 라우트가 **같은 바이트**를 낸다.  각자 사본을 들지 않는다.
         재는 법 — 두 응답의 바이트를 대는 시험 하나
   R35   제어판은 internal/api 를 안 임포트한다.  오늘 그대로다 (boundary_test.go).
         그래서 한 벌의 자리가 새 잎 패키지인 것이다
```

**`R32` 가 U5 의 줄을 바꾸는 유일한 자리다.** U5 의 `R1` 은 「라우트가 안 는다」로
그 유닛 안에서 참이었고, 이 유닛이 그 수를 하나 올린다. **U5 의 문서를 고치지
않는다** — 그 줄은 그 유닛이 병합될 때 참이었고, 바꾸는 유닛이 자기 문서에
적는 것이 이 저장소의 모양이다.

## 2. 한 벌의 경계 — 무엇이 `card.mjs` 안에 있나

```text
   R36   렌더러의 입력은 **사건 배열 하나**다.  원문 문자열을 안 받는다.
         재는 법 — export 한 함수의 인자에 원문이 0 이다
   R37   렌더러가 시계를 안 읽는다.  card.mjs 에 Date.now · new Date 가 0 번.
         경과(NC-1)와 갱신(NC-6)은 화면이 든다 (U5 의 R5 와 같은 값)
   R38   렌더러가 네트워크를 안 탄다.  card.mjs 에 fetch 가 0 번
   R39   펼침 열쇠는 tool_use_id 다 (R19 그대로).  현황판의
         details[data-testid] 보존 장치는 **카드 밖**에만 남는다
   R40   R30 을 글자 그대로 옮긴다.  raw 는 Sub 와 바이트 수만이다.
         **옮기면서 고치지 않는다** — 고치면 CB1 의 측정이 무효가 된다
   R41   그리는 종류는 transcript.Kind 일곱뿐이다 (R22 그대로)
```

**`R36` 이 한 벌이 한 벌로 남는 조건이다.** 두 입력을 받으면 함수 안에 갈림이
서고, 두 화면이 그 갈림의 다른 가지만 쓴다 — 한쪽 가지는 영영 안 밟힌다.

## 3. URL 과 창

```text
   R42   ?name= 은 steps[].id 다.  고정 문자열을 안 쓴다.
         재는 법 — 폴러에 "step" 리터럴이 0 이다
   R43   ?from= 을 안 쓴다.  매 폴링마다 처음부터 받는다.
         재는 법 — 폴러에 from 이 0 번
   R44   창의 열쇠는 (run, seq, attempt) 셋이다.  하나가 바뀌면 든 것을 버리고
         펼침 · 스크롤 · 원문 토글을 비운다 (U5 의 R20 과 같은 자리)
   R45   응답의 X-Enode-Log-Attempt 가 든 열쇠와 다르면 그 응답으로 이어 그리지
         않는다.  시도가 갈린 바이트를 한 카드에 섞지 않는다
```

**`R43` 이 이 유닛에서 가장 비싼 줄이다.** 창 `[0, N)` 과 `[N, M)` 을 따로 받으면
**N 을 가로지르는 줄이 양쪽에서 다 빠진다** — 앞 창에서는 `partial` 이고 뒤 창에서는
`head` 라 파서가 둘 다 버린다. 이 팩은 잘림을 값으로 내는 쪽이므로 (`truncated` ·
`capped` · NC-2) **조용히 사라지는 줄을 안 받는다.** 치르는 것은 바이트다.

## 4. 폴링

```text
   R46   타이머가 둘이다.  카드 2초 · 목록 5초.  **CB4 가 재는 것이 이 구조다**
   R47   폴러는 상세 자원을 구독하지 않는다.  방향이 화면 -> 폴러 한쪽이다.
         재는 법 — 폴러에 detail: 문자열이 0 이다
   R48   멈추는 신호는 둘뿐이다 — 상세의 DONE · FAILED, 응답의 source=sealed.
         **총 길이가 안 움직이는 것을 끝으로 읽지 않는다**
   R49   도는 단계(CLAIMED)만 2초로 돈다.  끝난 단계는 한 번 읽고 멈춘다
   R50   429 · 제한시간 · 연속 실패 얼리기의 계산은 client.mjs 의 함수를 쓴다.
         두 벌로 안 짓는다.  재는 법 — 폴러가 retryDelay 를 임포트한다
   R51   Run 상세가 안 열려 있으면 폴러의 요청이 0 이다
```

**`R48` 이 CB4 를 우연히 초록으로 만들지 않는 줄이다.** 「총 길이가 N 번 안
움직이면 끝」으로 두면 에이전트가 오래 생각하는 구간과 끝난 구간이 같은 모양이
된다. 그리고 목록 폴링을 막은 상태에서 그 규칙이 폴러를 멈추면 **CB4 가 재려던
동작이 사라진다.**

**`R50` 이 답 3 = A 의 조건이다.** `GET log` 는 데모 모드에서 무인증 + 한도이므로
(`api.go:82` 의 `read`) 카드가 그 규율을 진다. 안 빼면 두 벌이 생긴다.

## 5. 그리기

```text
   R52   X-Enode-Log-Bytes 가 안 움직였으면 DOM 을 안 건드린다.
         받는 것과 그리는 것을 가른다 (R43 은 받는 쪽이다)
   R53   사건 열은 replaceContents 를 안 탄다 — 그 함수가 scrollTop 을 **되돌리고**
         R21 은 바닥을 **따라간다.**  둘이 반대다.  사건 열의 스크롤은 렌더러가 진다
   R54   본문은 textContent 로만 그린다.  innerHTML 에 하네스 바이트가 0 번 닿는다
         (SECURITY-05 · U5 의 R18 그대로)
   R55   사건 배열에 계약 검사를 건다.  모르는 모양이면 던지고, 카드는 그것을
         **실패한 폴링**으로 그린다 (6절).  오늘 화면에 이 검사가 0 이다
   R56   상태 줄은 step.state == CLAIMED 일 때만 있다.  끝난 단계에 줄이 0 이다
   R57   상태 줄의 판정은 **짝짓기**다 — 마지막 tool_use 의 id 에 짝이 되는
         tool_result 가 없으면 「쓰는 중」.  마지막 사건의 종류만 보지 않는다
```

**`R53` 이 U5 가 CB1 에서 산 것을 지키는 줄이다.** `replaceContents` 를 태우면
「도는 동안 위로 올려 읽기」가 현황판에서 도로 빨개진다. 카드의 나머지(제목 ·
NC 줄 · 토글 버튼)는 그 함수를 그대로 탄다 — 반대되는 것은 사건 열뿐이다.

**`R55` 가 한 벌의 덤이다.** `model.mjs` 의 `parseObservation` 이 `nodes` ·
`runs` · `detail` · `asks` 넷을 필드마다 검증하는데 `as=events` 의 응답은 그 표에
없다. 이 유닛이 처음 그리고, **제어판도 같은 검사를 얻는다.**

**총 길이 0 과 404 를 가르는 것이 `R61` 이다.** `getLog` 는 없는 `seq` 를 404 가
아니라 **200 에 총 길이 0** 으로 낸다 (`log.go` 의 주석이 그 선택을 적는다).
404 는 없는 Run 하나뿐이다.

## 8. 잔여 — 이 유닛이 안 닫는 것

```text
   ①  R43 의 전체 재수신을 실측으로 안 쟀다.  U4 가 잰 N1 은 청크 PUT 과
      폴링이었고 **카드의 전체 재수신은 그 측정에 없다.**  CB4 에서 처음 밟는다.
      빨개지면 답 8 을 C 로 다시 연다 (서버가 「마지막 완전한 줄의 끝」을
      헤더로 하나 더 낸다) — U4 의 라우트를 다시 여는 일이라 회차 밖이다

   ②  사건이 수천일 때 매 2초 DOM 을 다시 짓는 비용.  R52 가 조용한 구간을 0 으로
      만들지만 말이 많은 구간은 안 줄인다.  U5 가 같은 자리를 링에서 겪었고
      (그쪽 잔여 ④) CB1 의 512 KiB 프롬프트가 그 자리를 잰다

   ③  데모 모드에서 카드가 하네스 원문을 **무인증으로** 보인다.  오늘도 라우트는
      열려 있었고 (read 의 갈림) 이 유닛은 그것을 **보이게** 만든다.
      표면을 넓히는 것이 아니라 이미 열린 것을 화면에 올리는 것이다 —
      진행자가 그 값을 다시 볼 자리를 9절에 낸다

   ④  CB1 의 카드 줄 재확인이 사람이다.  R40 이 「글자 그대로 옮긴다」로 옮김의
      범위를 줄였지만, 옮김이 안 깨졌다는 것을 자동으로 재는 것은
      ⑤ 의 새 시험이 처음이다 — 그 시험이 오늘 0 이라 비교 대상이 없다
```
