# U5 `panel-live` — 순서

```text
   유닛    panel-live (U5) · 웨이브 W-c
   답      1=A · 2=A · 3=A · 4=A · 5=C · 6=A · 7=A · 8=A
```

---

## 1. 모순 검사가 막은 것 둘

계획 5.2.1 이 전문이다. 순서에 닿는 부분만 여기 다시 적는다.

### 1.1 응답에 기간을 안 싣는다 — 안 그러면 침묵에서 시계가 언다

2 = A 가 **「`total` 이 안 바뀌었으면 앞 답을 다시 낸다」**이고 3 = A 가 경과를
낸다. 제어판이 **초 단위 수**를 계산해 실으면 그 수가 캐시에 얼어붙는다.

```text
   침묵 -> total 불변 -> 캐시 -> 「3초 전」이 영영 3초 전
```

**침묵이 NC-1 이 있는 이유인 구간이다.** 그 구간에서만 얼면 표시가 없는 것보다
나쁘다 — 읽는 사람이 **시계를 믿는다**.

**제어판은 시각만 싣고 브라우저가 뺀다.** 응답이 바이트의 순수 함수가 되어
캐시가 성립하고, 표시가 폴링 사이에도 흐른다.

### 1.2 펼침 상태를 `Event.ID` 로 든다 — 안 그러면 접힌 결과를 못 편다

8 = A 가 매 폴링마다 통째로 다시 그린다. CB1 이 **「결과가 접혀 있다」**를 재고,
접혀 있다는 것은 펴서 읽는다는 뜻이다.

```text
   편다 -> 1초 뒤 DOM 이 갈린다 -> 접힌다 -> 못 읽는다
```

**`Line` 을 열쇠로 못 쓴다** — `Parse` 가 창 안에서 1 부터 세므로 링이 감기면
전부 밀린다. **`Event.ID` 는 `tool_use_id` 이고 하네스가 준 신원이라 안 밀린다.**

## 2. `GET /api/transcript` 가 도는 순서

```text
    1  링 파일을 stat 한다 -> ModTime
       못 하면 available:false 로 끝낸다 (5절 ①)

    2  캐시 열쇠를 맞춘다 — (generation, total, mtime)
       맞으면 8 로 간다.  파싱을 0 한다

    3  ReadRing 으로 스냅샷을 읽는다
       못 읽으면 available:false 로 끝낸다 (5절 ①)

    4  truncated = snap.Total > snap.Capacity   **엄격 부등호다** (R4)

    5  transcript.Parse(snap.Data, truncated) -> Result

    6  봉투를 짓는다 — Result 를 transcript 키에, 원문을 data 키에.
       **같은 읽기의 같은 바이트다** (답 6 = A)

    7  캐시에 (열쇠, 봉투) 를 넣는다.  한 칸이다 — 링이 하나다

    8  no-store 로 낸다
```

**2 번이 침묵에서 듣는다.** 하네스가 수십 초 말이 없으면 `total` 이 안 변하고
파싱이 0 이 된다 — **NC-1 이 필요한 바로 그 구간이 가장 싸다.**

**1 번이 3 번보다 앞인 것이 값이다.** mtime 을 먼저 얻어야 캐시 열쇠가 서고,
`ReadRing` 이 512 KiB 를 읽기 전에 건너뛸 수 있다.

## 3. 화면이 한 폴링에서 도는 순서

```text
    1  fetch("/api/transcript")
       실패하면 카드를 회색으로 두고 마지막 값을 그대로 둔다 (5절 ③) -> 끝

    2  available 이 거짓이면 「아직 없음」 (5절 ①) -> 끝

    3  generation 이 바뀌었나
       바뀌었으면 펼침 상태 · 스크롤 · 원문 토글을 비운다 (R9)

    4  바닥에 있었나를 **그리기 전에** 잰다 (R8)

    5  transcript.events 를 통째로 다시 그린다.
       펼침 상태를 Event.ID 로 되건다 (1.2)

    6  4 에서 바닥이었으면 바닥으로 따라간다.  아니면 스크롤을 안 건드린다

    7  경과를 now - last_write 로 그린다.  **폴링과 별개 타이머로 1초마다 다시 그린다**
       (폴링이 늦어도 경과는 흐른다)

    8  truncated 면 잘림 줄을, 언제나 ring_path 줄을 그린다
```

**4 를 5 앞에 두는 이유** — 다시 그린 뒤에 재면 언제나 바닥이 아니다
(`innerHTML` 이 갈리면서 `scrollTop` 이 0 이 된다). **잰 값을 쓰려면 갈기 전에
재야 한다.**

**7 이 폴링과 별개 타이머인 것이 3 = A 의 값이다.** 폴링이 죽어도 경과는 흐르고,
그 흐름이 5 = C 의 회색과 만나 **「값이 낡았다」와 「에이전트가 조용하다」를
가른다** (5절).

## 4. 세대가 바뀌는 순간

```text
   언제      Ring.Reset() 이 gen++ 한다 — 단계마다 claim.go:455
   서버가    아무것도 안 한다.  generation 을 그대로 실어 나른다
   화면이    펼침 상태 · 스크롤 위치 · 원문 토글을 비운다.
             앞 단계의 tool_use_id 로 이번 단계의 사건이 펴지면 안 된다
```

**오늘 이 자리가 비어 있다** — `page.go:265` 가 비교하고 대입만 한다. 통째로
갈아치우는 덕에 안 틀렸을 뿐이고, **접기가 생기면 실제로 필요해진다** (계획 1.6).

## 5. 세 상태가 절대로 안 합쳐진다 — 5 = C 가 정한 자리

```text
   ①  링이 없다 · 못 읽는다     available:false.  「아직 없음 — 도는 단계가 없거나
                              아직 첫 글자 전이다」.  오늘의 문구 그대로
   ②  링을 읽었다              사건 열 · 경과 · 잘림 · 잔여를 그린다.  카드가 정상색
   ③  폴링이 실패했다           **마지막 값을 지우지 않는다.**  카드를 회색으로 두고
                              「값이 낡았다」를 적는다.  경과는 계속 흐른다
```

**셋을 합치면 각각이 못 보는 것이 있다.**

```text
   ① 과 ③ 을 합치면   폴링이 죽은 것이 「단계가 없다」로 보인다
   ② 와 ③ 을 합치면   화면이 마지막 값을 정상색으로 들고 있어 **멈춘 것을 도는 것으로 읽는다**
                    오늘이 정확히 이 모양이다 — .catch(function(){}) 가 조용히 삼킨다
```

**③ 이 이 유닛이 새로 짓는 것이다.** `features.md` 3.3 이 「밀렸다는 표시는 앞 팩
그대로」로 적었는데 **앞 팩에 0 이다** (계획 1.5).

## 6. 실패 경로

```text
   os.Stat 실패        available:false.  로그 0 — 단계가 없는 것이 정상이다
   ReadRing 실패       available:false.  오늘과 같다
   Parse              실패 경로가 0 이다.  못 읽은 줄은 raw 로 남는다 (파서의 규율)
   캐시 어긋남          없다.  열쇠가 안 맞으면 다시 읽는다.  틀린 답을 낼 길이 0
```

**`ReadRing` 이 「파일이 없다」와 「파일이 깨졌다」를 둘 다 `available:false` 로
접는다.** 이 유닛이 만든 것이 아니고 고치면 겉면이 는다 — **회차 밖으로 낸다**
(business-rules 8절).

## 7. 이 유닛이 U6 · U8 에 넘기는 것

```text
   U6   봉투의 키 이름.  transcript 키에 transcript.Result 통째로.
        U4 의 헤더 넷을 형제 키로 옮겨 담기만 하면 화면 함수가 하나로 선다
   U6   화면 함수 자체.  같은 것을 부른다.  두 벌로 두면 봉인 전후의 그림이 갈린다
   U8   Event.ID 로 펼침을 드는 규칙.  현황판도 같은 자리에서 같은 모순을 만난다
   U8   경과를 시각으로 실어 브라우저가 빼는 규칙.  같은 이유로 같은 모양이다
```
