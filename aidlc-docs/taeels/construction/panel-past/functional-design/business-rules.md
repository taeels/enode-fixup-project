# U6 `panel-past` — 불변식

```text
   유닛    panel-past (U6) · 웨이브 W-d · 브랜치 unit/panel-past
   답      1=A · 2=A · 3=A · 4=A · 5=A · 6=A
   기준선   b3c7a24
```

**U5 의 `R14` ~ `R30` 과 U8 의 `R31` ~ `R61` 이 이 유닛의 규칙이기도 하다.**
그리는 것이 한 벌이므로 그 규칙들이 지난 것에도 그대로 선다. 여기서는 `R62`
부터 이어 매기고, **이 유닛이 새로 세우거나 바꾸는 줄만** 적는다.

**세는 것으로 지킨다.** 각 줄에 무엇이 재는지를 적는다.

---

## 1. 출처 — 이 유닛의 이유

```text
   R62   internal/panel 에 archive/tar 가 0 이다.  재는 법 — 임포트도 낱말도 없다
   R63   제어판이 Client.Record 를 0 번 부른다.  **그 메서드는 안 없앤다** —
         cmd/runctl 이 쓴다 (runctl record <id> -o r.tar)
   R64   지난 것의 출처는 GET /v1/runs/{id}/steps/{seq}/log 하나다.
         재는 법 — 브라우저 네트워크 탭에 record 가 0 이고 log 가 단계 수만큼
   R65   라우트가 안 는다.  GET /api/record 가 이미 있다 — panel.go 의 11 그대로
   R66   새 외부 표면이 0 이다.  StepLog 이 기존 do() 를 그대로 탄다
```

**`R62` 가 CB2 의 한 줄이다.** 「출처가 GET 이고 tar 를 안 푼다」.

---

## 2. 봉투 — 화면 함수가 하나로 서는 조건

```text
   R67   단계의 사건 열은 transcript 키에 transcript.Result **통째로** 담는다.
         펼치지 않는다 — U5 의 liveTranscript 와 **같은 키 · 같은 타입**이다
   R68   꺼내는 식이 도는 것과 같다 — <봉투>.transcript.events.
         재는 법 — 그리는 쪽이 두 화면에서 같은 함수를 같은 인자로 부른다
   R69   data 는 같은 읽기의 같은 바이트다.  원문 토글이 그린다
   R70   source · total · capped 는 응답 헤더를 **그대로** 옮긴다.
         제어판이 다시 계산하지 않는다 — 규칙이 두 자리에 살면 갈린다
   R71   chosen 은 Step.Chosen 그대로다.  총 길이 0 의 이유를 가른다 (4절)
```

**`R67` 의 근거가 U5 의 문서에 미리 적혀 있다** — 「U6 이 U4 의 라우트로 출처를
바꿀 때 그쪽 몸통이 이미 `transcript.Result` 다. 같은 키에 그대로 담으면 화면
함수가 하나로 선다. 펼치면 U6 이 다시 조립해야 하고, 그 조립이 둘째 봉투다」.

---

## 3. 봉인 전과 뒤

```text
   R72   갈림을 제어판이 안 만든다.  GET log 가 갈라서 답하고 제어판은 헤더를
         옮겨 싣는다.  재는 법 — 「봉인됐나」를 판정하는 조건문이 0 이다
   R73   source 가 progress 면 화면에 「봉인 전」이 있다
   R74   **source 가 progress 면 transcript.elided 가 없다.**  걷는 일은 봉인
         때 일어난다 — 진행 파일에 봉인 표시가 섞이면 하나가 틀린 것이다
   R75   자동 갱신이 0 이다.  다시 누르면 다시 읽는다 —
         도는 것은 위의 카드가 그린다 (U5 · 1초)
```

**`R74` 가 한 방향인 것이 값이다.** 거꾸로는 불변식이 아니다 — `sealed` 인데
`elided` 가 없는 단계는 정상이다(명령 단계는 걷을 도구 결과가 0 이다).

---

## 4. 총 길이 0 — 문장이 셋이다

```text
   R76   SKIPPED · chosen 거짓   「경로가 갈려 안 갔다」
   R77   SKIPPED · chosen 참     「골랐는데 못 닿았다」
   R78   그 밖에 total 이 0      「돌았고 아무 말도 안 했다」
   R79   로그가 없는 단계를 목록에서 **안 뺀다.**  화면의 단계 수가 계약과 같다
   R80   상태로 미리 걸러 요청을 아끼지 않는다 — R78 은 총 길이를 봐야 안다
```

**`Step.Chosen` 이 있는 이유가 R76 과 R77 의 구별이다.** 그 열의 주석이
「false 를 생략하면 SKIPPED 하나가 두 가지를 다시 뜻하게 된다」로 적는다.
한 문장으로 접으면 그 열이 나른 값을 화면에서 버린다.

## 5. 그리기 — 부르기만 한다

```text
   R81   이 유닛이 그리는 코드를 **0 줄** 짓는다.  window.enodeCard.renderEvents 를
         부른다.  재는 법 — page.go 의 지난 것 경로에 createElement 가 0 이다
   R82   statusLine 을 안 부른다.  지난 것에 「쓰는 중」이 없다 (U8 의 R56 과 같은 값)
   R83   펼침 상태는 단계마다 따로 든다.  열쇠는 tool_use_id (U8 의 R39)
   R84   본문은 textContent 로만.  card.mjs 가 그 성질을 이미 진다 (U8 의 R54)
   R85   걷힌 줄은 단계마다 하나다.  Run 하나로 합치지 않는다 —
         합치면 어느 단계가 얼마나 걷혔는지가 사라진다
```

**`R81` 이 이 유닛이 작은 이유다.** 앞 판이었으면 지난 것을 그리는 코드를
`page.go` 안에 또 지어야 했고, 그것이 U5 와 같은 모양의 두 번째 벌이었다.
**U8 이 그 자리를 옮겨 놔서 부르기만 하면 된다.**

## 6. 안 올 때 — 세 상태를 안 합친다

```text
   R86   단계 하나가 실패해도 나머지는 그린다.  **그 단계 자리에 오류가 남는다**
   R87   Status 가 실패하면 「기록을 못 불러왔다」이고 markMediator(false) 다
   R88   404 는 「그런 Run 이 없다」이다.  빈 화면과 다르다
   R89   이 경로에 빈 catch 가 0 이다 (U5 의 R17 과 같은 값)
```

**`R86` 이 N+1 이 만든 새 자리다.** tar 는 통째로 오거나 안 왔으므로 그 구별이
없었다. 단계 하나의 실패가 화면 전체를 비우면 **읽는 사람이 그것을 「기록이
없다」로 읽는다.**

## 8. 잔여 — 이 유닛이 안 닫는 것

```text
   ①  **봉인 전 Run 을 누르면 진행 파일 전체가 한 응답에 실린다.**  봉인 뒤는
      선별본이라 작고 (세 단계 합 16,445 바이트) 봉인 전은 크다 (survey 한 단계가
      127,117).  브라우저 쪽은 루프백이라 안 아프고 아픈 쪽은 Mediator 의 N+1 이다.
      누를 때 한 번이고 폴링이 아니다.  **CB2 가 이 자리를 밟는다** — 아프면
      data 를 두 번째 쿼리로 미룬다 (U8 이 현황판에서 그렇게 했다)

   ②  단계가 스물인 Run 의 요청 21.  ① 과 같은 자리이고 같은 답이다 —
      누를 때 한 번이다

   ③  `GET log` 의 name 기본값이 아직 step 이다.  이 유닛도 U8 처럼 화면에서
      Step.ID 를 넘겨 비켜 간다.  서버를 고치는 것은 회차 밖이다

   ④  R81 을 재는 자동 시험이 0 이다.  제어판의 JS 를 재는 하네스가 여전히
      없다 — U8 이 렌더러를 .mjs 로 빼서 **그 안의 규칙**은 재게 됐지만,
      page.go 가 그 함수를 부르는지는 못 잰다.  **CB2 가 그 자리다**
```
