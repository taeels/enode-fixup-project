# U3 `progress-store` — 규칙과 불변식

**잴 수 있는 문장으로만 적는다.** 못 재는 문장은 다음 사람에게 규칙이 아니라
분위기로 간다.

번호는 `domain-entities.md` 와 `business-logic-model.md` 가 근거로 가리키는
값이다. 답은 **Q1 ~ Q9 = A · Q10 = B · Q11 = B**.

---

# 1. 자리와 이름 — R1 ~ R6

| | 규칙 | 근거 |
|---|---|---|
| R1 | 진행 트리는 `<Root>/progress/run-<safe(id)>/` 다. **기록 디렉터리 `<Root>/run-<id>/` 밖이다** | D1 (Q2 = A). `seal` 과 `Tar` 의 `Walk` 가 `s.dir(runID)` 만 돈다 (`record.go:159` · `:229`) |
| R2 | 파일 이름은 `NN-<safe(name)>.<attempt>.log` 다 | Q1 = A. `blobPath` 가 같은 파일에서 이미 시도를 이름에 넣는다 (`record.go:270`) |
| R3 | 디렉터리는 **쓸 때 만든다**. `0700` 이고 `Store.Open` 을 안 건드린다 | Q8 = A. `Seal` 이 `s.Open` 을 부르므로 (`record.go:96`) `Open` 에 넣으면 지우기 직전에 다시 만든다 |
| R4 | 파일은 `0600` · 디렉터리는 `0700` 이다 | `requirements.md` 5.4 — 「진행 파일의 권한은 0600. Mediator 프로세스만」 |
| R5 | **읽는 쪽은 언제나 최대 시도를 연다.** `ReadProgress` 에 시도 인자가 없다 | `component-methods.md` 2.1 의 서명. `OpenBlob` 이 같은 스캔을 이미 한다 (`record.go:326`) |
| R6 | 이름을 **오른쪽에서** 읽는다. 시도가 정수로 안 읽히는 이름은 **조용히 건너뛴다** | `safe()` 가 점을 안 바꾼다. `Blobs()` 가 `.tmp-*` 를 건너뛰는 것과 같은 태도 (`record.go:392`) |

**R6 이 낳는 것 하나** — `parseBlobName`(`record.go:263`)은 `%02d.%d-이름` 이라
왼쪽에서 읽는다. **재사용할 수 없고 새 헬퍼가 하나 는다.** 커버리지 예산이 그만큼
는다 (계획 1.11).

**시험이 잰다** — `01-build.step.2.log` 를 넣으면 단계 이름 `build.step` · 시도
`2` 가 나온다. 왼쪽 파싱이면 이 시험이 빨개진다.

# 2. 시도 — R7 ~ R9

| | 규칙 | 근거 |
|---|---|---|
| R7 | `attempt` 가 지금과 **같으면** 이어 붙인다 | — |
| R8 | `attempt` 가 지금보다 **작으면 버린다**. 0 바이트를 쓰고 **지금의** `Progress` 를 돌려준다 | Q6 = A. 시도는 앞으로만 간다. 노드는 돌아온 `Total` 로 오프셋을 맞추므로 (FR-5) 저절로 따라잡는다 |

## 2.1 R9 가 거는 것 둘

**계획 2.2.3 이 이름 붙인 긴장을 닫는 규칙이다.** Q1 = A 만으로는 앞 시도의
원문이 봉인까지 남아 `application-design.md` 8절이 D7 에 준 「노출 기간이 시도
하나」가 거짓이 됐다. **Q11 = B 가 그것을 되돌렸다.**

```text
   R9 가 걷는 범위   같은 (seq, name) 의 attempt 가 더 작은 파일만.
                    다른 단계는 안 건드린다.  다른 Run 은 당연히 안 건드린다

   R9 의 실패 등급   **보조다** (R25).  걷기가 실패해도 새 시도의 쓰기는 돈다.
                    관측 표면이 실행을 막으면 그것은 관측이 아니라 의존이다
                    (application-design.md 2.1)
```

## 2.2 R17 — 「앞 시도를 아무도 안 읽는다」를 **전제로 두지 않는다**

| | 규칙 | 근거 |
|---|---|---|
| R17 | 앞 시도의 파일은 **읽는 경로가 0 이다**. `ReadProgress` 가 R5 로 언제나 최대 시도만 열기 때문이다 | 계획 물음 11 = B 의 대가 줄이 「전제가 된다」고 적은 자리다. 전제인 채로 두면 다음 사람이 앞 시도를 읽는 경로를 열고 R9 가 그때 데이터를 지운다 |

**시험이 잰다** — 시도 1 을 쓰고 시도 2 를 쓴 뒤 `ReadProgress` 가 시도 2 의
바이트만 내는지. 그리고 시도 1 의 파일이 **디스크에 없는지**.

# 3. 상한 — R10 ~ R15

**`MaxBlobBytes` 를 쓴다. 새 상한을 안 만든다** (`decisions.md` 2절의 상한 행).
오늘 값은 기본 **10 MiB** 이고 (`config.go:100` 의 `10 << 20`) mediator yaml 의
`max_blob_bytes` 로 바뀐다.

| | 규칙 | 근거 |
|---|---|---|
| R10 | 상한 안이면 청크를 **통째로** 쓴다. 개행에 **안** 맞춘다 | 맞추면 `Total` 이 노드가 보낸 것보다 뒤처지고 노드가 그 차이를 다시 보내 루프가 돈다 |
| R11 | 상한을 넘기면 **상한 앞 마지막 개행까지만** 쓰고 나머지를 버린다. 남은 예산 안에 개행이 하나도 없으면 **0 바이트를 쓴다** | Q3 = A. 반쪽 줄이 파서에 안 간다 |
| R12 | 그때 표시 줄을 **정확히 한 번** 박는다. `{"type":"enode.capped","bytes":<상한>}` 에 개행 하나 | Q10 = B. 모양은 `elidedMark` 를 따른다 (`runner.go:415` · `:425`) |
| R13 | `Total` 은 **파일의 크기**다. **표시 줄도 든다.** 예외가 0 이다 | 아래 3.1 |
| R14 | `Capped` 의 근거는 **표시 줄의 존재 하나**다. 크기를 상한과 비교해서 판정하지 **않는다** | 아래 3.2 |
| R15 | 닿은 뒤에는 더 안 쓴다. 표시 줄이 언제나 **파일의 마지막 줄**이다 | R12 가 「한 번」인 것이 여기에 걸린다 |

## 3.1 R13 — 표시 줄이 총 길이에 드는 이유

**`Total` 의 정의를 하나로 두기 위해서다.**

```text
   드는 쪽으로 정하면   Total == 파일 크기 가 언제나 참이다.
                      from 이 언제나 진짜 바이트 오프셋이고 산술에 예외가 0 이다
                      대가 — 닿은 뒤 Total 이 상한을 넘는다

   빼는 쪽으로 정하면   Total != 파일 크기 인 상태가 생긴다.
                      from = Total 로 폴링하면 **표시 줄을 영영 못 읽는다** —
                      읽는 쪽이 가장 필요로 하는 바로 그 줄이다
```

**넘겨 적는 것이 이 집의 결이다.** 같은 파일의 `WriteBlob` 이 `limit+1` 을 읽어
초과를 가른다 (`record.go:287`) — 넘었음을 알려면 넘겨야 한다. 표시 줄도 같다.

## 3.2 R14 — 크기 비교가 판정이 **아닌** 이유

**양쪽으로 다 틀린다.**

```text
   Total < 상한 인데 닿았다    R11 이 마지막 개행까지만 쓴다.  예산 안에 개행이
                            없으면 0 바이트를 쓰므로 Total 이 상한보다 한참 작을
                            수 있다.  표시 줄을 더해도 여전히 작을 수 있다

   Total > 상한 인데 안 닿았다  일어나지 않는다.  다만 R13 때문에 **닿은 뒤에는**
                            언제나 넘으므로, 「넘었으면 닿았다」는 참이지만
                            「안 넘었으면 안 닿았다」가 거짓이다.  한쪽만 참인
                            것은 판정이 아니다
```

**그래서 마지막 줄을 본다.** 비용은 꼬리 한 번 읽기이고 R15 가 「표시 줄이 언제나
마지막」을 보장하므로 한 줄이면 족하다.

**시험이 잰다** — 개행이 없는 큰 청크 하나로 상한을 넘기면 `Total < 상한` 인데
`Capped` 가 참이다. 크기 비교로 적은 구현은 이 시험에서 빨개진다.

## 3.3 `type` 에 점을 넣는 근거

`elidedMark` 의 주석이 이미 적었다 — 실측한 하네스의 `type` 이 전부 홑단어라
(`system` · `assistant` · `user` · `result` · `rate_limit_event`) 부딪칠 수 없다.
`enode.capped` 에 그 근거가 그대로 선다.

## 5.1 R22 가 조기 반환보다 **앞**인 까닭

`putLog` 는 DB 의 `run.State` 로 410 을 내고 `Sealed()` 를 **안 본다**
(`api.go:879`). 그래서 늦은 청크의 창이 열린다.

```text
   t0   PUT 이 run.State 검사를 지난다.  아직 RUNNING 이다
   t1   Run 이 종료 상태가 되고 sealRecord 가 돈다
   t2   Seal 이 트리를 지운다
   t3   t0 의 PUT 이 닿는다.  **트리가 다시 생긴다**
   t4   조기 반환보다 뒤에 두면 다시 Seal 이 불려도 return nil 로 끝난다
```

**앞에 두면 t4 가 막힌다.** 완전히 막는 것은 R24 의 쓸기이고 R22 는 값싼 한
겹이다. **순서는 값이고 자리는 안전장치다 — 둘을 함께 둔다.**

**Q8 = A 가 이 자리를 가능하게 했다.** `Open` 이 진행 트리를 안 만들므로
(R3) 드롭을 `s.Open` 뒤로 밀 이유가 없다.

## 6.2 R27 — Q2 = A 의 경계와 오늘 `AppendLog` 이 틀린 자리

**U3 이 `AppendLog` 에 하는 것은 하나뿐이다** — 반환값의 뜻을 「이번 호출의
바이트」에서 「붙인 뒤의 총 길이」로 바꾼다 (D4). **상한도 자르는 자리도 표시도
안 바꾼다** (Q2 = A).

그 하나가 함정을 낳는다.

```go
// 오늘 — record.go:65. n 이 「이번 호출의 바이트」와 「돌려줄 값」을 겸한다
n, err := io.Copy(f, io.LimitReader(r, limit))
if n == limit { ... 표시 ... }
return n
```

`n` 을 그대로 총 길이로 바꾸면 **재시도에서 깨진다.** `logs/NN-*.log` 는 시도가
이름에 없어 이어 붙기 때문이다 (`record.go:58` · `claim.go:145` 의 URL 에
`attempt` 가 없다). 시도 2 에서 총 길이가 상한을 넘어 **안 잘렸는데 잘렸다고
표시**된다.

**그래서 둘을 갈라 든다** — 쓴 바이트로 판정하고 총 길이를 돌려준다.

## 6.3 오늘 `AppendLog` 의 `n == limit` 이 틀렸다 — **고치는 것은 U3 의 몫이 아니다**

```text
   틀린 것    n == limit 은 「잘렸다」가 아니라 「딱 맞았다」에도 참이다.
             정확히 상한 바이트인 로그에 안 잘렸는데 잘렸다고 적힌다

   옳은 꼴    같은 파일의 WriteBlob 이 limit+1 을 읽고 n > limit 로 센다
             (record.go:287).  **옳은 패턴이 같은 파일 안에 이미 있다**

   진행 파일   R11 · R12 · R14 가 그 옳은 꼴을 쓴다.  크기 비교를 아예 안 한다
```

## 7.1 R31 이 막는 함정

**뮤텍스를 맵에서 지우는 순간 그것을 쥔 쓰기가 있으면**, 다음 호출이 새 뮤텍스를

## 8.1 `safe()` 가 막지 **못하는** 것 — 실측 (2026-09-15)

```text
   개행       "step\nname"   -> 그대로.  리눅스 파일 이름에 개행이 legal 이다
   NUL        "step\x00name" -> 그대로.  os 가 뒤에서 invalid argument 로 거절한다
   길이        300자          -> 그대로.  ENAMETOOLONG
   빈 이름     ""             -> 그대로.  "01-.0.log" 가 된다
```

**이것은 오늘도 참인 기존 사실이다.** `logs/` 가 같은 `safe()` 를 쓰고 `name` 은
오늘도 `r.URL.Query().Get("name")` 에서 온다 (`api.go:884`). **U3 이 만든 결함이
아니고, 진행 트리가 같은 규칙을 물려받는다는 것이 여기 적는 값이다.**
