# U3 `progress-store` — 지켜야 하는 것

AI-DLC Construction · `progress-store` 유닛의 NFR Requirements 산출물 하나다.
**무엇을 지켜야 하는가**이고 어떻게는 여기가 아니다. 기술 선택은
`tech-stack-decisions.md`, 계획과 답 넷은
`aidlc-docs/taeels/construction/plans/progress-store-nfr-requirements-plan.md`.

정본 — 확장
`.aidlc/aidlc-rules/aws-aidlc-rule-details/extensions/security/baseline/security-baseline.md`
(차단성) · 팩 `requirements/transcript/` 의 `decisions.md` · `constraints.md` ·
이 유닛의 Functional Design 산출물 셋. **어긋나면 `enode-design` 이 이긴다**
(`requirements/transcript/canon.md`).

**이 유닛이 N2 를 진다** (`unit-of-work.md` 9절). 이 문서가 그 값이다.

## 1. 답 넷이 정한 것

물음 넷의 답이 **A · A · A · A** 다.

```text
   답      정한 것                                     이 유닛이 지는 일
   ─────   ─────────────────────────────────────────   ──────────────────────────
   1 = A   고아 판정은 **Run 상태와 나이를 둘 다** 본다  쓸기의 조건 둘.  2절 V3
   2 = A   종료 Run 의 유예는 **0**                     2절 V4
   3 = A   살아 있는 Run 의 노출 상한은 **6시간**        2절 V5.  **N2 의 중심**
   4 = A   디스크 바닥 거동을 **안 만든다**              2절 V6.  5절이 대가를 적는다
```

**Q3 = A 가 회차의 미결 하나를 닫는다.** 회차 `aidlc-state.md` 가 「① 에 상한이
없다 ... NFR Requirements 의 N2 가 그 자리다」로 들고 온 것이고 **여기서 값이
섰다** (7절이 고칠 글자를 적는다).

## 3. V5 의 6시간 — 정확히 무엇인가

**이 값이 이 단계의 중심이라 네 가지를 못 박는다.**

### 3.1 무엇의 나이인가 — **진행 파일의 마지막 쓰기**다

```text
   재는 것       그 진행 파일에 **마지막으로 바이트를 쓴 시각**부터 흐른 시간.
                파일의 mtime 이 그 값이다
   안 재는 것    Run 의 시작.  단계의 시작.  Run 이 종료 상태가 된 시각.
                셋 다 아니다
```

**왜 마지막 쓰기인가** — 노출은 **바이트가 앉아 있는 기간**이고 그것은 마지막으로
바이트가 는 순간부터 센다. Run 의 시작부터 세면 오래 도는 Run 의 **방금 쓴**
파일까지 걷힌다.

**끝난 단계의 파일이 여기서 걸린다.** 단계가 끝나면 더 안 쓰이므로 그 파일은
그 시점부터 나이를 먹고 6시간 뒤 걷힌다 — Run 이 아직 돌고 있어도 그렇다.

### 3.2 6시간이 지나면 무엇이 일어나나 — **지운다**

```text
   한다      그 파일을 지운다.  Run 단위가 아니라 **파일 단위**다 —
            같은 Run 의 방금 쓴 다른 단계 파일은 안 건드린다
   안 한다    더 안 받는 것.  **쓰기를 막지 않는다.**  다음 청크가 오면 다시 만든다
            (R3 의 게으른 MkdirAll)
```

**도는 Run 의 관측이 끊긴다 — 그 사실을 여기 적는다.**

6시간 넘게 조용한 **살아 있는** 단계의 파일이 걷히면 화면의 카드가 한 번 빈다.
**대가는 유계다.**

```text
   잃는 것     그때까지의 본문.  화면이 한 번 빈다
   안 잃는 것   단계 · 실행 · 봉인되는 logs/ 의 선별본.  **전부 안 다친다**
   되돌아오나   **온다.**  다음 청크가 파일을 다시 만들고 Total 이 0 부터 다시 센다
   화면이 아나   **안다.**  FD 의 R19 경로 2 가 이미 규칙이다 —
               Total 과 Attempt 가 **함께 0** 이면 화면이 카드를 비운다
```

**NC-1 이 그 침묵을 사람이 읽게 하는 자리다.** 카드가 빈 것과 단계가 멈춘 것을
NC-1 의 「마지막 사건 이후 경과」가 가른다 — 화면이 그 값을 그리므로 사람이
「지워졌다」와 「죽었다」를 안 헷갈린다.

**못 잰 것 하나** — 6시간 넘게 조용한 살아 있는 단계가 **실제로 있는지 안 재 봤다**
(계획 1.7). 저장소에 stream-json testdata 가 없고 하네스를 못 돌린다. **CB3 의
실측이 첫 숫자다.**

### 3.3 집행되는 자리 — V2 와 같다

```text
   자리     Reap() 안의 쓸기 하나.  V3 의 조건 둘을 순서대로 본다
   순서     **Run 상태를 먼저 보고, 종료가 아닐 때만 나이를 본다** (R37)
            뒤집으면 종료된 Run 의 트리가 6시간 남아 V4 = 0 과 어긋난다
   주기     V1 = 60초.  기동에도 한 번
   최대 지연  종료 Run 은 <= 60초.  살아 있는 Run 은 <= 6시간 + 60초
```

### 3.4 6시간을 설정으로 빼지 **않는다** — 상수다

**Q4 = A 가 「새 상한을 안 만든다」로 갔고 같은 결로 간다.**

```text
   근거 하나   decisions.md 2절의 상한 행이 「새 상한을 안 만든다」다.
              설정 키를 늘리는 것이 그 문장에 닿는다

   근거 둘     이 값은 **운영자가 조절할 값이 아니라 보안 태세의 값**이다.
              잔여 ① 의 노출 기간이고 그것을 인스턴스마다 다르게 두면
              requirements.md 5.4 의 문장이 인스턴스마다 다른 뜻이 된다

   근거 셋     오늘 값이 한 벌인 선례가 있다 — 링 512 KiB (transcript.go:28) ·
              청크 2초 · 64 KiB (decisions.md 2절).  전부 상수다

   되돌리는 값  값을 바꿔야 할 실측이 나오면 **상수 한 줄과 이 문서**를 함께 고친다.
              설정으로 빼는 것은 그때의 결정이고 지금의 결정이 아니다
```

## 4. 디스크 — Q3 = A 아래 다시 계산했다

### 4.1 무엇이 얼마나 앉나

```text
   한 단계의 진행 파일    <= MaxBlobBytes + 표시 줄.  기본 10 MiB + 약 40 바이트
                        (config.go:100 의 10 << 20 · FD 의 R12 · R13)
   한 (run, seq, name)   **파일 하나.**  R9 가 앞 시도를 걷는다
   Run 당 유지 수         min(S, 6시간 안에 마지막 쓰기가 있는 단계 수)
   동시에 도는 Run        <= 노드 수 (I1 — 한 노드에 한 Run)
```

### 4.2 봉투 — **6시간이 디스크를 자르는 것은 아니다**

| R 동시 Run | S 단계 | 단계 평균 | V5 전 | **V5 뒤** |
|---|---|---|---|---|
| 10 | 20 | 18분 (Run 이 6시간) | 2 GiB | **2 GiB — 안 준다** |
| 50 | 20 | 18분 | 10 GiB | **10 GiB — 안 준다** |
| 10 | 20 | 1시간 (Run 이 20시간) | 2 GiB | **700 MiB** |
| 10 | 200 | 10분 | 20 GiB | **3.7 GiB** |

**읽는 법을 문장으로 적는다.**

> **V5 의 6시간이 자르는 것은 노출 시간이고 디스크가 아니다.** 디스크가 주는 것은
> **Run 이 6시간보다 오래 도는 경우뿐**이다. 6시간 안에 끝나는 Run 에서는 값이
> 그대로다.

**그러므로 최악 10 GiB 가 그대로 서 있다.** Q4 = A 가 그것을 안 본다 — 5절이 그
대가를 규칙으로 적는다.

### 4.3 못 잰 것과 무엇이 있어야 재나

```text
   못 잰 것    단계 하나가 **실제로** 내는 바이트.  10 MiB 는 상한이지 보통값이 아니다
              단계 하나의 **평균 시간**.  4.2 의 셋째 열이 그래서 가정이다

   왜         저장소에 stream-json testdata 가 없다 (internal/enode/testdata 가
              존재하지 않는다 · 실측).  하네스를 여기서 못 돌린다

   무엇이 있어야  U1 이 자기 계획에 약속한 testdata 가 서면 줄 길이와 단계당 줄 수로
              봉투가 좁혀진다.  그 전에는 **CB3 의 실측이 첫 숫자다**

   안 쓴 값     링의 512 KiB 와 그 주석의 「80자 줄로 대략 6,400줄」.
              **판단이지 측정이 아니라서** N2 의 근거로 안 썼다
```

## 5. Q4 = A 의 대가 — 받아들이는 것이지 없애는 것이 아니다

**규칙으로 적는다.** 없애지 않았으므로 숨기지 않는다.

| | 규칙 | 근거 |
|---|---|---|
| **R37** | 쓸기는 **Run 상태를 먼저** 보고 종료가 아닐 때만 나이를 본다. 두 조건은 배타다 | 3.3. 뒤집으면 V4 = 0 과 어긋난다 |
| **R38** | **DB 에 Run 이 없으면 종료로 본다** | 진행 트리는 PUT 이 만들고 그 PUT 은 `GetRun` 을 먼저 지난다 (`api.go:869` 가 없으면 404). 「없다」는 「지워졌다」다 |
| **R39** | **쓸기는 봉인을 대신하지 않는다.** 진행 트리만 걷고 Record 는 안 건드린다 | 구멍 ① ② 가 낳는 「종료했는데 안 봉인된 기록」은 **이 유닛의 것이 아니다.** 고쳤다고 적지 않는다 |
| **R40** | **Mediator 는 자기 디스크를 안 본다.** 진행 파일 쓰기가 실패하면 보조로 떨어지고 청크가 버려진다 | Q4 = A · R25 |
| **R41** | **그 결과 진행 파일이 봉인을 굶길 수 있다.** 디스크가 차면 진행 쓰기(보조)만이 아니라 **봉인 쓰기(치명)도 실패한다** | 계획 1.6. **이 경로를 이름으로 적고 넘긴다** — 막는 코드가 0 이다 |
| **R42** | 최악의 봉투가 **10 GiB (R=50 · S=20)** 이고 V5 가 그것을 안 줄인다 | 4.2 |

**R41 이 이 유닛이 남기는 가장 큰 잔여다.** 없애는 길은 물음 4 의 B 였고 대가가
`freeBytes` 두 벌이었다 — 사용자가 값을 보고 A 를 골랐다.

## 6. security-baseline — 열다섯의 최종 판정

확장이 **Enabled** 다 (`decisions.md` 1절 · 사용자 결정 2026-09-11). 규칙은
**차단성**이다. **빈 칸이 0 이다 — N/A 에도 근거를 한 줄 적는다.**

취급 규율은 팩이 미리 적었다 (`decisions.md` 3절) — **새로 만드는 표면에만 걸고
기존 코드의 사실은 기록만 한다.**

| 규칙 | 판정 | 근거 |
|---|---|---|
| SECURITY-01 저장 · 전송 암호화 | **조건부** | 규칙은 **저장소**마다 걸린다. 진행 트리는 새 저장소가 아니라 **이미 있는 `Artifacts.Root` 안의 디렉터리 하나**이고 그 암호화 태세는 배포 계층의 사실이다 (`decisions.md` 3절이 기록만으로 닫았다). **Q3 = A 로 보상 통제 셋이 완성됐다** — `0600` (R4) · 봉인 때 삭제 (R22 · R23) · **6시간 상한** (V5). **그래도 준수로 안 굳는다 — 평문인 것은 그대로다** (6.2) |
| SECURITY-02 중간자 접근 로깅 | N/A | 로드밸런서 · API 게이트웨이 · CDN 이 0 이다. 이 유닛은 네트워크 요소를 안 만들고 안 지난다 |
| SECURITY-03 애플리케이션 로깅 | **준수 (새 표면 범위)** | 이 유닛이 내는 로그에 진행 파일의 **본문을 안 싣는다** — 실을 자리가 없다. 바이트를 다루고 내용을 안 판다. **잔여 ① 의 자리가 여기이고 그 노출 기간이 곧 V5 = 6시간이다** |
| SECURITY-04 HTTP 보안 헤더 | N/A | 이 유닛이 HTML 도 HTTP 응답도 안 만든다. `page.go` 의 헤더 다섯은 U5, `GET log` 의 헤더 넷은 U4 |
| SECURITY-05 입력 검증 | **조건부 (부분 준수)** | **두 유닛에 걸쳐 준수이고 U3 혼자로는 부분이다.** Q9 = A 가 검증을 U4 에 맡겼고 (FD 의 R32 ~ R34) `record` 가 보장하는 것은 **경로 탈출 차단 하나**다. **U3 의 몫은 전제를 규칙으로 적은 것이고 실제로 적었다** — 안 적으면 U4 가 무엇을 막아야 하는지 모른다 |
| SECURITY-06 최소 권한 | **준수** | 파일 `0600` · 디렉터리 `0700` (R4). **같은 저장소의 `logs/`(0644 · 0755)보다 닫는 쪽이고** 이유가 내용에 있다 — 그쪽은 선별본, 이쪽은 원문이다. IAM · 클라우드 정책은 대상이 아니다 (자원 0) |
| SECURITY-07 네트워크 구성 | N/A | 새 포트 0 · 새 리스너 0 · 새 전송 0. 로컬 파일만 만진다 |
| SECURITY-08 접근 제어 | N/A (U4 의 것) | `GET log` 의 보호는 `GET /v1/runs` 와 같은 규칙으로 U4 가 건다. **잔여 ② (같은 토큰이면 누구나 읽는다)가 그 자리이고 U3 의 것이 아니다.** 다만 `0600` 이 Mediator 프로세스 밖의 읽기를 막는다 |
