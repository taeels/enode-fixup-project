# U1 `transcript` — NFR 설계 패턴

규칙 Step 6 의 산출물 둘 중 첫째다. 둘째는 `logical-components.md`.

**형식은 Functional Design 이 닫았고 값과 검증 수단은 NFR Requirements 가
닫았다.** 여기서 닫는 것은 **그 규율이 어떻게 지켜지는가**다 — 회차 실행 계획이
이 단계의 범위를 「패턴 다섯만」으로 좁혔고 **그중 U1 이 지는 것은 ④ 하나다.**

**물음 0.** 근거는 5절.

---

## 0. 패턴 다섯 중 이 유닛이 지는 것

`execution-plan.md` 의 NFR Design 절이 회차 전체의 패턴 다섯을 적었다.
**유닛마다 지는 것이 다르므로 여기서 갈라 적는다.**

| | 패턴 | 지는 유닛 | 이 문서 |
|---|---|---|---|
| ① | 총 길이 상한에 닿았을 때의 거동과 **보이는 자리** (NC-4) | U3 (찍는 쪽) · U4 (헤더) · U5 (카드) | **반쪽만.** 3절 |
| ② | 청크 PUT 실패가 실행과 링을 안 막는 분리 | **U7** | 안 한다 |
| ③ | 폴링 타이머의 분리 — 목록 5초 · 단계 카드 2초 | **U8** | 안 한다 |
| ④ | **파서가 아는 키만 읽는 규율** (SECURITY-13) | **U1** | **1절 · 2절 — 이 문서의 전부다** |
| ⑤ | 봉인 때의 순서 — 진행 파일이 tar 보다 앞 | **U3** | 안 한다 |

**안 지는 넷을 이름으로 적는 이유** — 안 적으면 다음 사람이 빠뜨린 것으로
읽는다. `unit-of-work.md` 10절이 「스킵하는 둘도 그 자리에 근거를 적는다」로 세운
규율과 같다.

### 0.1 안 지는 넷 — 왜 여기가 아닌가

```text
   ①의 보이는 자리   값을 내는 쪽이 U3 이고 응답 헤더가 U4 · 카드 두 벌이 U5 · U8 이다.
                    이 유닛에는 화면도 응답도 없다.  **읽는 규율만 여기 있다** (3절)

   ②  청크 PUT 실패   업로더가 U7 의 신규 파일(internal/enode/upload.go)에 산다.
                    이 유닛은 네트워크를 안 만지고 고루틴을 안 만든다

   ③  폴링 타이머     내용이 JS 다 — internal/api/ui/static/shared/fleet/**.
                    U8 의 파일 행렬이고 이 유닛의 Go diff 와 교집합이 0 이다

   ⑤  봉인 순서       Seal 이 DropProgress 를 부르는 자리다 — internal/record.
                    U3 의 것이고 파일 행렬에서 이 유닛과 안 겹친다
```

**넷 다 이 유닛의 파일 행렬 밖이다** (`unit-of-work-file-matrix.md` 1절).
설계를 여기서 하면 그 유닛이 자기 FD 에서 다시 하거나, 안 하고 이 문서를
딛는다 — 둘 다 소유자가 흐려진다.

## 1. ④ 를 설계로 닫는다 — 규율이 깨지는 길 일곱

**형식은 FD 가 들었다** — `Fields`(`domain-entities.md` 2절) · R2 · R3 의 판정
사다리. **여기서 닫는 것은 그 형식이 무엇에 의해 지켜지느냐다.**

| | 깨지는 길 | 무엇이 막나 | 막는 힘 |
|---|---|---|---|
| **B1** | `Fields` 를 `map[string]any` 로 바꾼다 | **아무 기계도 안 막는다.** R2.1 이 규칙으로 있고 `Fields` 가 공개 겉면에 박혀 있어 바꾸면 공개 표면의 diff 로 보인다 | **사람** |
| **B2** | 아는 키를 타입 단언으로 읽는다 (`String` · `Bool` · `Int` 를 안 거친다) | **언어가 막는다.** `Fields` 의 값이 `json.RawMessage` 라 단언할 타입이 없다. 읽으려면 `json.Unmarshal` 을 불러야 하고, 그 셋이 그 호출의 유일한 정제된 꼴이다 | **언어** |
| **B3** | 모르는 키가 껍데기로 새어 나간다 | **형이 막는다.** `logShell` 이 필드 다섯의 구조체다 — 지우는 쪽이 아니라 **짓는 쪽**이라 원본에 새 키가 생겨도 안 실린다 (`runner.go:399-406` 의 근거 주석) | **형** |
| **B4** | 짓는 쪽과 읽는 쪽이 갈린다 | **왕복 시험이 막는다.** `Shell` 이 지은 바이트를 `Parse` 가 읽는 시험이 **같은 패키지 안에서** 빨개진다 (FD 8절) | **시험** |
| **B5** | 본문이 껍데기에 섞여 나간다 | **누출 시험이 막는다.** `assertNoLeak` 의 고정 문자열 셋 — `/etc/shadow` · `sk-ant-secret` · `root:x:0:0` (`logs_test.go:37`). 그 시험이 이 패키지로 따라온다 | **시험** |
| **B6** | 화면이 `Fields` 를 받아 직접 읽는다 | **겉면이 막는다.** `Parse` 가 `Fields` 를 안 돌려준다 — 나가는 것은 `Result` 와 `Event` 뿐이다. `Fields` 가 공개인 것은 `selectLogs` 하나를 위해서다 | **겉면** |
| **B7** | `internal/enode` 가 자기 사본을 둔다 | **시험이 막는다.** R11.1 과, `logs_test.go` 의 `selectLogs` 시험 아홉이 **한 줄도 안 고친 채** 초록이어야 한다는 조건 (FD R11.2) | **시험** |

**일곱 중 여섯을 기계가 막고 하나(B1)는 사람이 막는다.** 그 하나를 기계로
못 막는 것을 이름으로 적는다 — **도는 스크립트가 없는 채로 기계 검사라고 적으면
그것이 거짓 초록이다** (`CLAUDE.md` 의 같은 결). B1 은 단계 승인과 PR 에서 본다.

## 2. 패턴 셋 — 규율이 서는 구조

### 2.1 단일 통로 — 하네스 JSON 을 읽는 길이 하나다

```text
   바이트  ->  ParseLine  ->  Fields  ->  String · Bool · Int  ->  값
```

**이 통로 밖으로 하네스 JSON 을 읽는 길이 이 저장소에 0 이다.** 우회가 안 생기는
이유는 규칙이 아니라 **형**이다 — `Fields` 의 값이 `json.RawMessage` 라 꺼내
쓰려면 `json.Unmarshal` 을 불러야 하고, 그 호출에 「모양이 다르면 없는 것으로
본다」를 붙인 것이 그 셋이다 (B2).

**짓는 쪽도 통로가 하나다.**

```text
   Fields  ->  Shell  ->  logShell  ->  바이트
```

**둘이 만나는 곳이 한 패키지다.** 그것이 FD 8절이 값으로 삼은 구조이고, 이
문서는 그 값을 **왕복 시험 하나**로 집행한다 (B4).

### 2.2 허용목록을 형으로 굳힌다

**목록을 코드가 아니라 타입이 든다.**

```go
// internal/enode/runner.go:407 — 옮겨 온다. 필드를 안 바꾼다 (FD R13)
type logShell struct {
	Type    string
	Subtype string
	Tools   []string
	OK      *bool
	Tokens  map[string]int
}
```

```text
   목록을 늘리려면      타입을 고쳐야 한다
   타입을 고치면        Shell 이 채워야 하고 · Parse 가 읽어야 하고 ·
                      Event 에 자리가 있어야 하고 · 왕복 시험이 본다
   실수로는 못 는다     if 문 하나를 빠뜨려서 새는 경로가 없다.
                      **지우는 쪽이었다면 있었다** — 그것이 runner.go:401-403 의 근거다
```

**같은 규율이 읽는 쪽에도 선다.** `Kind` 가 닫힌 어휘 일곱이고 (FD R3.3) 사상표에
없는 `type` 은 `raw` 로 떨어진다 (R3.2 · R3.7) — **버리지도 않고 자리를 지어
주지도 않는다.**

### 2.3 경계를 컴파일러와 `go list` 가 세운다

```text
   표준 라이브러리만      internal/transcript 의 임포트가 넷이다 —
                       encoding/json · bytes · unicode/utf8 · testing
   금지 다섯            go list -deps 가 내부 의존을 자기 하나로 낸다 (FD R9)
   그래서 규율이 아래로 못 샌다   파서가 파일도 소켓도 시계도 못 만진다.
                       못 하는 것이 규칙이 아니라 **의존 그래프**다
```

**못 재는 자리를 함께 적는다** — `go list -deps` 는 **시험 임포트를 안 본다**
(FD 9.1 의 실측). 그 한계는 이 패턴이 아니라 사람이 진다.

## 3. 새 키가 늘 때 — 두 방향이 다르다

**이것이 ④ 의 설계가 실제로 시험받는 자리다.**

### 3.1 하네스가 필드를 더한다 — 아무것도 안 깨지고 아무것도 안 샌다

```text
   Fields 는 담는다        맵이므로.  그러나 아무도 안 읽는다
   Shell 은 안 싣는다      logShell 의 필드 다섯 밖이다
   Parse 는 raw 로 낸다    새 type 이면.  새 키면 그냥 안 읽는다
   화면은 안 바뀐다        Kind 가 닫혀 있다
```

**늘리기로 정하면 네 자리를 같은 커밋이 만진다** — `logShell` 의 필드 ·
`Shell` 의 채우는 줄 · `Parse` 의 읽는 줄 · `Event` 의 자리. **그 넷이 전부
`internal/transcript` 안이다.** 허용목록이 한 자리라는 말의 뜻이 이것이다.

**실례가 이미 있다** — 짝 팩의 U1 이 `estimated_tokens` 를 더했고 그 커밋이
「범위를 넓힌 자리라 이름으로 적는다」를 주석으로 남겼다 (`runner.go:466-468`).
**넓히는 것이 눈에 띄게 되어 있다.**

### 3.2 enode 가 표시 줄을 더한다 — 허용목록이 두 자리가 된다

**이 회차가 그 실례를 만들었다** — `enode.capped` (FD 3.3).

```text
   막는 규칙이 이미 있다   R3.5 가 enode. 접두를 갈래로 세우고
                        R3.7 이 모르는 enode.* 를 raw 로 떨어뜨린다.
                        **그래서 enode 가 새 표시 줄을 더해도 파서가 안 깨진다** —
                        원문 한 줄이 그대로 보인다

   자리를 주려면         사상표에 행 · 필요하면 Kind · 읽는 규칙.
                        enode.capped 가 실제로 그 셋을 밟았다
```

**그런데 짓는 쪽이 이 패키지 밖일 수 있다.**

| 표시 줄 | 짓는 쪽 | 읽는 쪽 | 왕복 시험이 잡나 |
|---|---|---|---|
| `enode.elided` | `ElidedMarker` — **이 패키지** | `Parse` | **잡는다** |
| `enode.capped` | `internal/record` — **U3** | `Parse` | **못 잡는다** |

**이것이 ④ 의 규율에 난 유일한 이음매다.** 허용목록이 한 자리인 것은 하네스
쪽이고, enode 쪽 표시 줄은 **두 자리**다. 맞대는 절차가 기계가 아니라 사람이고
그 자리를 `nfr-requirements.md` 16.1 이 이미 Code Generation 에 넘겼다 —
맞댈 것 둘(`type` 의 글자 · `bytes` 의 뜻)이 거기 이름으로 있다.

**그 비대칭이 옳다.** `internal/record` 가 파서를 임포트하면 진행 파일을 쓰는
코드가 화면의 모형을 딛게 되고 의존이 거꾸로 하나 는다 (FD 5.2). **두 자리인
대가보다 그 의존이 비싸다.**

### 3.3 이 회차가 그 실례에서 배운 것

**`bytes` 의 뜻이 한 번 갈렸다** — U1 은 총 길이로, U3 은 상한으로 적었고
**두 유닛 다 자기 모순 검사에서 0 이었다** (`plans/transcript-functional-design-plan.md`
4.1.3). 웨이브를 닫는 자리에서 진행자가 대 보고서야 보였다.

**그것이 3.2 의 이음매가 이론이 아니라는 증거다.** 이 문서가 그 자리를 패턴으로
적는 이유가 그 한 번이다.

## 4. 퍼즈가 ④ 의 어느 면을 재나

`nfr-requirements.md` 4.2 가 불변식 넷을 세웠다. **넷이 ④ 를 고루 재지 않는다.**

| | 불변식 | ④ 를 재나 | 무엇을 잡나 |
|---|---|---|---|
| **F1** | 패닉 0 | **간접으로 잰다** | 「모르는 모양에 단언을 걸어 터지는」 구현. `String` · `Bool` · `Int` 를 안 거치는 판(B2)이면 F1 이 빨개진다 |
| **F2** | `Cut > 0` 인 `Text` 가 올바른 UTF-8 | **안 잰다** | 자르기의 성질이다. 허용목록과 축이 다르다 |
| **F3** | 줄을 안 버린다 | **직접 잰다** | 「모르면 조용히 버리는」 구현. R3.2 · R3.7 이 모르는 것을 `raw` 로 남기는 것을 F3 이 센다 |
| **F4** | `Head` · `Partial` 의 경계 | **안 잰다** | 산술의 안전이다 |

### 4.1 퍼즈가 못 재는 ④ 의 면 — 셋

```text
   누출              퍼즈는 「본문이 껍데기에 실렸나」를 모른다.  무엇이 본문인지
                    아는 것은 사람이 고른 고정 문자열이다 -> assertNoLeak (B5)

   짓는 쪽과 읽는 쪽의 일치  퍼즈는 Parse 만 먹인다.  Shell 이 지은 것을 Parse 가
                    읽는지는 왕복 시험이 잰다 (B4)

   타입 선택          map[string]any 로 바꿔도 퍼즈는 여전히 초록이다.
                    B1 이 사람인 이유가 이것이다
```

**그래서 ④ 를 재는 것은 퍼즈 하나가 아니라 넷이다** — F1 · F3 · 왕복 시험 ·
누출 시험. **퍼즈만으로 SECURITY-13 을 닫았다고 적으면 그것이 거짓 초록이다.**

## 5. 물음 0 — 그 근거

**이 단계가 새로 여는 값이 0 이다.**

```text
   형식      Functional Design 이 닫았다 — Fields · Kind · Event · R2 · R3 사다리
   값        NFR Requirements 가 닫았다 — 상한 200 · 500 바이트(룬 경계) ·
            증폭 계수 · 퍼즈의 불변식 넷
   범위      회차 실행 계획이 패턴 다섯으로 좁혔고 이 유닛이 지는 것은 ④ 하나다
   구조      이 문서가 짓는 것은 **그 규율이 무엇에 의해 지켜지는가**이고,
            그것은 이미 있는 형과 시험을 세어 적는 일이지 고르는 일이 아니다
```

**규칙이 평가하라고 한 범주 다섯을 전부 쟀다.**

| 범주 | 물었나 | 근거 |
|---|---|---|
| Resilience Patterns | **안 묻는다** | 실패 등급이 0 이다 (FD R10.1). 재시도도 폴백도 없다 — `error` 를 안 돌려주므로 복구할 것이 없다. 청크 실패의 분리는 ② 로 U7 의 것이다 |
| Scalability Patterns | **안 묻는다** | 프로세스가 아니라 함수다. 인스턴스 · 풀 · 큐가 0 이라 「늘린다」의 대상이 없다. 규모의 값은 U4 의 N1 이 지고 이 유닛은 증폭 계수를 넘겼다 (`nfr-requirements.md` 5절) |
| Performance Patterns | **안 묻는다** | 비용이 입력의 약 2배로 이미 측정됐고 (`nfr-requirements.md` 6.1) 목표 수치는 부르는 쪽(제어판 1초 · Mediator 2초)의 예산이다. 캐시를 안 둔다 — 같은 입력에 같은 값이라 부르는 쪽이 캐시할 수 있고 파서가 상태를 들면 시계를 안 받는다는 값이 깨진다 |
| Security Patterns | **안 묻는다** | 이 문서의 전부가 그것이다 (1절 · 2절). 위협 모형과 잔여는 `requirements.md` 5.4 · 5.6 이 값으로 닫았고 사용자가 골랐다 |
| Logical Components | **안 묻는다** | 0 이다. 근거는 `logical-components.md` |

**억지로 만들지 않았다.** 진짜 갈림이 있었으면 멈추고 물었다.

## 6. 못 막는 것 — 이름으로 적는다

**허용목록이 닫는 것과 안 닫는 것을 가른다.**

```text
   ①  아는 키의 **값**은 여전히 신뢰할 수 없다
      허용목록은 「어느 키를 읽는가」를 닫지 「값이 무엇인가」를 안 닫는다.
      tool_use 의 name 이 "<script>" 일 수 있다.
      막는 것은 화면이다 — 본문을 텍스트로만 그리고 (U5 · U8) CSP 가 한 겹 더다
      (U5 의 헤더 다섯).  **파서는 안 고친다** — 마스킹 금지 (constraints.md §4)

   ②  ④ 는 **선별본**만 닫는다
      본문은 원문 경로로 여전히 나간다 — 링(노드 디스크)과 진행 파일(Mediator 디스크).
      그것이 requirements.md 5.4 의 잔여 ①③ 이고 사용자가 값을 보고 골랐다

   ③  plain 과 raw 의 Text 는 줄 원문 그대로다
      허용목록이 아니라 통째다.  「안 버린다」(R1)의 대가이고, 그래서 원문 토글이
      필요하다 (US-4).  비UTF-8 이면 as=events 가 U+FFFD 로 바꾼다 —
      그 잔여는 nfr-requirements.md 5.3 이 U4 에 넘겼다

   ④  enode 쪽 표시 줄의 허용목록이 두 자리다
      3.2.  왕복 시험이 안 잡고 사람이 맞댄다

   ⑤  시험 임포트를 경계 검사가 안 본다
      FD 9.1 의 실측.  go list -deps 가 _test.go 의 임포트를 안 낸다

   ⑥  Fields 가 공개다
      밖에서 json.Unmarshal 로 직접 읽을 수 있고 막는 것이 없다.
      그럴 이유가 있는 호출자가 selectLogs 하나뿐이라는 사실이 그 자리를 좁힌다 (B6)
```

**여섯 중 셋(①②③)은 설계가 고른 대가이고 셋(④⑤⑥)은 남은 빈틈이다.**
앞의 셋을 없애려면 파서가 본문을 고쳐야 하고, 그것을 팩이 금지했다.
