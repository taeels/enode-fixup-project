# U1 `transcript` — 규칙과 불변식

**잴 수 있는 문장으로만 적는다.** 못 재는 문장은 다음 사람에게 규칙이 아니라
분위기로 간다.

규칙 번호는 이 유닛 안의 것이다 — 정본 `enode-design` 의 `R1` ~ `R7`
(`agent-runtime`)과 다른 자리다.

---

## 1. 안 버린다 — 셀 수 있는 불변식

| | 규칙 | 근거 |
|---|---|---|
| **R1** | 읽은 줄마다 **사건 하나 이상**을 내거나 **집계 줄**이다. 사건을 0 개 내고 넘어가는 줄이 없다 | `constraints.md` §4 — 「파서가 사건을 고치거나 버리는 것」이 제외 기능이다 |

**세는 식.**

```text
   Lines == (집계 줄 수) + (사건을 낸 줄 수)
   집계 줄은 enode.elided 하나뿐이고 수는 0 또는 1 이다
       selectLogs 가 한 번만 쓴다 (runner.go:360)
   enode.capped 는 집계 줄이 아니라 사건을 낸 줄이다 — 둘째 항에 든다 (R3.6)
   len(Events) >= Lines - (집계 줄 수)
```

**`Head` 와 `Partial` 은 `Lines` 에 안 센다.** 읽지 않은 바이트이지 읽고 버린
줄이 아니다 (R7).

**시험이 잰다** — 실측 모양의 줄 열을 넣고 `Lines` 와 `len(Events)` 의 위 부등식이
서는지, 그리고 줄을 하나 지웠을 때 `Lines` 가 하나 주는지를 잰다.

---

## 2. 아는 키만 읽는다 (SECURITY-13)

| | 규칙 | 근거 |
|---|---|---|
| **R2** | 줄을 `Fields`(`map[string]json.RawMessage`)로 받고 **아는 키만 그때그때 푼다**. 구조체로 한 번에 안 받는다 | `runner.go:381-385` 의 근거 주석. 모르는 필드의 모양 하나가 줄 전체를 떨어뜨리는 것을 막는다 |
| **R2.1** | `map[string]any` 로 바꾸지 않는다 (Q7 = A) | `any` 는 도구 결과 본문을 파싱 시점에 통째로 메모리로 올린다. 「아는 키만 읽는다」가 「전부 읽고 아는 것만 쓴다」가 된다 |
| **R2.2** | 아는 키도 **아는 모양이 아니면 없는 것으로 본다**. `String` · `Bool` · `Int` 셋이 그 규율이다 | `runner.go:511-512` 의 주석 — 「판정을 짐작으로 메우지 않는다」 |

**모르는 것 셋이 각각 어디로 가나.**

```text
   모르는 키        안 읽는다.  Event 에 안 실린다.  원문 토글이 그 줄을 든다
   모르는 모양       없는 것으로 본다.  usage 의 service_tier(문자열) ·
                   cache_creation(객체)이 실측된 자리다 (⑳)
   모르는 Kind      raw 로 간다.  버리지 않는다 (R3.2)
```

**`component-methods.md` 1.2 가 `map[string]any` 로 적은 자리다** — 이 규칙이
그 문장을 대체한다. 고칠 문서 목록은 계획 6절.

**시험이 잰다** — `usage` 에 문자열과 객체를 섞어 넣고 `Tokens` 에 정수 넷만
남는지 잰다. `logs_test.go:210-215` 가 이미 그 시험이고 이 패키지로 따라온다.

## 3. 줄 하나가 어느 Kind 로 가나

| | 규칙 | 근거 |
|---|---|---|
| **R3.1** | JSON 객체로 안 풀리거나 `type` 이 문자열이 아니면 `text` 이고 `Sub` 가 `"plain"` 이다. `Text` 는 그 줄의 바이트 그대로다 | Q3 = A. 명령 단계의 링과 로그, 선별본 꼬리의 stderr 가 전부 이 자리다 |
| **R3.2** | JSON 이고 `type` 이 문자열인데 `enode.` 로 시작하지 않고 **사상표에 없으면** `raw` 이고 `Sub` 가 그 `type` 이다 | Q2 = A. 실측 넷 — `rate_limit_event` · `system/hook_started` · `system/hook_response` · `system/thinking_tokens` (⑳) |
| **R3.3** | `Kind` 는 **일곱**이고 그 목록은 닫혀 있다 — 하네스가 내는 여섯(`decisions.md` 2절)과 enode 가 찍는 하나(R3.6) | 어휘가 닫혀야 화면 셋이 안 갈린다 |
| **R3.4** | `Sub == "plain"` 인 `text` 를 화면이 **에이전트의 말로 안 그린다** | R3.1 이 `text` 에 두 사실을 지웠다. 가르는 것은 `Sub` 하나다 |
| **R3.5** | `type` 이 `enode.` 로 시작하는 줄은 **enode 가 찍은 표시 줄**이다. 하네스가 낸 사건이 아니다. 판정 사다리에서 **③ · ④보다 위**에 둔다 | 실측한 하네스의 `type` 은 전부 홑단어라 점이 부딪칠 수 없다 (`runner.go:415-418` 의 주석 · ⑳) |
| **R3.6** | 그 갈래 안에서 **`enode.elided` 는 사건이 아니고**(`Result.Elided`) **`enode.capped` 는 사건이다**(`Kind == capped`). 가르는 기준은 **위치가 값인가**다 | `elided` 는 파일 전체의 집계라 어느 줄에 있든 뜻이 같다. `capped` 는 「그 사건 다음부터 없다」가 전부라 사건 열의 자리를 잃으면 US-7 이 죽는다 |
| **R3.7** | 우리가 모르는 `enode.*` 는 `raw` 다. 아는 둘에만 자리를 준다 | 뜻을 모르는 줄에 화면이 문장을 지어 붙이면 그것이 거짓이 된다. 허용목록의 규율이 여기서도 같다 (R2) |
| **R3.8** | **언제 찍히는지를 이 유닛이 안 적는다.** 상한의 값과 찍는 조건은 `internal/record` 의 것이고 U3 의 FD 가 진다 | 두 문서가 같은 값을 두 벌로 들면 갈린다 (R11.1 과 같은 결) |
| **R3.9** | `enode.capped` 의 `bytes` 는 **닿은 상한**으로 읽는다. **총 길이가 아니다** | 표시 줄도 총 길이에 들어가므로 자기가 든 총 길이를 담을 수 없다 (U3 의 `R11` · `R13`). 총 길이는 `Progress.Total` 이 따로 나른다. 근거 전문은 `domain-entities.md` 4.4 |

**R3.1 과 R3.2 가 한 사다리다.** ①이 먼저 걸리므로 잘린 JSON 조각은 `raw` 가
아니라 `plain text` 로 간다 — 그리고 그 조각의 대부분은 R7 이 먼저 뗀다.

**`raw` 의 정의가 팩의 글자보다 넓다.** 팩은 「파싱 실패 줄의 원문」이고 여기는
「JSON 인데 Kind 를 모르는 줄」이다. **파싱 실패 줄은 `raw` 가 아니라
`plain text` 다.** 팩 `decisions.md` 2절이 고쳐야 할 자리다 (계획 6절).

**US-4 의 확인 글자가 이 답 아래서 갈린다.** 그 스토리는 「파서가 못 읽은 줄을
원문으로」이고 확인란이 「`raw` 사건」이다. R3.1 · R3.2 아래서 못 읽은 줄은
**`plain text` 이거나 `raw`** 이고, **둘 다 그 줄의 바이트를 그대로 `Text` 에
든다.** 스토리의 값(사람이 원문으로 판단한다)은 서고 글자만 갈린다 —
회차 문서를 고칠 자리다 (계획 6절).

**R3.5 ~ R3.8 은 U3 의 답이 들여온 것이다** (2026-09-15). U1 의 답 열둘은 한
글자도 안 바뀌었고 **기존 번호 R3.1 ~ R3.4 도 뜻이 안 바뀌었다** — R3.3 의
「여섯」이 「일곱」이 된 것 하나가 그 갈래를 센 결과다. 경위는
`plans/transcript-functional-design-plan.md` 4.1.2.

**`enode.capped` 가 `raw` 로 떨어지면 NC-4 가 반만 선다.** 화면이 문장 대신
`{"type":"enode.capped","bytes":10485760}` 을 그대로 그리고, 그것은 US-7 이
막으려는 오독(「단계가 멈춘 줄 안다」)을 못 막는다. **R3.5 의 「③ · ④보다 위」가
그 자리를 지킨다.**

**시험이 잰다** — 줄 여섯(비JSON · `type` 이 숫자 · `rate_limit_event` ·
`system/hook_response` · `enode.capped` · `enode.wibble`)을 넣고
앞 둘이 `text`/`plain`, 가운데 둘과 마지막 하나가 `raw`,
`enode.capped` 가 `capped` 로 떨어지며 **`raw` 로 간 것들은 `Text` 가 줄
원문과 같고 `capped` 는 `Info.Bytes` 가 줄의 `bytes` 그대로임**을 잰다 —
총 길이로 고쳐 읽지 않는다 (R3.9).

## 4. 껍데기 판정 (Q4 = A)

| | 규칙 | 근거 |
|---|---|---|
| **R4.1** | `type` 이 `assistant` 또는 `user` 인 줄에만 껍데기 판정을 건다 | 그 둘만 `Shell()` 이 본문을 걷는 대상이다 (`runner.go:434` 의 `message` 블록) |
| **R4.2** | 그 둘에서 `message` 키가 **없으면** 껍데기다 — `Event.Shell` 이 참이다 | 원문에는 언제나 있고 `logShell` 의 필드 다섯에는 없다 |
| **R4.3** | 그 밖의 `type` 에서는 `Shell` 이 언제나 거짓이다 | 가를 것이 없다 — `raw` 의 `Text` 가 줄 원문이라 원문이면 긴 줄, 껍데기면 짧은 줄이 보이고 **둘 다 그 줄의 진실**이다 |
| **R4.4** | 판정은 **파일이 아니라 줄마다** 한다 | 한 파일이 줄기를 섞는다 — 선별본은 앞이 JSON 이고 꼬리가 평문이다 |

**`Shell` 이 US-6 을 세운다.** 「에이전트가 아무 말도 안 했다」는 `Shell` 이
거짓이고 `Text` 가 빈 것이고, 「걷혔다」는 `Shell` 이 참이고 `Text` 가 빈 것이다.

**시험이 잰다** — 같은 `assistant` 사건을 원문과 `Shell()` 결과로 각각
`Parse` 해서 `Shell` 이 거짓/참으로 갈리는지 잰다.

## 5. 사건이 0 이 되지 않는다

| | 규칙 | 근거 |
|---|---|---|
| **R5** | 블록이 하나도 없는 `assistant` · `user` 줄도 사건 **하나**를 낸다 — `text` · `Text` 빈 문자열 | R1. 그리고 `{"type":"assistant"}` 가 사건 0 이 되면 US-6 이 화면에서 안 선다 |

**`{"type":"assistant"}` 는 실제로 나온다.** 말만 하고 끝난 턴의 껍데기가
그것이다 (`logs_test.go:196` 이 그 값을 잰다).

**시험이 잰다** — `{"type":"assistant"}` 하나를 넣고 `len(Events) == 1` 이며
`Shell` 이 참임을 잰다.

## 6. 예산 신호는 줄의 것이다

| | 규칙 | 근거 |
|---|---|---|
| **R6** | `Tokens` 는 그 줄이 낸 **첫 사건**에만 싣는다 | 와이어의 `usage` 는 줄 하나의 예산이지 블록 하나의 예산이 아니다. 사건마다 복사하면 화면이 합계를 내다가 같은 값을 여러 번 더한다 |
| **R6.1** | `usage` 에서 **이름으로 정수 넷만** 집는다 — `in` · `out` · `cache_write` · `cache_read` | ⑳ 의 실측. `usage` 안에 문자열 둘과 객체 하나가 있어 통째로 못 옮긴다 |
| **R6.2** | `estimated_tokens` 는 `thinking` 키로 싣는다 | `runner.go:466-474` 가 이미 그 자리이고 근거 주석이 「범위를 넓힌 자리라 이름으로 적는다」로 붙어 있다. 옮기면서 안 바꾼다 |

**시험이 잰다** — `tool_use` 블록 둘을 담은 `assistant` 줄을 넣고 `Tokens` 가
**첫 사건에만** 있는지 잰다.

## 7. 잘린 입력 — 머리와 꼬리

| | 규칙 | 근거 |
|---|---|---|
| **R7.1** | `truncated` 가 참이면 **첫 개행 뒤부터** 읽고 버린 바이트 수를 `Result.Head` 에 적는다 | `features.md` 3.2. 링이 감기면 첫 줄이 반만 남는다 |
| **R7.2** | 개행으로 안 끝나는 꼬리는 **안 읽고** 그 바이트 수를 `Result.Partial` 에 적는다 | Q6 = A |
| **R7.3** | `Head` 와 `Partial` 의 바이트는 `Lines` 에도 `Events` 에도 안 센다 | R1 의 식이 서려면 읽은 줄만 세야 한다 |

**R7.2 가 「버린다」가 아니라 「안 읽는다」인 이유** — 링과 진행 파일은 **쓰는
중에** 읽힌다. 그 바이트는 다음 폴링에서 개행이 붙어 완전한 줄이 된다.
읽어서 `plain text` 로 그렸다가 1초 뒤 제대로 된 사건으로 바꾸면 화면이
깜빡이고, **그 깜빡임이 US-1 이 막으려던 「멈춘 것인지 도는 것인지」의 오독과
같은 자리에서 난다.**

**남는 대가 하나를 이름으로 적는다** — 개행 없이 끝난 파일(크래시)의 마지막
줄이 사건으로 안 나온다. `Result.Partial` 이 0 이 아닌 것과 원문 토글이 그것을
덮는다. **화면이 `Partial > 0` 을 그리는 것은 U5 · U6 · U8 의 몫이고 이 유닛이
값을 준다.**

**시험이 잰다** — 같은 바이트를 개행 있이/없이 넣어 `len(Events)` 가 하나
차이나고 `Partial` 이 그 줄의 길이인지 잰다.

## 8. 상한과 마스킹 금지가 같이 서는 법 (Q5 = A)

| | 규칙 | 근거 |
|---|---|---|
| **R8.1** | 파서가 자른다 — `tool_use` 의 입력 요약 **200 바이트**, `tool_result` 의 본문 **500 바이트**. **상한을 넘지 않는 가장 긴 접두 중 마지막 룬이 온전한 데까지** 남긴다 | **숫자는 팩의 것이고 단위는 이 유닛이 정했다** (8.1). `decisions.md` 2절의 「200자 · 500자」를 바이트로 읽는다 — NFR Requirements 의 물음 1 = A |
| **R8.2** | 자른 양을 `Event.Cut` 에 적는다. **단위는 바이트다.** `Cut == 0` 이 「안 잘렸다」다 | 원래 길이는 `len(Text) + Cut` 이다. 룬 경계로 물러난 바이트도 `Cut` 에 든다 — 그래야 이 식이 그대로 참이다 |
| **R8.3** | `text` · `thinking` · `plain` · `raw` 의 `Text` 에는 **상한이 없다** | `decisions.md` 2절 — 「`text` 는 그대로」 |
| **R8.4** | **마스킹을 안 한다.** 자르기는 마스킹이 아니다 | `constraints.md` §4. 자르기는 앞에서부터 남기는 것이고 무엇을 가릴지의 규칙이 0 이다 |
| **R8.5** | 원문은 파서를 안 거치고 나가는 길이 언제나 있다 — 제어판의 `data` 와 `as=raw` | 「고치지 않는다」의 보증이 그 길에 있다. 파서가 틀려도 사람이 원문으로 판단한다 (US-4) |

**자르는 쪽이 파서인 것의 값은 응답 크기다.** `as=events` 를 중앙이 2초마다
받는다. 파서가 안 자르면 도구 결과 하나가 수십 KB 인 사건 배열이 그 주기로
흐르고, 그 부하를 **U4 의 N1 이 진다** (`unit-of-work.md` U4).

### 8.1 단위는 이 유닛이 정했다 — 그 갈림을 이 문서가 만들었다

**팩은 「자」이고 이 표는 「바이트」다.** 한국어는 UTF-8 에서 글자당 3바이트라
같은 숫자가 3배 다른 값이다.

```text
   팩        requirements/transcript/decisions.md:50   「200자 · 500자」   2026-09-11
   이 문서    R8.1 의 첫 판                             「200 바이트 · 500 바이트」
                                                       2026-09-15 · **나중이다**
```

**그 갈림을 이 문서가 만들었다.** 팩을 옮겨 적으면서 단위가 바뀌었고 그 사실을
안 적었다. **다음 사람이 팩과 이 표를 견줄 때 어느 쪽이 나중인지 알아야 한다** —
나중이 이것이고, 값을 정한 것은 NFR Requirements 의 물음 1 = A 다 (2026-09-15).

**「값은 팩의 것이고 이 유닛이 안 고른다」는 줄이 값에 대해서만 참이다.**

```text
   팩이 진다      숫자 — 200 과 500.  이 유닛이 안 고른다
   이 유닛이 진다  단위 — 바이트.  그리고 룬 경계로 물러나는 규칙
```

**팩을 진행자가 고친다** — `decisions.md`:50 의 「200자」를 「200바이트」로,
「500자」를 「500바이트」로. 이 유닛이 팩을 안 만진다
(`plans/transcript-nfr-requirements-plan.md` 8절 ①).

### 8.2 룬 경계 — 무엇을 보장하나

**보장은 하나다 — 자르기가 UTF-8 을 깨뜨리지 않는다.**

```text
   자르는 규칙   상한 바이트에서 시작해, 그 자리의 바이트가 UTF-8 이어바이트인
                동안 뒤로 물린다.  최대 세 번이다 — 룬의 최대 길이가 4 바이트다

   못 물리면     앞이 전부 이어바이트인 입력(이미 깨진 것)이면 빈 문자열이 되고
                Cut 이 전체 길이다.  멈추지 않는 경로가 0 이다

   고치지 않는다  원래 깨져 있던 바이트는 깨진 채로 남는다.  치환도 마스킹도 안 한다
                (R8.4 · constraints.md §4)
```

**입력이 올바른 UTF-8 이면, `Cut > 0` 인 사건의 `Text` 도 올바른 UTF-8 이다.**
상한이 걸리는 Kind 가 `tool_use` 와 `tool_result` 둘뿐이고 (R8.3), 그 둘 중
`tool_result` 의 `Text` 는 JSON 문자열을 디코드한 것이라 표준 라이브러리가
잘못된 UTF-8 을 이미 `U+FFFD` 로 바꾼다 (`decode.go:1209-1223`). **`tool_use`
쪽은 그 근거가 안 선다** — 아래 8.2.1 이 그 실측을 든다. 그래서 조건이 붙고,
그 조건 안에서 룬 경계 자르기가 올바름을 유지한다.

### 8.2.1 조건이 붙은 이유 — `json.RawMessage` 는 안 고쳐진다

이 절의 첫 판은 「그 둘의 `Text` 는 JSON 을 거쳐 오므로 표준 라이브러리가 두
길에서 이미 고쳐 준다」였다. **길 둘을 각각 돌려 보니 하나가 거짓이다**
(2026-09-15 · `go1.26.6`).

```text
   json.Unmarshal 로 문자열을 받는다        잘못된 바이트가 U+FFFD 가 된다   맞다
   json.Marshal 로 문자열을 낸다            같다                            맞다
   json.Marshal 로 json.RawMessage 를 낸다  **잘못된 바이트가 그대로 산다**   틀리다
```

```text
   tool_result   JSON 문자열을 디코드한 것이다 -> 자르기 앞에서 이미 올바르다
   tool_use      도구 입력 객체의 원문 JSON 바이트다 -> compact 를 지날 뿐이라
                 잘못된 UTF-8 이 살아남는다.  첫 판의 근거가 이 길에는 안 선다
```

**고치는 길 셋 중 조건을 다는 길만 규칙을 안 깬다.** 자른 뒤 `utf8.Valid` 가
거짓일 때 파서가 고치는 길은 마스킹이고 (R8.4 · `constraints.md` §4), `tool_use`
의 입력을 `any` 로 풀었다가 다시 마샬하는 길은 R2.1 이 막은 그 모양이다.
**조건을 다는 길은 파서의 코드를 한 줄도 안 바꾼다.**

**값은 한 글자도 안 바뀐다** — 상한도 단위도 자르는 규칙도 그대로다. 같은 문장이
`nfr-requirements.md` 2.2 · 4.2 에도 있었고 Code Generation 이 세 자리를 함께
고쳤다 (그 문서 8절 ⑥).

**입력이 이미 깨진 경우에 남는 보장을 따로 적는다** — `len(Text) + Cut` 이 원래
길이와 같고 자른 자리가 `utf8.RuneStart` 다 (R8.2). **그것은 입력의 유효성과
무관하게 참**이고 퍼즈가 F2 와 나란히 그것을 잰다.

**`plain` 과 `raw` 는 상한이 없어 안 잘린다** (R8.3). 그 `Text` 는 줄 바이트
그대로라 입력이 깨졌으면 깨진 채이지만, **파서가 깨뜨린 것이 아니다.**
그 잔여는 `nfr-requirements.md` 5.3 이 U4 에 넘긴다.

**시험이 잰다** — ① 600 바이트 도구 결과를 넣고 `len(Text) == 500` 이며
`Cut == 100` 인지, ② 같은 길이의 `text` 블록은 **안 잘리는지**, ③ 500 번째
바이트가 한글 룬 가운데인 입력에서 `len(Text)` 가 498 로 물러나고
`len(Text) + Cut` 이 원래 길이와 같은지. **③ 은 `FuzzParse` 의 불변식 F2 이기도
하다** (`nfr-requirements.md` 4절).

## 16. 이 유닛이 남기는 한계와 넘기는 것

### 16.1 실측으로 못 댄 것 둘

```text
   tool_use_id            R12 가 그 자리를 진다.  Code Generation 이 실물
                          stream-json 에서 확인한다

   enode.capped 의 글자    {"type":"enode.capped","bytes":<상한>} 을 **찍는 쪽이
   와 bytes 의 뜻         U3 이고 읽는 쪽이 여기**다 (domain-entities 5.2).
                          한 패키지 안의 왕복 시험으로 못 잡는 첫 자리다 —
                          enode.elided 는 짓는 함수가 이 패키지에 있어 잡힌다.

                          **실제로 한 번 갈렸다** (2026-09-15) — 이쪽이 bytes 를
                          「총 길이」로 적고 U3 이 「상한」으로 적었다.  웨이브를
                          닫는 자리에서 진행자가 대 보고서야 보였다

                          Code Generation 이 맞댈 것 **둘**이다
                            ① type 의 글자          "enode.capped" 한 글자까지
                            ② bytes 의 뜻           닿은 상한인가 총 길이인가
                          맞댄 결과를 code-summary.md 에 적는다
```

### 16.2 화면에 넘기는 값 여섯

파서가 값을 주고 그리는 것은 U5 · U6 · U8 이다.

```text
   Event.Shell      「걷혔다」와 「말을 안 했다」를 가른다        US-6
   Event.Sub        thinking 을 접을 근거 · plain 을 다르게 그릴 근거
   Event.Cut        잘렸음을 적을 근거
   Kind == capped   「상한 N 에 닿아 멈췄다」를 **그 자리에** 그릴 근거.
                    N 은 Info.Bytes 이고 닿은 상한이다 (R3.9)   US-7 · NC-4
   Result.Elided    「본문 N 개 · B 바이트가 걷혔다」 한 줄        US-6 · CB2
   Result.Partial   꼬리가 아직 안 왔음
```

**`capped` 만 `Result` 가 아니라 `Events` 에 있는 것이 값이다** (R3.6).
나머지 다섯 중 둘은 파일 전체의 사실이고 셋은 사건의 사실인데, `capped` 는
**사건 열의 자리 자체가 사실**이다.

### 16.3 이 유닛이 안 정하는 것 다섯

```text
   Event 의 JSON 태그          as=events 응답의 형식이다.  U4 의 FD
```
