## 2. 이 단계가 정한 것 하나 — 퍼즈를 표준 도구로 한다

**물음 3 = A 가 퍼즈 시험을 들였다.** 그것이 이 유닛의 유일한 도구 결정이다.

### 2.1 무엇을 고르지 않았나

```text
   고른 것       Go 표준 라이브러리의 testing.F.  go 1.18 부터 표준이다
   안 고른 것    property-based testing 라이브러리 (gopter · rapid 등)
```

**근거 셋.**

```text
   ①  새 의존 0 이 팩의 구조 불변식이다.  외부 라이브러리는 그 줄을 넘는다

   ②  property-based-testing 확장이 꺼져 있다 (팩 decisions.md §1 · 사용자 결정).
      **Go 의 표준 퍼즈는 그 확장이 아니다** — 성질을 선언하고 생성기를 짜는
      방식이 아니라 바이트를 변이시켜 크래시를 찾는 방식이다.
      그래도 그 결정의 결을 존중해 **라이브러리를 안 들인다**

   ③  대상이 바이트 하나를 받는 순수 함수다.  생성기가 필요 없다 —
      Parse(b []byte, truncated bool) 의 두 인자가 Go 퍼즈가 바로 다루는 종류다
```

### 2.2 그 선택이 새 의존을 안 늘리는 것을 무엇이 재나

```text
   go.mod 의 diff 가 0      require 블록이 한 줄도 안 는다
   go list -deps 의 내부 1   internal/transcript 가 자기 하나만 낸다
   go.sum 의 diff 가 0      새 모듈이 0 이므로 해시도 안 는다
```

**셋 다 기계가 잰다.** Code Generation 이 그 값을 다시 확인한다.

### 2.3 퍼즈가 늘리는 것 둘

```text
   testdata/fuzz/FuzzParse/   크래시가 나오면 그 입력이 파일로 쌓인다.
                              **저장소에 들어오는 바이트다** — 그것이 회귀 방지의 기작이다
   커버리지 분모              FuzzParse 의 몸통 문장이 몇 개 는다.
                              시드가 그 문장을 전부 밟으므로 덮인다
```

## 3. 이 패키지가 쓰는 표준 라이브러리

**예상이다.** Code Generation 이 실물로 확정한다.

```text
   encoding/json   ParseLine · Shell · ElidedMarker · Parse 가 쓴다
   bytes           SplitLines 와 껍데기 조립
   unicode/utf8    **룬 경계 자르기가 들여온다** (물음 1 = A).
                   RuneStart 하나면 족하다 — 표준 라이브러리의 한 줄이다
   testing         시험과 FuzzParse
```

**`unicode/utf8` 이 이 단계가 들여오는 유일한 새 임포트다.** 표준 라이브러리라
`go list -deps` 의 내부 의존은 그대로 자기 하나다 (FD 9.2) — **금지 다섯이 여전히
자동으로 초록이다.**

## 4. 안 들이는 것

| 안 들인다 | 왜 |
|---|---|
| 로깅 프레임워크 | 이 패키지는 로그를 한 줄도 안 남긴다 (SECURITY-03 의 근거). 로거를 받으면 본문이 로그로 샐 경로가 생긴다 |
| 단언 · 목 라이브러리 | 저장소 전체가 표준 `testing` 이다. 두 벌로 두지 않는다 |
| 스트리밍 JSON 파서 | `json.Decoder` 도 안 쓴다 — 입력이 이미 메모리의 `[]byte` 이고, 줄 나누기를 `selectLogs` 와 공유해야 한다 (FD R11.1) |
| 문자열 정규화 · 치환 | 마스킹 금지다 (`constraints.md` §4 · FD R8.4). 룬 경계 자르기는 치환이 아니라 **덜 남기는 것**이다 |
| 벤치마크 도구 | 표준 `testing.B` 로 족하다. 증폭 수치(224 B · 112 MB)는 그것이 잰다 |
