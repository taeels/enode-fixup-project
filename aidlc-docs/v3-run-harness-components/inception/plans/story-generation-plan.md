## 3. 질문 형식에 관한 기록 — 이 회차의 결함

`common/question-format-guide.md` 는 **모든 질문의 마지막 선택지로 `Other` 를
MANDATORY** 로 요구한다. 이 회차의 실측이다.

```text
   requirement-verification-questions.md   Other 4 개 — 지켰다
   application-design-plan.md              Other 0 개 — 어겼다
   unit-of-work-plan.md                    Other 0 개 — 어겼다
```

**이것이 「답이 권장으로 쏠렸다」의 진짜 원인에 가깝다.** 실제로 `Other` 가 있던
질문 파일에서는 답이 권장을 벗어났다 — Q1 과 Q2 의 답이 둘 다 B 였다. `Other` 가
없던 파일에서는 답이 전부 A 였고, 그런데도 Application Design Q3 의 **최종 값은
선택지 셋 어디에도 없던 것**(`Fingerprinter` · 종류 셋 · 셋째가 `repo`)이 됐다 —
탈출구가 필요했다는 증거다.

지난 질문 파일은 기록이라 안 고친다. **이 문서의 질문부터 `Other` 를 단다.**

## 4. 결정이 필요한 것 — `[Answer]:` 태그

### Q1. 진행자 페르소나의 스토리를 더 세우나

지금 진행자 스토리는 US-10(봉인만 열어 무엇으로 돌았는지 안다) 하나다.

```text
   A (권장)  하나로 둔다.  진행자가 이 팩이 만드는 표면을 안 쓴다 —
             게이트를 집행하고 병합할 뿐이고 그 절차는 scene-gates 가 진다
   B         집행 절차를 스토리로 세운다.  집행자 자격 · 보류 규칙 · 눈 검증
   C (Other) 직접 적는다
```

**[Answer]:** A

### Q2. US-5 를 스토리 목록에 두나

US-5(`runctl dry-run` 으로 조합 가용성을 본다)는 **이미 있는 기능**이라 어느
유닛도 안 맡는다.

```text
   A (권장)  둔다.  계약 작성자의 저작 경로가 열거 -> 확인 -> 제출로 이어지는데
             가운데를 빼면 US-4 와 US-6 사이가 끊긴다.  유닛 열에 (기존) 으로 적는다
   B         뺀다.  이 회차가 안 만드는 것은 스토리로 안 센다
   C (Other) 직접 적는다
```

**[Answer]:** A

## 5. 답 (2026-09-12)

Q1 · Q2 를 **A** 로 닫았다. 둘 다 이미 낸 산출물과 같은 값이라 재생성이 없다.
이 둘은 유닛 경계도 완료 조건도 안 바꾼다 — 바꿨다면 사용자에게 물었을 것이다.
