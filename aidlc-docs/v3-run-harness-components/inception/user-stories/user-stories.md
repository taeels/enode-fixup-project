# 사용자 스토리 — 최소

**왜 최소인가.** `scene-gates.md` 의 조각 일곱이 수용 기준을 실행 명령으로 이미
적었고 그것이 이 회차의 판정 기준이다. 스토리가 그것을 다시 쓰면 약한 사본이 된다.

**그런데 조각 일곱이 안 재는 자리가 있다.** 일곱은 전부 **「우리가 적은 값이
옳게 도는가」**를 재고, **「사람이 잘못 적었을 때 무엇을 보는가」**를 재는 조각이
0 이다. 이 문서는 그 자리만 짓는다.

```text
   안 쓴다   행복 경로.  CA0 ~ CA6 이 이미 재고 더 촘촘하다
   쓴다      저작 경로와 오류 경로.  사람이 손으로 적는 자리마다 하나씩
```

---

## 1. 스토리 아홉

`확인` 은 그 스토리가 초록임을 무엇으로 보는가다. 게이트가 이미 재는 것은 그
조각 이름을, 아니면 그 유닛의 완료 조건을 가리킨다.

### P1 노드 소유자

| | 스토리 | 유닛 | 확인 |
|---|---|---|---|
| US-1 | 노드 소유자로서 `enode.yaml` 에 사내 MCP 하나를 적어 **내 기계가 그것을 가졌다는 사실을 함대에 알리고** 싶다 | U3 | CA2 |
| US-2 | 노드 소유자로서 `mcp:` 절을 잘못 적었을 때 **노드가 뜨기 전에 그 사실과 이유를 알고** 싶다. 조용히 무시되면 내 기계가 함대에서 없는 것이 된다 | U3 | U3 완료 조건 — `mcp:` 검증. 모양이 틀리면 노드가 안 뜨고 사유를 로그에 낸다 |
| US-3 | 노드 소유자로서 선언한 서버가 지금 안 뜰 때 **광고에서 빠진 이유를 내 노드 로그에서** 보고 싶다. 값은 안 나가되 나에게는 보여야 한다 | U3 | CA2 의 둘째 줄 |

**US-2 가 이 문서를 짓게 한 스토리다.** `decisions.md` 2절이 「그 밖의 키는 그대로
허용목록에 옮긴다」로 **미지의 키 통과**를 값으로 박았으므로, 검증하는 것은
**아는 키의 모양**이다. 그 갈래가 없으면 오타 하나가 조용히 사라진다.

### P2 계약 작성자

| | 스토리 | 유닛 | 확인 |
|---|---|---|---|
| US-4 | 계약 작성자로서 **지금 함대에 어떤 `mcp.<이름>` 이 있는지 열거해** 보고 싶다. 이름을 모르면 `requires` 를 못 적는다 | U3 | `runctl capabilities` 에 `mcp.<이름>` 이 나온다 (U3 완료 조건 · `decisions.md` 6절 ⑬) |
| US-5 | 계약 작성자로서 **그 이름이 지금 실제로 잡히는지** 제출 전에 확인하고 싶다 | (기존) | `runctl dry-run`. 열거는 존재만 답하고 여유는 안 답한다 (`ADR-014` 결정 3) |
| US-6 | 계약 작성자로서 `agent.mcp` 에 없는 이름을 요청했을 때 **하네스가 뜨기 전에 그 사유로 단계가 실패하기를** 바란다. 조용히 빠지면 `exit 0` 으로 성공이 봉인된다 | U4 | CA4 의 셋째 줄 |
| US-7 | 계약 작성자로서 `agent.mcp` 를 배열이 아니라 문자열로 적었을 때 **제출 시점에** 걸리고 싶다. 노드 위에서 죽으면 이유를 찾기 어렵다 | U2 | U2 완료 조건 — 타입 검증 문구 둘 |
| US-8 | 계약 작성자로서 팩을 실어 보내 **그 스킬이 실제로 하네스에 떴는지** 보고 싶다 | U5 | CA5 |
| US-9 | 계약 작성자로서 팩이 tar 규약을 어겼을 때 **그 단계가 실패하고 무엇을 왜 거부했는지** 알고 싶다. 조용히 건너뛰면 스킬이 없는 채로 돈다 | U5 | U5 완료 조건 — SEC-A. `ADR-035` §3 「없음이 실패보다 나쁘다」 |

### P3 진행자

| | 스토리 | 유닛 | 확인 |
|---|---|---|---|
| US-10 | 진행자로서 **봉인된 묶음만 열어** 그 단계가 어느 서버와 어느 팩으로 돌았는지 알고 싶다 | U5 | CA6 (`ADR-005` 성질 4) |

## 2. 스토리가 유닛에 빠짐없이 앉는가

```text
   U1  isolation        US 없음 — 이 유닛은 사람이 쓰는 표면을 안 만든다.
                        끊는 일이라 저작 경로가 0 이다.  CA1 이 전부다
   U2  contract-vocab   US-7
   U3  advert           US-1 · US-2 · US-3 · US-4
   U4  sources          US-6
   U5  pack             US-8 · US-9 · US-10
   유닛 밖              US-5 (runctl dry-run — 이미 있다.  이 회차가 안 만든다)
```

**U1 에 스토리가 없는 것이 맞다.** 가짜 홈은 사람이 적는 값이 하나도 없다 — 우리가
값으로 박고 사람은 그것을 끌 수 없다 (`features.md` 3.1 「여는 값을 두지 않는다」).

---

## 3. 이 문서가 하류에 주는 것

`units-generation.md` 가 유닛을 「stories 의 논리적 묶음」으로 정의하고
`construction/functional-design.md` 가 story map 에서 배정된 스토리를 읽는다.
그 자리에 이제 실물이 있다.

```text
   unit-of-work-story-map.md   1절 옆에 스토리 사상을 더한다
   유닛별 Functional Design     자기 유닛의 스토리를 읽고 오류 문구와 로그 줄을 짓는다
```

---

## 4. 이 단계가 안 한 것

```text
   행복 경로 스토리     CA0 ~ CA6 이 더 촘촘하다.  다시 쓰면 약한 사본이다
   수용 기준 재작성     scene-gates.md 가 정본이다.  스토리는 그것을 가리킨다
   깊이 Standard 이상   최소로 돈다.  실행 계획이 스킵으로 닫았던 자리를
                      「규칙에서 벗어난다」로 다시 적고 최소 형태로 되살린 것이다
```
