# 페르소나 셋

`features.md` 2절의 용어와 3절의 각 기능에 이미 이름으로 박혀 있던 것을 꺼내
적은 것이다. 새로 만들지 않았다.

---

## P1 노드 소유자

그 기계를 가진 사람이다. `enode.yaml` 을 편집할 수 있는 유일한 사람이고
(`ADR-012` · `ADR-015` §2), 그 기계에 무엇이 깔려 있는지 아는 유일한 사람이다.

```text
   무엇을 쓰나     enode.yaml 의 mcp: 절.  실행파일 경로 또는 주소와 자격증명 이름
   무엇을 보나     노드 로그.  현황판의 자기 노드 카드
   무엇을 모르나   어느 계약이 자기 노드를 고를지.  그것은 매처가 정한다
   틀리면         그 기계의 MCP 가 함대에서 안 보인다.  조용히 안 보이는 것이 가장 나쁘다
```

## P2 계약 작성자

Run 을 내는 사람이다. `runctl` 로 직접 내거나, 오케스트레이터가 그 사람 대신
같은 문법으로 낸다 (`features.md` 3.6 — 「같은 길을 쓴다」).

```text
   무엇을 쓰나     requires 의 mcp.<이름> (매칭) · agent.mcp (실행) · agent.pack (팩)
                  그리고 팩을 가져오는 첫 단계의 argv
   무엇을 보나     runctl capabilities 로 함대의 어휘 · runctl dry-run 으로 조합 가용성
                  제출 응답(400 · 422) · 단계 error · runctl record 의 봉인
   무엇을 모르나   어느 노드가 잡을지.  그 노드에 무엇이 깔려 있는지 (이름만 안다)
   틀리면         422 로 후보가 0 이거나, 400 으로 거절되거나, 단계가 사유와 함께 실패한다
```

## P3 진행자

회차를 돌리고 게이트를 집행하고 병합하는 사람이다. **이 회차에서는 유닛을
구현하지 않는다** — 그래야 `scene-gates.md` 2절 머리의 집행자 자격을 만족한다
(`unit-of-work-dependency.md` 8.1).

```text
   무엇을 쓰나     없다.  이 팩이 만드는 표면을 안 쓴다
   무엇을 보나     조각 게이트 CA0 ~ CA6.  봉인된 묶음(runctl record)
                  워크스페이스 diff.  노드 로그
   틀리면         빨간 게이트를 초록으로 적는다.  앞 팩 CP6 이 그렇게 닫혔다
```
