## Question 1 — 장면 정본을 바꾸나 더하나

## Question 2 — 공개 데모 제출의 보안 태세 (차단성 확인)

데모 대시보드는 **공개·무인증(게스트)** 표면인데 **run 을 제출**한다. 이것은 팩의
「중앙은 읽기 전용」(`enode-features 3.1.1` · `design/README §1`)을 뒤집고,
켜져 있는 `security-baseline`(차단성)의 SECURITY-08(접근 제어)에 정면으로 걸린다.
그래서 위험을 **명시적으로 소유**하고 값으로 닫아야 다음 단계로 간다. 공통 전제 —
데모 Mediator 는 실 함대와 분리된 **일회용 인스턴스**이고 제출은 **고정 시나리오
allow-list** 로만 된다(임의 계약 불가).

A) **서버측 allow-list 라우트** — Mediator embed 가 데모 제출 엔드포인트를 내고,
고정 시나리오만 받아 **토큰을 서버측에서 주입**한다. 실 Mediator 토큰이 브라우저에
안 나온다. 새 라우트 하나가 늘지만 위험이 가장 작다. 수락 위험을 `decisions.md §3`
방식으로 기록. (권장)

B) **페이지에 범위축소 토큰** — 브라우저가 데모 전용 Mediator 토큰을 쥐고 기존
`POST /v1/runs` 를 부른다. UI 가 고정 시나리오로 제한 + 일회용 Mediator 로 위험을
가둔다. 새 라우트 0 이지만 토큰이 공개 페이지에 노출된다.

C) Other (please describe after [Answer]: tag below)

[Answer]: A

## Question 3 — 제출자 이름을 어디에 싣나 (계약·응답 모양)

"run 을 제출한 사람의 이름" 이 **작동 중 RUN 카드에 보여야** 하고, 동시에 **노드
하네스에 닿아야** 한다(mac 이 "xxx님 환영합니다" wav 를 만든다). 지금 `GET /v1/runs`
목록은 최소 열만 내고(`decisions.md 7.4` — 넓히는 것은 상세 하나뿐) `ADR-065` 는
노드에서 `principal` 을 안 낸다. 제출자 이름은 인증이 아니라 **표시 라벨**이다
(`ADR-015` — 식별이지 인증이 아니다).

A) **run 에 `submitter` 표시 필드** — 제출 시 받아 저장하고, `GET /v1/runs`
목록의 run 행에 노출하고, 스텝에 env/계약 입력으로 주입한다. 한 필드가 두 필요를
모두 진다. 목록 최소열 결정을 이 라벨 하나만큼 넓히는 것을 이 전환의 근거로 기록.
(권장)

B) **카드 표시만** — 목록에만 라벨을 싣고 하네스에는 안 준다. wav 의 이름은 게스트가
새-작업 모달에 적은 계약 본문에서 하네스가 읽는다.

## Question 4 — 웹캠 전송 (요청한 검토 포함)

검토 결론 먼저. 제약이 **Mediator 를 통한 중계·SSE·WebSocket·리버스 프록시**를
범위 밖으로 뒀다(`constraints §5·§6`). 그래서 웹캠은 **Mediator 밖(out-of-band)**
이어야 하고, 대시보드는 좌하단에 떠 있는 resizable `<video>`/iframe 으로 **소스를
임베드만** 한다(레이아웃 불변). 또 공개 페이지는 **뷰어가 여럿**이라 WebRTC 순수
P2P 는 SFU 없이는 여럿에게 못 뿌리고, 대회장 NAT 뒤에서는 TURN 까지 필요해 하루
안에 세우기엔 무겁다.

A) **호스트형 브로드캐스트 임베드** — 서드파티 스트림(또는 LiveKit 류 소형 SFU)을
고정 노트북이 송출하고 대시보드는 그 링크를 플로팅 임베드. enode·Mediator 무변경.
여럿 시청에 강함. (권장)

B) **자체 WebRTC(SFU + 시그널링 + STUN/TURN)** 를 **별도 서비스**로 세운다.
지연이 낮고 여럿에 강하지만 셋업 비용이 크다. enode·Mediator 는 여전히 무변경.

C) **LAN MJPEG/스냅샷** — 고정 노트북이 같은 망에 단순 스트림. 뷰어가 전부 대회장
망(예: 프로젝터 한 대)일 때만 성립. 공개 시청자는 못 닿는다.

D) Other (please describe after [Answer]: tag below)

[Answer]: A

# 진행자 기본 결정 (답이 없으면 이 값으로 감 · 틀리면 여기 적어 veto)

계약·보안에 안 걸리는 값은 아래로 정한다. 각 줄 뒤 `[Veto]:` 에 아니라고
적으면 바꾼다. 비워 두면 그대로 간다.

- **데모 Mediator 는 실 함대와 분리된 일회용 인스턴스.** 실 데이터·실 토큰과 안 섞는다. [Veto]: 
- **온보딩 「첫 방문」 판정은 브라우저 localStorage.** (토큰은 세션 저장소지만 온보딩은 세션을 넘겨 안 뜨게 해야 한다) 리셋 손잡이 하나 둔다. [Veto]: 
- **3D 뷰는 shonsin 의 pen.dev S6·S7 시안을 딛는다.** 함대(S6)·작업그래프(S7). export PNG 와 README 반영은 shonsin/진행자가 한다. 작업그래프는 run 목록을 안 가린다. [Veto]: 
- **고정 시나리오 둘의 계약 픽스처는 진행자가 `runctl example` 로 뽑는다.** (1) rpi LED blink toggle — 1초 heartbeat + persistent-on, 둘. (2) mac→rpi 음원 재생. [Veto]: 
- **cross-node 음원 전달은 봉인 Record blob 을 딛는다** — mac 스텝이 wav 를 blob 으로 올리고(`PUT .../blob`), rpi 스텝이 needs 로 그 산출에 닿아 `GET .../blob` 로 받는다. 「Mediator 무변경」을 지키고 새 경로 0. (사용자 원문의 "shon-sin 노트북에서 받아온다"를 직접 전송 대신 이 경로로 읽었다 — 아니면 veto) [Veto]: 
- **노드 능력**: windows 노드가 LED(ssh→rpi)·rpi 스피커를, mac 노드가 tts(higgsfield)를 광고한다. 고정 시나리오의 `requires` 가 이 능력을 겨눈다. [Veto]: 
- **새 화면 번호**: 온보딩(카드) · 게스트 로그인 · 새-작업 모달 · 웹캠 플로팅은 pen.dev 에 자리를 받는다(shonsin). S6·S7 3D 뷰는 S1·S2 를 대체가 아니라 뷰 전환으로 얹는다. [Veto]:
