# User Stories — 3.4 온보딩 카드뉴스 + Guest Login

전부 유닛 `cardnews-guest-login` 이 맡는다. 기존 일곱 기능의 스토리는
이 실행의 스코프 밖이라 여기 없다(`aidlc-docs/inception/requirements/
requirements.md` §2.1).

## US-1 랜딩에서 Guest 로 들어간다

**관람객으로서**, Mediator 토큰이 없어도 이 화면에 뭔가 눌러볼 자리가
있으면 좋겠다. **그래야** 관리자가 아니라는 이유로 바로 막히지 않는다.

- 인수 조건
  - 랜딩 화면에 Guest Login 버튼이 있다
  - 관리자 토큰 입력 자리와 시각적으로 분리돼 있다(같은 화면, 다른 영역)
  - 버튼을 누르기 전에는 아무 화면 전환도 없다
- 매핑: `enode-features.md` §3.4.1 기능 요구사항 · `scene-gates.md` CP8

## US-2 처음 누르면 배경부터 본다

**관람객으로서**, Guest Login 을 처음 눌렀을 때 곧장 빈 대시보드가 아니라
왜 이게 필요한지부터 보고 싶다. **그래야** 낯선 화면 앞에서 헤매지 않는다.

- 인수 조건
  - 처음 누르면 카드 시퀀스가 뜬다. 데모 현황판이 같이 뜨거나 뒤에
    걸쳐 있지 않다
  - 카드는 넘길 때 애니메이션으로 전환된다
  - 각 카드에 언제든 누를 수 있는 닫기 동작이 있다
- 매핑: `enode-features.md` §3.4.1 · `decisions.md` 8.1 · 8.2

## US-3 카드를 넘기거나 닫으면 다음 자리로 간다

**관람객으로서**, 카드를 끝까지 봤든 중간에 닫았든 다음에 뭘 봐야 할지
자연스럽게 이어지면 좋겠다. **그래야** 막다른 화면에서 멈추지 않는다.

- 인수 조건
  - 끝까지 넘기거나 닫으면 데모 현황판 자리로 이동한다
  - 이동한 뒤 카드뉴스 화면의 어떤 요소도 DOM 에 안 남는다
  - 데모 현황판 자리의 실제 내용은 이 스토리의 범위가 아니다 —
    placeholder 로 있어도 통과
- 매핑: `enode-features.md` §3.4.1 수용 기준 · `scene-gates.md` CP8

## US-4 다음에 다시 눌렀을 땐 바로 들어간다

**관람객으로서**, 같은 부스에서 한 번 더 보고 싶어서 Guest Login 을 다시
누르면, 방금 본 카드를 또 처음부터 보고 싶지 않다. **그래야** 반복
관람이 지루하지 않다.

- 인수 조건
  - 카드를 한 번 끝까지 본(또는 닫은) 뒤 다시 Guest Login 을 누르면
    카드 없이 곧장 데모 현황판 자리로 간다
  - 이 판정은 브라우저를 벗어나지 않는다(서버는 방문 여부를 모른다)
  - 데모 현황판에서 원하면 카드뉴스를 다시 볼 수 있는 경로가 있다
- 매핑: `enode-features.md` §3.4.1 · `decisions.md` 8.1(재방문) · 8.2(재열람 경로)

## US-5 (회귀) 관리자 흐름은 그대로다

**노드 소유자로서**(기존 페르소나), Guest Login 이 생겨도 내가 쓰던
Mediator 토큰 로그인이 그대로 동작해야 한다. **그래야** 새 기능이 내
작업을 방해하지 않는다.

- 인수 조건
  - 관리자 흐름(Mediator 토큰 -> S1)에 코드 변경이 없다 — 이 유닛은
    그 경로를 만지지 않는다
  - 관리자 토큰 입력 자리는 랜딩에 그대로 있다(자리만 있어도 통과 —
    실제 동작은 이 유닛의 스코프가 아니다)
- 매핑: `enode-features.md` §3.4.1 범위 경계 · `scene-gates.md` CP8

---

넷(US-1 ~ US-4)이 CP8 을 함께 만족시켜야 초록이다. US-5 는 회귀
확인이라 CP8 자체보다는 「관리자 화면을 손대지 않았다」는 사실 확인에
가깝다 — 코드 리뷰로 검증한다(이 유닛이 `internal/api` 의 기존 핸들러를
고치지 않았는가).
