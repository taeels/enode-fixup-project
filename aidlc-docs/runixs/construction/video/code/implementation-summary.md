# 영상 제작 구현 요약

2026-09-09 · runixs · [문서 인덱스](../README.md).

완성본은 1280×720, 24fps, 총 60초다. 캐릭터 대화와 승인 연기는 Kling으로
만들고, 한글 UI 합성과 후반 설명은 로컬 편집으로 구성했다. 영상 제작 코드는
`output/enode-video/`에 보존하며 이 문서 커밋에는 포함하지 않는다.

## 장면과 책임

| 전체 시간 | 화면·동작 | 대사 또는 설명 |
|---|---|---|
| 0–4초 | 파란 기사가 S2 개발환경 수소문 | 갤럭시 에스투 있는 분? 개발환경 찾고 있어요. |
| 4–7초 | 금색 동료가 놀람 | 에스투요?! 그거 언제 적 과제예요? |
| 7–11초 | 파란 기사가 급한 이유 설명 | 급한 이슈가 와서 업데이트 바이너리 돌려봐야 해요! |
| 11–15초 | 금색 동료가 담당자 안내 | 서대현님이 셋업했는데… 지금 휴가세요. |
| 15–23초 | 개발실에서 요청, 아직 승인 대기 | 그럼 이노드로 요청할게요. 업데이트 바이너리, 퓨징하고 동작 확인해 주세요. |
| 23–30초 | 메신저에서 대상·작업·범위를 읽고 승인 | 네, 이 작업만 승인할게요. |
| 30–36초 | 실제 함대 UI, Mediator에서 서대현님 PC로 요청 이동 | 승인된 요청의 전달 |
| 36–42초 | 실제 노드 상세 확대, enode에서 Claude 시작 | 실행 위치는 서대현님 장치 |
| 42–54초 | 주황 픽셀 Claude가 고정된 sandbox 경계 안에서 작업 | 바이너리 준비, 퓨징, 동작 확인, 로그 수집 |
| 54–60초 | 결과·로그 반환, 가상 Run 완료 | 승인한 작업만, 지정한 범위에서. |

앞 15초의 컷별 시간은 연출 목표다. 실제 발화 구간과 일부 프레이밍 차이는
[첫 영상 기록](../opening-15s-rewrite-v3.md)에 있다. 후반 화살표는 요청의 논리적
전달이며 특정 push 전송 구현을 주장하지 않는다. sandbox 광고 값이나 영상의
경계 그림을 실제 OS 격리 보장으로 해석하지 않는다.

## 캐릭터와 Kling 입력

DDTHON 9종 시트를 보존하고 이번 대화의 BLUE·GOLD만 이미지 Element로 연결했다.
서대현님의 얼굴·전신을 새로 설정하지 않았다. Claude는 코드로 그린 주황 픽셀
마스코트이며 내려받은 공식 원화가 아니다.

| 참조 | 고정 ID·특징 |
|---|---|
| BLUE | `320893737656451`; 균일한 파란 몸, 회색 뿔 투구, 분홍 볼, 갈색 끈, 오른손 창 |
| GOLD | `320893745305789`; 금색 몸·투구, 붉은 볏, 남색 망토, AI-DLC 가슴 표기 |
| 서대현님 | 청록색 손, 검은 현대형 휴대폰, 휴가지 테라스 |
| Claude Code | 주황 픽셀 몸, 어두운 눈, 픽셀 다리. sandbox 밖으로 이동하지 않음 |

등록 시 정면 표지와 3/4·측면·후면 참조를 조회해 대조했다. 이미지 Element는
음성까지 고정하지 않으며 별도 voice ID를 연결하지 않았다. 재개 시 로컬
`character-sheets/character-lock-v1.json`과 실제 서비스의 참조를 확인한다.

2026-09-09 확인한 Kling MCP는 1.3.1, 모델은 `kling-video-v3_0`이다. 세 클립
모두 720p·한국어 음성·`imageCount=1`이며, 각 시작 프레임을 `first_image`로 넣었다.
시트 전체를 장면 배경으로 넣지 않았다.

| 클립 | 길이 | 컷 구성 | 참조·시작 프레임 | 사용 크레딧 |
|---|---|---|---|---:|
| opening v3 | 15초 | 멀티샷 | BLUE·GOLD, 파란 몸체 보정 시작 장면 | 135 |
| 후속 개발실 | 8초 | 멀티샷 | 같은 두 Element, 채택 opening의 마지막 프레임 | 72 |
| 폰 승인 | 7초 | 고정된 한 컷 | 청록색 손·현대형 폰의 합성용 화면 | 63 |

프롬프트는 한 컷의 주동작과 화자를 분명하게 지정했다. 개발실의 추가 실행은
승인 전까지 대기로 표시하고, 폰은 읽는 시간과 한 번의 탭을 중심으로 구성했다.
실제 원문·요청·응답은 `opening-15s-v3-720p/`와
`continuation-45s-v1/clip02-lab-8s/`, `clip02-phone-7s/`에 보존한다.
이 절의 상대 경로 기준은 `output/enode-video/`다. 당시 지원 필드·비용은
역사적 기록이며 다음 유료 제작 시 현재 명세를 다시 확인한다.

## 모니터·폰 화면 합성

개발실 원본의 임의 글자를 enode 요청 카드로 덮었다. 원본 8초 컷의 화면 전환이
시작하는 64프레임부터 모니터를 추적해 교체한다. 요청자·대상·작업과
`/sandbox/s2-verify`를 표시하고 끝부분을 승인 대기로 바꾼다. 전면의 캐릭터와
투구는 가림 마스크로 보존한다.

폰은 `ddthon-6.jpeg`의 메신저 화면과 `ddthon-7.jpeg`의 회사 로고를 영상용으로
정리한 자산을 사용했다. 녹색 화면 전체와 생성된 임의 UI를 교체하면서 청록색
손과 윤곽선을 남겼다. 승인 후 상태는 폰 컷 127프레임, 약 5.292초부터 표시한다.
기존 Kling 승인 음성을 2초 늦춰 읽는 시간을 확보했다. 탭 위치의 작은 차이는
사용자 수용 사항이며 추가 유료 생성을 하지 않았다.

## 실제 웹 UI와 가상 관측 데이터

`internal/api/ui/static/shared/fleet/`의 `view.mjs`, `model.mjs`, `scene.mjs`,
`client.mjs`, `fleet.css`를 변경 없이 복사하고 실제 `DashboardView`에 가상
관측 데이터를 넣었다. 영상용 wrapper만 별도 경로에서 실행한다. 원본 API·DB·
공개 서버와 실제 노드 등록·작업을 변경하지 않았다.

| 가상 노드 ID | 표시 이름 | 영상 역할 |
|---|---|---|
| blue-dev | 개발자 PC | 요청자 환경 |
| seo-pc | 서대현님 PC | 요청 수신·Claude 실행, sandbox 범위 `/sandbox/s2-verify` |
| build-server | 빌드 서버 | 업데이트 바이너리 준비 맥락 |
| galaxy-s2 | Galaxy S2 | 연결된 검증 대상 장치 |
| shared-test | 공용 테스트 PC | 다른 공유 환경과 구분 |

가상 Run `S2-update-verify`는 QUEUED, RUNNING, SUCCEEDED 상태로 바뀐다.
단계는 요청 수신, Claude 실행, S2 검증, 로그 반환 순서다. 8개 UI 상태를
1600×900으로 캡처한 뒤 720p 영상에 배치했다. sandbox 확대 설명에서도 경계는
고정하고 개인 문서와 다른 프로젝트는 경계 밖에서 잠긴 상태로 표시한다.
후반 전체에 실제 웹 UI를 사용한 가상 시나리오임을 명시했다.

## 편집과 재개

로컬 `continuation-45s-v1/remotion/`에서 Remotion 4.0.522를 사용했다.
`Clip02Approval15s`는 360프레임, `AfterApproval30s`는 720프레임,
`EnodeFullFilm`은 1,440프레임이다. Noto Sans KR 폰트, 프레임 기반 이동과
상태 변경, 한국어 자막을 사용한다. 후반 내레이션은 macOS Yuna이고 UI 효과음은
직접 합성했다. 마지막 AAC 패딩만 정리해 컨테이너도 정확한 60초로 맞췄다.

재개에 필요한 로컬 자료는 원본 MP4·시트, 각 합성 `composite.py`,
`ui-source/scenario.mjs`, `ui-capture/capture.cjs`, Remotion `src/`·`public/`,
`finalize.py`, `verify_export.py`다. 새 체크아웃에는 이 자료가 없으므로 원본
제작 폴더를 전달받는다. 기존 채택 폰과 opening을 재생성하지 않고 후속 수정의
기준으로 사용한다. 렌더링 명령과 검사 결과는 [출력·검증](build-and-test.md)에 있다.
