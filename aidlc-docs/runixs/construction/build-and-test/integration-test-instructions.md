# 공개 갤러리 연결 검사

Mac mini Mediator → 전용 Lima VM enode → Bedrock Claude → 갤러리 MCP →
별도 게시 broker → 봉인 결과 → 공개 UI를 연결한다. 실행 중인 팀원 작업·DB·터널을
보존한다. 외부 실제 게시 검사는 승인된 사용자 요청 한 개로만 수행한다.

1. 공개 /ui/demo/에서 새 작업의 갤러리 카드를 연다. 팀 선택·예시·제약 목록·
   게시 확인 버튼 없이 메시지 입력과 보내기만 있어야 한다.
2. 프롬프트에 팀 이름과 댓글 요청을 적는다. API는 prompt/request_id/submitter만
   전송하고 한 Run을 접수한다. 접수 후 브라우저를 새로고침해도 동일 Run이 계속된다.
3. 결과 posted에는 실제 list_projects/get_project/post_comment 사건과 댓글
   ID·본문·대상이 있어야 한다. 공개 갤러리 GET으로 같은 댓글이 한 개 존재하는지
   확인한다. 성공을 확인하려고 다시 POST하지 않는다.
4. 초안만 요청하면 draft_ready이고 게시가 없어야 한다. 팀이 없거나 모호하면
   needs_project로 되묻는다. 답을 보내면 원래 요청과 함께 새 작업으로 접수한다.
5. 외부 사이트·파일·명령·투표·수정/삭제 또는 혼합 요청은 refused이며 게시가
   없어야 한다. 잘못된 UUID는 404다. 위조·잘못된 대상·중복·재시작 경계는
   단위/DB 검사에서 검증하고 실제 갤러리에 테스트 댓글을 반복하지 않는다.
6. 1440px/390px 화면에서 입력·결과·되묻기·닫기와 가로 넘침·JS 오류를 검사한다.
   기존 LED·음원 카드를 보존한다. UI 게시 회귀는 mock API도 사용한다.
7. 공개 주소·터널 PID·팀원 heartbeat·작업 상태·VM 정책 복원을 확인한다.
   게시 자격 증명은 worker에서 읽을 수 없어야 하며 새 서비스는 기존 프록시만 쓴다.

증거는 Git 제외 local/gallery-build-20260909에 저장한다. 원래 UUID와 자격 증명을
PR·문서에 넣지 않는다. 운영 Run 기록과 게시 중복 방지 DB는 삭제하지 않는다.
부하·스트레스 시험은 수행하지 않는다. 고정 한도/동시 접수 검사를 근거로 하며,
이 인수를 공동 CP6/CP10이나 토큰 단위 스트리밍 검사로 확대하지 않는다.
