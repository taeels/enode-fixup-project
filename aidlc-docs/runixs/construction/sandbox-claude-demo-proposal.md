# 새 작업의 해커톤 기여 MCP 체험 제안

2026-09-09. 사용자가 갤러리를 읽고 참가팀 게시글에 댓글을 남겨, 데모 관람객이
해커톤에 직접 기여하는 흐름을 제안했다. 이전 버그 수정·미니게임·일반 도구 체험
후보를 이 방향으로 대체한다. UI·MCP 구현은 아직 시작하지 않았다.

## 최신 요청 정책

사용자는 짧은 프롬프트를 받고, 정상 댓글 요청을 처리하며 그 밖의 요청은 실제
Bedrock Claude의 거절 transcript로 보여 달라고 구체화했다. 외부 웹페이지 열기,
파일·키 접근, 투표·삭제, 허용·비허용 작업을 섞은 요청을 거절 대상으로 삼는다.
[요청 정책·transcript 추가 설계](demo-back/functional-design/gallery-comment-policy.md)에
실행 도구·서버 검증·일회성 게시·거절/오류/게시 결과 구분을 정리했다.
현재 하네스를 기준으로 첫 버전은 실행 상태 표시와 완료 후 transcript 반환이다.

## 게스트가 하는 일

`새 작업 → 해커톤에 의견 남기기`에서 프로젝트를 고르고 짧은 의견을 입력한다.
예시: “이 프로젝트의 장점을 짚고 실제 사용이 궁금한 점을 질문으로 써줘.”
Claude가 선택한 게시글을 읽고 의견을 구체적인 댓글 초안으로 다듬는다.
관람객은 같은 웹 화면에서 내용을 확인·수정하고 게시를 선택한다.
완료 후 등록된 댓글과 갤러리 원문 링크를 보여준다.

읽기·초안·게시의 실제 상태와 실패 원인을 표시한다. 프롬프트는 의도 데이터로
취급하고 실행 명령이나 외부 주소를 지정하는 입력으로 사용하지 않는다.

## 연결할 MCP

갤러리 전용 MCP 하나에 필요한 동작만 둔다.

| 도구 후보 | 역할 |
|---|---|
| `list_projects` | 갤러리의 현재 프로젝트 목록 조회 |
| `get_project` | 선택한 글과 필요한 댓글 맥락 조회 |
| `post_comment` | 관람객이 확인한 글·본문으로 댓글 한 개 게시 |

대상 호스트는 `main.d3gkmtkue9o7ly.amplifyapp.com`으로 고정한다. 임의 URL,
댓글 수정·삭제, 투표, 계정 관리 기능은 도구 목록에 넣지 않는다.
게시 전에는 본문과 대상이 관람객이 확인한 값과 같은지 서버에서 대조한다.
모델 지시만으로 게시 권한을 만들어내지 않는다.

## 확인된 전제

- 프로젝트·댓글 조회와 팀 로그인·댓글 쓰기 API가 같은 호스트에 있다.
- 댓글 작성에는 팀 계정이 필요하고, 현재 글별 `enabled`·`canWrite`를 확인할 수 있다.
- 사용자가 제공한 팀 계정으로 Run Away 게시글에 댓글 한 개를 남기는 명시적 지시를
  이행했다. VM API 호출과 로그인하지 않은 게스트 화면 노출을 확인했다.
- [실제 연결·댓글 검증](hackathon-gallery-integration.md)은 완료했다.
  MCP 설치·Claude 도구 호출·게스트 입력 UI의 완료와는 구분한다.

## 첫 구현의 경계

1. 기존 새 작업 모달에 프로젝트 선택·짧은 의견·초안·게시·결과 화면을 추가한다.
2. 기존 Run·queue 관측을 사용하고 실제 MCP 호출 이벤트를 확보해 표시한다.
3. 게스트 전용 Claude는 승인된 MCP만 사용하도록 구성한다. 셸·개인 파일 접근과
   불필요한 내장 도구·skill·plugin 통로는 제한하고 실제 노출 도구를 검증한다.
4. 팀 계정 로그인 세션은 제한된 서버 측 도구가 관리한다. 비밀번호·세션·Bedrock 키는
   게스트 브라우저, 모델 프롬프트, 공개 로그나 결과에 포함하지 않는다.
5. 공개 결과는 해당 작업의 게시글·초안·게시 결과만 제공한다. 기존 전체 record API의
   인증은 유지한다. 댓글 본문은 텍스트로 표시한다.
6. 등록 주체가 Run Away 팀 계정임을 화면에서 알린다. 관람객 의견과 계정의 주체를
   혼동하지 않도록 게시 형식을 정한다.
7. 글·본문 길이, 실행 시간, Claude 호출 수, 게시·대기열 총량을 제한한다.
   게시 응답이 불확실하면 조회로 확인하고 자동 POST 재시도로 중복 댓글을 만들지 않는다.
8. 기존 VM의 호스트 파일 미공유·권한·네트워크 제한을 유지한다. 사이트 호스트 허용과
   사이트 내부의 작업 권한 제한은 별도로 적용한다.

이 작업은 runixs의 ui·demo-back과 VM 운영 설정이 중심이다. 팀장 소유의 프로젝트
제어용 enode MCP와는 별도의 외부 도구 연결이다. 공용 상태·디자인 파일은 수정하지
않으며 기존 LED·음원·방송 공동 CP10 완료로 기록하지 않는다.
