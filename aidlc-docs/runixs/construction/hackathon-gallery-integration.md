# 해커톤 갤러리 연결·댓글 검증

2026-09-09. 사용자가 해커톤 갤러리만 샌드박스에서 허용하고, 데모 관람객의
의견을 참가팀 게시글의 댓글로 전달하는 시나리오를 제안했다. 이후 팀 계정을
제공하며 Run Away 게시글에 댓글 한 개를 등록하도록 명시적으로 지시했다.

## 확인한 사이트 계약

대상은 https://main.d3gkmtkue9o7ly.amplifyapp.com 이며 공개 갤러리는 `/projects`다.
목록·상세·댓글 조회는 게스트로 가능하고 댓글 쓰기는 팀 로그인이 필요하다.
로그인·갤러리·댓글 API는 같은 호스트를 사용한다. 사이트의 외부 글꼴 호스트를
차단한 새 브라우저에서도 게시글과 댓글을 읽을 수 있었다.

| 동작 | 확인한 경로 |
|---|---|
| 팀 로그인 | `POST /api/auth/login` |
| 세션 확인 | `GET /api/auth/me` |
| 프로젝트 목록 | `GET /api/projects` |
| 프로젝트 상세 | `GET /api/projects/{id}` |
| 댓글 목록 | `GET /api/projects/{id}/comments` |
| 댓글 작성 | `POST /api/projects/{id}/comments`, 본문 `{"body":"..."}` |

댓글 UI에는 500자 제한이 표시된다. 댓글 API의 `enabled`, `canWrite`를 확인하고
실행 시점에 마감·권한 상태를 다시 검사해야 한다. 프로젝트 화면에 보이는 다른
API 동작을 일반 도구로 공개하지 않는다.

## 적용한 네트워크 설정

기존 Mediator·Bedrock 필수 연결을 유지하고 위 갤러리 호스트의 HTTPS만 추가했다.
다른 새 호스트나 일반 인터넷 접근은 허용하지 않았다. VM 관리 스크립트가 터널
주소를 갱신할 때 승인된 추가 호스트를 보존하도록 수정하고 `start` 경로를 실행했다.

VM worker UID 1001에서 갤러리 조회 성공과 미허용 `example.com`의 프록시 403을
확인했다. 기존 systemd 파일·권한 제한과 작업 UID의 직접 네트워크 차단은 유지한다.

## 실제 댓글 한 개 등록

최초 제공된 이메일은 로그인 API가 401 `User does not exist.`로 거절했다.
사용자가 이메일을 정정한 뒤 로그인과 Run Away 팀 신원, 댓글 쓰기 가능 상태를
확인했다. 실패한 로그인에서는 댓글 POST를 실행하지 않았다.

- 대상: [RunAway 프로젝트](https://main.d3gkmtkue9o7ly.amplifyapp.com/projects/mttihtdn0idx0)
- 댓글 ID: `6abb0aaa-ca54-4309-b246-524b0263ed29`
- 실제 실행: 전용 VM에서 UID 1001·권한 상승 금지·파일 보호·자원 제한을 적용한
  임시 systemd 작업이 로그인·댓글 API를 호출했다.
- 댓글 POST는 한 번 실행했다. 같은 본문 존재 여부와 시도 기록을 확인하고,
  응답이 불확실할 때 POST를 자동 재시도하지 않도록 했다.
- 등록 후 API로 댓글 ID·본문을 다시 조회했다. 로그인하지 않은 새 브라우저에서도
  같은 댓글이 정확히 하나 보이고 `canWrite=false`인 게스트 상태임을 확인했다.

게시한 내용:

> Run Away 팀의 데모 연결 확인 댓글입니다. Mac mini의 격리된 VM에서 이 갤러리로 댓글을 전송했습니다. 관람객의 질문과 피드백이 참가팀에 직접 전달되는 체험으로 연결하겠습니다.

이번 검증은 VM에서 갤러리 API를 직접 호출한 것이다. Claude·MCP를 통한 댓글
게시나 게스트 프롬프트 UI 구현이 완료됐다는 근거로 사용하지 않는다.
자격 증명은 메모리·표준 입력으로만 전달했고 실행 명령 인자·소스·로그·Git에
저장하지 않았다. 이번 로그인 세션은 작업 종료 시 폐기했다.

로컬 증거는 Git 제외 경로 `local/hackathon-gallery-20260909/`의
`comment-post-result.jsonl`, `public-comment-verification.json`과 조회 기록에 있다.

## 후속 UI·MCP 범위

[현재 제안서](sandbox-claude-demo-proposal.md)는 프로젝트 선택·의견 입력·댓글
초안·게스트의 게시 선택·등록된 원문 확인을 중심으로 한다. 서버가 게시할 글과
본문을 고정하고 팀 계정 자격 증명을 브라우저나 모델에 전달하지 않도록 설계한다.
이번 한 댓글의 승인은 다른 게시글에 대한 임의·일괄 댓글 게시 승인으로 해석하지 않는다.
제품 코드·rc1·기존 공동 CP10 완료 상태와 영상 세션의 변경은 유지했다.
