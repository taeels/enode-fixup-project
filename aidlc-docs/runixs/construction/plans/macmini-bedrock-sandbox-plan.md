# Mac mini Bedrock 실행 노드 격리 구성

2026-09-09 사용자가 기존 `ccb`의 Bedrock Claude를 enode에서 안전한 샌드박스로
실행하도록 요청했다. 현재 제공되는 `harness_bin`과 별도 VM 배치를 사용한다.
제품의 OS sandbox 기능 추가나 공동 CP10 전체 완료로 기록하지 않는다.

- [x] `ccb`의 인증 종류·리전·모델, enode 하네스 실행·환경 필터 확인. 비밀 값 출력 제외.
- [x] 기존 Lima 설치와 자원 확인. 기존 VM·다른 서비스 유지.
- [x] 별도 Linux VM 생성. 호스트 파일 공유·SSH agent 전달·자동 포트 전달 비활성화.
- [x] 일반 사용자 enode·고정 버전 Claude 배치. 전용 작업 공간과 Bedrock 실행 래퍼 구성.
- [x] 작업 프로세스에서 호스트·사설망 접근과 권한 상승 제한. Mediator·Bedrock 연결 확인.
- [x] 파일·권한·네트워크 격리 검사 후 실제 enode→Bedrock 짧은 실행·봉인 결과 검증.
- [x] 성공 후 기존 Mac 직접 실행 노드를 종료하고 VM 노드로 전환. Mediator·팀원 연결 유지.
- [x] 시작·중지·키 갱신 안내와 검증 한계 기록. 비밀 값을 Git에 저장하지 않음.

Bedrock 키를 사용하는 실행 프로세스로부터 키 자체를 완전히 숨길 수 있다고
주장하지 않는다. 이번 구성은 개인 호스트의 파일·서비스와 작업 실행을 분리한다.
공유 Mediator 토큰의 권한 범위도 그대로이며 별도 권한 체계 구현으로 해석하지 않는다.

[구성과 검증 기록](../macmini-bedrock-sandbox.md). 기존 키의 AWS 403을 확인하고
사용자가 새로 제공한 키로 실제 Run `bedrock-vm-proof-b8f111c2` 성공과 봉인 파일을
검증했다. 격리 검사 15개, 기존 호스트 프로세스 종료, VM과 팀원 두 노드의 heartbeat,
공개 UI 세 경로의 HTTP 200을 확인했다. 제품 코드·rc1·공동 CP10 상태는 유지한다.
