# ui — obs 전달 전 사전 준비 계획

**상태**: 사전 준비 산출물 완료. 당시 미실행한 Go 패키지 검증도 후속 실행에서
92.3% statements로 통과했다. 상세 설계는 [W1 설계 계획](ui-functional-design-plan.md).
사용자 승인 범위는 UI 설계 초안 · 소비 API 계약표 · 상태별
샘플 응답 · 통합 검증 항목이다. 정식 Functional Design 완료나 코드 생성 승인은
아니다. 담당 runixs, 브랜치 `unit/runixs-ui`, 기준 코드 `c010841`, 설계 정본
서브모듈 `29c89cd`.

## 범위와 근거

2026-09-08 사용자가 사전 준비 제안에 “일단 너가 말한대로 진행해줘”라고 답했다.
`ui -> obs` 의 실제 연동 의존은 유지하면서 그 전에 할 수 있는 준비를 수행한다.
기존 공용 실행 계획과 roster 는 수정하지 않는다. 게이트 통과와 병합은 실제
선행 구현과 검증 증거가 필요하다.

문서는 `aidlc-docs/runixs/construction/ui/preparation/`, 샘플 JSON 은
`internal/api/ui/testdata/obs-contract/` 에 둔다. 후자는 UI 담당의 테스트 입력이며
`static/` 밖이라 기존 embed 대상이 아니다. 런타임 코드 · obs · queue · api.go ·
store · design/*.pen 은 이번 범위에 없다.

## 준비 완료 기준

네 종류의 산출물이 실제 파일로 존재하고 읽는 순서가 안내돼 있다. 샘플의 각
형식은 정본 예시, 기존 코드, 또는 미확정 후보 중 어느 것인지 구분한다.
