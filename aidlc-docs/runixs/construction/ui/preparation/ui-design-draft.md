# ui 설계 초안 — 실 함대 모드

**범위**: obs 이전 사전 준비 당시의 초안이다. 후속 FD 승인·UI 구현·obs/queue
인수·sandbox 출처 승인은 [현재 담당 상태](../../../aidlc-state.md)를 따른다.
아래 미정·미구현은 이 초안 작성 시점의 기록이며 현재 대기 조건이 아니다.
화면 번호·동작은 `design/README.md`, `requirements/enode-features.md` §3.1.1·3.2.3,
`scene-gates.md` §2.1 에서 가져온다. API 데이터는 [계약표](api-contract.md)를 따른다.

## 1. 사용자 흐름

| 화면·상태 | 입력과 조작 | 결과·제약 |
|---|---|---|
| S0 토큰 입력 | 토큰 입력, 제출 | nodes/runs 읽기 성공 후 실 함대 진입. 현재 landing 의 비활성 관리자 구역을 확장할 후보 |
| S0b 인증 실패 | 잘못된 토큰 제출, 다시 입력 | 보호된 화면으로 넘어가지 않음. 일반 오류 안내. 토큰 값 재출력 금지 |
| 최초 조회 중 | 입력 성공 뒤 조회 대기 | 로딩 표시. 이전 사용자·샘플 데이터를 실제 결과처럼 표시하지 않음 |
| S1 함대·목록 | 노드/Run 선택, 격자·그래프 전환, 재시도 | 카드와 Run 목록을 함께 유지. 중앙 submit·drain 조작 없음 |
| 빈 목록 | 정상 응답의 nodes/runs 가 빈 배열 | 빈 함대/작업 없음. 서버 오류와 구별 |
| 일부 조회 실패 | nodes 또는 runs 갱신 실패 | 각 자료의 마지막 성공 시각과 미갱신 표시. 성공한 한쪽이 다른 쪽 실패 횟수를 지우지 않음 |
| S1b 갱신 중단 | 연속 3회 실패, 재시도 | 오래된 데이터 표시, 해당 카운트다운 정지. 성공 시 실제 새 스냅샷으로 복구 |
| S2 작업 상세 | Run 행 선택, 다른 Run 선택, 격자로 복귀 | steps/needs 로 그래프. 목록이 선택 이동의 손잡이로 남음 |
| CP7 사람 대기 | ASKED 상태와 인박스 조회 | answerers·asked_at·deadline 유무·실행할 명령 안내. 중앙 답변 전송 없음 |

실 함대와 공개 guest 모드는 구분한다. 기존 guest 이름·카드뉴스 재방문 흐름을
보존하고 실 함대 토큰을 guest 데이터 경로에서 사용하지 않는다. 정확한 실 모드
URL 은 FD 에서 D7 과 함께 확정한다.

## 2. 화면 구성과 소유 상태

| 구성 | 읽는 자료 | 갖는 상태·책임 |
|---|---|---|
| 진입 화면 | 인증 결과 | 입력 중 토큰·제출 중 여부·일반 오류. 토큰은 sessionStorage 와 메모리만 |
| 현황판 | nodes/runs/asks 스냅샷 | 현재 모드·선택 Run·뷰 종류. guest localStorage 와 토큰을 분리 |
| 연결 상태 표시 | 자료별 성공 시각·실패 횟수 | 전체 정상 표시에는 필수 읽기 모두 성공 필요. asks 실패는 인박스 미확인 표시 |
| 함대 격자·노드 카드 | nodes 와 임대별 Run 상세 | node_id 기준 카드. label·capabilities·광고 시각·임대·draining |
| Run 목록·행 | runs 목록 | run_id 기준 행. 상태·submitter·선택 여부. QUEUED 를 노드에 배정하지 않음 |
| 요구 능력 표시 | 선택 Run 의 requires | as·capability·속성. 능력 비교는 관측 시각의 비교이며 배정 확정이 아님 |
| 작업 그래프 | 상세 steps | id/needs 간선, state, chosen, node. label 은 표시용 |
| 사람 대기 카드 | ASKED 단계 + asks | run_id/seq 로 연결. 누락된 인박스를 “질문 없음”으로 확정하지 않음 |

기술 스택은 기존 HTML/CSS/JavaScript 와 Go embed 를 활용하는 방향이다.
새 프레임워크나 Go 의존은 이번 준비에서 추가하지 않는다.

## 3. 데이터 흐름 초안

HTTP 읽기 → 응답 계약 확인 → UI 내부 데이터 → 화면 렌더링의 순서다.
샘플 응답을 사용할 때도 같은 계약 확인과 화면 처리 경로를 거치도록 후속 구현을
설계한다. raw JSON 을 DOM 전체에 직접 바인딩하지 않는다.

- 목록은 `GET /v1/nodes`, `GET /v1/runs` 로 읽는다. 선택 Run 과 관측된 lease 의
  고유 run_id 에 대해서만 상세를 읽고, 같은 Run 의 중복 조회를 합친다.
- 노드 카드의 현재 단계는 해당 Run 의 `CLAIMED` 또는 `ASKED` 단계와 node_id 를
  연결한다. 단지 Run 이 RUNNING 이라고 특정 단계·진행률을 추정하지 않는다.
- Run 선택이 A 에서 B 로 바뀐 뒤 A 의 늦은 응답이 와도 B 를 덮지 못하도록
  요청 세대나 취소 처리를 둔다. 인증 변경에도 같은 규칙을 적용한다.
- `observed_at` 이 있는 응답과 없는 상세/asks 의 수신 성공 시각을 구분한다.
  nodes 와 runs 를 받은 시각이 다르면 순간적인 배정 불일치에 완료/실패 의미를
  새로 붙이지 않는다.
- 필수 필드 오류는 계약 불일치다. 세부 화면에 자료 부족을 표시하고 그 기능의
  통합 검증을 실패 처리한다. 정상 빈 목록으로 바꾸지 않는다.

## 4. 표시 규칙

1. **광고 만료**: expires_at 잔여 30초 이하이면 흐림. 실제 노드 제거는 성공한
   다음 nodes 응답을 따른다. 흐림이 프로세스 종료 확정은 아니다.
2. **임대**: not_after 는 임대 만료 시각이다. 작업 완료 예상 시간이나 진행률로
   표현하지 않는다. 갱신으로 뒤로 밀리는 값도 그대로 반영한다.
3. **draining**: 모드를 보존한다. 관측된 lease 가 있으면 “진행 중”, 없으면
   “대기 중” 배지 후보로 표시한다. snapshot 실패 중에는 마지막 관측이라는
   표시를 유지한다. C4/C5 실제 판정은 CP4 에서 검증한다.
4. **QUEUED**: 목록에 남고 카드에는 배정되지 않는다. 클릭하면 requires 를 읽는다.
   화면의 능력 대조 결과는 현재 관측으로 한정하며 큐 승격을 예측하지 않는다.
5. **분기**: SKIPPED+chosen=false 는 안 고른 경로, SKIPPED+chosen=true 는 고른
   뒤에도 도달하지 못한 상태다. 후자를 정상 생략처럼 그리지 않는다. chosen 이
   없는 응답은 obs 확장 누락이므로 false 로 바꾸지 않는다.
6. **사람 대기**: ASKED 가 연결된 카드는 일반 lease 카운트다운 대신 질문 대기를
   보인다. deadline 이 없으면 남은 시간을 만들지 않고 asked_at 기준 경과 시간을
   보인다. 인박스 실패 시에도 ASKED 사실을 일반 실행으로 되돌리지 않는다.
7. **당시 미정 데이터**: sandbox는 이후 FD에서 광고값/미제공 표시로 정하고 승인받았다. submitter 미노출과
   이름이 없는 과거 작업을 구별하는 정책은 D4 에서 닫는다.

## 5. 장애·보안·시간

5초 폴링, 연속 실패 3회 기준은 결정표 §2 를 따른다. 테스트는 시계를 고정하고
성공 → 실패 세 번 → 회복 순서를 실행한다. 서버 응답이 영원히 지연되면 세 번을
셀 수 없으므로 요청 timeout 과 주기 스케줄링을 후속 FD 에서 명시한다.

401 은 인증 실패로 즉시 처리하고 보호된 자료를 숨긴다. 네트워크 실패는 인증
실패로 간주하지 않는다. 폴링 실패 중 카운트다운이 계속 줄어 잘못된 만료를
보이지 않게 한다. 회복 시 로컬 추정값 대신 서버의 새 시각을 사용한다.

토큰·헤더는 로그·URL·샘플 파일에 남기지 않는다. label·submitter·attrs·prompt
등 서버 문자열은 텍스트로 렌더링한다. 기존 CSP 와 보안 헤더를 유지하고
inline script·eval 을 추가하지 않는다. 공개 데모는 서버측 allow-list·토큰 주입
계약으로만 제출한다는 기존 결정을 후속 단계에 보존한다.

## 6. 후속 범위

게스트 투어·3D·모달·웹캠은 같은 ui 유닛의 데모 모드지만 이번 초안은 실 함대
접점에 집중한다. 데모 제출 경로·payload 와 무토큰 읽기 경계가 정해지기 전에
가상의 endpoint 를 구현하지 않는다. 정식 FD 에서는 유닛의 두 모드와 CP7 표시를
함께 검토하고, 현재 초안을 필요한 네 FD 산출물로 발전시킨다.
