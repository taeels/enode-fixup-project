# ui 통합 검증 — obs 전달 후 실행할 항목

**현재 상태**: obs 병합 인수·기존 관측 테스트 대조를 완료했다. 실제 UI 연결과
장면은 미실행이다. [인수 기록](obs-integration-review.md)과 구분한다. CP0·CP1·CP2·CP7 의 기준은
`requirements/scene-gates.md` 와 `unit-of-work-story-map.md` 다.

## 1. 인수할 때

- [x] 현재 ui 브랜치와 obs 의 실제 커밋·FD·검증 결과를 확인한다. 전달된 코드와
  문서를 읽고 D1~D5 를 확정한다. 다른 담당의 미완료 상태를 임의로 고치지 않는다.
- [ ] GET /v1/nodes·runs 가 실제 노드·Run 을 반환하는지 확인한다. 200 빈 배열만
  받으면 빈 상태 검증일 뿐 노드·임대·대기 장면 검증으로 세지 않는다.
- [x] ui 계약표의 requires 중첩/평탄 차이, lease 부재, terminal verdict,
  submitter 과거값, chosen=false 누락 여부를 실제 Handler/DB 관측 테스트와 대조한다.
- [x] 최종 계약에 맞춰 샘플을 갱신한다. 후보를 남겨야 하면 용도를 명시하고
  실제 계약 검사가 서로 다른 형태를 모두 통과시키지 않게 한다.
- [ ] 관측한 데이터만 인수 기록에 남긴다. 토큰·Authorization 헤더·사용자의
  실제 소스 내용은 기록하지 않는다. 합성 응답을 실제 캡처로 기록하지 않는다.

## 2. 실제 API 와 같은 경로로 확인할 계약

후속 구현의 응답 검사 함수를 합성 JSON 과 실제 응답 양쪽에 적용한다. 그 함수가
미확정 계약을 숨기지 않도록 아래 의미 검사도 함께 둔다. 지금 그 함수는 없다.

- [ ] nodes/runs 의 observed_at 과 배열이 존재한다. 잘못된 JSON·HTML·필수 키
  누락은 조회 성공이나 빈 목록으로 처리하지 않는다.
- [ ] draining 세 문자열을 각각 확인한다. boolean·알 수 없는 문자열을 정상으로
  바꾸지 않는다. lease 부재와 배정 가능 판정은 구분한다.
- [ ] QUEUED 목록의 assigned 가 비어 있고, 상세 requires 가 있어도 카드를
  점유시키지 않는다. 별칭 as 는 requires 항목 안에서 steps[].uses 와 연결한다.
- [ ] steps[].needs 는 빈 배열과 실제 의존을 보존한다. chosen=false 가 직렬화되고
  누락과 구별된다. SKIPPED+true 를 실패 원인 조사 대상 상태로 구별한다.
- [ ] 현재 상세의 assigned/steps 생략과 optional node/시각을 처리한다.
  RUNNING 에 steps 가 없으면 자료 미확인으로 보이고 성공·작업 없음으로 단정하지 않는다.
- [ ] 200+warnings+requires 생략의 부분 응답과 공개 읽기 429/Retry-After를
  실제 UI 소비 경로에서 검증한다. 공개 모드가 asks를 호출하지 않는지 확인한다.
- [ ] 목록의 verdict 와 상세의 verdict 를 동일한 문자열로 가정하지 않는다.
  과거 Run의 빈 submitter와 필수 키 누락을 구분한다. 상세에서는 목록 이름을 결합한다.

## 3. CP1 — 토큰·격자·연결

- [ ] `/ui/` 무인증 접근은 허용하고 S0 진입이 가능하다. 기존 Guest 카드뉴스
  진입·재방문·이름 유지가 깨지지 않는다. 중복 /ui/ 마운트가 없다.
- [ ] 틀린 토큰은 401 안내를 보이고 보호된 화면에 들어가지 않는다. 정상 토큰을
  다시 입력하면 실제 조회 뒤에 진입한다. query string 이나 로그에 토큰이 없다.
- [ ] 탭을 닫고 새로 열면 실 함대 토큰을 다시 묻는다. Guest localStorage 는
  실제 인증으로 사용하지 않는다. 저장소 접근 실패도 토큰 유출 없이 처리한다.
- [ ] 실제 노드 6개이면 카드 6개. label·capabilities·lease·draining·갱신 시각이
  실제 JSON 과 맞고, 임대 갱신이 not_after 에 반영된다. 진행률로 그리지 않는다.
- [ ] 실제 만료 임박 노드가 30초 기준으로 흐려지고, 다음 성공 스냅샷에서
  광고가 사라지면 카드에서 빠진다. 프로세스 생존 여부를 추정하지 않는다.
- [ ] Mediator 를 중단해 연속 3회 갱신 실패를 만든다. 5초 주기 기준 S1b 와
  카운트다운 정지를 확인한다. timeout 으로 응답 없는 요청도 실패에 포함된다.
- [ ] nodes 만 실패·runs 만 성공, 반대 조합을 각각 확인한다. 성공한 endpoint 가
  실패한 endpoint 의 stale 상태를 해제하지 않는다.
- [ ] 복구 시 새 응답의 관측 시각과 임대로 돌아온다. 실패 중 샘플로 자동 대체하거나
  실패 횟수를 임의로 지우지 않는다. HTTP 200 의 잘못된 JSON 도 검증한다.

## 4. CP2 — queue 반영 뒤

- [ ] 실제 같은 자원을 요구하는 Run 둘을 제출한다. 둘째는 202/QUEUED 이고
  목록에는 있지만 카드에 없다. 행 선택 시 실제 requires 가 보인다.
- [ ] 첫째 종료 뒤 둘째 RUNNING 을 실제 서버에서 확인한다. UI 가 요청한 적 없는
  승격을 로컬 타이머·샘플 순서로 만들어 내지 않는다.
- [ ] 함대에 없는 능력은 422/FAILED 라는 기존 규칙과 화면이 맞는다.
- [ ] 갈래 있는 실제 Run 의 SKIPPED·chosen 을 API 와 대조한다. needs 간선이 맞고
  목록을 통해 다른 Run 을 선택할 수 있다.
- [ ] A 선택 후 B 선택, B 응답 뒤 A 응답 도착 순서에서도 B 화면이 유지된다.
  로그아웃/토큰 변경 뒤 이전 응답으로 보호된 화면이 복구되지 않는다.

## 5. CP7 표시와 다른 게이트의 경계

- [ ] ASKED 단계와 asks 항목을 run_id·seq 로 연결한다. answerers 와 안내 명령이
  해당 작업을 가리킨다. 중앙에 답변 전송 버튼을 새로 만들지 않는다.
- [ ] 기한 없는 질문에는 경과 시간을, 기한 있는 질문에는 실제 deadline 을
  표시한다. 일반 lease not_after 가 지나도 ASKED 를 만료로 오인하지 않는다.
- [ ] asks 만 실패하거나 항목이 잠시 안 보일 때 ASKED 를 일반 실행으로 바꾸지
  않는다. 응답 완료 뒤 인박스와 실제 단계 전이를 읽어 표시를 갱신한다.
- [ ] C4/C5 draining 진행/대기 배지는 CP4 의 실제 제어판 장면에서 별도로 확인한다.
  샘플 화면 통과로 drain 게이트를 닫지 않는다.
- [ ] 공개 데모 CP8·CP9·CP11, 하드웨어 완주 CP10 은 별도 FD/구현/실검증으로
  남긴다. guest 토큰 노출 우회 없이 읽기·제출 계약을 먼저 확정한다.

## 6. 병합 전 검사

- [ ] 실제 UI 구현의 버튼·탭·행 선택·뷰 전환·재시도 동작을 모두 나열하고
  브라우저로 검증한다. API 검사와 화면 검사를 각각 기록한다.
- [ ] label·attrs·submitter·prompt 에 HTML 모양 문자열을 넣어 텍스트로 보이는지
  확인한다. 기존 보안 헤더와 CSP 를 유지한다.
- [ ] `go test -count=1 -cover ./internal/api/ui` 로 패키지 회귀와 80% 하한을
  확인한다. Go 커버리지가 브라우저 JavaScript 동작을 검증하지는 않는다.
- [ ] `scripts/testdb.sh` 로 DB 를 준비한 뒤 scene-gates 의 CP0 전체 명령과
  해당 유닛의 장면 검사를 실행한다. DB 테스트 스킵을 통과로 기록하지 않는다.
- [ ] 파일 행렬·임포트 경계·공유 파일 변경을 검토한다. obs·queue 와 겹치는 파일은
  합친 코드로 재검증한다. main 병합은 해당 장면 게이트가 초록인 뒤다.

게이트 기록에는 실행 시각, 코드 커밋, 환경과 장면 데이터, 실행 명령, 기대값,
실제 결과, 실패·보류 이유를 남긴다. 이 문서의 체크박스는 실제 실행 뒤에만 바꾼다.
