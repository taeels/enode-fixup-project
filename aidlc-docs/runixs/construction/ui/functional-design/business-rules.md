# ui 표시·검증 규칙

**2026-09-09 가독성 보완**: [후속 계획](../../plans/ui-readability-plan.md)을 적용한다.
임대 대상은 현재 `node.lease.run_id`와 일치하는 `runs[].submitter`만 표시한다.
Run이 목록 밖이면 제출자 미확인, 빈 이름이면 미제공이다. 이전 목록 값이면 갱신
지연을 표시한다. 과거 assigned나 장치 label을 사람의 신원으로 해석하지 않는다.
시각은 브라우저 시간대의 한국어 날짜로 표시하고 time 요소 title·기술 상세에 원문을
보존한다. 남은 시간은 기존 서버 관측 시계와 freeze 규칙을 사용하며 0 이하에서는
만료 시각 지남으로 표시한다. 이것으로 임대·Run 상태를 변경하지 않는다. ASKED는
일반 임대 카운트다운 대신 사람 응답 대기 안내를 유지한다.

**상태**: 실 함대·공개 데모 검토안. 값의 정본은 `requirements/decisions.md` §2·§3·§7·§8,
의미의 정본은 protocol/INVARIANTS 와 ADR-032·047·060·065·069 다.

## 1. 표시 판단

| ID | 규칙 | 검증 사례 |
|---|---|---|
| BR-01 | nodes 성공 응답의 노드 수와 카드 수가 같다. 로컬 만료만으로 삭제하지 않는다 | 여섯 광고, 빈 배열, 다음 응답에서 광고 제거 |
| BR-02 | expires_at 까지 30초 이하면 흐림. 관측 시각·만료 시각을 함께 보인다 | 31초/30초/0초 경계, 광고 갱신 |
| BR-03 | lease.not_after 는 임대 만료다. 진행 막대·진행률로 바꾸지 않는다 | 다음 관측의 not_after 가 뒤로 밀림 |
| BR-04 | draining 모드 문자열을 보존하고 lease 유무로 진행 중/대기 중을 구분한다 | graceful+임대, at-boundary+임대 없음, boolean 은 오류 |
| BR-05 | QUEUED 는 목록에만 남고 요구 능력은 상세에서 읽는다 | 요구 보드를 가진 노드가 점유 중인 합성 사례 |
| BR-06 | 간선은 steps[].needs 그대로, 단계 순번만으로 연결하지 않는다 | 분기 DAG, 시작점 [], 알 수 없는 선행 id |
| BR-07 | SKIPPED+false 는 안 고른 경로, SKIPPED+true 는 선택됐으나 도달 못함 | 두 상태를 다른 문구로 표시. chosen 누락은 미제공 |
| BR-08 | ASKED 사실이 일반 임대 시간 표시보다 우선한다 | not_after 가 지나도 음수 임대 카운트다운을 보이지 않음 |
| BR-09 | 질문 기한이 없으면 기한 없음, asked_at 이 있으면 경과 시간 | 인박스 누락/실패와 실제 빈 질문을 구분 |
| BR-10 | 명시적 advertised sandbox 만 노드 값으로 읽는다 | 값 없음/능력별 상이/요구 값만 존재 |
| BR-11 | state 는 원문 enum, 노드 배지는 관측에서 파생한 설명 | VERIFYING 보존, CLAIMED 사용, SEALED 생성 금지 |
| BR-12 | 목록에 과거 assigned 가 있어도 현재 노드 점유로 붙이지 않는다 | 종료 Run 의 node01 과 실제 유휴 node01 |

ASKED 와 draining 은 함께 표시할 수 있다. 전자는 Run 의 대기 이유, 후자는
노드의 자원 회수 모드다. 만료 임박 흐림도 별도 표시다. 하나의 색만으로 이
사실들을 서로 덮지 않는다. 실제 노드의 CLAIMED 단계는 step.node 로 결합한다.

## 2. 시각과 실패

- 조회 시작 간격은 5초, 각 요청 제한시간은 4초다. 같은 자원의 진행 중 요청을
  중복 시작하지 않는다. 수동 재시도는 같은 규칙을 사용한다.
- 실패는 자원별 완료 결과 하나당 한 번 센다. 503·네트워크·제한시간·잘못된 JSON/
  계약 불일치가 대상이다. 선택 변경/로그아웃으로 취소한 요청은 실패로 세지 않는다.
- 공개 읽기 429도 실패로 세고 한도 초과를 표시한다. `Retry-After`의 초 또는
  HTTP 날짜를 읽어 공개 조회 셋에 재요청 가능 시각을 공유한다. 그 전에는 수동
  재시도도 제한하며 다음 허용된 5초 주기에서 재개한다. 현재 서버 값은 1초다.
- 상세가 200+warnings와 함께 requires를 생략하면 Run 상태·받은 단계는 보여주되
  요구 정보는 미확인으로 표시한다. 요구 정보를 빈 배열로 만들거나 정상 갱신으로
  세지 않는다. 마지막 요구 자료가 있다면 이전 관측임을 표시한다.
- 첫째·둘째 실패부터 마지막 갱신 시각과 미갱신 상태를 알린다. 셋째 실패에 해당
  자료의 카운트다운을 멈추고 S1b 로 표시한다. 새 성공만 그 자원을 회복시킨다.
- 즉시 연결 거절 시 성공 0초, 실패 5/10/15초, 회복 20초를 검증한다. 응답이
  아예 오지 않는 경우에는 요청 제한시간 때문에 셋째 실패 확정이 19초가 될 수
  있다. 따라서 마지막 성공 수신 뒤 15초 동안 새 자료가 없으면 관련 시간 표시를
  먼저 멈추고 갱신 지연을 알린다. 이 신선도 제한으로 실패 횟수를 올리지는 않는다.
  S1b의 3회 실패 판정과 구분해 검증하며, 새 성공 시 두 표시를 함께 회복한다.
- 서버 observed_at 을 수신 당시 단조 시계에 고정해 남은 시간을 계산한다.
  음수는 0으로 제한하되 로컬 시간이 지났다는 이유로 서버 상태를 종료로 바꾸지
  않는다. 서버 시각이 없는 asks 의 시간 계산은 마지막 유효 관측 기준과 출처를
  보존하며, 기준이 없으면 시각 원문만 표시한다.
- 노드 광고 시간은 nodes, 임대/사람 대기 표시는 nodes 와 관련 상세/asks의
  신선도에 의존한다. 필요한 자료가 중단되면 관련 시간만 멈춘다. asks 실패로
  이미 관측한 ASKED 를 일반 임대로 되돌리지 않는다.

## 3. 입력과 계약 검증

토큰은 빈 값·줄바꿈을 거절하고 입력을 가린다. 서버가 인증을 판단한다. ID·시각·
배열·draining 등의 필수 구조가 틀리면 해당 자원 오류를 표시한다. 확장에 필요한
requires/chosen 이 없으면 해당 상세 기능을 미제공으로 보이고 CP2를 완료하지 않는다.
추가 필드는 소비하지 않아도 되지만 이미 읽는 필드의 타입을 임의 변환하지 않는다.
관측 requires는 중첩 attrs만 받는다. lease·목록 submitter·단계 chosen은 병합된
obs의 필수 키다. 상세 warnings는 텍스트로 표시하며 Run의 실행 실패와 구분한다.

nodeId/runId/step id·seq 중복과 needs 의 미존재 참조·순환을 탐지한다. 문제가 있는
그래프는 오류 안내와 단계 목록을 보이며 임의 간선을 그리지 않는다. 원래 Run
상태·오류 코드·문자열은 텍스트로 남긴다. 선택 상세의 404는 해당 Run 미존재로
표시하고 nodes/runs 전체를 오류로 만들지 않는다.

## 4. 보안 범위와 검사

| 대상 | 적용 |
|---|---|
| 토큰·인증 | Bearer 는 같은 origin 의 명시된 GET 경로로만 전달. URL·로그·fixture·guest localStorage 금지. 401 즉시 삭제·숨김·요청 취소 |
| 문자열 | label·submitter·attrs·prompt·오류 사유는 textContent 등 텍스트 삽입. 서버 값을 HTML·링크·실행 명령으로 평가하지 않음 |
| 명령 안내 | 일반 템플릿과 Run/seq 를 텍스트로 제시. 자동 실행·답변 값 생성·토큰 포함 없음 |
| 정적 파일 | 기존 CSP·보안 헤더 유지. 외부 CDN·inline script·eval 없음. 테스트 데이터는 embed static 밖 |
| 회귀 | 문자열 삽입, 인증 교체 중 늦은 성공/401, 제한시간과 선택 취소를 검증 |

security-baseline 의 SECURITY-04·05·08·11·12·15를 위 규칙에 반영한다.
SECURITY-01·03·07은 결정표 §3의 기존 적용 범위를 상속한다. 나머지 규칙의
배포·운영·의존 검증은 이번 문서만으로 통과 처리하지 않는다. 비활성 확장 둘과
SKIP 된 NFR/인프라 단계를 새로 시작하지 않는다.

| UI-BR-21 | 모든 단계·노드 상태는 기존 관측 의미. 모델 모양이 능력을 증명하지 않음 | 모르는 기기·capability 다중값·sandbox 없음 |

투어와 모달은 동시에 열지 않는다. 투어는 마지막 단계에서 닫은 뒤 새 작업을
사용할 수 있고, 모달은 열었던 버튼으로 포커스를 돌린다. polling은 활성 요소를
교체하지 않는다. 투어의 배경 강조는 포커스 가능한 실제 버튼을 복제하지 않는다.

기기 모형은 명시적 광고 속성으로 식별할 수 있을 때만 보드/워크스테이션 형태로
구분한다. label 문자열을 잘라 종류·권한·sandbox를 추론하지 않는다. 종류를 알 수
없는 노드는 공통 모형과 실제 label·capability를 표시한다.

## 6. 방송 설정과 CSP

`static/demo/settings.json`의 webcam은 null 또는 공개 HTTPS embedUrl이다.
배포 시 같은 파일을 UI와 Go 헤더 구성이 읽는다. URL에 사용자정보·송출 토큰을
넣지 않으며 사용자 query/hash·관측 응답으로 주소나 허용 origin을 바꾸지 않는다.
잘못된 설정은 외부 iframe을 만들지 않고 방송 준비 중/설정 오류로 표시한다.

기존 default-src 'self'와 보안 헤더는 유지하고 데모 HTML에만 설정 URL의 정확한
origin을 frame-src로 허용한다. 와일드카드·unsafe-inline·unsafe-eval·외부 script를
추가하지 않는다. 자체 페이지의 X-Frame-Options: DENY는 그대로다.
프레임 src 허용과 플레이어 측 임베드 허용은 별개이므로 실제 공급자로 검증한다.
postMessage 연동이 필요하면 지정 origin·source·메시지 형태를 모두 검사한다.
