# ui 업무 흐름 — 실 함대·공개 데모

**상태**: W1·CP7·D1~D5 설계 검토안. [설계 계획](../../plans/ui-functional-design-plan.md)
의 승인 전이다. obs `0a159a4`의 코드·계약 테스트를 인수했으며 UI 연결은 남았다.
전체 범위는 [담당 범위](../../runixs-scope.md)에 있다. 데모 제출은
[공동 제출 계약](../../demo-back/functional-design/submission-contract.md)을 소비한다.

## 1. 책임과 사용자 흐름

중앙 현황판은 Mediator 가 관측한 함대를 읽는다. 노드 소유자의 프로세스 제어나
배정 판단을 대신하지 않는다. 자료 출처는 기존 HTTP 조회뿐이며 DB 엔티티를
새로 소유하지 않는다.

| 흐름 | 행동 | 도달 상태 |
|---|---|---|
| S0 진입 | `/ui/` 에서 토큰 입력·제출 | nodes 와 runs 를 읽는 동안 제출 중 |
| S0b 인증 거절 | 필수 조회 또는 후속 조회의 401 | 토큰·보호 자료를 지우고 같은 진입 화면에서 재입력 |
| S1 진입 | nodes/runs 모두 최초 성공 | `/ui/fleet/` 에 격자와 Run 목록, 별도 asks 상태 |
| S2 선택 | 목록의 Run 또는 임대된 노드의 Run 선택 | 상세 로딩 뒤 그래프·요구 능력·단계 정보 |
| S1 복귀 | 격자 버튼 | 목록 선택은 유지하고 함대 격자로 복귀 |
| 갱신 중단 | 자료별 연속 실패 3회 | 그 자료의 마지막 성공 값·시각을 보이고 S1b 표시 |
| 회복 | 재시도 또는 정기 조회 성공 | 해당 자료만 새 응답으로 갱신, 실패 횟수 초기화 |
| 사람 대기 | 상세에 ASKED 단계 또는 인박스 질문 | Run/임대 카드에 사람 대기, 목록 아래 질문과 명령 안내 |

최초 조회의 503·네트워크 오류는 인증 거절과 다른 오류다. 이 경우 S0 에 조회 실패와
재시도를 보이고 함대에 들어가지 않는다. `/ui/fleet/` 직접 방문도 토큰이 없으면
`/ui/` 로 돌아간다. 세션 토큰이 있으면 최초 조회 성공을 다시 확인한다.

## 2. 조회에서 표시까지

1. 응답의 상태 코드와 JSON 구조를 확인한다. 실패를 정상 빈 배열로 바꾸지 않는다.
2. 서버의 스냅샷 시각과 브라우저 수신 시각을 분리해 저장한다.
3. nodes 는 node_id, runs 는 run_id, 상세 단계는 Run 안의 id/seq 로 색인한다.
4. 현재 선택 Run 과 nodes 의 lease.run_id 집합에 대해서만 상세를 조회한다.
   같은 Run 조회는 합치고 집합에서 빠진 상세는 요청 취소·캐시 정리한다.
5. [자료 모델](domain-entities.md)의 의미에 맞춰 표시 자료를 만든다. 그래프는
   상세의 steps/needs, 사람 대기는 run_id/seq 조인으로 만든다.
6. 선택·포커스를 보존하며 변한 자료를 렌더링한다. 다른 자료의 성공이 실패 상태를
   지우지 않으며, 선택 A 의 늦은 응답이 B 의 그래프를 덮지 못한다.

nodes/runs/detail/asks 는 서로 다른 시각의 관측이다. 목록에서 Run 이 사라져도
선택 상세가 성공하면 계속 볼 수 있다. 임대와 상세가 순간적으로 맞지 않으면
관측 차이를 표시하고 배정·종료·실패를 새로 추정하지 않는다.

## 3. QUEUED 와 작업 그래프

QUEUED 는 Run 목록의 독립 행이다. 어느 노드에도 붙이지 않는다. 행을 고르면
requires 의 별칭·능력·개수·속성을 보여준다. 관측된 능력의 일치와 임대 유무를
옆에 보여줄 수 있지만 큐 순번·배정 가능·예상 시작 시각은 계산하지 않는다.

그래프 노드는 steps[].id, 간선은 해당 단계의 needs 원소에서 그 단계로 향한다.
분기 선택은 state 와 chosen 을 함께 읽는다. 선택한 단계의 실제 node·uses·attempt·
시각을 검사 패널에 표시한다. 결과물 본문·로그·봉인 자료는 이 조회의 정보가 아니다.

## 4. 사람 대기

ASKED 는 노드에서 실행되는 단계가 아닐 수 있다. 노드 카드에는 lease.run_id 에
연결된 Run 의 사람 대기를 표시한다. ASKED 단계에 node 가 없다는 이유로 숨기지
않고, 질문을 특정 노드가 실행했다고 붙이지 않는다. 다른 가지의 CLAIMED 단계는
별도 실제 단계 정보로 남긴다. 임대가 없는 Run 도 목록·인박스에서 질문을 볼 수 있다.

인박스의 answerers·asked_at·deadline 을 표시한다. deadline 이 없으면 “기한 없음”,
asked_at 이 없으면 경과 시간도 “미제공”이다. 목록 아래 안내는 실제 CLI 도움말의
`runctl asks`, `runctl answer <run-id> <seq> --set field=value` 형식을 쓴다.
field/value 는 사용자가 질문 스키마를 보고 채울 자리이며 자동 답을 만들지 않는다.
중앙 화면에는 답변 제출 버튼이 없다.

## 5. 상태 수명과 인증 변경

토큰은 탭의 세션 저장소와 메모리에만 둔다. 인증 성공 전 입력·검증 상태와 인증 후
함대 상태를 분리한다. 401·로그아웃·토큰 교체 시 요청 세대를 바꾸고 모든 진행 중
요청·폴링·보호 자료를 정리한다. 이전 요청의 성공도 새 세션에 적용하지 않는다.
저장소 사용이 막힌 브라우저에는 오류를 보이고 재입력을 허용한다. 토큰을 URL 에
싣는 대체 경로는 없다.

게스트 진입은 기존 이름·온보딩 판정을 그대로 사용한다. 실 함대 토큰은 게스트
이름에 포함하지 않고 공개 데모 API 에 전달하지 않는다. 공개 읽기는 obs가 제공한
`Config.Demo`의 무인증 nodes·runs·detail 셋을 사용한다.
공개 모드에서 인증이 필요한 asks를 호출하지 않는다. 제출 계약은 demo-back FD에서
정한다. 공개 조회가 401이면 데모 서버 설정 오류로 표시하고 실 함대 토큰을 요구하지 않는다.

## 6. 데모 진입·투어

정상 진입은 기존 `/ui/`의 Guest 버튼이다. 기존 카드뉴스 완료 판정에 따라
`/ui/cardnews/` 또는 `/ui/demo/`로 가며 카드뉴스의 마지막 버튼은 데모로 간다.
시안의 D0/D1 과거 순서로 이 구현을 다시 바꾸지 않는다. 데모 직접 URL에는
인증이나 카드뉴스 재이동 guard를 추가하지 않아 저장소 차단 시 이동 루프를 피한다.

Guest 이름은 기존 helper에서 받는다. D2는 기본 3D 함대, Run 목록, 노드 상세
덮개, 웹캠으로 구성한다. 로딩·정상 빈 결과·조회 실패에서도 이 틀과 다시 보기
진입점은 남긴다. 공개 모드는 nodes·runs·detail만 읽고, ASKED이면 대기 상태만
표시한다. 실 모드의 질문 본문·answerers를 공개 데이터처럼 만들지 않는다.

투어 완료 키가 없으면 DOM의 네 대상이 준비된 뒤 웹캠→함대→Run 목록→새 작업
순서로 진행한다. 함대가 비거나 조회가 실패해도 구조를 설명할 수 있다.
다음은 다음 대상으로, 마지막 시작하기·건너뛰기·Escape는 완료 기록 후 닫는다.
투어 다시 보기는 함대 뷰로 이동해 1단계부터 시작하며 선택 Run은 지우지 않는다.
카드뉴스 다시 보기는 기존 링크이며 투어/Guest 이름을 초기화하지 않는다.

## 7. 새 작업과 결과 확인

1. 새 작업을 누르면 현재 함대/그래프 선택 위에 D4 모달을 연다. LED Toggle·
   사운드 재생 두 버튼이 각각 고정 시나리오 제출이다. 이름 입력 칸은 없다.
2. 클릭 한 번에 요청 의도를 만들고 두 버튼을 비활성화한다. 세 요청 값을 보존해
   POST한다. 진행 중 polling은 계속하되 모달·포커스를 다시 만들지 않는다.
3. 확정 200/201/202이면 모달을 닫고 응답 run_id를 선택, 표현은 3D로 전환한다.
   runs/detail을 갱신하며 상세가 늦으면 그래프 위치에 로딩을 표시한다.
4. 실제 목록에 아직 없으면 목록 밖 접수 안내에 ID만 표시한다. 임의 created_at,
   submitter 서버 확인, 가짜 첫 행을 만들지 않는다. 목록 필터는 전체로 돌린다.
5. 202는 접수됨/대기 중이다. 요구 능력을 표시하되 노드 배정·순번·완료 시각을
   만들지 않는다. 상태 전이는 이후 관측으로만 반영한다.
6. 거절·미확인 응답은 제출 계약에 따라 안내한다. 같은 요청 재시도와 새로운
   작업 의도를 구분한다. 페이지 재진입 시 미확인 요청은 자동 전송하지 않는다.

제출 중에도 모달을 닫을 수 있다. 이때 요청과 접수 안내는 DemoShell에 남고 새
요청을 중복 시작하지 않는다. 닫기를 취소 완료로 표시하지 않는다. 미확인 요청은
같은 요청 재시도로 해결하거나 '다른 작업 시작'을 명시적으로 선택해야 새 ID를 만든다.
후자는 앞선 작업이 이미 접수됐을 수 있다는 안내를 함께 보인다.
모든 응답은 요청 ID와 화면의 요청 세대를 대조한다. 이전 요청의 늦은 응답이
새 요청 상태·선택 Run을 덮거나 새 요청의 sessionStorage 기록을 지우지 못한다.

## 8. 웹캠의 독립 수명

웹캠 설정은 배포자가 채우는 공개 정적 `demo/settings.json`에서 읽는다.
방송 URL이 없으면 방송 준비 중, 로드가 실패하면 연결 안내와 다시 연결을 보인다.
iframe load만으로 실제 송출 중이라고 단정하지 않는다. 공급자가 제공하는 검증된
재생 상태가 있을 때만 LIVE, 없으면 플레이어 표시/상태 미확인으로 구분한다.

함대↔Run·2D↔3D·polling에서 같은 플레이어 DOM을 유지한다. 모달/투어 동안에도
방송 수신은 계속한다. 확대·이동은 이 브라우저의 표시 상태이며 방송이나 보드를
조작하지 않는다. 브라우저 카메라 권한·getUserMedia·Mediator 중계를 사용하지 않는다.

[UI 개선 변경 계획](../../plans/ui-feedback-plan.md)을 적용한다. 웹캠 가시성은

장면 전환에서 닫고, 모달/투어도 배경 클릭으로 닫는다. Guest는 한글 두 단어로
이전하되 저장된 미확인 제출의 원래 이름과 ID는 보존한다.
