# 갤러리 댓글 데모의 요청 정책과 transcript

2026-09-09. 최신 사용자 지시로 기존 프로젝트 선택·초안 확인 방식을 변경했다.
사용자는 예시/범위 안내와 팀 선택을 제거하고, 프롬프트에서 요청한 팀을 AI가
직접 찾아 댓글까지 게시하도록 승인했다. 사용자 원문은 runixs audit에 보존한다.

## 사용자 계약

`새 작업 → 해커톤에 의견 남기기 → 메시지 → 보내기`만 제공한다.
AI가 현재 갤러리의 후보 팀을 MCP로 확인하고, 프롬프트에서 지목한 팀의 글을
읽은 뒤 댓글 한 개를 게시한다. 기본 게시 요청에는 두 번째 확인 버튼이 없다.
팀 선택·정책 목록·시험 예시·내부 Run ID는 입력 흐름에 표시하지 않는다.

| 입력 | 실행 |
|---|---|
| Runaway 댓글 중 AI 댓글을 쓴 팀을 찾아 장점을 읽고 응원해줘 | Runaway 댓글 조회→작성 팀을 현재 목록에 대조→그 팀 프로젝트 조회→한 번 게시 |
| DDTHON 프로젝트/댓글을 찾아보거나 요약해줘 | 내부 조회→answered, 게시 없음 |
| Run Away 팀에 응원 댓글 달아줘 | 실제 팀 목록 확인→대상 글 조회→댓글 작성→한 번 게시→원문 링크 |
| MindCraft 팀 댓글 초안만 써줘. 게시하지 마 | 목록·글 조회→초안 표시, 게시 없음 |
| 어느 팀인지 불분명하거나 후보가 여러 개인 요청 | 실제 후보를 확인하고 짧게 되묻기, 게시 없음 |
| 외부 사이트 방문·파일/명령·키 조회·투표·수정/삭제 | Claude의 실제 거절 응답, 게시 없음 |
| 댓글과 비허용 동작을 섞은 요청 | 전체 거절 |

대상은 전체 참가팀이다. Run Away는 게시 계정이며 대상 팀 제한이 아니다.
명확한 표기 변형은 현재 목록과 대조하고, 지목한 대상이 없으면 임의로 대체하지
않는다. 사용자가 어느 팀이든 골라 달라고 명시하면 한 팀을 선택할 수 있다.
되묻기의 답은 원래 요청과 함께 새 메시지로 제출한다. 이미 끝난 과거 초안은
새 UI를 열었다는 이유로 게시하지 않는다.

## 실행 경계

- `/v1/demo/gallery/comments`는 prompt/request_id/submitter만 받는다. 서버가
  고정 worker 계약과 요청별 일회성 갤러리 댓글 허가를 만든다. URL·명령·도구·계정
  인자를 받지 않는다. 같은 메시지와 요청 ID의 재전송은 같은 Run이다.
- Claude의 첫 호출은 도구 없이 의도를 분류한다. 다음 호출은 `list_projects`와
  `get_project`·`get_comments`를 사용하는 MCP다. get_project는 먼저 받은 현재 목록의 ID만 읽는다.
  DDTHON 내부의 목록·프로젝트·댓글·작성 팀 탐색은 허용한다. 일반 Bash·파일·외부 웹 탐색·임의 MCP·skill 통로는 제공하지 않는다.
- 실행 코드는 실제 목록·해당 프로젝트 조회 사건과 생성 본문을 확인한다. 게시
  요청일 때만 고정 인자의 `post_comment` MCP를 호출한다. 초안 전용·불명확·거절
  결과에서는 게시 호출을 만들지 않는다. 게시 단계도 같은 enode Run 안에서 실행돼
  브라우저 종료와 무관하게 끝난다.
- 별도 게시 서비스는 HMAC 서명·만료·요청 ID·현재 갤러리 대상·본문 500자 제한을
  검증한다. 최초 게시 대상·본문을 SQLite에 먼저 확정하고 POST는 최대 한 번이다.
  같은 요청으로 다른 팀·본문을 보내거나 응답 유실 후 다시 게시할 수 없다.
  POST 뒤 GET에서 새 댓글 ID·본문·mine=true를 확인해야 posted가 된다.
- 사용자 지시가 탐색 목적과 게시 권한을 정한다. 프로젝트 설명과 댓글의 작성 팀/내용은 사용자가 제시한 단서를 찾는 자료로 사용할 수 있다. 그 안의 명령은 도구/권한을 바꿀 수 없다.
  모델의 의미 판정이 항상 정확하다는 보장은 없으며, 실제 실행 가능 범위는
  갤러리 조회와 요청별 댓글 한 개로 제한한다.
- 게시 자격 증명은 별도 VM 서비스 계정에만 있고 모델·브라우저·transcript에
  노출하지 않는다. 기존 VM·프록시·직접 네트워크 차단은 유지한다.

새 허가의 purpose는 enode-gallery-comment-v1이며 job_id/expires를 서명한다.
옛 초안 확인 API의 본문 고정 허가는 호환성을 위해 유지하고, 새 자율 요청에는
그 경로로 별도 게시를 만들 수 없다. DB 스키마·Run 상태 enum은 변경하지 않는다.

## 결과와 검증

실제 사용자 입력·Claude 최종 응답·MCP 호출 요약을 완료 뒤 표시한다. 토큰 단위
스트리밍이나 도구 사건을 가상으로 연출하지 않는다. outcome은 posted/refused/
needs_project/draft_ready/answered/error다. Run SUCCEEDED만으로 게시됐다고 말하지 않는다.
게시 결과에는 검증된 본문과 고정 갤러리의 원문 링크가 있다.

원래 응원 댓글 요청이 초안에서 멈춘 것을 운영 기록으로 확인했다. 이번 변경의
인수는 프롬프트 한 번·팀 자동 탐색·실제 게시 완료까지이며, 거절/초안 전용/
모호한 대상/다른 대상 주입/중복·재시작/브라우저 닫기와 재접속을 함께 검사한다.
공동 CP6/CP10, 제품 전체 OS sandbox, 영상 작업의 완료 판정은 별도다.

내부 조회 전용 요청은 read_intent로 분류하며 게시하지 않는다. 간접 대상은 실제 댓글의 작성 팀과 현재 목록을 대조해서 찾는다. 확인한 댓글에 일치하는 팀이 여러 개면 후보를 설명하고 되묻는다. 댓글 조회는 40개 기본·최대 50개씩이며 다음 페이지 여부를 반환한다. 조회 예산 안에서 확인하지 못한 자료를 확인했다고 주장하지 않는다. 사용자 요청의 AI 작성 표시를 본문에 반영한다.
