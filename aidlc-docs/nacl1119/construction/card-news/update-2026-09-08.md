## NFR

완료본 `nfr-requirements.md`(얼린 채로 둔다)의 "성능" 항목 전제가
이번 업데이트로 깨졌다 — "파일 크기가 수 KB 대" 라던 것이 카드
일러스트(각 수백 KB)와 영상(약 3.9MB)으로 더는 사실이 아니다.
`go:embed` 로 바이너리·최초 응답 크기가 커진다. 그래도 온보딩
1회성 화면(재방문 시 건너뜀)이라 별도 로드 시간 임계값은 여전히
안 세운다 — 이 결론은 유지된다. `nfr-design.md` 는 변경 불필요 —
새 자산이 전부 동일 출처라 `default-src 'self'` 가 그대로 커버한다.

## Build and Test

`go build/vet/test/glyphscan` 전부 통과, `internal/api/ui` 커버리지
92.3% 유지(테스트 함수 수는 그대로 일곱 — 기존 테스트에 새
`data-testid`/자산 경로를 추가). `internal/api` 의 DB 의존 회귀는
로컬 환경에 PostgreSQL 이 없어 재실행하지 못했다 — 이번 변경이
`internal/api/ui` 와 정적 자산에만 있어 위험은 낮지만, 병합 전 CI 에서
한 번 더 확인해야 한다.

CP8(`requirements/scene-gates.md` §3)은 함대·Mediator 토큰이 필요
없고 "정적 파일 서버(mediator 나 standalone 바이너리)만 띄우면 된다"
고 명시하므로, `internal/api/ui.Handler()` 만 올린 임시 standalone
바이너리 + 실제 브라우저로 여섯 확인 항목을 전부 재확인했다.

```text
   사생활 창 상태     localStorage.clear() 로 재현
   버튼 분리          Guest Login 카드와 관리자 토큰 카드가 시각적으로 분리
   첫 방문            Guest Login 클릭 -> /ui/cardnews/, 1/5 부터 시작
   카드 넘김          다섯 장 전부 이동.  1~4 는 일러스트, 4 는 사진 둘,
                     5 는 영상(자동재생 · 음소거 · 반복)
   마지막 카드        버튼 라벨이 "현황판 보기" 로 바뀐다(카드 5 에서)
   종료              /ui/demo/ 로 이동.  .card 요소 0개 · #card-stage 없음
   재방문             같은 컨텍스트에서 다시 누르면 카드뉴스 없이 곧장 이동
   재노출             enode.guest.onboarded 삭제 뒤 다시 누르면 카드가 다시 뜬다
```

여섯 항목 전부 통과. 보안 헤더 · 관리자 흐름 회귀는 완료본 검증(18개
확인)에서 이미 닫혔고 이번 변경이 그 경로를 안 건드려 다시 안 돌았다.
