# drain — Business Rules

규칙마다 **정본 출처**를 단다. 출처가 없는 규칙은 이 유닛이 정한 것이고 그렇게 적는다.

---

## 1. 정책 규칙

| 규칙 | 출처 |
|---|---|
| 정본은 노드의 파일. 중앙은 광고로 받은 복사본을 `nodes.draining` 에 둔다 — 관측이지 판정이 아니다 | `ADR-063` §4 · `decisions` §1 |
| 어휘 셋 — `""` · `graceful` · `at-boundary`. 기본은 `graceful`(파일에 값을 적는 순간의 기본). 파일이 없으면 안 걸린 것 | `ADR-063` §4 · `decisions` §1 |
| 정책은 만료되지 않는다. 푸는 것은 소유자다 — 임대가 0 이 돼도 자동으로 안 풀린다 | `ADR-063` §4 · `decisions` §1 |
| 소유 증명은 그 기계의 파일을 쓸 수 있다는 것. 중앙은 소유권을 판정하지 않는다. 중앙 라우트 없음 | `ADR-063` §3 · `constraints` §4·§7 |
| 광고는 계속 보낸다 — `draining` 을 실어서. 현황판에 「있는데 안 빌려준다」로 보인다 | `ADR-063` §4 · `decisions` §1 |
| 매 광고 직전에 읽는다. 캐시 없음 | `enode-features` 3.2.2 「광고 직전에」 |
| dry-run 은 draining 을 안 본다 (새 코드 0) | `ADR-063` §6 · queue |

## 2. 두 모드 · 경계 규칙

| 규칙 | 출처 |
|---|---|
| 둘 다 단계 도중에 끊지 않는다. 놓는 자리는 단계 경계뿐 — 선점이 아니다 | `ADR-063` §2.1 · `INVARIANTS` §2 · `constraints` §1 |
| `graceful` — 새 임대만 막는다(매칭 제외). 도는 Run 은 끝까지. Worker 는 그대로 집는다 | `ADR-063` §2.1 |
| `at-boundary` — 도는 단계는 끝까지. 결과 보고 뒤 Mediator 가 그 Run 을 취소한다(`store.Cancel(run, "drain:<node_id>")`). Run 전체가 FAILED. 끝난 단계의 산출은 Record 에 남는다(I4) | `ADR-063` §2.1 · `decisions` §1 |
| **취소는 `Cancel` 그대로** — `verdict.checks[0] = {what:"cancelled", ok:false, note:"cancelled by: drain:<node_id>"}`. 목록의 `verdict` 가 drain 으로 닫힌 FAILED 와 진짜 실패를 가른다 | `decisions` §1 · §2(`GET /v1/runs` 행) |
| **되돌림(rolled) 뒤에도 취소한다.** 경계는 경계다 — 되돌린 단계가 다시 돌면 「더 집지 않는다」가 깨진다 | **이 유닛이 정한다.** 근거 — `ADR-063` §2.1 「결과를 보고한 뒤 임대를 놓고 더 집지 않는다」에 되돌림의 예외가 없다 |
| 마지막 단계의 보고면 정산이 먼저 닫는다 — 취소할 것이 없다. 정산이 이긴다 | `INVARIANTS` §2(`RUNNING -> VERIFYING`) |
| **Worker 는 at-boundary 를 안 순간부터 claim 을 안 건다.** 기준은 파일이 아니라 응답의 값(중앙이 받아 적은 것) | **이 유닛이 정한다.** 근거 — 정본 「데몬은 응답의 값을 Worker 에 넘긴다」 · 4절의 tx 창을 닫는 방법 |
| 지연 상한 없음 — 바닥(도는 단계의 남은 시간 + 광고 주기)이 곧 값. 급하면 제어판 `stop` | `decisions` §1 · `ADR-063` §4 |
| 여러 노드에 걸친 Run 도 전체가 닫힌다 — 일부만 살리는 것은 부분 복구고 I5 가 막는다 | `ADR-063` §2.1 |

## 3. 파일 규칙 (Q1 · Q3)

| 규칙 | 출처 |
|---|---|
| 위치 — 설정 파일 `<dir>/<stem>.yaml` 옆의 `<dir>/<stem>.policy.yaml`. 노드마다 하나. 설정 경로가 신원(ADR-017)이라 정책도 그 옆에 | 계획 Q1 = A |
| 형식 — yaml · 키 하나 `drain`. 모르는 키는 무시한다(뒤에 `panel_token` 이 이 파일에 앉는다 — `decisions` §2) | `decisions` §1 「같은 형식(yaml)」 · §2 |
| 없음 → `""` · 로그 없음. 파싱 실패 · 어휘 밖 → `""` · Warn 한 줄(값 원문 포함 · 같은 원인이 이어지면 다시 안 찍는다) | **이 유닛이 정한다.** 근거 — 광고가 하트비트를 겸한다(ADR-016). 값 하나로 노드를 세우지 않는다. 노드 로그는 소유자의 것이라 값을 적어야 고친다 |
| 권한 — 유닉스에서 그룹·타인 쓰기 비트가 있으면 Warn 한 줄, 값은 그대로 쓴다. 윈도우는 안 본다. `0600` 이 권장값이고 이 유닛은 쓰지 않으므로 만들지 않는다 | 계획 Q3 = A · `decisions` §3·§6.3 |
| 쓰는 쪽은 소유자 손과 panel 의 토글. 이 유닛은 쓰지 않는다 — CP3 는 손으로 쓴다 | 유닛 정본 · roster |

| 규칙 | 출처 |
|---|---|

## 5. 보안 확장 (security-baseline · 켜짐) — 이 유닛에서의 취급

새 HTTP 표면 0. 새 **파일 표면 하나**(정책 파일 · 읽기만).

| 규칙 | 판정 | 근거 |
|---|---|---|
| SECURITY-03 로깅 | 준수 | 노드 로그에 정책 값 원문을 적는다 — 소유자의 기계·소유자의 파일이고 비밀이 아니다. Mediator 쪽은 obs 규칙 그대로(값 원문 안 찍음). 토큰 · principal 안 찍음 |
| SECURITY-05 입력 검증 | 준수 | 파일 값은 어휘 셋 allowlist 로 접는다(노드에서 한 번 · 저장소에서 또 한 번). 파싱은 `yaml.v3` 고정 타입. Mediator 의 `postResult` 갈래는 새 입력 없음(`body.Node` 는 기존 입력) |
| SECURITY-08 접근 제어 | 준수 | 소유 = 그 기계의 파일 쓰기(ADR-063 §3). 중앙 라우트를 안 만들어 토큰만으로 남의 노드를 빼는 표면이 없다 |
| SECURITY-09 하드닝 | 준수 | 권한 경고(Q3). 기본값이 안 걸린 것(`""`). 오류 문구는 로그뿐 |
| SECURITY-15 fail-safe | 준수 | 파일 오류는 「안 걸린 것」으로 접는다 — 열리는 것이 없다(안 걸리면 오늘 그대로). Cancel 실패는 로그 · 보고는 받는다 · Worker 가 안 집어 창을 닫는다 |
| SECURITY-01 · 07 · 12 | 기록만 | `decisions` §3. 새 리스너 · 자격증명 0 |
| SECURITY-11 | 준수 | 관심 분리 — 정책 읽기는 `policy.go` 하나. 오용 사례: 다른 사용자가 정책 파일을 써서 남의 노드를 뺀다 → 권한 경고가 알리고, 회수는 파괴가 아니다(도는 단계는 끝까지 · 산출은 Record). 막는 것은 파일 권한(운영자) |
| 나머지 (02 · 04 · 06 · 10 · 13 · 14) | N/A | 중간장치 · HTML · IAM · 새 의존 0 · 외부 자원 0 · 운영 범위 밖 |
