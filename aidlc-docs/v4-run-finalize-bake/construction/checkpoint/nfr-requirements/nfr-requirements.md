여기에는 요구에 쓰는 값만 옮긴다. 작성 2026-09-30T14:26:33Z.

## 1. N2 — 두 한도의 값 (답 1 · 2)

N2 는 NFR 값 둘째 — 보존본 하나의 상한과 inode 한도다 (유닛 정의 8절).

| 키 | 기본 | 규칙 |
|---|---|---|
| `max_gb` | 32 | 보존본 하나의 측정한 바이트가 32 GiB 를 넘으면 퇴출 (규칙 6절 3) |
| `max_total_inodes` | 몫 | 적지 않았거나 0 이면 `capacity_percent` x (`kept` 의 측정한 inode 합 + statfs 의 남은 inode). statfs 의 전체 inode 가 0 이면 (btrfs) inode 한도를 보지 않는다. 숫자를 적으면 그 숫자다 |

- 두 몫은 판정마다 한 번 정한다 — 퇴출한 것은 여유로 돌아오므로 판정 동안 그대로다 (규칙 6절 4)
- 보고 전 받아들임은 inode 를 보지 않는다 — 측정 전이라 모른다 (규칙 5절)
- **32 는 측정한 가장 큰 upper 를 받는다** — 처음부터 굽기 23 GB · 하루치 9.3 · 8.6 GB (ADR-077 §12)

**값을 대 보면** (upper 는 ADR-076 §4.1 · ADR-077 §12 · 디스크는 계획 2절)

| 자리 | 바이트 몫 | inode 몫 | 하루치 (9.3 GB · 184,528 항목) | 처음부터 (23 GB · 681,670 파일) |
|---|---|---|---|---|
| 이 기계 (가용 95.6 GB · 남은 inode 8,820,007) | 19.1 GB | 1,764,001 | 바이트로 둘 · inode 로 아홉 | 몫 하나를 넘어 퇴출 |
| SunnyVM (가용 344.7 GB · 남은 inode 28,285,100) | 68.9 GB | 5,657,020 | 바이트로 일곱 · inode 로 서른 | 바이트로 둘 · inode 로 여덟 |

**Yocto upper 에서는 바이트 몫이 먼저 닿는다.** 항목 평균이 34 ~ 59 KB 이고, inode 몫이 먼저 닿는 것은 항목 평균이 가용 바이트 / 남은
inode (이 기계 10.8 KB · SunnyVM 12.2 KB) 보다 작은 upper 뿐이다. inode 한도는 작은 파일 더미를 막는다.

## 2. 성능

| # | 요구 | 값 · 근거 | 확인 |
|---|---|---|---|
| P1 | 보존이 보고 전 창에 더하는 일은 upper 크기와 무관하다 | 결정 2-4 · 흐름 1절 | integration — 큰 upper 와 빈 upper 의 `finalized_at - exited_at` 이 같은 수준 (조각 4 의 방식) |
| P2 | **보존은 단계의 finalize 판정을 바꾸지 않는다** — 보존에 든 시간 때문에 finalize_timeout 이 나지 않는다 | FR-10 끝 줄. 쓰기 부하 (같은 filesystem 에 3 GiB) 에서 예약이 한 번 4.2 초 멈췄다 | 모양은 NFR Design (6절). 시험 — 느린 예약을 끼운 가짜 store 에서 finalize 칸 · error · exit 이 그대로다 |
| P3 | 한가할 때 창 안의 보존 일은 p99 1 ms 아래 | 측정 p50 0.16 ms · p99 0.46 ms · 최대 24 ms. 게이트가 아니라 기록이다 | integration 에 한 줄 |
| P4 | 기록에 fsync 하지 않는다 | 쓰기 부하에서 fsync 는 p99 4.4 초 · 최대 7.2 초. fsync 없이 p99 87 ms | 시험 없음. R2 가 받는다 |
| P5 | spool 잠금을 기다리는 것은 형제의 판정과 조정뿐이다. 보고 전 창 · 받아들임 · 조회는 기다리지 않는다 | 규칙 5 · 13절. 측정은 upper 하나에 2.6 ~ 3.95 초 (ADR-077 §12 · 따뜻한 캐시) | 시험 — 잠금을 쥔 채 예약과 조회가 끝난다 |
| P6 | 만료는 늦어도 10분과 측정 시간 뒤에 거둔다 | 규칙 6절 · 삭제자의 `DefaultEvery` | 표 시험 (시계를 넣는다) |
| P7 | 받아들임의 넘침은 다음 판정 (보고 뒤 몇 초) 까지다. 여유 하한은 늘 그 순간의 statfs 로 본다 | 규칙 5절 | 표 시험 |

## 3. 보안 (규칙 11 · 12절 · 결정 2-11 · `requirements.md` 5.3)

| # | 요구 | 확인 |
|---|---|---|
| C1 | spool · 항목 폴더 0700, 기록 0600 — umask 와 무관 | 시험 — umask 0 으로 만든 뒤 mode |
| C2 | host 경로가 receipt · `diagnostics.checkpoint` · 단계 로그 · 광고에 없다 | 시험 — 표지 글자를 담은 scratch 경로로 규칙 2절의 갈래를 모두 돌려 result JSON 과 올린 단계 로그에 그 글자가 없다 |
| C3 | 오류 문장은 errno 의 글만 | 시험 — `PathError` · `LinkError` 를 넣는다 |
| C4 | `show` 의 `unshare` 안내로 컨테이너 root 가 쓴 0600 파일이 읽힌다 | integration · 조각 9 (5절) |
| C5 | 자격증명 캐시 안내가 on-failure · always 에서만 보인다 | 제어판 시험 |
| C6 | 계약과 agent 출력에 보존 칸이 없다 | 시험 한 줄 — 계약 문법에 `checkpoint` 칸이 없다 |
| C7 | 기록은 `O_NOFOLLOW` · 보통 파일 · 1 MiB 까지만 읽는다. 넘으면 읽을 수 없는 기록이다 | 시험 — symlink · 큰 파일 |
| C8 | **이미 있는 spool 자리** (답 3) — 기동 때 lstat 로 본다. 남에게 열린 비트는 0700 으로 좁히고 로그 한 줄. symlink · 디렉터리 아님 · 주인이 노드 uid 가 아님은 고치지 않고 거절 — 요구한 단계는 `failed`(`io`) 와 문장, 기동 로그 warn. 노드는 뜨고 drain 하지 않는다. 예약은 spool 을 `O_NOFOLLOW` 로 연다 | 시험 — 세 모양마다 기동 로그 · receipt · 노드가 뜸 |

C8 은 lower-state 의 상태 자리 규칙과 같다 (`lower-state-code-generation-plan.md:145-162`) — 남이 놓은 symlink 를 따라가면 밖에 파일이
생긴다.

## 4. 신뢰 · 가용 · 규모 · 유지 · 쓰기

| # | 요구 |
|---|---|
| R1 | 보존의 어떤 오류도 단계를 멈추거나 광고를 막지 않는다. 예외는 규칙 3절의 Close 오류다 (보존이 아니다) |
| R2 | 전원이 나가 기록이 없거나 · 비었거나 · 읽을 수 없으면 조정이 미완료로 거둔다 — 항목 잠금을 쥘 수 있을 때만 (규칙 9절 · 이 단계에서 고침) |
| R3 | 판정과 조정의 오류는 로그 warn 이고 다음 때에 다시 돈다 |
| S1 | 항목 수는 몫과 TTL 이 막는다 (1절 표). 판정과 조회는 항목 수에 비례하고 upper 크기와 무관하다 |
| M1 | 패키지별 커버리지 80% 이상 — `internal/scratch` · `internal/enode` · `cmd/enode` (지금 80.8%). 규칙마다 표 시험 · 새 의존 0 · 크로스 빌드 셋 · `glyphscan` · 문구는 영어 (제어판만 한국어) |
| U1 | 보이는 문구는 FD 규칙 12 · 13 · 14절 그대로다. 이 단계가 더한 문장 둘은 규칙 2절 ⑤ 와 14절 (답 3) |

## 5. 잔여 — 확인하지 못한 채 둔다 (답 4)

| 무엇 | 확인하는 자리 | 빨가면 |
|---|---|---|
| 노드 uid 로 못 여는 항목을 `unshare` 로 읽기 | integration (SunnyVM) · 조각 9 | `show` 의 open 줄의 문구를 고친다 |
| 보고 뒤 측정의 찬 캐시 · 사내 규모 시간 — 판정이 spool 잠금을 쥐는 시간 | 없음. 정본도 측정하지 않았다 (ADR-076 §4.1) | 잠금 범위 (6절) 가 받는다 |
| 전원이 나간 뒤의 기록 | 없음. 끊어 볼 수 없다 | R2 가 거둔다 |
| btrfs · xfs 의 statfs inode 값 | 없음. 이 기계와 SunnyVM 은 ext4 다 | 1절의 「전체 inode 가 0 이면 보지 않음」 이 받는다 |

## 8. 정본 되돌림에 더할 것 (진행자가 올린다 · FD 흐름 12절에 이어)

| 자리 | 한 줄 |
|---|---|
| ADR-076 §10 | N2 — 보존본 하나의 상한 기본 32 GiB · inode 한도의 기본은 보존 용량과 같은 비율 · statfs 가 inode 수를 안 내면 보지 않는다 (답 1 · 2) |
| ADR-076 §5 | spool 자리 — 느슨한 비트는 좁히고 symlink · 디렉터리 아님 · 남의 것은 거절한다. 보존만 못 하고 노드는 뜬다 (답 3) |
