# 규칙 — demo-pen

시안이 지켜야 하는 것과, 시안이 구현에 넘기는 것을 가른다.

## R1. 첫 방문은 브라우저가 안다

- `first_visit` 와 `tour_done` 은 브라우저 캐시에 산다. 지우면 다시 첫 방문이다
- 첫 방문의 순서는 D0(온보딩 카드, 타 팀원) -> D1 -> D2 위에 D3
- 재방문은 D1 을 건너뛰어도 되는가 — **아니다.** user_<번호> 가 캐시에 있으면
  D1 은 배정된 번호를 보이고 같은 버튼으로 들어간다. 시안은 첫 방문 상태만 그린다

## R2. user_<번호> 는 식별이지 인증이 아니다

- Q2 의 답. 이름 사전을 두지 않고 번호 하나를 배정한다
- 번호는 브라우저 캐시에만 산다. 서버는 그것을 저장하지 않는다
- **Mediator 토큰은 브라우저에 오지 않는다.** 데모 페이지가 어떻게 Mediator 에
  닿는지(프록시 · 데모 전용 토큰)는 코드 회차가 정한다. 시안은 그 사실을
  D1 의 각주 한 줄로만 말한다

## R3. 우 열은 어느 장에서도 안 가린다

- 요청의 「작업 그래프가 run 목록을 가리지 않게」. Q3 · Q4 가 좌 3D · 우 목록으로 닫았다
- D3 의 덮개는 우 열을 어둡게 하되 스포트라이트 스텝 3 · 4 에서 밝힌다
- D4 의 덮개는 우 열 위에도 얹힌다. **이것은 가림이 아니라 모달이다** — 닫으면
  그대로 돌아온다. 그래도 목록 윤곽이 비치게 불투명도를 60% 로 둔다

## R4. 어휘는 enum 원문

- Run 은 RUNNING · QUEUED · SUCCEEDED · FAILED, 단계는 PENDING · CLAIMED ·
  DONE · FAILED · SKIPPED · ASKED (design/README.md 6절)
- 범례는 한글과 enum 을 나란히 적는다
- 노드 배지는 한글이다 (임대 없음 · 임대 중 · draining · 만료 임박 · 사람을 기다림)

## R5. 값을 지어내지 않는다

- 필드는 API 가 주는 것만 (domain-entities.md 1절)
- 새 작업 버튼 둘은 미리 적힌 계약에 대응한다. 계약 본문 · run_id 규칙 ·
  requires 는 코드 회차가 적는다. 시안의 `led-toggle-0417` 은 샘플이다
- 폴링 간격 · 만료 임박 임계값 · 페이지네이션은 자리만 (design/README.md 5절)
- principal 을 중앙 표면에 내지 않는다 (ADR-065)

## R6. 3D 는 S6 · S7 을 복사한다

- 모형 · 평면 · 상태색은 `enode-ux.pen` 의 것을 인스턴스로 가져온다
- 데모에서 달라지는 것은 배치(1920) 와 패널 헤더뿐이다

## R7. 표기

- 시안의 글과 주석에 장식 문자를 넣지 않는다 (CONVENTIONS.md 1.2)
- 강조는 짧은 문장과 위치로 한다

## 구현에 넘기는 것 (시안이 안 정함)

```text
   프리셋 계약 둘의 JSON              코드 회차
   Mediator 접근 경로 (프록시/토큰)    코드 회차
   폴링 간격 · 임계값                 decisions.md 2절
   웹캠 스트림 방식                   코드 회차 (브라우저 직접 수신이 전제)
   user_<번호> 의 자릿수 · 충돌 처리    코드 회차
```
