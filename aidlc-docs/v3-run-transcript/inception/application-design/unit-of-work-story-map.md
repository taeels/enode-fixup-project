# 스토리 사상 — 유닛이 무엇을 지나

세 벌을 유닛에 앉힌다 — **스토리 열하나 · 새 완료 조건 여섯 · 기능 여덟.**
셋 다 마지막에 **배정 안 된 것을 센다.**

```text
   지는 유닛    그 값을 사람이 볼 수 있게 만드는 유닛.  하나다
   재료 유닛    그것 없이는 지는 유닛이 못 서는 유닛.  여럿일 수 있다
```

**가르는 이유** — 재료까지 「진다」고 적으면 게이트가 빨개졌을 때 돌아갈 자리가
여럿이 된다. Q2 = A 가 「마지막으로 완성하는 유닛이 진다」인 것과 같은 결이다.

### 1.1 스토리가 유닛에 몰리는 모양

```text
   U5 panel-live    US-1 · US-2 · US-3 · US-4     넷.  P1 의 전부다
   U4 log-api       US-5 · US-7 · US-8            셋.  P2 의 셋
   U6 panel-past    US-6 · US-10                  둘
   U8 fleet-card    US-9 · US-11                  둘
   U1 · U2 · U3 · U7   지는 스토리 0.  전부 재료다
```

**지는 스토리가 0 인 유닛 넷이 빠뜨린 것이 아니다.** `user-stories.md` 2.3 이
같은 자리를 이미 적었다 — 「FR-1 에 스토리가 0 인 것이 빠뜨린 것이 아니다.
끊고 잇는 일이라 사람이 보는 표면이 없다」. 파서 · 링 · 진행 파일 · 업로더가
그 자리다.

## 2. 새 완료 조건 여섯

`user-stories.md` 3절이 낳았고 **Units Generation 이 유닛에 내린다**고 넘긴 것이다.

| | 완료 조건 (줄임) | 지는 유닛 | 재료 유닛 | 낳은 스토리 |
|---|---|---|---|---|
| NC-1 | 마지막 사건 이후 경과가 보인다 | **U5** | — | US-1 |
| NC-2 | 링이 감겨 앞이 잘렸음이 적힌다 | **U5** | U2 | US-2 |
| NC-3 | 링에 원문이 남는다는 사실이 카드에 | **U5** | U2 | US-3 |
| NC-4 | 상한에 닿았음이 응답과 화면에 | **U4** | U3 · U5 · U8 | US-7 |
| NC-5 | `mediator-api` 가 봉인 전후를 적는다 | **U4** | — | US-8 |
| NC-6 | 현황판 카드에 마지막 갱신 시각 | **U8** | U4 | US-9 |

**배정 안 된 완료 조건 0.**

### 2.1 NC-4 가 유닛 넷에 걸친다

여섯 중 유일하게 넷이 필요하다.

```text
   U3   값을 만든다        총 길이가 상한에 닿았음을 Progress.Capped 가 진다
   U4   응답에 싣는다       X-Enode-Log-Capped.  **지는 유닛이다**
   U5   제어판이 그린다     카드 한 줄
   U8   현황판이 그린다     카드 한 줄
```

**U4 가 지는 이유** — NC-4 의 문장이 「**응답과** 화면에 적힌다」이고 응답이
먼저다. 화면 둘은 응답이 실은 값을 그린다. 응답에 없으면 화면이 지어내야 한다.

### 2.2 NC-5 는 문서도 함께다

`mediator-api` 의 `GET log` 절이 「봉인 전 응답은 원문이고 봉인 뒤는 선별본이다」를
적는 것이 NC-5 다. **그 문서는 `enode-design` 정본이므로 진행자가 올린다**
(`requirements.md` 11절). U4 는 **그 문장의 초안**을 자기 산출물로 낸다.

(`requirements.md` 2.5) CB5 와 같은 이유로 유닛이 0 이다.
