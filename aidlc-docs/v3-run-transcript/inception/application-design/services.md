# 서비스 — 순서와 오케스트레이션

**여기는 시간 순서다.** 컴포넌트가 무엇을 하는지는 `components.md` 가, 겉면은
`component-methods.md` 가 적는다. 여기서 정하는 것은 **무엇이 무엇보다 먼저
일어나고 어디서 죽을 수 있는가**다.

---

## 1. 한 단계가 도는 순서 (노드)

```text
   ①  링을 비운다                claim.go:456.  오늘 그대로.  gen 이 오른다
   ②  업로더를 만든다             그 단계의 runID · seq · attempt · name 을 안다
   ③  tee 를 잇는다              io.MultiWriter(ring, uploader).
                                claim.go:794 가 Job.Transcript 로 넘긴다
   ④  하네스를 띄운다             runner.go.  stdout 이 tee 를 지난다
   ⑤  Decode 가 배출한다          줄 단위.  emit 은 종류만 노드 로그에 적는다
   ⑥  업로더가 주기로 올린다       새 바이트가 있으면 2초, 64 KiB 면 즉시
   ⑦  단계가 끝난다               업로더를 Close 한다 — 남은 것을 마지막으로 올린다
   ⑧  선별본을 올린다             claim.go:796.  오늘 그대로 logs/ 에 간다
```

**⑥ 과 ⑧ 이 다른 파일로 간다** (질문 1 = B). 그래서 두 벌이 안 생기고, 팩이
요구했던 「꼬리만 올린다」가 필요 없어졌다.

**어디서 죽을 수 있나.**

```text
   ①  링 없음        오늘과 같다.  ring == nil 이면 tee 의 갈래가 하나 줄 뿐이다
   ②  업로더 없음     Mediator 주소가 없거나 만들기 실패.  갈래가 하나 준다
   ⑥  PUT 실패       **보조다.** 다음 청크에 이어 보낸다.  실행도 링도 안 막는다
   ⑥  상한 도달       더 안 올린다.  노드 로그에 한 번 남기고 Capped 가 참이 된다
   ⑦  Close 실패     보조다.  단계의 결과를 안 바꾼다
   ⑧  업로드 실패     오늘과 같다 (`_ =` 로 버린다)
```

**⑥ 이 보조인 것이 이 설계의 값이다.** 관측 표면이 실행을 막으면 그것은 관측이
아니라 의존이다.

## 2. 재시도가 도는 순서 (Q1 = A)

```text
   ①  단계가 다시 잡힌다          attempt 가 1 오른다 (claim.go:156)
   ②  링이 비워진다               claim.go:456.  오늘 그대로
   ③  첫 청크가 attempt 를 싣는다   PUT .../log?progress=1&attempt=<n>
   ④  Mediator 가 갈린다          곁파일의 시도와 다르면 **진행 파일을 먼저 비운다**
   ⑤  총 길이가 0 부터 다시 센다    응답이 0 을 돌려주고 노드가 오프셋을 맞춘다
   ⑥  화면이 카드를 비운다         응답 헤더의 X-Enode-Log-Attempt 가 바뀐 것으로 안다
```

**⑥ 이 Q1 = A 의 대가를 닫는다.** 비우면 총 길이가 뒤로 가는데, 링이 같은 자리를
`gen` 으로 이미 풀었으므로 (`transcript.go:148`) 같은 답을 쓴다. 화면은 세대가
바뀐 것을 이미 다룰 줄 안다.

**봉인된 것은 안 잃는다** — `logs/NN-*.log` 는 `O_APPEND` 라 시도 둘이 다 남는다
(`record.go:59`). 비워지는 것은 **도는 동안 보는 것**뿐이다.

## 3. 봉인의 순서 (Q2 = A)

```text
   ①  종료 상태에 이른다           reap.go 의 SettleIfDone · Cancel · sealExpired
   ②  store.sealRecord 가 부른다    seal.go:204 -> record.Store.Seal
   ③  Seal 이 진행 트리를 지운다     **가장 먼저다.**  DropProgress(runID)
   ④  blobs/ 의 .tmp- 를 걷는다     record.go:112.  오늘 그대로
   ⑤  manifest · verdict 를 쓴다    오늘 그대로
   ⑥  seal(dir) 이 굳힌다          Walk 로 0444 · 0555
```

**③ 이 ⑥ 보다 앞이라는 것이 전부다.** 다만 Q2 = A 라서 **순서가 틀려도 원문이
영구가 되지 않는다** — 진행 트리는 `dir` 밖이라 `seal` 의 `Walk` 가 못 닿는다.
순서는 값이고 자리는 안전장치다. 둘을 함께 둔다.

**③ 이 실패하면** 봉인은 그대로 진행한다. 남은 진행 트리는 지울 수 있는 상태로
남는다 (0644). 그 청소의 값이 N2 다 (NFR Requirements).

## 4. 읽는 쪽의 순서 (Mediator)

```text
   GET .../log 가 오면
   ①  입력을 검증한다             seq · from · as · name.  밖이면 400 (SECURITY-05)
   ②  Run 이 있나 본다            없으면 404
   ③  Sealed(runID) 로 갈린다     record.go:76.  **이 한 줄이 D3 의 답이다**
       봉인 전   ReadProgress.   Source: progress.  원문이다
       봉인 뒤   logs/NN-*.log.  Source: sealed.    선별본이다
   ④  as=events 면 파서를 거친다   transcript.Parse.  봉인 뒤면 껍데기를 읽는다
   ⑤  헤더 넷을 싣는다             Bytes · Source · Attempt · Capped
```

**③ 이 NC-5 를 세운다** — 「봉인 전 응답은 원문이고 봉인 뒤는 선별본이다」가
헤더로 응답에 적혀 있다. 읽는 쪽이 `from` 오프셋을 그대로 이어 쓰다 엉뚱한
자리를 읽는 일이 그래서 막힌다.

## 5. 두 화면의 순서

### 5.1 제어판 — 출처가 둘이다

```text
   도는 것    1초 타이머 -> GET /api/transcript -> 로컬 링.  Mediator 를 안 탄다
              **데몬이 죽어도 읽힌다** (ReadRing 의 주석)
   지난 것    사람이 Run 을 누를 때 한 번.  Status 로 단계 목록 ->
              단계마다 StepLog -> 같은 파서로 그린다
```

**도는 것이 Mediator 를 안 타는 것이 오늘의 값이고 그대로 둔다.** 노드 소유자의
화면은 함대가 끊겨도 자기 노드를 본다.

### 5.2 현황판 — 출처가 하나다

```text
   목록       5초 타이머.  client.mjs:67.  오늘 그대로
   단계 카드   2초 타이머.  **별개다.**  Run 상세가 열려 있을 때만 돈다
              도는 단계는 from 을 이어 가며 자라고, 끝난 단계는 한 번 읽는다
```

**타이머를 가르는 이유** — 목록 폴링을 멈춰도 카드는 자라야 한다 (CB4).
하나로 묶으면 그 조각을 못 잰다.

## 6. 화면이 「안 자란다」를 가르는 순서 (NC-1 ~ NC-6)

`user-stories.md` 3절의 여섯이다. **다섯이 같은 모양이라 한 자리에 모은다.**

```text
   NC-1   경과      마지막 응답 시각을 화면이 들고 「지금 빼기 그것」을 그린다 (Q3 = A)
   NC-2   잘림      total > capacity 면 링이 감긴 것이다.  ReadRing 이 이미 total 을 낸다
   NC-3   링 잔여   카드에 한 줄.  자리와 덮이는 시점을 함께 적는다.  값이 아니라 문장이다
   NC-4   상한      X-Enode-Log-Capped 를 그대로 그린다
   NC-5   출처      X-Enode-Log-Source 를 그대로 그린다.  문서에도 적는다 (11절)
   NC-6   갱신      마지막으로 total 이 움직인 시각.  화면이 들고 뺀다 (Q3 = A)
```

**파서가 내는 것은 NC-2 의 재료와 NC-4 의 값뿐이다.** 나머지는 헤더가 내거나
화면이 뺀다 — 파서에 시계를 안 넣는 값이 여기서 돌아온다.
