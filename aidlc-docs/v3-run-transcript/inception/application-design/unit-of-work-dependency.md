# 유닛 의존과 착수 순서

**두 가지를 적는다** — 유닛 사이의 의존(웨이브)과 한 손이 실제로 달리는
순서(Q3 = B). **둘이 다르다.** 웨이브는 무엇이 가능한지를, 순서는 무엇을 먼저
하는지를 적는다.

---

## 1.1 의존이 0 인 유닛 셋

**U1 · U2 · U3 가 아무것도 안 기다린다.**

```text
   U1   새 패키지다.  표준 라이브러리만 임포트한다
   U2   링 tee 도 Decode 도 파서를 안 쓴다 — 바이트를 흘리고 사건을 만들 뿐이다
   U3   바이트를 다루지 사건을 안 다룬다.  파서를 안 쓴다
```

**U2 가 U1 을 안 기다리는 것이 이 그래프의 값이다.** `selectLogs` 가 파서를 쓰게
하는 일은 U1 안에 넣었고 (`unit-of-work.md`), `Decode` 와 tee 는 그것과 무관하다.

## 2. 웨이브

```text
   W0   U1 transcript · U2 node-stream · U3 progress-store      의존 0
   W1   U4 log-api (U1 · U3)  ·  U5 panel-live (U1 · U2)
   W2   U6 panel-past (U4 · U5)  ·  U7 chunk-push (U2 · U4 · U5)
   W3   U8 fleet-card (U4 · U7)
```

**깊이가 넷이다.** 한 손이므로 (질문 3 = B) 웨이브는 병렬 기회가 아니라
**순서의 하한**이다 — W1 의 것을 W0 보다 먼저 못 한다.

## 3. 착수 순서 (Q3 = B) — CB1 을 먼저 세운다

```text
   ①  U1 transcript       파서.  코드 게이트만
   ②  U2 node-stream      Decode 배출 · 링 tee.  코드 게이트만
   ③  U5 panel-live       **CB1 초록.**  여기서 사람이 처음 눈으로 본다
   ④  U3 progress-store   진행 파일.  코드 게이트만.  N2 를 진다
   ⑤  U4 log-api          **CB0 초록.**  라우트 17 -> 18.  N1 을 진다
   ⑥  U6 panel-past       **CB2 초록.**  archive/tar 가 사라진다
   ⑦  U7 chunk-push       **CB3 초록.**  실패 주입이 필요한 조각이다
   ⑧  U8 fleet-card       **CB4 · CB6 초록.**  장면이 여기서 완주한다
```

**왜 ③ 이 셋째인가** — `scene-gates.md` 2절이 CB1 의 「먼저 서는 기능」을
(없음)으로 적었고 CB2 · CB3 이 CB1 을 딛고 CB4 가 CB3 을 딛는다. **그래프가
이미 이 순서를 가리킨다.**

**왜 일찍 봐야 하는가** — CB1 이 빨가면 파서의 모양이나 링의 내용이 틀린 것이고,
그것을 여덟을 다 짓고 나서 알면 되돌릴 것이 여덟이다. 앞 팩의 CP6 이 그 눈을
늦게 떠서 이 팩이 생겼다 (`scene-gates.md` 2절).

## 3.1 웨이브와 순서가 어긋나는 자리 하나

③ U5 가 W1 이고 ④ U3 가 W0 이다. **웨이브를 거스른다.**

```text
   왜 괜찮나   U5 는 U1 · U2 만 딛는다.  U3 와 의존이 0 이다.
               웨이브는 순서의 하한이지 순서 자체가 아니다
   무엇을 얻나   CB1 이 다섯째가 아니라 셋째에 선다
```

```text
   ③ 뒤   CB1   흐른다               사람 눈.  실제 하네스
   ⑤ 뒤   CB0   기동이 안 깨졌다       기계.  유닛마다 도는 연기 시험이기도 하다
   ⑥ 뒤   CB2   읽힌다               사람 눈
   ⑦ 뒤   CB3   올라간다             사람 눈 + 실패 주입 (Mediator 를 10초 멈춘다)
```

**사람 눈이 넷이고 보류로 안 넘긴다** (`scene-gates.md` 4절 · `requirements.md` 6절).

## 5. 병합 지점

### 5.1 직렬 병합 — `CONVENTIONS.md` 3.1 이 경고한 자리

```text
   internal/api/api.go   **만지는 유닛이 U4 하나뿐이다.**  등록 줄과 putLog 의
                         갈림이 같은 유닛이라 직렬이 실제로 안 생긴다
```

**규약이 경고한 자리가 이 회차에서는 안 부딪친다.** 라우트를 더하는 유닛이
하나뿐이기 때문이다.

### 5.2 실제로 직렬인 자리 셋 — 파일 행렬이 찾았다

```text
   internal/enode/runner.go     U1 (셋을 덜어낸다) -> U2 (tee)
   internal/enode/claim.go      U2 (transcript()) -> U7 (업로더)
   internal/panel/transcript.go U5 (도는 것)      -> U6 (지난 것)
```

**셋 다 착수 순서가 이미 그 순서다** (③ 절). 한 손이라 충돌이 0 이고,
순서만 지키면 재작업도 0 이다. 전문은 `unit-of-work-file-matrix.md`.

### 5.3 짝 팩과의 접점

**0 이다.** `v3-run-harness-components` 의 유닛 다섯이 이미 `main` 에 들어왔다
(`aidlc-state.md`). `constraints.md` 의 접점 절이 `claude.go` 의 `Argv` 를
접점으로 적었으나 저쪽이 이미 가져갔고 (`claude.go:343`) 이 회차는 `Decode` 만
만진다.

```text
   FR-2 링      U2 node-stream
   FR-5 청크    U7 chunk-push
```

무르려면 U3 · U7 을 되돌린다. **둘이 다른 PR 이다.**
