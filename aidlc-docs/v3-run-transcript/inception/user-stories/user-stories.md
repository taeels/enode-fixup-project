# 사용자 스토리 — 최소

**왜 최소인가.** `scene-gates.md` 의 조각 일곱과 `requirements.md` 6절이 수용
기준을 실행 명령으로 이미 적었고 그것이 판정 기준이다. 스토리가 그것을 다시
쓰면 약한 사본이 되고, 갈리는 날 어느 쪽이 이기는지 정할 자리가 없다.

**그런데 조각 일곱이 안 재는 자리가 있다.** 일곱은 전부 **「값이 옳게 흐르는가」**
를 잰다. **「흐르지 않을 때 사람이 무엇을 보는가」**를 재는 조각이 0 이다.

```text
   안 쓴다   행복 경로.  CB0 ~ CB6 이 이미 재고 더 촘촘하다
   쓴다      오독 경로와 침묵 경로 — 화면이 안 자랄 때 · 본문이 없을 때 ·
            상한에 닿았을 때 · 내 기계에 무엇이 남는지
```

짝 팩에서 이 빈자리는 **저작 경로**였다 (사람이 잘못 적었을 때 무엇을 보는가).
이 팩은 읽는 표면이라 저작 경로가 거의 0 이고 빈자리가 다른 데 있다.

```text
   묶는 법     Persona-Based (Q3 = A).  이 팩의 값이 「누가 무엇을 읽는가」다
   FR 열      묶는 법이 아니라 추적이다.  Units Generation 이 이것으로 유닛에 앉힌다
   확인 열     초록임을 무엇으로 보는가.  게이트가 이미 재면 그 조각 이름을,
              아니면 3절의 새 완료 조건 번호를 가리킨다
```

# 1. 스토리 열

## P1 노드 소유자

| | 스토리 | FR | 확인 |
|---|---|---|---|
| US-1 | 노드 소유자로서 카드가 한참 안 자랄 때 **에이전트가 생각 중인지 멈춘 것인지** 구별하고 싶다. 둘이 같아 보이면 나는 매번 로그를 열어야 한다 | FR-2 · FR-4 | NC-1 |
| US-2 | 노드 소유자로서 링이 감겨 앞이 잘렸을 때 **앞이 잘렸다는 것**을 화면에서 알고 싶다. 모르면 단계가 늦게 시작한 줄 안다 | FR-4 | NC-2 |
| US-3 | 노드 소유자로서 **내 기계의 링 파일에 하네스 원문이 남는다는 것**을 알고 싶다. 에이전트가 자격증명을 도구 결과에 실으면 그것도 거기 남는다 | FR-2 | NC-3 |
| US-4 | 노드 소유자로서 파서가 못 읽은 줄이 있을 때 **그 줄을 원문으로** 보고 싶다. 파서가 틀렸을 때 사람이 판단할 수 있어야 한다 | FR-3 · FR-4 | CB1 (원문 토글 · `raw` 사건) |

**US-3 이 이 문서를 짓게 한 스토리다.** `requirements.md` 5.4 가 잔여 ③ 을
적었는데 **그것은 AI-DLC 산출물이고 노드 소유자가 읽는 자리가 아니다.**
사람이 모르는 잔여는 안 적은 잔여와 같다.

# 2. INVEST 와 사상

## 2.1 INVEST

```text
   Independent   열하나가 서로를 안 기다린다.  US-1 · US-2 는 화면 한 장,
                 US-5 · US-7 은 응답 하나, US-9 는 카드 하나다
   Negotiable    「무엇을 보는가」만 적고 어디에 어떻게 그리는지는 안 적는다 —
                 3절의 완료 조건이 그 자리를 Application Design 에 넘긴다
   Valuable      열하나 전부 사람이 잘못 읽는 것을 막는다.  값이 없는 것은 안 실었다
   Estimable     FR 열이 붙어 있어 어느 코드가 움직이는지 보인다
   Small         하나가 화면 한 줄 또는 응답 필드 하나다
   Testable      확인 열이 게이트 조각 이름이나 완료 조건 번호를 가리킨다.
                 가리킬 것이 없으면 그 스토리는 안 실었다
```

## 2.2 페르소나 사상

```text
   P1 노드 소유자    US-1 · US-2 · US-3 · US-4
   P2 계약 작성자    US-5 · US-6 · US-7 · US-8
   P3 진행자        US-9 · US-10 · US-11
```

**사상 안 된 페르소나 0 · 수용 기준 없는 스토리 0.**

## 2.3 FR 사상

```text
   FR-1  Decode                 US 없음 — 사람이 쓰는 표면을 안 만든다.  CB1 이 전부다
   FR-2  링 되살리기             US-1 · US-3
   FR-3  공용 파서               US-4 · US-6 · US-10
   FR-4  제어판 카드             US-1 · US-2 · US-4 · US-6
   FR-5  청크 푸시               US-7 · US-9
   FR-6  진행 로그 GET           US-5 · US-7 · US-8
   FR-7  현황판 카드             US-9
```

**FR-1 에 스토리가 0 인 것이 빠뜨린 것이 아니다.** 짝 팩의 U1(isolation)이
같은 자리였다 — 끊고 잇는 일이라 사람이 보는 표면이 없다.

# 3. 이 단계가 낳은 새 완료 조건 — 여섯

Q4 = A 에 따라 **스토리가 이것을 지고 `requirements.md` 는 안 고친다.**
Units Generation 이 유닛에 내린다.

| | 완료 조건 | 낳은 스토리 | 오늘 상태 |
|---|---|---|---|
| NC-1 | 마지막 사건 이후 경과가 화면에 보인다. 침묵과 정지가 화면에서 갈린다 | US-1 | 없다. `features.md` 3.1 이 「수십 초 침묵이 있을 수 있고 화면이 그 사실을 적는다」고 적었는데 게이트 조각이 0 이다 |
| NC-2 | 링이 감겨 앞이 잘렸음이 화면에 적힌다 | US-2 | **표시가 없다.** `handleTranscript` 가 `total` 을 이미 내는데 `page.go` 가 그것을 안 그린다 — 용량과 대면 잘림을 알 수 있다 |
| NC-3 | 링 파일에 하네스 원문이 남는다는 사실이 제어판 카드에 한 줄로 적혀 있다. 자리와 덮이는 시점을 함께 적는다 | US-3 | 없다. `requirements.md` 5.4 잔여 ③ 이 AI-DLC 산출물에만 있다 |
| NC-4 | 진행 파일이 상한에 닿았음이 응답과 화면에 적힌다. 「멈췄다」와 「끝났다」가 갈린다 | US-7 | 없다. `requirements.md` FR-5 가 「노드 로그에 남긴다」까지만 적었다 — 노드 로그는 계약 작성자가 안 본다 |
| NC-5 | `mediator-api` 의 `GET log` 절이 「봉인 전 응답은 원문이고 봉인 뒤는 선별본이다」를 적는다 | US-8 | 없다. `requirements.md` 11절이 그 절을 올리기로 했으나 내용에 이 문장이 없다 |
| NC-6 | 현황판 카드에 마지막 갱신이 언제였는지 보인다. 청크가 밀린 것과 단계가 멈춘 것이 갈린다 | US-9 | 없다. CB3 은 실패를 **한 번** 시키고 이어붙는 것만 잰다 — 계속 실패하는 경로를 아무도 안 잰다 |

**여섯 중 다섯이 같은 모양이다** — 「안 자라는 것」과 「끝난 것」을 사람이 구별할
수 있는가. 이 팩이 만드는 것이 **자라는 화면**이라 그 구별이 곧 이 팩의 오독
경로다. 게이트 일곱이 전부 「자란다」를 재고 「안 자란다」를 재는 조각이 0 이다.

# 4. 이 문서가 하류에 주는 것

```text
   Workflow Planning    이 단계가 돌았다는 사실과 새 완료 조건 여섯
   Application Design   NC-1 ~ NC-6 이 어느 화면의 어느 자리인가.
                        표시의 모양은 거기가 정한다 — 스토리는 「보인다」까지만 적었다
   Units Generation     스토리 열하나와 완료 조건 여섯을 유닛에 앉힌다.
                        배정 안 된 것이 0 임을 거기서 센다
   게이트                NC-1 ~ NC-6 은 CB 조각에 없다.  조각을 늘릴지
                        유닛 완료 조건으로 둘지는 Units Generation 이 정한다
```

# 5. 이 단계가 안 한 것

```text
   행복 경로 스토리      CB0 ~ CB6 이 잰다
   수용 기준 재작성      scene-gates.md 와 requirements.md 6절이 정본이다
   유닛 사상            유닛이 아직 없다.  Units Generation 의 몫
   requirements.md 수정  Q4 = A.  승인된 문서를 안 건드린다
   에픽 · 포인트 추정     이 저장소는 그것으로 진행을 안 잰다
```
