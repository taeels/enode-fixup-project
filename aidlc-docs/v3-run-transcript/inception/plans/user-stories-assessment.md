# User Stories Assessment — 트랜스크립트 (v3-run-transcript)

`user-stories.md` 의 Step 1 이 요구하는 판정이다. **짝 팩이 이 자리를 스킵했고
검증이 그것을 규칙 위반으로 셌다** — 그래서 이 회차는 판정을 문서로 남긴다.

---

## Request Analysis

```text
   원래 요청     하네스가 뱉는 것을 사람이 읽는다.  노드에서도, 중앙에서도
   사용자 영향   Direct.  화면 둘을 바꾼다 — 제어판 카드와 현황판 Run 상세
   복잡도        Complex.  여섯 패키지 · 사람 눈 게이트 둘 · 보안 잔여 셋
   이해관계자    노드 소유자 · 계약 작성자 · 진행자
```

## Assessment Criteria Met

**High Priority — 셋이 걸린다.**

- [x] **User Experience Changes** — 제어판의 트랜스크립트 카드가 바뀌고
      현황판에 없던 카드가 생긴다. 사람이 보는 것이 달라진다
- [x] **Multi-Persona Systems** — 셋이 서로 다른 것을 본다. 노드 소유자는 링을,
      계약 작성자는 `GET log` 를, 진행자는 두 화면과 봉인을 본다
- [x] **Complex Business Logic** — 봉인 전과 뒤의 내용이 다르고, 그 갈림이
      화면에 보여야 한다. 시나리오가 하나가 아니다

**Medium Priority — 둘이 더 걸린다.**

- [x] **Security Enhancements** — `requirements.md` 5.4 의 잔여 셋은 사람이
      「무엇이 어디에 남는가」를 아는가에 걸린다. 그것을 재는 게이트 조각이 0 이다
- [x] **Testing** — CB1 · CB4 가 사람 눈 게이트다. 사용자 수용 검증이 곧 판정이다

## Skip 사유에 걸리는 것이 있나

**없다.** 순수 리팩터링도, 고립된 버그 수정도, 사용자에게 안 보이는
인프라 변경도 아니다.

## Decision

**Execute User Stories**: Yes
**Depth**: minimal — 짝 팩과 같은 태도다.

**왜 minimal 인가.** `scene-gates.md` 의 조각 일곱이 수용 기준을 실행 명령으로
이미 적었고 그것이 판정 기준이다. 스토리가 그것을 다시 쓰면 약한 사본이 된다.

**그런데 조각 일곱이 안 재는 자리가 이 팩에 있다.** 일곱은 전부 **「값이 옳게
흐르는가」**를 재고, **「흐르지 않을 때 사람이 무엇을 보는가」**를 재는 조각이
0 이다. 짝 팩에서는 그 빈자리가 **저작 경로**(사람이 손으로 적는 자리)였다.
이 팩은 읽는 표면이라 저작 경로가 거의 없고, 빈자리가 다른 데 있다.

```text
   짝 팩의 빈자리   저작 경로와 오류 경로 — 사람이 잘못 적었을 때 무엇을 보는가
   이 팩의 빈자리   오독 경로와 침묵 경로 — 화면이 안 자랄 때 사람이 무엇을 보는가
```

**이 갈림이 이 단계가 값을 내는 이유다.** 봉인 뒤에 본문이 없는 것을 사람이
「에이전트가 아무 말도 안 했다」로 읽으면, 이 회차가 만든 화면이 거짓을 말한다.

## Expected Outcomes

```text
   ①  게이트가 안 재는 자리를 이름으로 만든다 — 그 자리가 곧 새 완료 조건이다
   ②  Units Generation 이 스토리를 유닛에 사상할 때 배정 안 된 스토리가
      0 임을 확인할 수 있다 (짝 팩의 절차와 같다)
   ③  보안 잔여 셋을 사람이 아는가를 스토리로 잰다.  requirements.md 5.4 가
      그것을 적었지만 화면에 보이는가는 안 적었다
```
