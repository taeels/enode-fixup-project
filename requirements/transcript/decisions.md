# 결정표 — 이미 정해진 것. 다시 논의하지 않는다

이 표는 `features.md` 의 미정을 **착수 전에 값으로 닫은 것**이다. 게이트에서는
확인만 한다. 새로 묻지 않는다.

**게이트 규칙 한 줄 — 권장을 벗어나면 근거를 적는다.**

```text
   1절   사용자가 확정한 것          값이다
   2절   팩이 채운 권장값            값이다.  벗어나면 근거를 적는다
   3절   보안 확장 아래서의 취급      SECURITY 규칙마다 처리를 미리 적었다
   4절   이월
   5절   앞 팩의 문장 중 대체하는 것   앞 팩의 파일은 고치지 않는다.  여기서 센다
   6절   정본에 되돌려 올리는 것
```

정본과 어긋나면 `enode-design/protocol/INVARIANTS.md` 가 이긴다 (`canon.md`).

```text
   정본이 이미 지는 값 — 팩이 고를 자리가 아니다

     Mediator 는 노드를 부르지 않는다          ADR-014 결정 2.  청크는 노드가 민다
     봉인되지 않은 것은 Record 가 아니다        I4.  진행 로그는 Record 가 아니다
     진행 상태에 판정 · 산출물 본문을 안 싣는다  ADR-025 §5
     logs/ 는 원문 그대로                       ADR-005.  파서는 읽을 뿐 바꾸지 않는다
```

# 1. 사용자가 확정한 것 (2026-09-11)

| 항목 | 값 | 근거 |
|---|---|---|
| 범위 | 사내 실측 후속을 팩 둘로 가른다. 이 팩은 트랜스크립트. 다른 팩은 `requirements/harness-components/` | 축이 둘이고 독립이다 |
| 제어판 트랜스크립트 | JSON 을 그대로 보이지 않는다. 파싱해서 읽을 수 있게 보인다 | 사용자 진술. 사내 실측 |
| Mediator 의 실시간 트랜스크립트 | **범위로 들인다.** 앞 회차의 기각을 되돌린다 | 사용자 진술 「사용하다 보니 꼭 필요한 기능」. `ADR-025` §7 ③ 의 여는 조건이 충족됐다 |
| 확장 opt-in | **security-baseline 켬.** resiliency-baseline · property-based-testing 끔 | 앞 회차의 선택을 그대로 잇는다 |

# 2. 팩이 채운 권장값

| 항목 | 권장값 | 근거 |
|---|---|---|
| 출력 형식 | `-p --output-format stream-json --verbose` | 실측 — print 모드의 stream-json 은 `--verbose` 를 요구한다. `Decode` 주석이 잡아 둔 자리 |
| 토큰 단위 | `--include-partial-messages` 를 켜지 않는다 | 메시지 단위면 1초 폴링에 충분하다. 줄 수가 줄어 링이 덜 감긴다. 앞 팩 `constraints.md` §5 의 「토큰 단위 중계 제외」와도 맞는다 |
| 봉투 | 마지막 `result` 줄. 봉투 파서(`ParseClaude` · `lastJSONObject`)는 안 바꾼다 | 마지막 JSON 객체를 집는 방식이 stream-json 의 마지막 줄에 그대로 맞는다 |
| 파서 패키지 | `internal/transcript`. 표준 라이브러리만. `enode` · `panel` · `api` 가 임포트한다 | 앞 팩 구조 불변식 「새 기능은 새 패키지」. 하나여야 화면이 안 갈린다 |
| 사건 종류 | `init` · `text` · `tool_use` · `tool_result` · `result` · `raw`. 명령 단계의 stdout · stderr 는 `text` | stream-json 의 `system/init` · `assistant` · `user`(tool_result) · `result` 에 대응한다. 낯선 줄은 `raw` 로 남겨 잃지 않는다 |
| 표시 규칙 | `text` 는 그대로. `tool_use` 는 이름과 입력 요약 200자. `tool_result` 는 앞 500자와 잘림 표시. `result` 는 사유 · 턴 · 비용 한 줄. `init` 은 도구 수 · MCP 서버 이름 · 모델 한 줄. `raw` 는 접힌 원문 | 읽는 화면이 셋이라 규칙을 한 곳에 둔다. 값은 화면이 아니라 파서가 든다 |
| 링 | 형식 · 크기 · 비우기 · 권한 전부 앞 팩 §6.2 · §6.3 그대로. 감겼으면 첫 개행 뒤부터 파싱 | 윈도우가 정한 모양을 안 건드린다. 내용만 NDJSON 이 된다 |
| 원문 토글 | 제어판과 현황판 둘 다 JSON 줄을 그대로 보는 토글이 있다 | 파서가 틀렸을 때 사람이 원문으로 판단할 수 있어야 한다 |
| 청크 주기 | 새 바이트가 있으면 2초마다. 64 KiB 가 쌓이면 즉시. 끝에는 꼬리만 | 광고 주기(60초)보다 짧고 1초 폴링과 어울린다. 값은 CB3 이 실측한다 |
| PUT 응답 | `200` 에 `{"bytes": <총 길이>}`. 노드가 그 값으로 오프셋을 맞춘다. 옛 노드는 본문을 안 읽으므로 그대로 돈다 | 이어 붙이기 뒤 연결이 끊기면 노드는 성공 여부를 모른다. 총 길이가 재동기화의 유일한 근거다 |
| 두 벌 방지 | 단계 끝의 `UploadLog` 전체 업로드를 꼬리 업로드로 바꾼다 | 안 바꾸면 도중 청크 + 끝의 전체로 로그가 두 벌이 된다 |
| 상한 | `MaxBlobBytes` 와 잘림 표시 그대로. 넘으면 청크를 멈추고 노드 로그에 남긴다 | 앞 팩과 같은 값. 새 상한을 안 만든다 |
| GET 라우트 | `GET /v1/runs/{run}/steps/{seq}/log?from=<바이트>&as=raw` 기본. `as=events` 면 파싱된 사건 배열. 헤더 `X-Enode-Log-Bytes` 에 총 길이. 파일이 없으면 총 길이 0 · 빈 본문. 없는 Run 은 `404` | 요청-응답이라 `ADR-025` §7 ③ 의 「표면의 성격」이 안 바뀐다. 파일이 없을 때 `404` 를 안 내는 이유 — 폴링하는 쪽이 「아직」과 「없다」를 가르기 쉽다 |
| GET 보호 | `GET /v1/runs` 와 같은 규칙 | 관측 표면의 선례를 그대로 쓴다 |
| 봉인과의 관계 | 진행 로그와 봉인 tar 의 `logs/NN-<단계>.log` 는 같은 파일이다. 봉인 뒤에도 GET 이 같은 것을 답한다. `GET record` 의 `409` 는 그대로 | `I4` 를 안 건드린다. `ADR-025` §5 의 선과 같다 |
| 제어판 「지난 것」 | tar 를 풀던 우회를 걷고 GET 라우트를 쓴다. `verdict` 는 Run 목록에서 | 앞 팩 §6.5 가 tar 를 고른 이유는 「Mediator 를 안 건드린다」였고 이 팩이 그 경계를 값으로 무른다 |
| 현황판 폴링 | Run 상세가 열려 있을 때만 2초. 목록 폴링(5초)과 별개 타이머 | 제어판 링 폴링(1초)과 같은 태도 — 열려 있을 때만 |
| 명령 단계 | 같은 경로다. stdout · stderr 원문이 청크로 올라가고 `text` 로 그려진다 | 링에 이미 명령 단계도 tee 하고 있다 |
| MCP 도구 | `run.log` 하나. 앞 팩 3.3.1 이 `main` 에 있을 때만. `GET` 을 감싸고 글자까지 같다 | `ADR-022` §9.3 「감싸기만 한다」. 없으면 이월 |

# 3. 보안 확장 아래서의 취급

`security-baseline` 이 켜져 있다. 규칙은 **차단성**이다. 규칙마다 처리를 미리 적는다.

```text
   SECURITY-01  전송 암호화     기존 코드 사실로 기록만.  수정 안 함
   SECURITY-03  로깅            기존 사실 기록 — 하네스 출력에 비밀이 찍힐 수 있고
                               오늘도 logs/ 에 원문이 봉인된다.  이 팩은 시점만
                               앞당긴다.  마스킹은 이월 (4절)
   SECURITY-07  네트워크        기존 코드 사실로 기록만.  새 포트 0.  라우트 하나
   SECURITY-08  접근 제어       새 표면에 적용.  GET log 는 GET /v1/runs 와 같은 보호.
                               제어판은 루프백 규칙 그대로.  판정을 싣지 않는다
   SECURITY-12  인증 · 자격증명  해당 없음 — 새 자격증명 0.  PUT 은 기존 토큰 규칙
```

**하지 말 것** — 로그를 보안 이유로 다듬는 것. 원문이 봉인이고 `ADR-005` 가 그것을
요구한다.

# 4. 이월 — 이번에 정하지 않는다

```text
   SSE · WebSocket            범위 밖.  폴링으로 족하고 표면의 성격이 안 바뀐다
   토큰 단위                  범위 밖.  메시지 단위로 족하다
   입력 스트림                 범위 밖.  되묻기는 ADR-032 그대로
   마스킹 · 검색 · 필터        막고 있는 값 — 무엇을 가릴지의 규칙
   트랜스크립트 구독 (MCP)     막고 있는 값 — 툴의 구독 표현.  폴링 도구로 대신한다
```

# 5. 앞 팩의 문장 중 이 팩이 대체하는 것

앞 팩의 파일은 고치지 않는다 — 그 회차의 기록이다. 어느 문장이 더는 값이
아닌지를 여기서 센다.

```text
   decisions.md §6.2 Q2   「하네스의 원문 stdout.  --output-format 을 안 건드린다」
                          -> 원문 stdout 은 그대로이나 형식이 stream-json 이다
   decisions.md §6.4      「stream-json 전환 이월」 -> 범위
                          「Mediator 중계 안 한다.  트랜스크립트는 노드 밖으로 안 나간다」
                          -> 청크 푸시와 폴링 GET.  토큰 단위 중계는 여전히 안 한다
                          「Mediator 의 변경 0」 -> 라우트 하나 · PUT 응답 하나
   decisions.md §5.4      「트랜스크립트 구독 이월」 -> 그대로 이월.  폴링 도구는 별개
   constraints.md §5      「Mediator 를 통한 토큰 단위 트랜스크립트 중계」 -> 그대로 제외.
                          메시지 단위 청크는 범위.  「SSE · WebSocket」 -> 그대로 제외
   enode-features.md 3.1.3 보안 요구 「트랜스크립트는 노드 밖으로 안 나간다」 -> 대체.
                          도는 동안의 원문이 Mediator 로 간다.  끝난 뒤 가던 것과 같은 파일이다
   scene-gates.md CP6     「보류」로 남은 눈 검증 -> 이 팩의 CB1 이 그것을 잰다
```

# 6. 정본에 되돌려 올리는 것

이 회차가 끝나면 진행자가 `enode-design` 에 올린다.

```text
   ADR-025 §7 ③   실행 중 로그를 연다.  폴링.  여는 조건 충족 일자와 근거(사내 실측).
                  「스트리밍이면 표면의 성격이 바뀐다」 -> 폴링이라 안 바뀐다
   mediator-api   GET /v1/runs/{run}/steps/{seq}/log 절.  PUT 의 응답 본문
   agent-runtime  R3 · R4 — Decode 가 사건을 배출한다.  stream-json 이 기본 형식이다
```
