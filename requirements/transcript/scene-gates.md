# 장면 조각 게이트 — 진행의 단위는 유닛 완료가 아니라 장면 완주다

장면 하나를 조각 일곱으로 잘랐다. **조각마다 실행 명령이 있고, 조각 게이트가
초록이 아니면 다음 유닛을 착수하지 않는다.** 이것은 요구사항의 **수용 기준**이다.

집행자는 **그 유닛을 구현하지 않은 사람**이다. 이 팩의 조각은 전부 스크래치
함대와 실제 하네스 하나로 돈다 — 사내 MCP 가 필요 없다.

---

# 1. 장면 — 실측자가 계약을 던지고 두 화면을 연다

```text
   ①  에이전트 단계 둘과 명령 단계 하나가 있는 계약을 낸다.  첫 에이전트 단계는
      도구를 여러 번 부르는 일이다 (파일 몇 개를 읽고 하나를 쓴다)
   ②  제어판을 연다.  단계가 끝나기 전에 카드에 문장이 흐른다.  도구 호출이
      이름으로 보이고 그 결과가 그 아래 접혀 있다
   ③  같은 시각 현황판의 Run 상세를 연다.  같은 문장이 흐른다
   ④  단계가 끝난다.  사유 · 턴 · 비용 한 줄이 붙는다
   ⑤  다음 단계의 첫 줄이 오면 제어판 카드가 갈린다.  현황판은 단계마다 카드라 갈리지 않는다
   ⑥  Run 이 끝난다.  제어판의 지난 작업에서 그 Run 을 누르면 같은 모양으로 읽힌다.
      runctl record 로 푼 로그와 GET 의 마지막 답이 같은 바이트다
   ⑦  원문 토글을 켜면 JSON 줄이 그대로 보인다
```

② 와 ③ 이 이 장면의 가치다. **도는 동안 사람이 읽을 수 있고, 노드 앞에 있든
중앙에 있든 같은 것을 본다.**

# 2. 조각 일곱

| | 조각 | 확인 (실동작) | 집행자 | 대상 | 재는 기능 | 먼저 서는 기능 |
|---|---|---|---|---|---|---|
| CB0 | 기동이 안 깨졌다 | 앞 팩의 CP0 그대로. 기존 라우트 수가 하나 늘어 있다 | 기계 | 스크래치 | 바닥 | (없음) |
| CB1 | 흐른다 | 계약을 던지고 제어판을 연다. **단계가 끝나기 전에** 읽을 수 있는 문장이 흐르고 도구 호출이 이름으로 보인다. 512 KiB 를 넘겨도 안 깨지고 첫 줄이 잘린 채로도 파싱된다. 다음 단계 첫 줄에 갈린다. 원문 토글이 JSON 줄을 보인다 | 사람 | 스크래치 | 3.1 · 3.2 · 3.3 | (없음) |
| CB2 | 읽힌다 | 끝난 Run 을 제어판 지난 작업에서 누른다. 같은 파서의 같은 모양이다. 출처가 GET 이고 tar 를 안 푼다. `verdict.checks` 는 그대로 보인다 | 사람 | 스크래치 | 3.3 · 3.5 | CB1 |
| CB3 | 올라간다 | 도는 동안 `curl` 로 GET log 를 두 번 부르면 총 길이가 늘어 있다. PUT 을 한 번 실패시켜도(Mediator 를 잠깐 멈춘다) 다음 청크가 이어 붙고 두 벌이 안 생긴다. 봉인 뒤 tar 의 로그와 GET 의 답이 같은 바이트다. `GET record` 는 봉인 전 `409` 그대로 | 사람 | 스크래치 | 3.4 · 3.5 | CB1 |
| CB4 | 보인다 (중앙) | 현황판 Run 상세의 단계 카드에 제어판과 같은 문장이 같은 시각 흐른다. 목록 폴링을 멈춰도 카드는 자란다 — 별개 타이머다. 원문 토글이 있다 | 사람 | 스크래치 | 3.6 | CB3 |
| CB5 | 도구 (조건부) | `runctl mcp` 가 `main` 에 있을 때만. `run.log` 의 답이 GET 과 글자까지 같다. 없으면 보류가 아니라 「해당 없음」으로 적는다 | 사람 | 스크래치 | 3.7 | 앞 팩 3.3.1 |
| CB6 | 한 장면 | 1절 ① ~ ⑦ 을 끝까지 | 사람 | 스크래치 | 전부 | 전부 |

**CB1 이 이 팩의 이유다.** 앞 팩의 CP6 이 「끝나기 전에 글자가 흐른다」를 눈으로
안 보고 닫혔고 사내 실측이 그 첫 눈이었다. CB1 은 사람이 실제 하네스로 보지
않으면 초록이 아니다.

## 2.1 화면 검증

```text
   CB1   S3   트랜스크립트 카드에 문장 · 도구 이름 · 접힌 결과.  원문 토글.
              밀렸다는 표시.  데몬 로그 카드는 그대로 옆에 있다
   CB2   S3   지난 작업에서 누른 Run 이 같은 모양.  아직 안 끝난 Run 은 「봉인 전」이 적혀 있다
   CB4   S2   Run 상세에 단계마다 카드.  도는 단계는 자라고 끝난 단계는 사유 한 줄로 닫힌다.
              그 카드가 그래프와 목록을 가리지 않는다
```

화면 자리는 이 회차의 새 `.pen` 이다 — 진행자가 그린다 (`CLAUDE.md` 의 layering).

# 3. 조각마다의 명령

값은 시작값이다. 유닛의 Code Generation 계획이 이것을 실제 스크립트로 굳힌다.

```text
   게이트를 돌리기 전에

     eval "$(scripts/testdb.sh)"
     export M=http://<Mediator 주소>:8080
     export T=<bootstrap 토큰>
     jq 가 필요하다.  로그인된 claude 가 있는 노드 하나
```

```text
   CB0   앞 팩의 CP0 명령 그대로.  grep -c 'mux.HandleFunc' internal/api/api.go 가 하나 늘었다

   CB1   runctl example agent > a.json  (도구를 여러 번 부르는 프롬프트로 고친다)
         runctl submit a.json
         enodectl serve <name> 로 제어판을 연다 -> 단계가 끝나기 전에 문장이 흐른다
         tool_use 의 이름이 보이고 결과가 접혀 있다
         512 KiB 를 넘기는 프롬프트(큰 파일을 여러 번 읽게 한다) -> 안 깨진다
         단계가 끝난다 -> 사유 · 턴 · 비용 한 줄
         다음 단계의 첫 줄 -> 카드가 갈린다
         원문 토글 -> JSON 줄

   CB2   지난 작업에서 그 Run 을 누른다 -> 같은 모양.  브라우저 네트워크 탭에
           GET /v1/runs/<id>/record 가 없고 .../log 가 있다

   CB3   도는 동안
         curl -sI -H "Authorization: Bearer $T" "$M/v1/runs/<id>/steps/1/log" | grep X-Enode-Log-Bytes
         잠시 뒤 다시 -> 값이 늘어 있다
         curl -s -H "Authorization: Bearer $T" "$M/v1/runs/<id>/steps/1/log?as=events" | jq '.[0]'
         Mediator 를 10초 멈췄다 켠다 -> 노드 로그에 실패 한 줄, 다음 청크가 이어 붙는다
         끝난 뒤
         runctl record <id> -o /tmp/r.tar && mkdir -p /tmp/rx && tar -xf /tmp/r.tar -C /tmp/rx
         curl -s -H "Authorization: Bearer $T" "$M/v1/runs/<id>/steps/1/log" | cmp - /tmp/rx/logs/01-*.log
         curl -i ... /record 를 봉인 전에 부르면 409

   CB4   현황판에서 그 Run 을 연다 -> 단계 카드가 자란다
         브라우저 네트워크 탭에서 목록 폴링을 막아도 카드가 자란다

   CB5   runctl mcp 가 있으면: run.log 의 답 == curl 의 답 (diff 로 센다)
         없으면 「해당 없음」

   CB6   1절 그대로
```

# 4. 게이트가 빨간 채로 다음 유닛을 착수하면

착수하지 않는다. 빨간 이유가 그 유닛 밖이면 진행자가 이 회차의 `audit.md` 에
적고 조각을 **보류**로 표시한 뒤 넘어간다. **보류는 통과가 아니다.**

**눈 검증을 보류로 넘기지 않는다.** CB1 · CB4 는 사람이 실제 하네스로 보는 것이
곧 게이트다. 코드 게이트가 초록이라는 것으로 대신하지 않는다 — 앞 팩의 CP6 이
정확히 그렇게 닫혔고 이 팩이 그 대가다.
