# 트랜스크립트 팩 — 하네스가 뱉는 것을 사람이 읽는다. 노드에서도, 중앙에서도

사내 실측(2026-09-11) 후속 둘 중 하나다. 다른 하나는
`requirements/harness-components/` 이고 둘은 독립이다. 이 팩은 **하네스 출력을
읽을 수 있는 모양으로, 단계가 끝나기 전에, 제어판과 현황판 둘 다에** 보이게 한다.

```text
   decisions.md         이미 정해진 값.  앞 팩의 문장 어느 것을 대체하는지도 여기
   scene-gates.md       장면 조각 게이트 CB0 ~ CB6.  이 문서의 수용 기준이다
   canon.md             enode-design 과의 연결.  어긋나면 INVARIANTS 가 이긴다
   constraints.md       안 만드는 것 · 구조 불변식 · 접점
```

## 1. 개요

### 1.1 무엇을 만드나

앞 팩(루트의 다섯 파일)의 3.1.3 이 트랜스크립트를 제어판에 들였다. 링 파일에
tee 하고 카드가 1초로 읽는다. 사내 실측이 둘을 봤다.

```text
   제어판       카드가 도는 동안 비어 있다.  단계가 끝나면 JSON 한 줄이 통째로 뜬다.
               사람이 읽을 수 없다
   현황판       실시간 트랜스크립트가 없다.  앞 회차가 기각했는데 써 보니 꼭 필요하다
```

### 1.2 왜 그런가 — 원인은 결정에 있다

링은 하네스의 **원문 stdout** 을 흘린다 (앞 팩 `decisions.md` §6.2 Q2). 어댑터는
`claude -p --output-format json` 으로 띄운다. **이 형식은 프로세스가 끝날 때 결과
봉투 하나만 찍는다.** 그래서 에이전트 단계가 도는 동안 링에는 아무것도 안 들어오고,
끝나면 개행이 이스케이프된 JSON 한 줄이 들어온다. 명령 단계만 실시간으로 보인다.

```text
   앞 팩이 정한 것            이 팩이 보는 것
   §6.2 Q2  원문 stdout       json 형식의 원문은 끝에 한 줄이다.  실시간이 아니다
   §6.4     stream-json 이월   그 이월이 곧 「도는 동안 0 줄」의 원인이다
   §6.4     Mediator 중계 없음  중앙에 실시간이 없는 이유
   CP6      눈 검증 보류        「끝나기 전에 글자가 흐른다」를 한 번도 안 봤다
```

**CP6 의 눈 검증이 보류로 남은 채 유닛이 닫혔다.** 코드 게이트는 초록이었고,
「흐른다」는 사람이 실제 하네스로 봐야 하는 것이었는데 사내 실측이 그 첫 눈이
됐다. 이 팩의 게이트는 눈 검증을 보류로 넘기지 않는다 (`scene-gates.md` 4절).

### 1.3 정본이 열어 둔 자리

`ADR-025` §7 ③ 은 실행 중 로그를 순연하면서 여는 조건을 적었다 — **「로그를
실행 중에 봐야 하는 사례가 나올 때」**. 그리고 「여는 순간 스트리밍이냐 폴링이냐가
따라오고, 스트리밍이면 표면의 성격이 바뀐다」고 덧붙였다. 사내 실측이 그 사례이고,
이 팩은 **폴링**을 고른다 — 표면의 성격(전부 요청-응답)이 안 바뀐다.

되돌리는 절차는 앞 팩이 두 번 쓴 것과 같다 (Mediator MCP · 트랜스크립트). 진행자
권한이고 근거를 `decisions.md` 에 남긴다. 대체되는 문장은 `decisions.md` 5절이 센다.

### 1.4 정본

`canon.md`. 설계 정본은 서브모듈 `enode-design/` 이고 어긋나면
`protocol/INVARIANTS.md` 가 이긴다.

### 1.5 가치의 고정점

`scene-gates.md` 의 장면 하나다 — **계약을 던지고 제어판과 현황판을 열면 단계가
끝나기 전에 읽을 수 있는 문장이 흐르고, 도구 호출이 이름으로 보이며, 끝난 뒤에도
같은 모양으로 읽힌다.** 완결성은 그 장면(CB6)이 끝까지 도는가로 판단한다.

## 2. 용어

```text
   사건         하네스가 stream-json 으로 내는 줄 하나.  system · assistant · user · result
   봉투         마지막 사건(result).  사유 · 턴 · 비용 · 세션.  HarnessResult 의 재료
   링           노드의 고정 크기 트랜스크립트 파일 (앞 팩 §6.3).  형식은 안 바뀐다
   청크         노드가 단계 도중 Mediator 에 올리는 새 바이트
   진행 로그    봉인 전에 Mediator 디스크에 쌓이는 logs/NN-<단계>.log.  Record 가 아니다
   파서         사건 줄을 화면이 그릴 모양으로 바꾸는 Go 패키지 하나.  셋이 쓴다
```

## 3. 기능 요구사항

### 3.1 stream-json 전환 — 하네스를 배치가 아니라 스트림으로 부른다

**목적**: 도는 동안 사건이 나온다. 봉투는 마지막 줄로 그대로 온다.

**기능 요구사항**:
- 어댑터 인자를 `-p --output-format stream-json --verbose` 로 바꾼다. **print
  모드의 stream-json 은 `--verbose` 를 요구한다** — 실측 (`claude` 2.1.266,
  `Error: When using --print, --output-format=stream-json requires --verbose`)
- `--include-partial-messages` 는 켜지 않는다. 메시지 단위면 1초 폴링에 충분하고
  링이 덜 감긴다. 긴 응답 중에는 수십 초 침묵이 있을 수 있고 화면이 그 사실을 적는다
- `Decode` 가 줄 단위로 읽어 사건을 배출한다. `HarnessResult` 는 마지막 `result`
  줄에서 그대로 나온다 — 봉투 파서는 출력 끝의 마지막 JSON 객체를 집으므로 안
  바뀐다. 낯선 줄은 버리지 않고 `raw` 사건으로 넘긴다
- 명령 단계는 그대로다 — stdout · stderr 원문이 링과 로그로 간다

**기존 코드에서 확인된 것**: `Decode` 의 주석이 이미 「배치는 스트리밍의 퇴화형이다.
stream-json 으로 바꿔도 이 시그니처는 안 바뀐다」로 자리를 잡아 두었다. 사건
종류는 `final` 하나였고 「stream-json 을 켤 때 실물을 보고 늘린다」였다 — 지금이
그때다.

**수용 기준**: CB1. 에이전트 단계가 도는 동안 링에 줄이 쌓인다. 끝난 뒤
`HarnessResult` 의 사유 · 턴 · 비용이 전과 같이 채워진다.

### 3.2 공용 파서 — 하나를 셋이 쓴다

**목적**: 도는 것(링) · 지난 것(로그) · 중앙(진행 로그)이 같은 모양으로 읽힌다.
파서가 둘이면 화면이 갈린다.

**기능 요구사항**:
- 새 패키지 `internal/transcript`. 표준 라이브러리만 임포트한다. `enode`(Decode) ·
  `panel` · `api` 가 이것을 임포트한다. 이 패키지는 셋 중 어느 것도 임포트하지 않는다
- 사건 종류와 화면 표시 규칙은 `decisions.md` 2절 — `init`(도구 수 · MCP 서버 ·
  모델 · 버전) · `text` · `tool_use`(이름과 입력 요약) · `tool_result`(길이 상한) ·
  `result`(사유 · 턴 · 비용) · `raw`(파싱 실패 줄의 원문)
- 링이 감겨 첫 줄이 잘렸으면 첫 개행 뒤부터 읽는다. 총량이 용량 안이면 처음부터
- 사용자 메시지 안의 `tool_result` 는 그 도구 호출에 붙여 그린다. 붙일 호출이
  없으면 그대로 사건이다
- 파서는 마스킹을 하지 않는다 (`constraints.md` 5). 원문 그대로가 봉인이다

**수용 기준**: CB1 · CB2. 같은 로그를 링에서 읽든 `record` 에서 읽든 같은 사건
열이 나온다 — 테스트가 그것을 센다.

### 3.3 제어판 카드 — 도는 것과 지난 것

**목적**: 노드 소유자가 자기 기계에서 읽는다.

**기능 요구사항**:
- 「하네스 트랜스크립트」 카드가 파싱된 사건을 그린다. 원문 토글이 있어 JSON 줄을
  그대로 볼 수 있다. 1초 폴링 · 세대가 바뀌면 비우기 · 밀렸다는 표시는 앞 팩 그대로
- 「지난 작업」의 봉인된 트랜스크립트는 같은 파서를 거친다. 출처는 3.5 의 GET
  라우트로 바꾼다 — tar 를 통째로 풀어 로그만 꺼내던 우회를 걷는다. `verdict`
  는 지금처럼 Run 목록에서 온다
- 데몬 로그 카드는 그대로 있다. 둘이 다른 물건임이 화면에서 보인다

**수용 기준**: CB1 · CB2.

### 3.4 노드가 청크를 올린다 — 방향은 노드에서 Mediator 로

**목적**: 중앙이 도는 동안의 출력을 갖는다. Mediator 는 노드를 부를 수 없다
(`ADR-014`) — 노드가 민다.

**기능 요구사항**:
- 이미 있는 `PUT /v1/runs/{run}/steps/{seq}/log` 를 쓴다. 서버의 `AppendLog` 가
  이어 붙이기이므로 단계 도중 여러 번 올려도 같은 파일이다. **새 라우트 0**
- 노드는 링에 쓰는 것과 같은 tee 한 겹에서 새 바이트를 모아 올린다. 주기와
  크기는 `decisions.md` 2절. 끝에는 남은 꼬리만 올린다 — 지금처럼 끝에 전체를
  한 번 더 올리면 두 벌이 된다
- PUT 응답이 그 파일의 **총 길이**를 돌려주고 노드가 그 값으로 자기 오프셋을 맞춘다.
  실패한 청크는 다음에 이어 보낸다. 실패가 실행이나 링을 막지 않는다
- 상한(`MaxBlobBytes`)과 잘림 표시는 오늘 그대로다. 상한을 넘으면 청크를 더
  올리지 않고 노드 로그에 남긴다

**기존 코드에서 확인된 것**: `UploadLog` 는 단계 끝에 한 번, 전체 버퍼를 올린다.
`putLog` 는 봉인된 Run 에 `410` 이고 봉인 전에는 언제나 받는다 — 도중 호출을
막는 것이 없다.

**보안 요구사항**: 하네스 출력에 비밀이 찍힐 수 있다는 것은 오늘도 참이다 —
`logs/` 에 원문이 봉인된다. 이 팩은 시점만 앞당긴다. 기록만 하고 마스킹은
이월이다 (`decisions.md` 3절).

**수용 기준**: CB3. 도는 동안 총 길이가 늘고, 봉인 뒤 파일 크기가 마지막 총
길이와 같다.

### 3.5 Mediator 가 진행 로그를 낸다 — 폴링 GET 하나

**목적**: 현황판과 제어판과 도구가 같은 것을 읽는다. 요청-응답이라 표면의 성격이
안 바뀐다.

**기능 요구사항**:
- `GET /v1/runs/{run}/steps/{seq}/log?from=<바이트>` **신규**. 응답은 그 오프셋부터의
  원문이고 헤더에 총 길이를 싣는다. `as=events` 면 3.2 의 파서를 거친 사건 배열이다
- **봉인 전에도 답한다.** 이것은 Record 가 아니다 — `ADR-025` §5 가 진행 상태에
  그은 선과 같다. `GET record` 의 `409` 는 그대로다. 봉인 뒤에도 같은 파일을 읽으므로
  답이 바뀌지 않는다
- 아직 파일이 없으면 총 길이 0 에 빈 본문이다. 없는 Run 은 `404`
- 보호 규칙은 `GET /v1/runs` 와 같다. 판정을 싣지 않는다 (`ADR-065` 의 선)
- `api.go` 는 등록 줄 하나만 는다. 핸들러는 새 파일이다

**수용 기준**: CB3 · CB2. `curl` 로 도중에 두 번 부르면 총 길이가 늘어 있다.
`record` 의 tar 안 로그와 마지막 응답의 바이트가 같다.

### 3.6 중앙 현황판 — Run 상세의 단계 카드

**목적**: 함대를 보는 사람이 도는 단계의 출력을 그 자리에서 읽는다.

**기능 요구사항**:
- Run 상세에 단계마다 트랜스크립트 카드. 도는 단계는 폴링으로 자라고, 끝난
  단계는 한 번 읽는다. 간격은 `decisions.md` 2절 — 목록 폴링(5초)과 별개 타이머다
- 표시 규칙은 제어판과 같다 (3.2). 원문 토글이 있다
- 화면은 이 회차의 새 `.pen` 으로 진행자가 그린다 — Run 상세 안의 카드 하나이므로
  S2 의 확장이다 (`design/README.md` 의 규칙)

**수용 기준**: CB4. 제어판에 흐르는 문장이 같은 시각 현황판에도 흐른다.

### 3.7 Mediator MCP 도구 `run.log` — 조건부

**목적**: 사용자 Claude 가 같은 것을 읽는다.

**기능 요구사항**: 앞 팩의 3.3.1(`runctl mcp`)이 `main` 에 있을 때만 도구 하나를
더한다 — `GET .../log` 를 감싼다. 구독이 아니라 폴링이라 앞 팩 §5.4 의 「구독
표현」 문제를 안 건드린다. 3.3.1 이 없으면 이월이다.

**수용 기준**: CB5. 도구의 답이 `GET` 과 글자까지 같다.
