# 정본 — `enode-design` 과 이 팩의 연결

설계 정본은 이 저장소의 서브모듈 `enode-design/` 이다. **어긋나면
`enode-design/protocol/INVARIANTS.md` 가 이긴다.** 이 팩의 문서는 정본을
요약하거나 값을 채운 것이지 정본을 대체하지 않는다.

```text
   서브모듈 고정       gitlink 이 진다.  git ls-tree HEAD enode-design 이 답한다
   정본과의 거리       cd enode-design && git rev-list --count HEAD..origin/main
                       0 이 아니면 이 문서가 낡은 것이다
   갱신                git submodule update --remote 는 진행자만.  갱신하면 이 문서의
                       1절 표와 3절을 다시 본다
```

# 2. 정본이 코드와 어긋나 있는 자리

**`ADR-065` 의 구현은 정본 구현 저장소의 병합되지 않은 가지
`feat/runaway-dashboard-observation` 에 있고 `main` 에는 없다.** 정본이 그
사실을 스스로 적는다 (2026-09-04 정정). 그래서 이 저장소의 코드에
`GET /v1/nodes` 가 없다. 라우트는 15개 그대로다. 구현은 정본의 병합되지
않은 가지에 있으나 **이 팩은 그 가지를 참조하지 않는다** — 이 저장소의
`main` 이 보는 것만 본다. 중앙 현황판은 `ADR-065` §2 의 응답 모양에서
새로 만든다.

**커밋을 글자로 박지 않는다.** 이 저장소는 정본에서 갈라져 나왔고 `upstream`
원격이 그것을 가리킨다. 「정본과 얼마나 떨어졌나」는 문서가 아니라
`git log HEAD..upstream/main` 이 답한다 — 문서에 적으면 그 줄이 조용히
낡는다. 설계 정본과의 거리도 같다. 머리의 명령이 답한다.

# 3. 정본 쪽에서 착지한 것 — 이 팩이 딛고 선 개정 셋

이 팩의 2판이 「정본에 먼저 들어가야 한다」로 적었던 셋이 2026-09-04 에 전부
들어왔다. 지금은 선행 조건이 아니라 **이 팩이 딛는 바닥**이다.

```text
   ADR-065 개정      GET /v1/nodes 노드 항목에 draining 이 있다.  값은 "" ·
                     graceful · at-boundary 이고 소유자 정책의 복사본이다.
                     중앙 현황판의 draining 배지가 이 필드를 읽는다

   ADR-063 개정      §2.1 이 두 모드를 갈라 적는다 — graceful 은 Run 을 죽이지
                     않고, at-boundary 는 놓인 Run 을 취소 경로로 닫는다
                     (Run 전체가 FAILED · 사유 drain:<node_id>)

   ADR-063 · 064     둘 다 결정이다.  ADR-063 §4 의 미결 넷과 ADR-064 §6 의
                     크래시 복구가 정본 안에서 닫혔다
```

**정본 쪽에 남은 선행 작업은 없다.** 거리는 1절 머리의 명령이 답한다.

# 4. 이 팩이 정본에 더하는 것 (역방향 요약)

**둘이다.** 2판이 다섯을 들었는데 넷은 2026-09-04 에 정본이 스스로 받았고
(3절), 하나가 남아 있다. 3판이 하나를 더했다. 둘 다 이 회차가 끝나면 올린다.

```text
   호스트 제어판의 위치 · 바인딩 · 포트            decisions.md 1 · 2절
                                                  ADR-063 §3.3 이 「기본값이 안전한
                                                  쪽」만 정했고 포트와 바인딩 주소는
                                                  안 정했다

   QUEUED 가 무엇을 기다리는지                     ADR-069.  글은 정본 저장소의
                                                  adr/ 에 있고 상태도 결정이다.
                                                  mediator-api 의 GET /v1/runs/{id}
                                                  절만 아직 그것을 안 받았다
```

**`ADR-069` 는 다른 것과 상태가 다르다.** 값이 미정이라 밖에 있는 것이 아니라
**글까지 써서 정본 저장소에 올린 것**이고 상태가 이미 결정이다. 그래서 이 팩은
그것을 딛고(1절 표) 게이트도 그것을 잰다(`scene-gates.md` CP2 · `enode-features.md`
3.1.1). 남은 것은 `protocol/mediator-api.md` 의 `GET /v1/runs/{id}` 절이 `requires`
를 받아 적는 것 하나뿐이다.

**정본이 이미 받은 넷은 여기 없다.** 찾으려면 그 자리다 —
`INVARIANTS` §2 (전이 · 202) · `ADR-063` §2.1 과 §4 (drain 두 모드 · 해제 ·
통보) · `mediator-api` §2 (`GET /v1/runs`) · `ADR-064` §6 (크래시 복구).
