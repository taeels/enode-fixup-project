# 결정표 — 이미 정해진 것. 다시 논의하지 않는다

이 표는 `enode-features.md` 의 미정을 **착수 전에 값으로 닫은 것**이다.
게이트에서는 확인만 한다. 새로 묻지 않는다.

**게이트 규칙 한 줄 — 권장을 벗어나면 근거를 적는다.** 벗어나는 것은
허용이다. 근거 없이 벗어나는 것이 금지다.

```text
   1절   사용자가 확정한 것          값이다.  게이트에서 묻지 않는다
   2절   팩이 채운 권장값            값이다.  벗어나면 근거를 적는다
   3절   보안 확장 아래서의 취급      SECURITY 규칙마다 처리를 미리 적었다
   4절   이월                        이번에 정하지 않는다.  물어도 답이 「이월」이다
   5절   범위에 들어온 것             이월이던 것을 되돌린 자리.  근거를 함께 적는다
   6절   범위에 들어온 것 둘째         트랜스크립트 (2026-09-06)
   7절   범위에 들어온 것 셋째         되묻기 (2026-09-08)
```

정본과 어긋나면 `enode-design/protocol/INVARIANTS.md` 가 이긴다
(`canon.md`).

```text
   정본이 이미 지는 값 — 팩이 고를 자리가 아니다

     GET /v1/nodes 의 draining      ADR-065 §2 (2026-09-04 개정) ·
                                    mediator-api.md GET /v1/nodes
     GET /v1/runs 의 응답 모양       ADR-064 §4 · mediator-api.md GET /v1/runs
     QUEUED 크래시 복구             ADR-064 §6
     dry-run 은 draining 을 안 본다  ADR-063 §6

   넷은 이 팩이 값을 준 뒤 정본이 받아 적은 것이다 (ADR-063 §4 머리).
   지금은 정본이 지므로 2절의 「벗어나면 근거를 적는다」가 안 걸린다 — 벗어날
   수 없다.
```

# 1. 사용자가 확정한 것 (2026-09-04)

| 항목 | 값 | 근거 |
|---|---|---|
| 범위 | MVP 넷 — 중앙 현황판 · 대기열 · drain · 호스트 제어판. 그리고 `scene-gates.md` 의 장면 절단면. **5절이 2026-09-05 에 다섯째(Mediator MCP)를, 6절이 2026-09-06 에 여섯째(트랜스크립트)를 더했다 — 이 행은 그날의 기록이므로 고치지 않는다. 지금 세는 값은 `enode-features.md` 4절의 일곱이다** | 이틀 예산. 넷이 `dhseo` 장면 하나를 만든다 |
| 제어판 서버 위치 | `enodectl serve` 별도 프로세스. 새 실행파일 없음 | 멈춘 데몬을 `start` 하려면 데몬 밖에 있어야 한다. `packaging/` 비용 회피. 차단 게이트 하나가 여기 걸린다 — `ci.yml:479` 가 `enodectl.exe` 의 `net/http` T 심볼을 50, `crypto/tls` 를 10 으로 막고 `continue-on-error` 가 없다. 지금 값은 6 과 1 이다. `serve` 가 그 실행파일 안에서 HTTP 서버를 직접 부르면 넘는다 (앞 회차 실측 39배 · 14배). 서버를 별도 실행 경로 뒤에 두는 것이 그 게이트를 넘기는 방법이고 `cmd/enodectl/setup.go` 가 같은 모양을 보인다 |
| drain 표면 | 노드 로컬 정책 파일이 정본. 데몬이 광고 직전에 읽어 광고에 실어 보내고, 중앙은 후보에서 빼고 광고 응답으로 통보한다. **중앙 라우트 신설 없음** | `ADR-042` 방향. 소유의 증거가 「그 기계의 파일을 쓸 수 있다」로 닫힌다. 중앙 라우트로 받으면 토큰만 있으면 남의 노드를 뺄 수 있다 |
| 정책 저장 | 정본은 노드의 파일. 중앙은 광고로 받은 복사본을 `nodes` 열에 둔다 — 현황판과 매칭이 그것을 읽는다 | drain 표면에서 따라온다. `UpsertAdvert` 가 정책도 갱신한다 |
| 정책 파일 위치 · 형식 | 모델 몫 — Functional Design 에서 정한다. 기존 `enode` 설정 파일 옆, 같은 형식(yaml) | 사람이 고를 값이 아니다 |
| drain 기본 모드 | `graceful` | 놀라움이 적다. `at-boundary` 로 올리는 것은 소유자의 명시다. CP3 는 `at-boundary` 를 명시해서 돈다 (`ADR-063` §4) |
| drain 중 광고 | 계속 보낸다. `draining` 을 실어서 | 안 보내면 중앙이 draining 을 모르고 통보 경로가 끊긴다. 현황판에 「있는데 안 빌려준다」로 보여야 한다 (`ADR-063` §4) |
| drain 해제 | 소유자가 명시적으로 푼다. 도는 Run 이 끝나도 자동으로 안 풀린다. 푸는 순간 후보로 돌아가고 대기 Run 이 집을 수 있다 | 정책은 만료되지 않는다 (`ADR-063` §2). 자동 복귀는 「돌려받았다」를 무효로 만든다 |
| `at-boundary` 의 뜻 | 도는 단계는 끝까지 간다. 결과를 보고한 뒤 임대를 놓고 더 집지 않는다. **놓인 Run 은 취소 경로로 종료한다** — 끝난 단계의 산출은 Record 에 남고, 남은 단계는 새 Run 으로 다시 낸다. 닫는 쪽은 Mediator — `postResult` 끝에서 그 노드가 `at-boundary` 면 `store.Cancel(run, "drain:<node_id>")`. 다중 노드 Run 도 Run 전체가 `FAILED` 다 | 단계 도중에 끊으면 선점이다 (`INVARIANTS` §2 재개 없음). 회수당하고도 죽지 않는 것은 `ADR-064` §3.4 — 이월. 새 신호를 만들지 않고 기존 취소 경로를 쓴다. `ADR-063` §2.1 이 2026-09-04 에 그 문장을 `graceful` 로 한정하고 `at-boundary` 를 갈라 적었다. 이 행은 그 개정의 근거였고 지금은 정본이 진다 (`ADR-063` §2.1 · `INVARIANTS` §2 의 `* -> FAILED` 행) |
| 대기 상한 | 없다. `QUEUED` 는 무기한. 빠져나가는 길은 `cancel` 뿐 | 상한은 정책이고 정책 틀은 안 만든다 (`constraints.md` §2). drain 무기한 x 대기 무기한의 상호작용은 CP3 가 실동작으로 덮는다 (`ADR-064` §5) |
| `at-boundary` 지연 상한 | 없다. 바닥(도는 단계의 남은 시간 + 광고 주기)이 곧 값 | 상한을 두면 단계 도중에 끊어야 한다. 더 급하면 소유자가 제어판에서 `stop` 한다 — 그쪽이 명시적 폐기다 (`ADR-063` §4) |
| 대기 응답 코드 | `202 Accepted` | `201` 은 「만들었다」, `202` 는 「받았고 나중에」. `QUEUED` 의 뜻과 맞다 |
| `READY` 상태 | 만들지 않는다 | `INVARIANTS` §1.2 에서 `READY` 와 `QUEUED` 는 같은 순간의 두 이름이다 (`ADR-064` §1.1) |
| 임대 표면 | `GET /v1/nodes` 에 내장. 별도 `/v1/leases` 없음 | `ADR-065` 결정의 응답 모양 그대로 (`lease{run_id, not_after}`) |
| 우선순위 | 이월. FIFO 만 | 예산. 우선순위는 큐 순서에만 닿는다는 경계는 `ADR-064` §2.2 에 이미 있다 |
| 깨우기 | 임대가 지워지는 모든 지점 뒤에서 `store.WakeQueued` 를 부른다 — `postResult` · `postCancel` · `Reap`(만료 회수) · `postNodes` 의 재기동 감지(`FailRestarted` -> `SettleIfDone`) · `applyStepEffects` 의 부분 반납 · drain 해제를 받은 광고 처리. **부르는 요청의 트랜잭션 안에서 동기로 돈다** | reaper 주기에 얹으면 지연이 주기에 묶인다. 다만 임대를 지우는 자리는 셋이 아니라 여섯이다 — 만료 회수와 재기동 감지 뒤에 안 부르면 대기 Run 이 다음 종료까지 멎는다 (검토 2026-09-04 에서 넓힘). 동기인 이유는 `scene-gates.md` §3 의 CP2 가 「a 가 끝난 뒤 `runctl status <b>` -> `RUNNING`」을 요구해서다 — 비동기면 그 줄이 경쟁이 된다 |
| 확장 opt-in | **security-baseline 켬.** resiliency-baseline · property-based-testing 끔 | 사용자 결정 2026-09-04. 취급은 3절 |
| `dhseo` 장면의 일 | 보드의 **LED 점멸 패턴을 바꾸는 ko 또는 프로그램을 작성**하고 그 보드에서 돌려 확인한다 | 사용자 결정 2026-09-04. 눈으로 성패가 보이는 일이라 CP4 의 판정이 사람 눈으로 닫힌다 |

# 2. 팩이 채운 권장값

1절이 닫지 않은 미정이다. 값과 근거를 적었다. **벗어나면 근거를 적는다.**
머리말의 「정본이 이미 지는 값」 넷은 여기 없다 — 그것은 벗어날 수 있는 값이
아니다.

| 항목 | 권장값 | 근거 |
|---|---|---|
| 호스트 제어판 바인딩 · 포트 | `127.0.0.1:8081`. LAN 노출은 `--listen` 명시 | `127.0.0.1` 은 `ADR-063` §3.3 결정. 포트는 Mediator `:8080` 옆 |
| 중앙 현황판 위치 | Mediator 에 embed. `GET /ui/` 아래 정적 파일. Mediator 기존 포트 | 새 프로세스 없음. `constraints.md` §6 이 리버스 프록시를 뺀다 |
| 폴링 간격 | 둘 다 5초. 화면은 값 대신 「마지막 갱신 시각」을 보인다 | 광고 주기보다 짧으면 의미가 없고 길면 CP4 의 눈이 늦다 |
| `GET /v1/runs` 응답 | `{observed_at, runs:[{run_id, state, verdict, work_id, created_at, ended_at, assigned}]}`. 시간 역순. 필터 `state` · `since` · `work` · `limit`(기본 100) | 정본이 `mediator-api.md` 의 `GET /v1/runs` 절로 이 모양을 이미 받아 적었다 (2026-09-04). **필터가 보는 열을 여기 적는다** — `state` 는 `runs.state`, `since` 는 `runs.created_at` 하한, `work` 는 `runs.work_id` 일치. 열은 `runs` 표의 열만. `verdict` 는 drain 으로 닫힌 `FAILED` 와 진짜 실패를 목록에서 가르는 유일한 열이다. `principal` 필터는 없다 — `ADR-065` 와 같은 이유다 |
| 페이지네이션 | 없다. `limit` 뿐 | `ADR-065` §4 「노드 수가 커지면 페이지 경계를 정한다」와 같은 조건. 이틀 안에 안 온다 |
| `QUEUED` 크래시 복구 | 기동 시 `WakeQueued` 를 한 번 부른다 (`cmd/mediator/main.go`) | 「재기동 후에도 `QUEUED` 가 참」이라는 것 자체는 `ADR-064` §6 이 정본으로 진다 (머리말). 여기 남는 것은 그것을 어디서 부르는가뿐이다 |
| 제어판 LAN 노출의 토큰 | `--listen` 이 `127.0.0.1` 밖이면 정책 파일의 `panel_token` 이 필수. 없으면 기동 거부. Mediator 토큰 재사용 안 함 | 사용자 결정 2026-09-04. Mediator 토큰은 함대 전체의 신뢰 경계라 기계 하나의 제어판에 흘리지 않는다. 이 회차에는 켜지 않는다 — 한 줄이면 된다 |
| dry-run 과 draining | 응답 변경 없음. `busy` 에 draining 을 합치는 것은 `api.go` `submit` 의 `if !dry` 안이다 | 「dry-run 이 draining 을 안 본다」는 `ADR-063` §6 이 정본으로 진다 (머리말). 여기 남는 것은 코드의 어느 분기 안에서 합치는가다 (`api.go:389~395`) |
| 새 패키지의 커버리지 | 패키지별 하한 80% 를 새 패키지에도 그대로 건다. `internal/panel` · `internal/api/ui` 는 DB 없이 도는 테스트로 채운다 | 하한을 집행하는 자리는 `ci.yml:269` 의 `awk -v floor=80` 이고 그 값은 거기 박혀 있다 — 새 패키지는 프로파일에 나타나는 순간 자동으로 걸린다. `.coverage-contract.yml` 은 게이트 입력이 아니라 기준선 스냅숏이고, 지금 낡았다 (`measured_at_commit fa444f2` 가 이 저장소에 없는 객체이고, 실측이 5,979 -> 6,200 statements · 87.5% -> 87.4%). 이 유닛은 그 파일을 안 고치되, 유닛을 닫을 때 낡은 정도를 한 줄로 적는다 |
| 만료 임박 임계값 | `expires_at` 까지 30초 이하면 카드가 흐려진다 | `design/README.md` §5. 값이 어느 문서에도 없어서 여기서 정한다 |
| 갱신 실패 임계값 | 연속 3회 실패하면 카운트다운을 멈추고 S1b 로 간다 | 한 번은 흔들림, 셋은 끊김 |
| S3 「현재 작업」의 출처 | Mediator 조회 — `GET /v1/nodes` 에서 자기 `node_id` 행의 `lease`, 그 `run_id` 로 `GET /v1/runs/{id}` 의 `CLAIMED` 단계. 데몬 로그를 읽지 않는다 | 관측 기준을 하나로 둔다 (`ADR-065` §3). 데몬이 상태 파일을 남기는 것은 새 기계다 |
| S3 의 Mediator 연결 상태 | 「Mediator 마지막 응답 시각」을 보인다. 실패가 이어지면 drain 통보가 늦어진다는 문구 | S1b 의 짝. 로컬 기능은 살아 있고 drain 통보만 Mediator 를 거친다 |
| 트랜스크립트 | **6절이 범위로 들여왔다.** `runner.go` 의 tee 와 링 파일과 제어판의 카드. S4 화면은 여전히 자리만이고 살아나는 것은 S3 의 카드다 | 이 행은 처음에 MVP 밖이었다. 되돌린 근거는 6.1 — 제어판에 하네스 출력이 0 줄이었다 |

# 3. 보안 확장 아래서의 취급

`security-baseline` 이 켜져 있다. 규칙은 **차단성**이다 — 미준수는 단계 완료를
막는다. 그래서 규칙마다 처리를 미리 적는다. **범위가 새지 않게 하는 것**이
목적이다.

```text
   SECURITY-01  전송 암호화     기존 코드 사실로 기록만.  수정 안 함
                               (평문 HTTP · sslmode=disable 은 constraints §6)
   SECURITY-03  로깅            기존 코드 사실로 기록만.  수정 안 함
                               (bootstrapToken 이 stderr 에 토큰을 찍는다)
   SECURITY-07  네트워크        기존 코드 사실로 기록만.  수정 안 함
                               (Mediator Listen :8080).  새 표면은 127.0.0.1 기본
   SECURITY-08  접근 제어       새 표면에 적용.  객체 수준 권한만 해당 없음 —
                               ADR-015 §1 (principal 은 식별이지 인증이 아니다).
                               제어판 127.0.0.1 은 명시적 public 표면이다
   SECURITY-12  인증 · 자격증명  새 표면에 적용.  토큰 하나가 신뢰 경계다 (ADR-010).
                               제어판 LAN 노출의 토큰은 2절.  비밀 관리자는
                               도입하지 않는다 — 토큰은 설정 파일에 산다
                               (ADR-015 §1)
```

**새 표면에는 적용한다.** `enodectl serve` 의 바인딩 기본값 · 정책 파일 권한 ·
`GET /v1/runs` `GET /v1/nodes` 의 토큰 보호 · 입력 검증(`limit` 상한 · 정책 값
enum). 그것이 이 확장을 켠 이유다.

**하지 말 것** — TLS 를 넣는 것 (`constraints.md` §6). 그것을 실으려고
`cmd/mediator` · `internal/config` 를 보안 이유로 고치는 것. 둘은 기존 코드이고
이 절 첫 줄이 「기존 코드 사실로 기록만」으로 정한 자리다.

# 4. 이월 — 이번에 정하지 않는다

이월은 두 종류다. 「범위 밖이라 안 한다」와 「값이 없어서 밖에 있다」.
뒤의 것은 값을 정하는 순간 들어올 수 있다 — 5절과 6절이 각각 그 자리였다.
아래 목록에서 뒤의 것에는 「막고 있는 값」을 함께 적는다.

```text
   역할 맵 키 이름               역할 주입이 MVP 밖.  ADR-045 의 roles 와 충돌 회피는 그때
                                 막고 있는 값 — 계약 문법
   stream-json 전환 여부         같음.  막고 있는 값 — claude.go 의 Argv 와 Decode 를
```

## 5.1 Mediator MCP — 이월에서 범위로

진행자 결정. CP2 가 닫힌 뒤에 들어왔다.

| 전송 | **stdio 하나.** streamable HTTP 를 안 연다 | 사용자 Claude 가 로컬에서 붙는 첫 실물이다. 포트도 TLS 도 안 는다 — `constraints.md` §6 이 TLS 와 리버스 프록시를 범위 밖으로 뒀으므로 HTTP 를 열면 그 문장과 정면으로 걸린다. 원격이 필요해지면 그때 더한다 |

SDK 를 받으면 `go.mod` 직접 의존이 셋에서 넷이 되는데, 유닛마다 「새 Go 의존 0」을 게이트로 세어 온 것이 끊긴다 |


**여덟째를 두기로 닫았다 — `run.get`.** `ADR-022` §9.3 의 목록은 `ADR-025`

2026-09-05 에 여덟으로 승인했다** — 그 회차의 산출물은 이 저장소에 없다.
새 REST 0 · 새 의미 0 · 새 Go 의존 0 은 그대로다.

# 6. 범위에 들어온 것 둘째 (2026-09-06)

4절의 「트랜스크립트 위치 · 보존」이 되돌아왔다. 진행자 결정이고, CP4 가

## 6.1 트랜스크립트 — 이월에서 범위로

**되돌린 근거 — 제어판에 그 물건이 아예 없다.**

처음에 「단계가 끝나면 기록에 봉인되므로 절반은 있다」고 셌는데 **그것은
운영자가 `runctl record` 로 tar 를 푸는 이야기이고 제품 표면의 이야기가
아니다.** 제어판의 「로그」는 `cmd/enodectl/main.go` 의 `tailIndent` 가 읽는
데몬 로그(`logOf` 가 만드는 `<이름>.log`)이고 `design/enode-ux.pen` 의 S4
화면이 「헤더의 「로그」는 데몬 로그다. 다른 물건이다」로 이미 갈라 두었고
`design/index.html` 의 S4 절이 그것을 문장으로 푼다. 하네스가 뱉는 글자는
제어판에 한 줄도 안 나온다.

```text
   제어판에서 지금 보이는 것   데몬 로그의 마지막 50줄.  값이 박혀 있고
                             바꾸는 깃발이 없다 (-f 는 따라간다)
   제어판에서 안 보이는 것     하네스의 출력.  0 줄이다
   기록에 있는 것             단계가 끝난 뒤의 전문.  runctl record 로만 닿는다
```

**그리고 도는 동안은 어디에도 없다.** `internal/enode/runner.go` 가
`bytes.Buffer` 로 통째로 받아 `cmd.Run()` 이 끝나야 `Decode` 를 부른다.
데몬 자신도 프로세스가 끝나기 전에는 아무것도 못 본다.

|---|---|---|
| 되묻기의 웹 표면 | 중앙은 **보이기만** 한다. 답하는 표면은 `runctl` 과 MCP 도구 둘(`asks.list` · `run.answer`) | 중앙에서 답을 받으면 `answerers` 의 403 이 장식이 된다 — `internal/api/api.go` 의 `auth` 가 `X-Enode-Principal` 을 검증 없이 넣고(`ADR-015` 가 식별로 못 박았다) 브라우저에는 그것을 댈 신원이 없다. `constraints.md` §4 가 다중 사용자 권한을 이번 범위에서 뺐다. `runctl` 과 MCP 는 그 사람 기계에서 그 사람 설정으로 돈다 |
| 호스트 제어판의 `stop` | 제어판이 `POST /v1/runs/{id}/cancel` 을 먼저 부르고 데몬을 끈다. Mediator 가 안 닿으면 확인 문구가 「임대 만료로 죽는다」를 말하고 그대로 끈다 | 아무것도 안 하면 그 Run 이 `lease expired: renewal stopped` 로 죽어 **소유자가 껐다는 사실이 기록에 안 남는다.** drain 은 `verdict` 가 `drain:<node_id>` 를 지는데 그 대칭이 깨진다. `Cancel` 이 이미 `cancelled by: <principal>` 을 남기고 그 라우트도 이미 있다 — 새 라우트 0 |
| `GET /v1/runs/{id}` 의 폭 | 요구 능력을 내보낸다. 목록(`GET /v1/runs`)은 2절이 정한 최소 열 그대로 | CP2 가 QUEUED 의 이유까지 재기로 했는데 지금은 **어느 조회 표면도 「이 Run 이 무슨 능력을 기다리는가」를 안 낸다.** `steps[].uses` 는 별칭이라 답이 안 된다. `runView` 주석의 「새 표면을 만들지 않고 이미 있는 조회를 넓힌다 — 표면 개수가 비용이다」가 정확히 그 자리다 |

이유가 한 가지 모양뿐인 것도 셋째 행의 근거다. CP2 가 「함대에 없는 능력은
`422` -> `FAILED`」로 정했으므로 **QUEUED 는 언제나 「능력은 있는데 그것을 가진
노드가 전부 차 있거나 draining」**이다. 답의 모양이 하나인데 그 답을 낼 열이
없었다.

## 7.3 범위가 일곱이 된다

`enode-features.md` 4절의 「필수 — 여섯」이 일곱이 되고 `§3.2.3 되묻기` 가 그
자리다. 관측이 아니라 제어 아래 두는 이유는 게이트가 재는 것이 「답하면 Run 이
이어진다」이기 때문이다 — 대기열(3.2.1) · drain(3.2.2)과 같은 축이다.

5.3 의 「도구 여덟」이 **열**이 된다. `ADR-022` §9.3 의 「감싸기만 한다 · 새
의미 0 개」는 그대로다 — 늘어나는 것은 개수뿐이고 둘 다 기존 REST 를 감싼다.

`design/` 이 **아홉 장**이 된다. 7.1 이 「여덟 장의 사용성 검토」로 적은 것은
그날의 수이고, 그 검토가 S3b 를 낳았다 — `scene-gates.md` CP4 가 drain 을 걸기
전과 건 뒤를 둘 다 보라고 요구하는데 한 장에는 못 그린다.

`scene-gates.md` 의 조각이 **여덟**이 된다. CP7 은 장면 밖이다 — 1절의
`dhseo` 장면에 되묻기가 안 나오므로 CP4 의 조건이 아니다.

# 8. 새 축이 들어왔다 (2026-09-08) — 온보딩 카드뉴스 + Guest Login

5절 · 6절 · 7절은 **이월을 되돌린 것**이었다. 이 절은 다르다 — 3.4 는 요구
팩 다섯 파일 어디에도 있던 적이 없는 **새 축**이다. `v1-run-dhseo-cardnews`
착수 요청이 열었고, 사전 화면 디자인도 없다 — `design/enode-ux.pen` 아홉
장은 이 축을 안 담는다. Functional Design(유닛 `cardnews-guest-login`)이
화면 디자인 산출물을 직접 낸다.

## 8.1 사용자가 확정한 것

| 항목 | 값 | 근거 |
|---|---|---|
| 진입 흐름 | Guest 로그인 버튼 -> 카드 시퀀스 -> 카드를 닫는다(끝까지 넘기거나 닫기) -> 데모용 enode 현황판 자리로 이동 | 착수 요청이 그대로 값으로 박았다. 게이트에서 재론하지 않는다 |
| 트리거 시점 | 카드 시퀀스는 **Guest 로그인 클릭**이 트리거다. 페이지 로드 시점이 아니다 | 같음 |
| 재방문 판정 | 클라이언트 로컬 저장소에 첫 방문 완료를 남긴다. 재방문에 Guest 로그인을 누르면 카드 없이 곧장 데모 현황판으로 간다 | 같음 |
| 범위 경계 | 관리자 화면(S0 -> S1)은 손대지 않는다. 카드뉴스는 독립 화면 — 데모 현황판에 조건부로 섞여 들어가는 구조 금지. 데모 현황판의 실제 내용은 이 축의 스코프가 아니다 — placeholder | 같음. 3.1.1 을 맡는 축과의 경계선 |

## 8.2 이 실행이 닫은 값

미정으로 열려 있던 것을 진행자(이 실행)가 Functional Design 이전에
계약(파일 경로 · 라우트 · 저장소 키 모양)에 걸리는 만큼만 먼저 닫는다.
세부(카드 문안 · 정확한 애니메이션 곡선 · 와이어프레임)는 유닛의
Functional Design 이 낸다.

| 항목 | 값 | 근거 |
|---|---|---|
| Guest Login 버튼 위치 | 랜딩 화면(`GET /ui/`) 안, 관리자 토큰 입력 자리와 나란히 · 시각적으로 분리 — 별도 화면으로 안 뺀다 | 수용 기준 초안이 "랜딩 화면에 ... 분리돼 있다"로 이미 같은 화면을 전제한다. 관리자 로그인 자리는 자리만 잡아 두고(placeholder) 그 안의 실제 동작은 3.1.1 축이 채운다 — "손대지 않는다"는 동작을 안 만든다는 것이지 레이아웃에서 자리를 못 잡는다는 뜻이 아니다 |
| 패키지 · 번들 경계 | `internal/api/ui` 아래 `static/index.html`(랜딩) · `static/cardnews/`(카드뉴스 번들) · `static/demo/`(데모 현황판 placeholder 번들) 셋으로 가른다. 서로 다른 HTML 진입점 · 서로 다른 CSS/JS 파일 | 요구가 건 제약 그대로 — "컴포넌트/번들 단위로 데모 현황판과 분리". 한 파일에 조건부로 섞으면 그 제약을 어긴다 |
| 라우트 | 새 백엔드 라우트 **하나** — `GET /ui/`(정적 파일 서빙, 무인증). 그 아래는 전부 정적 파일 경로이지 별도 핸들러가 아니다. `POST`·상태 라우트 0 | "새 백엔드 라우트는 최소화한다". 이 하나도 3.1.1 축이 어차피 낼 라우트이고 이 실행이 먼저 세운다 — 파일 행렬에 접점으로 남긴다(8.5) |
| Guest 식별 표시 | 클라이언트에서 형용사+명사 조합으로 만든 이름(예 `guest-vivid-otter`)을 생성해 로컬 저장소에 담고 화면에 보인다. **서버에 전달하지 않는다** — 요청 헤더 · 쿼리 · 바디 어디에도 안 싣는다 | `ADR-015` principal = 식별, 인증 아님을 유지하는 가장 좁은 구현 — 서버가 아예 모르면 인증으로 격상될 표면 자체가 없다 |
| 로컬 저장소 키 | `enode.guest.onboarded`(첫 방문 완료, `"1"`) · `enode.guest.id`(생성된 이름) | 네임스페이스를 `enode.guest.` 로 둬 다른 기능이 나중에 로컬 저장소를 쓸 때 충돌하지 않는다 |
| 카드뉴스 재열람 경로 | 데모 현황판 placeholder 에 "카드뉴스 다시 보기" 링크를 둔다. 눌러도 `enode.guest.onboarded` 플래그는 건드리지 않는다 — 강제 재생 쿼리(`?replay=1`)로 다시 튼다 | 가장 적은 상태 변경. 첫 방문 판정 로직과 재생 로직을 분리해 둘이 서로 간섭하지 않는다 |
| 카드 전환 애니메이션 | CSS `transform`(슬라이드) + `transition`. 새 JS 의존 0 — 라이브러리를 안 받는다 | `go.mod` 도 `packaging/` 도 안 건드리는 이 저장소의 관례를 프런트엔드에도 맞춘다. 애니메이션 라이브러리를 받을 이유가 없을 만큼 효과가 단순하다 |
| 카드 소재 | 착수 요청의 시나리오 둘(희귀 구형 보드 · 동료 보드 공유)에 소개 카드 하나 · 마무리 카드 하나를 더해 넉 장. 늘리지 않는다 | "같은 결의 시나리오를 더 넣어도 된다"는 선택이지 요구가 아니다. 카드가 늘수록 관람객이 다 넘기지 않고 닫을 확률이 커진다 — 이 축의 목적은 배경을 주는 것이지 완전한 설명이 아니다 |

## 8.3 보안 확장 아래서의 취급

## 8.5 파일 행렬 접점 — 3.1.1 과 만나는 자리

`internal/api/ui` 패키지 자체와 `GET /ui/` 등록 줄(`internal/api/api.go`)이
접점이다. 이 실행이 먼저 만들고, 3.1.1 을 맡는 축이 나중에 `static/`
아래 자기 화면(S0 ~ S5)을 더할 때 **랜딩(`static/index.html`)의 관리자
로그인 placeholder 자리를 실제 동작으로 채우면 된다** — 카드뉴스 ·
데모 번들 디렉터리는 건드리지 않는다. 병합 순서는 `CONVENTIONS.md` 3.1의
「의존 없는 유닛부터」를 따른다 — 이 축은 3.1.1 에 의존하지 않지만
`internal/api/ui` 패키지 자체를 먼저 세우므로, 3.1.1 이 나중에 병합되는
쪽이 파일 충돌이 적다.

`scene-gates.md` 의 조각이 **아홉**이 된다. CP8 은 장면 밖이다 — 1절의
`dhseo` 장면에 온보딩이 안 나오므로 CP4 의 조건이 아니다.
