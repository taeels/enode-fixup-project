# 하네스 구성요소 팩 — 부칠 수 있는 것은 싣고, 노드에 묶인 것만 광고한다

사내 실측(2026-09-11) 후속 둘 중 하나다. 다른 하나는 `requirements/transcript/`
이고 둘은 독립이다. 이 팩은 **하네스에 무엇을 물리고, 무엇을 막고, 무엇을
광고하는가**를 닫는다.

```text
   decisions.md         이미 정해진 값.  다시 논의하지 않는다
   scene-gates.md       장면 조각 게이트 CA0 ~ CA6.  이 문서의 수용 기준이다
   canon.md             enode-design 과의 연결.  어긋나면 INVARIANTS 가 이긴다
   constraints.md       안 만드는 것 · 구조 불변식 · 접점
```

## 1. 개요

### 1.1 무엇을 만드나

에이전트 하네스가 도는 환경에 설치된 MCP 가 실행에서 거부된다. 사내 실측이
그것을 봤고, 사내 MCP 를 실제로 써야 한다. 그런데 **정본은 이미 답을 갖고
있었다** — `ADR-034`(팩) · `ADR-035`(광고와 요구) · `ADR-067`(경계는 도구에도)
셋이 이 축을 갈라 두었고, 코드는 그중 첫 겹만 구현했다. 이 팩은 그 셋을
코드로 내리고 `ADR-067` 을 초안에서 결정으로 올린다.

```text
   정본이 가른 축        부칠 수 있는 것          노드에 묶인 것
                        스킬 · 서브에이전트 ·      자격증명이 필요한 MCP · 장비를 여는
                        순수 npm MCP · 프롬프트    MCP · 사내 바이너리 · 하네스 자체
                             ▼                          ▼
                        팩이 나른다.  광고도        노드가 선언하고 광고한다.
                        요구도 안 한다             계약이 요구한다
```

### 1.2 실측이 보인 것

사내 실측은 「설치된 MCP 가 거부된다」였다. 로컬에서 그 거부가 어느 층에서
나는지 쟀다 — `claude` 2.1.266 · `claude mcp list` · API 호출 없음.

| 조합 | 계정 커넥터 (claude.ai) | 개인 `~/.claude.json` 서버 | 워크스페이스 `.mcp.json` |
|---|---|---|---|
| 오늘의 enode — `--setting-sources ""` | 통과 | 차단 | 차단 |
| 가짜 홈 (`CLAUDE_CONFIG_DIR`) 만 | 차단 | 차단 | 남음 · 승인 대기 |
| 가짜 홈 + `--setting-sources ""` | 차단 | 차단 | 차단 |
| 가짜 홈 + `project` 소스 + `enableAllProjectMcpServers` | 차단 | 차단 | 로드 |

**오늘 코드는 거꾸로다.** `ADR-067` 이 막으려는 것(계정 커넥터 — 노드를
나간다)은 통과시키고, 열어야 한다고 한 것(노드나 워크스페이스가 명시한 서버)은
막는다. 사내에서 거부된 것이 정확히 뒤쪽이다.

실측이 함께 준 사실 셋.

```text
   --strict-mcp-config    --mcp-config 파일과 함께일 때만 뜻이 있다.  단독은 무변화
   claude mcp list        --strict-mcp-config · --mcp-config 를 반영하지 않는다.
                          그 둘의 효과는 -p 세션 첫 줄의 system/init 이 싣는
                          mcp_servers 로만 검증된다
   .mcp.json 의 승인      project 소스가 꺼져 있으면 파일 자체를 안 읽는다.
                          켜면 저장소의 .claude/settings.json 도 같이 딸려온다
```

### 1.3 코드가 서 있는 자리

```text
   있다     --settings <훅 설정> --setting-sources ""     hook.go WriteHookSettings
            CLAUDE_CODE_DISABLE_AUTO_MEMORY=1              claude.go Fixed
   없다     CLAUDE_CONFIG_DIR 가짜 홈                      ADR-034 §5 「오늘 하는 것」 ①②
            agent.pack · 팩 펴기                           ADR-034 §2.2
            enode.yaml 의 mcp: 선언 · 탐지기 순회 ·          ADR-035 §4.2 ~ §4.4
              mcp.<이름> 광고 키.  detect.go 는 아직
              하네스 하나에서 break 한다
            --strict-mcp-config --mcp-config 허용목록        ADR-067 §2.1
            AgentParams 의 알려진 키 검증                    ADR-034 §5 ④
```

`grep -rn 'strict-mcp-config\|CLAUDE_CONFIG_DIR\|"pack"' internal cmd` 가
0 줄이다. 이 문장은 낡을 수 있으므로 세는 명령을 적는다.

### 1.4 정본

`canon.md`. 설계 정본은 서브모듈 `enode-design/` 이고 어긋나면
`protocol/INVARIANTS.md` 가 이긴다. 이 팩이 정본에 되돌려 올릴 것은
`canon.md` 4절이다.

### 1.5 가치의 고정점

`scene-gates.md` 의 장면 하나다 — **사내 MCP 하나를 요구한 계약이 그 MCP 를
가진 노드에서만 돌고, 하네스는 계약이 요청한 서버와 팩의 스킬만 본다. 계정
커넥터는 0 이다. 무엇을 물렸는지가 Record 에 남는다.** 완결성은 그 장면(CA6)이
끝까지 도는가로 판단한다.

## 3. 기능 요구사항

### 3.1 가짜 홈 — 계장이 홈을 짓고 고정값이 그 주소를 박는다

**목적**: 개인 설정 · 계정 커넥터 · 자동 메모리가 실행에 섞이지 않는다. 팩이
펴질 자리가 생긴다.

**기능 요구사항**:
- 어댑터의 고정값(`Fixed`)에 `CLAUDE_CONFIG_DIR=<계장 임시 디렉터리>/home` 을
  더한다. **값으로 박는다.** 통과 목록에 넣으면 노드에 그 변수가 없을 때 조용히
  안 걸린다 (`ADR-034` §2.1)
- 계장(`Instrument`)이 그 홈을 짓고 오늘의 훅 설정을 그 안의 `settings.json`
  으로 옮긴다. 게이트웨이 인증 필드(`apiKeyHelper` · `env`) 복사는 오늘 그대로다
- **계장 실패와 독립이다.** 계장이 실패해도 홈은 갈아끼워져 있고 비어 있을
  뿐이다 — 틀리면 닫히는 쪽으로 틀린다
- `--setting-sources ""` 는 **유지한다.** 1.2 의 표가 보이듯 이것이 개인 · 프로젝트
  설정과 `.mcp.json` 을 끊는 층이고, 가짜 홈이 계정 커넥터를 끊는 층이다. 둘은
  다른 것을 끊는다
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 도 유지한다. 가짜 홈에는 메모리가 없지만
  값 하나가 두 겹을 만든다

**기존 코드에서 확인된 것**: 자격증명은 홈에서 빌려오지 않는다는 결정이 이미
있다 — 환경변수 경로(`claudeEnv` 의 다섯)와 게이트웨이 필드가 그것이다.
그런데 **개인 OAuth 로그인 노드는 자격증명이 `~/.claude` 의 파일에 산다.** 홈을
옮기면 `Not logged in` 이 된다 (`ADR-034` §3 ① 실측). 이 팩은 그 파일을 가짜
홈에 복사한다 — 값과 근거는 `decisions.md` 2절. `Usable()` 은 실제 홈으로 재는
오늘 그대로다. 같은 파일을 복사하므로 광고와 실행이 어긋나지 않는다.

**보안 요구사항**: 복사한 자격증명 파일은 `0600` 이고 계장 임시 디렉터리와
함께 단계 끝에 지워진다. 임시 디렉터리는 `$OUT` 밖이라 수확되지 않는다.

**수용 기준**: `scene-gates.md` CA1. 개인 서버가 있고 계정 커넥터가 있는 기계에서
단계를 돌리면 `system/init` 줄의 `mcp_servers` 가 허용목록의 것뿐이다. OAuth
로그인 노드와 게이트웨이 노드 둘 다에서 인증이 산다.

### 3.2 MCP 허용목록 — 파일 하나가 정책이다

**목적**: 하네스가 이 단계에서 물릴 서버의 집합을 우리가 정한다. 계약이 요청한
것만 열리고, 나머지는 0 이다.

**기능 요구사항**:
- 계장이 `<계장 임시 디렉터리>/mcp.json` 을 쓰고 어댑터가
  `--strict-mcp-config --mcp-config=<경로>` 를 넘긴다. **등호 형태다** —
  `--mcp-config` 는 가변인자라 뒤따르는 인자를 삼킨다 (`ADR-034` §3 ②)
- 파일의 내용은 셋의 합집합이다
  ```text
     팩의 서버 중 요청된 것   팩 tar 의 mcp.json 중 계약의 agent.mcp 가 이름을 적은 것
     노드 선언 중 요청된 것   enode.yaml mcp: 중 계약의 agent.mcp 가 이름을 적은 것
     워크스페이스 중 요청된 것 워크스페이스 .mcp.json 중 계약의 agent.mcp 가 이름을 적은 것
  ```
  **셋 다 필터를 탄다** (`decisions.md` 6절 ⑥ · 2026-09-12 교정). 처음 이 절은
  팩만 「적힌 것 전부」로 적었는데, 그러면 계약 작성자가 `agent.mcp` 에 이름을 안
  적고도 임의의 stdio 서버를 물릴 수 있고 `--strict-mcp-config` 도 가짜 홈도 그것을
  안 막는다 — 허용목록 자체가 싣기 때문이다. 이 절 머리의 「계약이 요청한 것만
  열린다」와 정면으로 어긋났다. **팩은 정의의 출처이지 허가의 출처가 아니다**
- 계약이 아무것도 요청하지 않으면 파일은 빈 목록이다. 팩이 서버를 실었어도 그렇다. `ADR-067` 이
  「빈 파일을 주면 정당한 것까지 죽는다」고 적은 것은 기준을 보이려는 실측이었고,
  **요청이 없을 때 0 은 의도다**
- 요청한 이름이 셋 어디에도 없으면 하네스를 띄우지 않고 그 단계를 실패로
  보고한다. 사유는 `mcp server <이름> is not available on this node`. 조용히
  빼면 `ADR-035` §3 의 「없음이 실패보다 나쁘다」를 되풀이한다
- **노드가 선언한 이름을 팩이 덮으면 거절한다** — `pack redefines node-declared
  mcp server <이름>` (`decisions.md` 6절 ⑦). 허용하면 계약이 `requires` 로
  소유자의 선언을 보고 노드를 고른 뒤 자기 팩의 정의로 그 이름을 덮어 실행할 수
  있다. **매칭은 소유자의 값으로 하고 실행은 계약의 값으로** 하게 된다
- 파일에는 서버의 이름 · 종류 · 실행 경로나 주소 · 환경변수 **이름**만 적는다.
  값은 적지 않는다 — 노드 환경이 R1 화이트리스트로 넘긴다
- **종류는 `type` 키다.** 선언이 그것을 안 적으면 계장이 채운다 — `command` 가
  있으면 `stdio`, `url` 이면 `http`. 안 채우면 하네스가 그 항목을 `mcp_servers`
  에서 **말없이 뺀다** (`decisions.md` 6절 ㉓). `ADR-035` §4.4 의 예시가 그 모양이다
- **워크스페이스와 팩의 항목은 원문 그대로 옮긴다.** 그 파일들은 하네스의 형식으로
  적혀 있고 우리 어휘에 없는 키(`headers` 같은)를 담는다. 우리 형식으로 번역하면
  잃거나 뜻이 뒤집힌다 — 그 출처의 `env` 는 이름이 아니라 값이다

**수용 기준**: CA4. 노드가 서버 둘을 선언했는데 계약이 하나만 요청하면
`mcp_servers` 에 하나만 있다. 없는 이름을 요청하면 단계가 그 사유로 실패한다.

### 3.3 노드 선언과 광고 — 노드에 묶인 것만 `mcp.<이름>` 으로

**목적**: 계약이 「그 MCP 를 가진 노드」를 고를 수 있다. 매처는 안 고친다.

**기능 요구사항**:
- `enode.yaml` 에 `mcp:` 절을 더한다 (`ADR-035` §4.4 그대로)
  ```yaml
  mcp:
    gerrit: { url: https://gerrit.example/mcp, credential: GERRIT_TOKEN }
    serial: { command: /opt/tools/serial-mcp, args: [--port, /dev/ttyUSB0] }
  ```
- 탐지가 「뜨나」를 확인한다 — `command` 는 resolve 되는가, `credential` 이름의
  환경변수가 노드 환경에 있는가. **실제 연결은 하지 않는다.** 광고마다 남의
  서버를 두드리게 된다. 비싼 탐지 자리(`Detector`, 5분)에 앉는다 (`ADR-068`)
- 뜨는 것만 `mcp.<이름>: "1"` 로 광고한다. 안 뜨면 빠지고, 빠진 것이 곧
  「지금은 못 한다」다 (`ADR-017` 결정 3). 빠진 이유는 노드 로그에 남긴다
- `detect.go` 의 하네스 순회에서 `break` 를 걷고 탐지기 순회로 바꾼다.
  하네스도 `harness.<이름>: "1"` 로 싣고, 옛 `harness` 키는 한동안 같이 싣는다
  (`ADR-035` §4.3 · §6)
- **노드 설정에 안 적힌 MCP 는 광고되지 않는다.** 그것이 부칠 수 있는 것을
  실수로 매칭에 넣는 길을 막는다

**보안 요구사항**: 광고에는 자격증명의 **이름**만 실린다. 값은 어디에도 안 실린다.
이름이 실리는 것 자체가 정보라는 `ADR-035` §8 의 질문은 `decisions.md` 2절이
값으로 닫는다.

**「뜨나」는 존재이지 동작이 아니다** (`decisions.md` 6절 ⑭). 못 잡는 것 셋을
적어 둔다 — 다음 사람이 「검증됐다」로 읽지 않게 하려는 것이다.

```text
   못 잡는다   자격증명이 틀렸다         환경변수 이름만 본다.  값을 안 본다
   못 잡는다   엔드포인트가 죽었다       접근을 안 한다
   못 잡는다   실행은 되나 MCP 가 아니다   CA2 의 가짜 서버 true 가 바로 그 경우다
```

깊은 검증(HTTP 접근 · stdio 구동)을 안 하는 근거는 순연이다 — 5분마다 전 노드가
남의 서버를 두드리면 그 서버가 죽을 때 함대가 함께 죽는다. `tools/list` 로 내용을
아는 것도 범위 밖이다 (`constraints.md` 제외 4 · `ADR-012`).

**열거 면은 이미 있다** (`decisions.md` 6절 ⑬). `mcp.<이름>` 이 attrs 로 실리므로
`GET /v1/capabilities` 와 `runctl capabilities` 에 자동으로 나타난다 — 계약
작성자가 실제로 보는 면이 그것이고, `GET /v1/nodes` 는 운영자 면이다. 열거는
**존재만 답하고 여유는 안 답한다** (`ADR-014` 결정 3) — 조합 가용성은
`runctl dry-run` 이 답한다.

**수용 기준**: CA2 · CA3. 선언 하나가 `GET /v1/nodes` 에 키로 보이고
`runctl capabilities` 에도 나온다. 실행파일을 치우면 다음 탐지 뒤 키가 빠진다.
`requires` 에 그 키를 적은 계약은 그 노드에만 가고, 없는 키는 `422` 다.

### 3.4 워크스페이스 감지 — 허용목록에는 쓰고 광고에는 안 쓴다

**목적**: 저장소가 `.mcp.json` 으로 선언한 서버를 사람이 노드마다 다시 적지 않아도
계약이 요청할 수 있다.

**기능 요구사항**:
- 실행 시점에 계장이 워크스페이스의 `.mcp.json` 을 읽어 계약이 요청한 이름을
  허용목록으로 옮겨 적는다. `project` 소스는 켜지 않는다 — 켜면 저장소의
  `.claude/settings.json` 의 훅 · 권한까지 딸려온다 (1.2)
- **광고에는 싣지 않는다.** 워크스페이스 안의 것은 같은 저장소 · 같은 rev 를
  가진 노드마다 똑같아서 후보를 가르지 못한다. 매칭 정보가 없는 키는 광고만
  무겁게 한다
- 그 항목이 환경변수 자격증명이나 로컬 실행파일을 요구해 노드마다 달라지면,
  노드 소유자가 `enode.yaml` 의 `mcp:` 로 옮겨 적는다. 그것이 그 항목을
  광고하는 유일한 길이다. 자동으로 광고하지 않는 이유는 3.3 의 마지막 줄이다
- 워크스페이스의 `.claude/skills/` 는 하네스가 스스로 읽는지 실측한다 (CA5).
  안 읽으면 팩으로 나른다 — 팩 저장소가 그 디렉터리를 담으면 된다

**수용 기준**: CA4 의 둘째 줄. `.mcp.json` 에 서버가 있고 계약이 요청하면
`mcp_servers` 에 나타난다. 요청하지 않으면 안 나타난다.

### 3.5 계약 문법 — 매칭은 `requires` 에, 실행은 `agent` 에

**목적**: 계약이 「어느 노드」와 「무엇을 물릴까」를 각각 적는다. `ADR-013`
결정 4 의 선 그대로다.

**기능 요구사항**:
- `requires[].mcp.<이름>: "1"` — 이미 있는 문법이다. 속성 키 하나가 늘 뿐이고
  매처는 부분집합 비교 그대로다
- `agent.mcp: ["gerrit", "serial"]` — 이 단계가 물릴 서버 이름. 실행 파라미터다
- `agent.pack: "<blob 이름>"` 과 `in.from: ["<단계>.<blob 이름>"]` — 팩이 어느
  blob 인가. `ADR-034` §2.2 의 문법 그대로
- `agent` 맵의 **알려진 키를 검증한다.** 모르는 키는 `400` 으로 거절한다
  (`ADR-034` §5 ④). 알려진 키는 오늘의 다섯(`model` · `max_turns` · `max_tokens` ·
  `ask` · `harness`)과 이 팩의 둘(`mcp` · `pack`)이다. `max_tokens` 의 개명은
  이 팩 밖이다 (`decisions.md` 4절)
- `runctl example` 에 사내 MCP 하나를 요구하고 요청하는 예시를 더한다.
  `runctl schema steps` 가 새 키를 낸다 — 구조체에서 뽑으므로 저절로 는다
- 계획(`expands`)이 짓는 단계도 같은 문법을 쓴다. 문법 안내(`ADR-053`)에
  `agent.mcp` · `agent.pack` 이 들어간다. 계획이 안 적으면 그 단계는 팩 없이
  돈다 — 오늘 그대로

**수용 기준**: CA3 · CA4. `runctl lint` 가 통과한 계약이 그대로 돈다. 모르는
`agent` 키는 `400` 이다.

### 3.6 팩 — 전달과 출처

**목적**: 계약이 스킬 · 서브에이전트 · npm MCP 정의를 하네스에 실어 보낸다.
`runctl` 을 쓰는 사람도 오케스트레이터도 같은 길을 쓴다.

**기능 요구사항**:
- 팩은 **tar 하나**다. 디렉터리 규약은 `decisions.md` 2절
  (`skills/<이름>/SKILL.md` · `agents/<이름>.md` · `mcp.json`)
- 계장이 `$IN` 의 팩을 가짜 홈에 편다 — `skills/` · `agents/` 는 그대로,
  `mcp.json` 은 허용목록에 합친다. 팩의 `settings.json` 은 이 회차에 읽지
  않는다 (훅 설정과 충돌한다 · `ADR-034` §7)
- **팩의 출처는 팩 단계다.** 계약의 첫 단계가 명령 단계로 `$OUT/pack` 에 tar
  하나를 낸다. 셸이 없으므로 argv 하나로 끝나는 방법을 계약 저자가 적는다 —
  `git archive --remote=<url> -o $OUT/pack <rev>` 나 `curl -o $OUT/pack <tar 주소>`.
  새 전송이 0 이고, rev 가 argv 에 박혀 manifest 에 남고, blob 이라 봉인이 공짜다
  (`ADR-034` §2.2 의 「새 부품 0 개」)
- `runctl` 은 무상태라 파일을 실어 보낼 경로가 없다. 제출 시점에 blob 을 심는
  `runctl submit --pack` 은 **이월**이다 — 매칭 전 쓰기를 허용하는 API 자리가
  필요하다 (`decisions.md` 4절)
- 오케스트레이터(`cmd/iapadapter`)의 설정에 팩 단계의 argv 를 적는 자리를
  두고, 계약 템플릿이 그 단계 하나와 `agent.pack` 을 더한다. 설정이 비면 오늘
  그대로다

**기존 코드에서 확인된 것**: `$IN` 은 `0444` · `0555` 로 잠긴다(`collect.go`).
팩을 펴는 것은 읽기이므로 그 잠금과 부딪히지 않는다. 계장 임시 디렉터리는
`$OUT` 밖이라 수확되지 않는다.

**수용 기준**: CA5. 팩 단계가 tar 를 내고, 다음 에이전트 단계의 `system/init`
줄에 그 스킬이 `slash_commands` 로 보인다. 팩의 서버는 **그 단계가 `agent.mcp` 로
이름을 적었을 때만** `mcp_servers` 에 보인다 (3.2 의 필터).

### 3.7 기록 — 무엇을 물렸나가 봉인에 남는다

**목적**: 봉인된 묶음만 보고 그 단계가 어느 서버와 어느 팩으로 돌았는지 안다
(`ADR-005` 성질 4).

**기능 요구사항**:
- `HarnessResult` 에 허용목록의 서버 이름과 팩의 다이제스트를 남긴다
  (`ADR-034` §5 의 「팩 다이제스트」 자리)
- 하네스 자신의 증언도 남는다 — `system/init` 줄이 `mcp_servers` 와
  `slash_commands` 를 싣고 그 줄이 `logs/` 에 남는다. **이 팩이 그 줄을 나오게
  한다** (`decisions.md` 6절 ⑮ — `Argv` 에 `stream-json --verbose` 한 줄). 게이트
  셋이 그것을 읽는다. **하네스 단계의 링 tee 는 이 팩이 끈다** (`decisions.md` 6절 ⑲) —
  그 tee 가 `logs/` 선별 앞이라 안 끄면 누출이 링으로 간다. 링을 선별과 함께
  되살리는 것과 사건 배출은 `requirements/transcript/` 의 몫이다

**수용 기준**: CA6. `runctl record` 로 푼 묶음에서 서버 이름과 팩 다이제스트가
읽힌다.
