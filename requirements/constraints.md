# enode 기능 추가 예외사항 — 3판

이 워크샵에서 **구현하지 않는 것**이다. 요구사항 문서가 말하지 않은 것을
「빠뜨린 것」이 아니라 「뺀 것」으로 읽게 한다. 1판과 다른 곳은 §5 · §6 · §8
과 보안 확장 항목이다. 끝의 구조 불변식 절은 2판 뒤에 붙었다 —
`unit-boundaries.md` 를 걷으면서 유닛과 무관하게 참인 것만 여기로 옮겼다.

## 제외 기능 (구현하지 않음)

### 1. 실행 중 선점
- 도는 Run 을 밀어내고 자원을 뺏는 것
- run 우선순위에 따른 자동 중단
- 선점 금지 옵션 (선점이 없으므로 금지할 대상이 없다)

근거 — `INVARIANTS` §2 가 `RUNNING -> RUNNING` 을 비멱등으로 두고 「재개하지
않는다」를 결정했고, 종료하면 Record 가 봉인된다(`I4`). 선점은 곧 진행분 폐기다.
`at-boundary` drain 은 단계 도중에 끊지 않는다 — 놓는 자리가 경계뿐이라는 것은
`INVARIANTS` §2 의 바닥이다. 놓인 Run 이 어떻게 끝나는지는 `decisions.md` 1절이 정한다.

### 2. 공정성 정책
- FIFO 외의 대기열 정책 (가중치 · 공평 배분 · 기아 방지)
- 정책을 갈아끼우는 틀
- 대기 상한 · 타임아웃
- 우선순위 (이월. `decisions.md` 4절)

근거 — `INVARIANTS` §1.2 의 `QUEUED` 행이 「대기열을 만들면 공정성 정책이
따라온다. 그건 값이 아니라 새 부품이다」로 예고했고, `ADR-002` 는 대기열을
「별도 ADR 로 연다」로 미뤘다. 부품 하나만 만든다.

### 3. 격리 강화
- OS 수준 샌드박스 (`sandbox: os`)
- 컨테이너 · VM 격리
- `run:` 단계의 도구 제한

근거 — `R7` 이 「하네스가 주는 만큼」으로 정했고 `ADR-042` 가 경계를 노드에 뒀다.

### 4. 인증
- 중앙에서의 소유권 판정
- `principal` 을 인증으로 승격하는 것
- 다중 사용자 · 역할 기반 권한
- `GET /v1/nodes` 에 `principal` 을 내는 것

근거 — `ADR-015` §1 이 `principal` 을 식별로 두었고 자격증명 조사가 미완이다.
그래서 제어 표면을 노드에 둔다.

### 5. 실시간 스트림 · 트랜스크립트
- SSE · WebSocket 표면
- Mediator 를 통한 토큰 단위 트랜스크립트 중계
- ~~노드 로컬 트랜스크립트 tail~~ — **2026-09-06 에 범위로 들어왔다**
  (`decisions.md` 6절). 파일 tee 로 간다. 나머지 둘은 그대로 제외다

제어판의 「현재 작업」은 Mediator 조회로 채우고 데몬 로그를 읽지 않는다.
화면 S4 의 자리는 그대로 두되 **S3 호스트 제어판의 트랜스크립트 카드가
살아난다** — 그 카드가 읽는 것은 노드의 링 파일이고 Mediator 를 거치지 않는다.

### 6. 배포 · 운영
- 대시보드의 인증 · 계정
- HTTPS · TLS · 리버스 프록시 구성
- 다중 Mediator · 고가용성
- 함대 자동 확장
- 페이지네이션 (`GET /v1/runs` 는 `limit` 만)

### 7. 기존 계약 변경
- `success_when` 문법 확장
- Record 봉인 규칙 변경
- 임대 키 변경 (`leases.node_id` 기본키)
- 새 상태 `READY` (`ADR-064` §1.1)
- drain 을 위한 중앙 라우트 (`POST /v1/nodes/{id}/drain` 류). 경로는 광고뿐이다
- `I1` · `I2` · `I4` · `I5` 를 건드리는 모든 것

### 8. 이번에 안 고르는 후보 — **두 종류다**

「범위 밖이라 안 한다」와 「값이 없어서 밖에 있다」는 다른 것이다. **뒤의 것은
값이 정해지는 순간 범위에 들어올 수 있다** — 이 문서에서 그 일이 이미 두 번
일어났고 (§5 의 트랜스크립트 tail · 아래의 Mediator MCP) 둘 다 취소선으로
남겨 뒀다. 다음에 움직일 수 있는 줄이 어느 것인지 여기서 읽게 한다.

**범위 밖이라 안 한다**

- 계정 MCP 커넥터 차단 · 노드를 나가는 도구 차단. **값이 없어서 밖에 있는 것이
  아니라 정본이 아직 결정을 안 했다** — `ADR-067` 이 main 에 들어왔으나 상태가
  **초안**이고 「§5 의 미결 둘이 정해지면 올린다」로 스스로 못 박는다.
  `ADR-065` 는 이제 관측 결정이라 이 축을 안 진다. 이 저장소는 안 만든다
- 장애 주입과 복구 검증. `QUEUED` 크래시 복구는 예외 — `decisions.md` 2절

**값이 없어서 밖에 있다** — 값이 정해지면 들어올 수 있다

- ~~Mediator MCP~~ — **2판을 판 뒤에 범위로 들어왔다.** `decisions.md` 5절이
  전송(stdio)과 토큰 전달(환경변수)을 닫았다. 이 줄을 지우지 않고 남기는 것은
  「왜 밖에 있다가 안으로 들어왔나」를 다음 사람이 여기서 읽게 하기 위해서다
- 역할 주입. 1판에서 고른 것이었고 2판에서 이월했다 — `decisions.md` 4절.
  막고 있는 값은 계약 문법이다
- 보드 살아있음 확인. 포트에 무엇이 달렸는지는 사람이 적은 값이라 보드가 뽑혀도
  광고에 남는다 (`internal/enode/detect.go` 의 주석). 확인하려면 임대와 맞물려야
  해서 `ADR-068` §4.1 · §5.1 이 순연으로 뒀다. 하네스 로그인은 이 자리가 아니다 —
  `ADR-059` 가 이미 닫았다
- 별칭 · 메모 (`ADR-063` §2 의 「자리만」). 막고 있는 값은 그 둘이 광고에
  실리는지다

## 구조 불변식 — 유닛을 어떻게 가르든 참이다

**여기 있는 것은 제약이지 계획이 아니다.** 어느 유닛이 무엇을 맡는지는
**Units Generation 이 정한다** — 이 팩은 그것을 미리 정하지 않는다.

### 임포트 금지 넷

```text
   internal/panel  ->  internal/store     금지.  제어판은 HTTP 로 Mediator 를 본다
   internal/panel  ->  internal/api       금지
   internal/api/ui ->  internal/store     금지.  화면은 정적 파일이다
   internal/enode  ->  internal/panel     금지.  데몬은 제어판을 모른다
```

**기계로 센다.** `go/parser` 로 각 패키지의 임포트를 읽는 **경계 검사
테스트**를 낸다. 패키지 이름이 바뀌면 표도 같이 바꾼다. 검사기는 표를 읽는다.
**첫 장면 게이트의 조건이 아니다** — CP0 에는 검사할 패키지가 아직 없어서
그때 돌리면 항진명제다. 검사는 `internal/panel` 을 만드는 유닛이 함께 낸다
(`scene-gates.md` §2).

**같은 자리에 하나가 더 있다.** 시험은 저장소의 추적 파일을 안 고친다.
지금 `go test ./cmd/enodectl/` 이 `cmd/enodectl/probe.lock` 을 고치고 통과한다 —
유닛 경계 밖이라 이 회차가 안 고치더라도, 첫 장면 게이트가
`test -z "$(git status --porcelain)"` 로 그것을 보이게 한다. 안 보이면 유닛마다
커밋 앞에서 사람이 되돌린다.

**금지가 한쪽 방향뿐인 것에 뜻이 있다.** `internal/enode -> internal/panel`
만 막고 그 반대는 연다 — 제어판이 데몬의 함수를 쓰는 것은 괜찮고, 데몬이
제어판을 아는 것은 안 된다.

### 새 표면의 모양

```text
   새 기능은 새 패키지        기존 패키지에 밀어 넣지 않는다.  임포트가 얽힌다
   겉면은 얇게               Config · Server · New 로 끝낸다.  화면과 제어판은
                            관측 API 를 HTTP 로 부르고 store 를 직접 안 부른다
   api.go 는 등록 줄만       새 핸들러는 새 파일에 짓는다.  api.go 에는 mux 등록
                            한 줄만 는다 — 그 파일이 병목이 되지 않게
```

### 새 표면이 넘어야 하는 차단 게이트 다섯

**기계가 비교 연산자로 판정하고 `continue-on-error` 가 없다.** 넘으면 CI 가
빨개진다. 새 표면을 짓는 유닛은 착수 전에 자기가 어느 줄에 걸리는지 본다.

```text
   crypto/tls T 심볼 (enodectl.exe)      상한 10       ci.yml:485 판정
   net/http  T 심볼 (enodectl.exe)       상한 50       ci.yml:485 판정
   패키지별 커버리지                      하한 80%      ci.yml:269 판정
   허용목록 밖의 스킵 (전 패키지)          상한 0        ci.yml:341-343
   U+2605 을 담은 파일 수                 상한 0        ci.yml:74-79
```

**심볼 둘이 `enodectl serve` 를 규정한다.** 그것은 위임이다 — HTTP 서버를
직접 세우지 않고 `enode` 의 제어판 프로세스를 실행하고 표준 입출력 셋을 잇고
종료 코드를 그대로 쓴다. `cmd/enodectl/setup.go` 가 이미 같은 방법을 쓴다.
상한은 취향이 아니라 사건의 흔적이고 경위가 `scripts/avprobe/README.md` 에
있다 (`ci.yml:467` 의 주석이 가리킨다). 임포트 금지 표와 어긋나지 않는다 —
막은 방향은 `internal/enode -> internal/panel` 하나이므로 `cmd/enode` 가
제어판을 임포트하는 것은 규칙 안이다.

**커버리지 하한이 새 패키지 둘에 걸린다.** `internal/panel` 과
`internal/api/ui` 다. 값은 `decisions.md` 2절이 정했다 — 계약 파일을 안 고치고
DB 없이 도는 테스트로 채운다.

**이 게이트들은 `push` 로는 `main` 에서만 돌고 그 밖에는 PR 로 돈다**
(`ci.yml:2-5`). 유닛 브랜치는 PR 을 열어야 판정을 받는다.

### Units Generation 에 거는 요구 하나

**파일 행렬을 반드시 낸다.** 유닛마다 만지는 파일을 표로 세고, 한 파일을 둘
이상이 만지면 그 자리를 접점으로 적고 처리를 정한다.

**행렬을 이 팩이 주지 않는 이유** — 그것이 그 단계가 결정할 일이기 때문이다.
미리 주면 단계가 옮겨 적기만 한다. 요구는 **산출물을 요구하는 것**이지
산출물을 대신 내는 것이 아니다.
